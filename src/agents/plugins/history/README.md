# @fly-novel/history

历史事件版本 1 格式、受控存储、事件查询和 Agent 工具工作区包。字段、世界时间及兼容策略见[历史资料契约](../../../../docs/workflows/word-initialization/world-initialization-stage-6a-history-contract.md)。本包不创建历史 Agent 或实现角色认知。

`parseHistoryEvent` 和 `formatHistoryEvent` 校验单份 JSON；`validateHistoryEventGraph` 针对调用方提供的完整同世界事件集合校验上级及事件关系目标存在、事件 ID 唯一和上级无环。该检查不读取文件，不核验人物、组织和地点引用，也不推断时间或因果。

`HistoryStore.open` 需要可信世界 ID、已有真实根及 `events/`、`candidates/` 子目录、文件后端、访问模式和 `singleWriterProcess: true`；同一进程中相同世界或根不能重复打开。调用方负责目录准备、提供必要的同世界人物／地点／组织解析器及后端生命周期，并等待 `close()`；此声明不是跨进程锁。默认每个事件或候选最大 1 MiB，事件目录最多 10000 个条目，可由可信应用配置。读取损坏、未知版本、缺失关联或跨世界事件会拒绝，不把错误伪装成无结果。

创建事件生成 ID 并独占写入，未确认事件按读取版本更新；已有候选、确认状态和过期版本会拒绝直接覆盖。已确认事件可创建一份独占的待审候选，候选保留当前事件基线；读取时返回是否过期。当前不提供候选确认、提交或演化历史留存。发布结果不确定时返回 `HISTORY_COMMIT_UNKNOWN` 和相对路径，须先核查实际文件；目录登记和成果保存相互独立。

`HistoryQueries` 按事件权威文件扫描并检验图，支持事件搜索、子事件和上级、关联、时间线及有限的一致性检查。结果的 `scope: recorded` 指仅扫描已记录文档，不代表世界中没有其他历史。多上级查询返回各路径和全部已记录上级；未展开及遍历截断分别说明。时间筛选保留不能判断的候选，仅对单个同基准、同单位的精确时间点排序；约略、区间、未知或多个时间表达不强行比较，不同纪年组之间没有先后。分页版本绑定数据和查询条件；扫描只核验实际文件，不代表跨文件原子快照或历史世界全部覆盖。

`historyToolsPlugin` 将工具注册到当前 Agent 作用域，释放时注销；存储及跨模块解析器由调用方持有。只读绑定不提供写工具，读写绑定支持事件创建、未确认更新和已确认候选。工具和查询是规划者完整视图，可能包含隐藏内容，不能直接作为故事角色的认知视图；角色认知及普通文件、搜索旁路隔离需由后续角色运行机制解决。
