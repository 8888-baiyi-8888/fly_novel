# @fly-novel/character

人物资料、人物关系的格式、受控存储及工具工作区包。调用方显式提供可信世界、目录与权限，并负责存储及解析器的生命周期。

人物资料沿用版本 1 YAML 元数据和 Markdown 正文；关系使用版本 1 JSON，已关联人物只保存 ID。未知版本、损坏资料和不一致的索引被拒绝，不自动迁移或删除已有用户数据。人物关系存储按可信世界和人物解析器核验身份，在单可信写入进程内保证无序人物配对唯一，未建档线索关联后保留原线索。查询按人物、相对方向和关键词筛选；分页版本反映匹配的关系文档，姓名由解析器即时提供，不是跨文件快照。

`CharacterStore.open(root, true)` 仅初始化空目录，现有目录用 `open(root)`，恢复操作可使用 `open(root, false, true)`；使用完毕后等待 `close()`。角色资料的待审提交保留基线及恢复记录；初始化直接更新要求可信调用方确认阶段并提供读取摘要，已确认资料、已有待审候选、未完成操作或版本变化时拒绝。失败恢复使用独立备份和操作记录，无法确定时保留文件并拒绝。取消只在资料发布前检查，发布后继续处理索引和结果。

`CharacterRelationshipStore.open` 打开已存在的真实目录，要求可信应用绑定世界、人物解析器和单写入进程；调用者使用完毕后等待关闭。初始化关系按摘要更新，已确认关系拒绝直接覆盖；发布结果不确定时报告可核查路径。存储使用直接文件访问，不提供跨进程锁、系统级隔离或跨文件事务。

`characterToolsPlugin` 在 Agent 作用域注册人物资料工具并在释放时注销；可信应用可显式开启初始化更新工具及绑定关系工具，插件不拥有存储和解析器。关系工具按 ID 读取当前姓名，区分未建档线索和解析器报告缺失的人物；解析错误不会伪装成不存在。工具面向有权读取完整资料的规划者，不提供角色视角过滤；应用必须限制原始文件及其他读取入口。角色创建 Agent 的具体装配见[应用说明](../../../app/README.md)。

在仓库根目录执行：

```bash
pnpm --filter @fly-novel/character typecheck
pnpm --filter @fly-novel/character build
```
