#`recovery/discovery.ts` 由可信应用提供完整世界配置和相互隔离的现有记录根，扫描讨论、候选、影响报告、审阅、确认及发布记录，复用各业务格式校验并报告未知版本、损坏、身份冲突、读取失败和未配置范围；支持基于快照摘要分页，并指出部分孤立记录。可选 Session 服务列出会话但不证明世界归属或业务完成。扫描不写入、不自动恢复，不提供跨文件事务，旧模块候选、人物索引和世界正文不在扫描范围内。

 世界初始化业务模块

本目录用于组织世界初始化的业务能力，包括世界工作区、资料目录和资料读取；Agent 框架与通用文件工具分别位于 [`agents/`](../agents/README.md) 和 [`tools/`](../tools/README.md)。本目录是源码目录，不是运行时存放世界资料的工作区。

`discussion/` 提供可信应用持有的世界级讨论服务及已有资料适配。调用方预先准备与世界读取根和 Session 根隔离的真实目录及 `discussions/`、`candidates/` 子目录，提供文件后端、所有世界根、所属模块存储和单可信写入进程保证，使用后等待服务关闭。版本 1 候选支持 `active` / `abandoned`；发布时条件升级为版本 2 的 `publishing`，核实后标为 `committed`。核实没有发布时按条件恢复为版本 1 的 `active`，正文和基线保留但文件版本变化；旧读取器拒绝版本 2，未知版本、未知目标类型或损坏时保留并拒绝。候选以目标独占，发布中的候选继续占用目标；更新及放弃要求候选版本，过期基线不能更新。旧模块候选及人物未完成操作不会自动迁移或覆盖；发布结果不确定时按发布记录核查。适配覆盖地点、人物、人物关系、组织及成员、历史、局势、规划、专有内容和负责人授权的现有文件；只支持修改已有目标，新增或删除目标及人物关系新增条目不支持。应用需校验世界与负责人配置并负责借用句柄生命周期；读取候选时校验已存正文格式，写候选时另行核对当前关联和引用。

`impact/` 提供可信应用持有的只读影响线索服务。调用方提供完整世界配置、讨论服务、可选的同世界地图 / 历史 / 组织存储和与世界读取根、讨论根及 Session 根隔离的现有报告目录，负责借用资源生命周期并等待服务关闭。地点检查覆盖已记录直接父子地点、直接连通与已关联历史；人物检查覆盖已关联组织成员与历史。未装配、未关联及无法覆盖的范围明确报告；失败、取消和检查期间候选变化分别标记，不能视为无冲突。报告是严格解析的版本 1 JSON，返回正文、候选版本、范围版本、来源正文及报告摘要；未知版本或身份错误拒绝。`verify` 可复查候选和已检查范围，返回当前、变化或失败；它不检查未覆盖范围，也不是锁、用户确认或提交授权。报告发布结果不确定时按返回标识核查。

`impact/review.ts` 供可信应用保存审阅和用户确认，目录须与世界、讨论、报告和 Session 根隔离，并预先建立 `reviews`、`confirmations` 子目录。审阅记录和确认记录使用严格版本 1 JSON，未知版本拒绝读取并保留原文件。审阅包含报告全文、可核对来源、逐项选项和候选依赖；语义发现由调用方提供，不能把关联线索自动视为已证实冲突。确认要求用户明确继续、逐项知悉未覆盖范围，验证重要冲突和候选依赖，重读报告及其范围；显式选择优先，没有显式选择时仅采用已展示且有效的建议。关闭或取消审阅而不调用确认不会保存确认。确认记录并不发布资料，提交前仍需在受协调的写入边界内重新验证。应用负责确保确认调用来自用户动作，不能将此服务交给模型工具；发布响应不确定时按记录 ID 读取核查。

`impact/commit.ts` 为可信应用提供单个地点或人物的受控发布。调用方先注册覆盖世界读取根、讨论、报告、审阅及发布记录根的 `WorldAccess`，准备独立发布记录目录并提供同世界的讨论、检查、审阅、所属存储及全部 Session 根；只接受已接入协调的本机文件后端，并拒绝业务记录与 Session 根重叠。调用方必须使所有进程内写入口参与协调，保证单可信写入进程，并在服务关闭后释放协调器。服务在协调范围内复核确认、报告、候选、正文及依赖，按版本发布后保存结果并结束候选占用；其他目标和多目标确认拒绝发布。人物发布保留原确认状态，拒绝旧候选，并使用人物初始化操作记录恢复索引。

`impact/batch-commit.ts` 和 `impact/target-publisher.ts` 为可信应用提供逐项发布，覆盖已有地点、人物、人物关系、组织及成员、历史、局势、规划、专有内容和负责人授权的既有文件。发布装配核对完整世界和负责人配置，未由候选适配器绑定到该世界的目标拒绝发布。发布前复核全部选定候选及报告，按用户选定顺序写入；每项重新检查所属模块的图、引用、状态和基线。已确认正文保持原确认状态，旧模块候选存在时拒绝。新增或删除目标以及新增人物关系条目不支持。批次记录是独立严格版本 1 JSON，未知版本保留并拒绝；每项记录实际阶段、基线、预期正文摘要、发布版本和目录核查状态。

批次在失败或取消时停止后续目标，已发布项保留实际结果，未开始项不自动执行；进程中断后先标记停止，再逐项核查。结果不确定时继续占用候选，可信应用展示当前版本并接收用户明确选择；恢复不自动继续后续目标，剩余修改须重新检查并取得新的确认。目录与正文分开保存，发布后核对目录是否未配置、未登记、当前或过期；目录检查失败记录为独立失败并停止后续写入。目录简介不自动重写，可由负责人更新后重新核查。

发布操作记录使用严格版本 1 JSON，记录确认、报告、候选、正文摘要及发布阶段；未知版本保留并拒绝。`reconcile` 按当前正文、人物恢复记录和候选核查：发布尚未开始时可恢复活动候选；正文已核实发布且版本未变化时完成候选状态；发布结果不确定时保持候选占用，须向用户展示实际版本后接收明确决定。用户选择保留基线后的 `failed` 表示当前没有保留本次修改，不证明中断期间正文从未写入。后续正文变化时拒绝自动恢复。记录、正文和候选不是跨文件事务；协调仅覆盖接入的进程内入口，不是跨进程锁或断电持久性保证。

`storage/` 提供世界资料共享存储装配和跨模块引用解析；`world.ts` 按可信世界配置建立共享存储所有者。地图、组织、人物及人物关系、历史、初始局势、世界发展规划和世界专有内容存储由可信应用持有，按需打开并复用各自实例；借用方不负责关闭，所有者结束时等待关闭。人物初始化失败可能已创建索引，因此不能盲目重试初始化。共享能力只在单可信写入进程内生效，不提供跨进程锁。

共享人物与关系的读取能力在首次实际查询时打开对应存储；只装配历史或其他引用工具不会初始化人物目录。真实读取失败会传递给调用方，不表示人物不存在。

共享工作区与资料读取的范围、待确认事项和开发步骤见[第五阶段详细计划](../../docs/workflows/word-initialization/world-initialization-stage-5-workspace-plan.md)。业务代码和测试按实际实现建立；测试放在 `src/world-init/tests/`。

`workspace/config.ts` 的 `validateWorldWorkspaceConfigs` 校验可信应用提供的一组世界配置：每个世界包含稳定世界 ID、读取根、已确认资料根、资料目录保护根，以及主 Agent 和特殊 Agent 的稳定 ID 与专属目录。所有目录必须存在且使用绝对真实路径；同世界各专属目录和受保护目录位于读取根内且两两不重叠，世界 ID 和同世界 Agent ID 唯一，不同世界读取根不能重叠。函数返回冻结的配置快照，不修改目录。调用方须提供本次装配范围内的全部世界；该函数不保存配置、不锁定文件或目录，也不能防止本机并发替换和硬链接。应用装配及当前范围见[应用说明](../app/README.md)。

`workspace/agent-lease.ts` 提供按 `(世界 ID, Agent ID)` 区分的进程内身份占用。调用方在启动前取得占用，仅在启动回滚或资源释放成功后解除；清理失败时保留占用。该机制不记录持久映射或跨进程锁，也不会恢复记忆。

`workspace/catalog/` 包含工作区资料目录相关实现：`format.ts` 定义版本 1 JSON、严格解析和序列化；`initializeCatalog` 只在现有真实目录内独占创建 `catalog.json`，`readCatalog` 校验世界配置及可解析目标的重复别名。成果暂时缺失或不可访问时保留记录，未知版本、损坏、重复字段或重复目标拒绝读取。`path.ts` 的 `resolveCatalogTarget` 将可信世界和 Agent 身份与模型提供的规范相对路径结合，检查现有普通文件属于其专属目录，并返回真实目标的规范相对路径。

`workspace/catalog/service.ts` 提供可信世界级 `CatalogService`，仅打开已经初始化的目录；同一进程中相同世界或目录只能打开一次。可信应用打开时须声明 `singleWriterProcess: true`，并持有服务，通过 `bind(agentId)` 创建共享队列的身份句柄，使用完毕后等待 `close()`。登记和更新使用实际文件字节摘要，记录 revision 控制更新和删除，分页使用目录文件内容摘要检查版本。目录文件读取上限 `maxCatalogBytes` 默认为 16 MiB，可由可信应用配置；目录发布结果无法确认时报告 `CATALOG_COMMIT_UNKNOWN`，不假定操作回滚。发布后检查成果状态，取消或发布过程的外部竞争不构成跨文件事务。该声明不是跨进程锁；应用负责确保同一世界只有一个写入进程，路径检查不能防止恶意进程并发替换及硬链接。主子 Agent 的工具装配见[应用说明](../app/README.md)。

更新简介须先由同一身份句柄调用 `readSource` 完整读取本人负责的 UTF-8 成果，取得绑定路径、记录 revision 和文件摘要的一次性凭据。服务受理更新后消费凭据并重新核对成果，凭据不持久化；关闭绑定或服务会撤销凭据。`maxSourceBytes` 默认 1 MiB、`receiptTtlMs` 默认 5 分钟、`maxReceipts` 默认每个绑定 32 个，均由可信应用配置；超限、过期或文件变化时明确拒绝。凭据证明服务提供了该版本内容，不证明简介语义正确。目录文档仍使用版本 1。

`readSharedSource` 使用可信世界绑定和目录记录 revision 完整读取同世界已登记成果，返回正文、实际内容 SHA-256 和相对目录记录的 `current` 或 `stale` 状态；不签发更新凭据。读取上限使用 `maxSourceBytes`，无记录、旧 revision、读取期间变化、无效编码和过大成果分别拒绝；不自动发现未登记文件。读取结果只描述单次读取，不提供跨文件快照，也不表示用户确认或生成任务完成。

`checkPage` 按路径顺序检查已登记记录，每页默认 50 项、最多 100 项；后续页必须携带首个结果的 `version`。每页返回记录及文件状态、总数、起点、下一位置和 `completed` 或 `cancelled`。取消时保留已完成项，`nextOffset` 指向下一未检查位置；页首及返回前的目录版本不一致时拒绝返回有效页。只有从 0 开始按顺序取得同一版本的所有完成页，才能报告对已登记记录的全量检查完成；文件状态仅反映各自检查时刻，不扫描未登记文件。取消前未取得目录快照、目录损坏或复核失败时返回错误。

人物及关系的格式、存储、查询和工具见[人物插件](../agents/plugins/character/README.md)。
