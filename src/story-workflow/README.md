# 故事级工作流业务模块

`workflow.ts` 负责故事推进顺序。继续时由 `progress.ts` 核对暂停位置，演绎时由 `simulation.ts` 处理模拟器和提前汇报。数据定义和文件读写分别由 `types.ts` 和 `store.ts` 维护。

当前模块管理单轮初步事件规划：调用方提供任务、已知事实和发展方向，导演返回事件初步安排或无可推进事件及原因。程序生成独立运行 ID 与事件 ID；计划不代表事件已发生，也不更新世界状态。导演和模型由[应用入口](../app/story-workflow.ts)装配。

### 读取父子故事

`readStory({ planRoot, collaborationRoot, protectedRoots }, planId, storyId?)` 查询多层推进记录。省略故事 ID 时返回根故事。结果包含保存的任务节点 `node`、直接上级 `parent`、从零开始的 `siblingIndex`、当前演绎或拆分安排 `decision`、可核实的回报 `result`，以及按拆分顺序排列、补充项在末尾的 `children`。根故事的上级和同层位置均为 `null`。

子项状态为 `planned`（安排存在，尚无推进决定或节点）、`cancelled`（上级已取消）、`incomplete`（开始推进但结算证据不足）或 `completed`（回报及其所需证据存在）。拆分故事核对评估与回报，直接演绎故事核对模拟经过与回报。目标节点缺失时可从上级的子项列表核查其安排。目标或上级记录缺失、身份或归属冲突、格式无效时抛错。该入口使用既有版本 1 文件，只检查所查故事的上级链及直接子项，不消费暂停批次。

### 保存和读取场景设置

从[应用入口](../app/story-workflow.ts)调用 `createStoryScene(options, planId, storyId, { order, situation, preparation })`。目录配置沿用故事查询，故事必须已保存直接演绎决定。顺序使用故事内的正安全整数，处境与准备信息必填。程序按运行 ID、故事 ID 和顺序生成 `sceneId`，以 `<sceneId>.setup.scene.json` 在协作目录独占创建版本 1 设置。同一故事内重复使用同一顺序会占用同一场景身份，后一次创建抛错并保留原记录。

`readStoryScene(options, planId, storyId, sceneId)` 按身份读取并核对归属。`listStoryScenes(options, planId, storyId)` 按顺序升序返回该故事的场景。读取会拒绝身份、顺序或格式与文件不一致的记录。只有设置时返回 `pending`。旧运行没有设置文件时列表为空，旧模拟经过和回报仍通过故事记录读取。

### 保存模拟结果并形成故事回报

多层推进将 `recordSceneResult(sceneId, { status, simulation })` 提供给可信模拟器。模拟器应等待每次写入，`simulation` 使用已有的模拟经过格式，包含摘要、变化、未解决事项和依据。只有当前子故事已保存设置的场景可独占写入 `<sceneId>.result.scene.json`。结果文件使用版本 1，保存后由场景查询返回原始记录及状态。状态 `completed` 表示正常结束，`terminated` 表示提前终止且已结算截至终止的经过，`unresolved` 表示结果未决且需要核查。每个场景只写一次，结果保存后可继续处理同一故事的其他场景。

模拟器返回后，程序重读该故事的所有设置和结果。存在待演绎或未决场景时停止形成回报。全部场景结算后，导演获得各场景的模拟原文和模拟器返回的故事级汇总。故事级模拟记录写入后，创建入口拒绝追加场景。场景结果和故事回报分别保存，模型回报失败时仍可单独读取原始场景。

含场景的直接演绎回报使用版本 2，在 `sceneIds` 中保存按顺序排列的引用。调用方可用 `readStory` 的 `result.sceneIds` 逐项调用 `readStoryScene`。每次写读回报时核对场景归属、顺序和结算证据。携带版本 2 回报的暂停快照也使用版本 2，现有版本 1 的回报和暂停文件继续可读。没有场景记录的模拟流程仍按原格式保存。故事级批次计数仍在子故事回报保存且重读后发生。

`PlanStore` 在可信应用选择的现有真实目录中，以运行 UUID 为文件名独占创建版本 1 JSON，保存输入和规划结果。调用方必须提供全部需要隔离的业务根和 Session 根；记录目录不得与它们重叠。未知版本、重复键、损坏、无效身份和不符合格式的记录拒绝读取并保留原文件；不自动迁移其他格式。创建失败或结果不明时报告运行 ID，调用方须核查原文件，不盲目重试或覆盖。单个文件只创建不更新，不承诺跨文件事务、跨进程锁或断电持久性；路径检查不能防止恶意并发替换及硬链接。

`CollaborationStore` 在与规划根隔离的可信目录中，按规划 ID 和事件 ID 保存独占尝试记录、模拟经过和最终协作结果，格式均为版本 1。一次协作仅处理一个初步事件：程序创建父故事与协作身份，并将所选事件作为子故事；最终记录保留所用完整规划、父导演任务、子导演安排、明确标记的模拟经过、子导演回报和父导演接收结果。重新读取时核对尝试、经过和结果的身份及内容；未知版本、损坏或不一致拒绝读取并保留原文件。

调用导演或模拟器前先独占创建尝试记录；同一规划的同一事件已有尝试时拒绝再次执行。模拟经过在回报前单独保存；失败、取消或结果不明时保留已有记录，调用方可读取模拟经过并核查，但不能自动重试。完成结果与尝试和经过是多个文件，不声称跨文件原子、跨进程锁或断电持久性；删除占用、重新尝试及完整恢复不属于本阶段。调用方保证记录根与世界、Session 和其他业务根隔离。

`runStorySiblings` 顺序处理一轮规划中的事件，为它们分配共同的父故事身份。每一项开始前，父导演依据已保存的模拟回报决定继续、调整或取消，程序保存决定及原因；继续或调整时再由父导演结合已有回报制定任务。每次判断和协作使用独立导演实例，相关上下文由程序传递，不依赖实例持续驻留。取消的事件不演绎；任何失败或结果不明都会停止后续处理。

兄弟推进新增版本 1 的父故事身份记录和事件决定记录，不修改已有版本 1 规划、模拟和协作文件。每轮独占创建父故事身份，同一规划不能自动重新开始；失败后保留已有记录以供核查，目前不提供自动恢复或重试。`readStorySiblingDecision` 可读取决定并核对身份。调用方仍须保证单可信写入进程，记录不构成跨文件事务。

`runStoryTree` 使用程序维护的栈逐层推进初步事件：父导演依据本层已完成回报决定当前子故事，子导演判断继续拆分还是直接模拟。拆分后先按顺序处理下级，再形成回报并交给直接上级；每次导演调用后释放实例，不要求上级持续等待。故事节点、拆分安排、逐项决定、模拟经过和回报分别以版本 1 文件独占保存；子节点要求上级已经存在，节点本身不代表演绎完成。取消或失败时停止推进并保留已有记录，当前不自动恢复或重试；模型输出和模拟结果不是实际世界事实。

多层推进时，父导演根据已经保存的子故事回报评估目标。程序允许每个父故事最多安排一个补充子故事，补充安排保存后沿用原有推进流程。目标仍未达成时，最终评估记录调整内容和未解决事项，历史记录保留。条件变化时，父导演也可以提前终止父故事，剩余子故事不再启动。补充安排和最终评估作为独立的版本 1 记录保存，父故事的结果回报沿用原记录。

多层推进的每批数量默认是 5。直接演绎的子故事在回报保存并重读成功后计入本批。拆分、取消和父故事评估均不占用数量。用完数量后，程序仍会结算已经处理完下级的父故事，并在即将启动下一项时保存版本 1 暂停记录。继续时核对原规划、父子关系、决定及结果，再独占消费该暂停批次。失败或取消时保留已有记录供核查，只有正常暂停才提供继续位置。

在多层模拟演绎中，重大情况可使当前故事在 `reportEarly` 处等待。程序请子导演整理提前回报，保存后，依据已记录的父子关系请直接上级决定继续、调整或终止。程序先保存决定，再返回给模拟器。同一子故事中的相同通知只处理一次，内容冲突或并发提交不同通知会停止当前故事。提前汇报和上级决定使用独立的版本 1 记录。上级失败或取消后保留已有记录供核查。终止时保存至终止为止的模拟经过和单独形成的最终回报，并记录终止原因。该子故事不增加本批完成数。

整轮结束以根故事结果和一致的评估记录为凭据。正常的按量暂停使用独立的暂停记录，结果不明的批次只保留已写入的数据供核查。用户选择继续演化后，应用层可以核查上一轮结果并提交更新后的资料形成新计划。调用方区分新一轮的已知事实与本轮模拟经过。

本阶段运行在调用方提供的模拟器上。导演实例按调用创建并释放，程序使用业务记录推进故事和核对恢复位置。

整轮调试用例集中在 [round.test.ts](tests/round.test.ts)。在仓库根目录执行 `pnpm run build:tests`，再执行 `node --test .test-dist/story-workflow/tests/round.test.js` 即可单独运行。

在仓库根目录执行 `pnpm run story-workflow-debug` 可用本机 DeepSeek 配置测试真实导演回复。调试入口把曲水城合成资料发送给模型，使用模拟器提供演绎经过，并把记录保存在终端显示的 `tmp/story-workflow-debug-*` 目录。也可通过 `pnpm run story-workflow-debug qwen` 选择本机已配置的 Qwen。 [调试入口](../app/story-workflow-debug.ts)
