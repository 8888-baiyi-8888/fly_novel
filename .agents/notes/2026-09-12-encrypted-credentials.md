# 本地凭据加密

## 问题

API Key 原先明文保存，需要独立开发命令加密保存、解密查看，并继续使用固定 APP_HOME。

## 决定

使用 Node crypto 的 AES-256-GCM，随机 32 字节密钥保存在 .encryption-key，每次加密生成随机 12 字节 IV，凭据引用作为认证数据。凭据文档版本升级到 2；原 version 1 只能显式 migrate，运行时拒绝明文。普通设置仍为 version 1。

## 影响

加密密钥和真实凭据不提交 Git。密钥遗失且已有密文时拒绝重新生成。写操作以独占锁串行化，临时文件写完后原子替换；进程意外终止可能留下锁，须确认无运行写入者后手动清理。写入时不保留明文备份。加密文件与密钥同时泄露仍能解密，Windows 访问权限由目录 ACL 控制，POSIX mode 不等于 Windows 权限隔离。

## 验证

使用临时目录与虚构凭据验证往返、随机 IV、错误密钥、篡改、引用绑定、迁移、未知版本、密钥丢失和文件锁。类型检查、构建与 CLI 冒烟测试；不调用真实模型 API。
