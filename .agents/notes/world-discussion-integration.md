# 局部讨论集成验证与后续交接

问题：第 8 阶段需要可区分当前正文、候选、基线、候选版本和目标归属的数据，同时不能把会话恢复或候选保存当作确认。

决定：可信应用使用讨论服务读取每个目标的当前正文、候选全文、隐含修改意图、基线及实际候选版本；第 7 阶段不提供提交。关联目标由应用明确授权并在重建时重新提供，目录不是正文或确认凭据。

验证：双世界固定模型替身使用真实地图、人物和组织存储，分别保存地点、人物、成员候选，检查跨世界绑定及直接写入拒绝。另一固定替身样例覆盖问答、连续修改、切换、恢复、取消、失败和放弃。真实模型在隔离世界对同一地点执行两轮修改，候选包含夜间关闭及商队例外，原地点保持不变；该结果只覆盖此样例，内容仍需人工审阅。沙箱内请求返回 `fetch failed`，使用网络权限重试后通过。

复现：先运行 `pnpm run build:tests`，再运行 `node --test .test-dist/app/tests/world-discussion-integration.test.js .test-dist/app/tests/world-discussion-e2e.test.js`；真实模型测试在 PowerShell 中设置 `$env:FLY_NOVEL_REAL_LLM_TEST='1'` 后运行 `node --test .test-dist/app/tests/world-discussion-real.test.js`，需要本机模型配置、凭据和网络。测试输出隔离目录，保留结果供检查。

边界：只支持修改已有目标；新增、删除目标和新增人物关系条目不支持。地图概览及连通候选未接入。应用负责名称检索、同名选择、第一版完整判断和可信目标授权；当前没有独立交互界面。候选和关联读取不是跨文件原子快照；单可信写入进程不提供跨进程锁或系统级隔离。局势起点候选未自动检查历史时间影响。

第 8 阶段须单独实现影响检查、用户选择和受控提交，并核对基线、候选版本、遗留候选及跨模块引用；不得把人物既有单对象提交当作完整跨模块确认。第 9 阶段处理完整初始化恢复及最终交付。
