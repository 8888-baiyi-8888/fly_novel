# 角色卡标识与存储

## 决定

N5 角色卡使用程序生成的稳定 `characterId`，由 `novelId`、规范化角色名的拼音和短哈希构成。N7 书目录在 `characters/` 下保存每个角色的 JSON 文件，并生成角色索引和批量读取汇总；关系条目引用目标角色 ID。N5/N6 和 N7 角色数据标注 schema version 1。

## 影响

N6 角色状态和章节级角色卡、角色状态均携带同一 `characterId`。旧 N5/N6 产物缺少版本或 ID 时，工作流按小说 ID 与角色名计算兼容 ID；未知版本明确拒绝读取。重命名角色会生成新 ID；同名角色在 N5 校验时拒绝，避免无法区分的身份关联。

## 验证

通过 TypeScript 正式构建检查跨模块类型与导入关系。角色存储文件由 N7 workspace 生成，章节流优先读取汇总 JSON。
