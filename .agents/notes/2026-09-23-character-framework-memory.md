# CharacterAgent 复用框架会话记忆

日期：2026-09-23

问题：每轮新建 Deep Agent 导致角色对象无法延续对话；手工 loadMemory 占位接口容易引向重复建设框架记忆能力。

决定：每个 CharacterAgent 延迟创建并持有一个 Deep Agent，使用框架 MemorySaver 和固定 thread_id。不同实例拥有独立检查点，同一实例拒绝并发。仅提交当前消息，历史由框架管理；移除 loadMemory 空接口，保留人物资料、状态和性格的业务接口。

范围：检查点仅存在于内存；未开放文件读写或接入长期记忆、跨进程恢复、正式经历提交。后续长期记忆基于 Deep Agents memory 与存储后端扩展，项目负责角色隔离与记忆业务策略。模型解析成功并创建执行单元后固定模型。失败或取消不承诺回滚框架已保存的部分检查点。

验证：构建测试并运行 CharacterAgent 聚焦测试，覆盖历史传递、实例隔离、并发拒绝、取消初始化及解析失败后的重试；样例通过声明入口构建，未调用真实供应商。
