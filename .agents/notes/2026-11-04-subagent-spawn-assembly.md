# Spawn 可信创建能力与会话边界

## 问题

项目的 Manager 由 bootstrap 返回，父 Agent 的最小身份视图不包含子 Agent 所需的最终模型配置。Spawn 包若直接依赖 Agent 包，后续内置插件装配可能形成包循环。

## 决定方向

可信应用向 Spawn 装配提供现有 Driver 使用的创建函数，由闭包持有 Manager、明确的子 Preset 和插件配置；创建成功后通过同一 Manager 释放。正式 Spawn 必须约定并验证创建函数使用可证明的新会话配置，不将任意回调天然视为安全或隔离。子模型与工具授权必须显式确定，不从父身份静默推导。

## 影响与验证

当前测试用真实 Manager、固定模型替身和两个显式创建的子 Agent 验证独立内存会话、父历史不进入子请求、父 Session 不因子任务变化及分别清理。该测试没有验证正式 Spawn Provider、持久化配置拒绝或任意 Preset 的行为；它们留待实现阶段验证。
