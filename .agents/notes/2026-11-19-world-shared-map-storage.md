# 世界地图存储共享

问题：地图 Agent 自行打开存储，而组织和人物引用需要调用方持有同一地图存储；独占约束使两者无法同时装配。

决定：世界初始化入口按需持有一个地图存储，地图 Agent 借用读写句柄，组织与人物通过已有只读工具或引用解析器借用；独立入口保留自有存储。共享存储在主 Agent 的子运行结束后关闭，外部地图引用与自动共享不能同时配置。

影响：不改变持久化格式、单可信写入进程假设或地图实例内串行语义；人物、组织、历史、局势、发展规划与专有内容可通过既有只读能力使用共享地图。其他业务存储的自动共享需后续接入。

验证：聚焦应用测试覆盖地图委派后人物和组织按实际地点 ID 并发查询、只读工具、单实例并发借用及 Agent 关闭后读取；类型检查与相关独立入口测试用于检查兼容性。

组织存储同样由世界入口按需持有，组织 Agent 借用写入，人物和其他引用方获得各自的只读能力；组织引用地图的解析器使用共享地图。关闭时先释放组织，再释放地图。人物存储的自动共享不属于该次接入。

人物及人物关系存储由世界入口持有并在角色 Agent 与引用方之间共享；组织核验人物时才获取人物存储，避免双方互查时启动循环。人物索引初始化失败可能已产生文件，失败后不自动重试初始化；关闭按组织、人物关系、人物资料、地图顺序执行。

历史存储由世界入口共享，局势和后续规划可核验历史事件。历史存储在其引用的组织、人物和地图之前关闭；单次打开的后端和存储由共享资源一起释放。

初始局势存储由世界入口共享，发展规划与专有内容可核验局势；关闭时先释放局势，再释放其引用的历史及其他存储。

世界发展规划存储由世界入口共享，专有内容可核验规划成果；关闭时先释放规划，再释放其引用的局势及其他存储。

共享资源验证并发打开合并、关闭等待打开、普通失败重试及清理失败禁止重试；不同世界地图实例分别保持独立。现有应用测试覆盖主 Agent 取消子任务及同身份占用。

跨模块引用解析和世界共享存储的统一装配位于 `src/world-init/storage/`；Agent 入口只负责各自运行、工具与 Session 装配。统一所有者按引用依赖的逆序关闭业务存储。

世界专有内容存储在世界入口中同样由共享所有者管理；目前没有额外的专有内容跨模块消费者，独立入口继续自行管理存储。
