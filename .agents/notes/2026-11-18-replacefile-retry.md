# Windows 文件替换 1175 有限重试

独立 .NET 实验中，失败后的 10 毫秒和 50 毫秒单次重试仍会失败，因而不能把一次等待当作保证。原始排查记录及局限见 [1175 排查](2026-11-17-replacefile-1175-investigation.md)。

仅当 Windows `ReplaceFileW` 明确返回 1175 时，原暂存文件最多重试三次，间隔由可信配置控制。重试前核对目标版本、暂存文件身份和完整内容；取消或检查不通过时不发布，持续失败保留原有错误语义。该保护遵循现有单可信写入进程假设，不提供跨进程原子比较和替换。移动操作在原有最后取消点后继续完成。

真实后端实测中，1175 可改变暂存文件的 ctime 而不改变内容、身份和 mtime；因此不直接以原暂存文件的完整版本判断，而在每次重试时检查身份、内容和读取期间版本稳定性。真实 Windows 工作区两轮各 1000 次更新中，底层分别捕获到 6 次、12 次 1175，均最终成功；后一轮抽查一次失败时暂存文件 DACL 与原文件相同。故障注入覆盖成功、持续失败、非 1175 错误、取消以及目标或暂存内容变化；这不证明根因已消除、所有权限配置均已验证或所有环境均可恢复。
