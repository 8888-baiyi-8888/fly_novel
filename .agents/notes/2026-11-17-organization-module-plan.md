# 组织模块规划与成员关系归属

- 问题：组织、人物和地图资料相互引用；人物可能在多个组织任职，重复维护成员资料容易发生分歧。
- 决定：用户确认组织需要独立专用插件，组织与委派工具定义集中放在插件内；组织模块维护成员关系、人物侧查询展示；每个组织和每条关系独立使用 JSON 文件，组织资料采用未展开、概况、详细三个等级。初始化期间组织、组织间关系及成员关系按版本直接覆盖；世界演化后采用待实施的旧内容快照和变更记录方案。秘密成员关系由组织 Agent 和世界规划者读取，故事角色按世界、角色及组织绑定的查询等级读取。
- 影响：现有角色 `faction` 分类不会自动成为权威成员关系，也不自动迁移或覆盖；历史留存和角色查询等级是规划方案，不能宣称已有细粒度访问控制。计划不预设通用跨模块关联服务已经实现。
- 验证：对照世界资料目录、角色资料与工具、地图存储及 Agent 装配，并以修仙宗门、城邦联盟、未建档人物及分级秘密成员访问走查边界；第一步场景见组织模块场景文档，该变更仅涉及规划文档。
