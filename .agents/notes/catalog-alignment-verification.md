# 资料对齐验证

问题：单项目录测试不能证明主 Agent、角色 Agent 和持续 Session 形成可观察的检查与复查链路。

决定：使用真实 Agent 和目录工具运行固定模型脚本，检查主负责人及角色负责人的过期记录、更新和最终状态；重新创建子实例后验证历史会话与旧凭据失效。

影响：测试验证装配和工具行为，不证明真实模型会始终遵循提示词。未配置负责人、并发更新及目录记录重建保留原成果并分别报告。

验证：运行目录服务、主子 Agent、持续身份和委派工具的聚焦测试。

Windows 排查：工作区目录的原生 `ReplaceFileW` 和独立 .NET `File.Replace` 均偶发 1175；同样的 .NET 实验在系统临时目录 2000 次未复现。在工作区一次 2000 次替换中出现 3 次 1175，立即再次调用均成功；受控的禁止删除共享句柄返回 32，因此不能将 1175 直接归因于普通文件占用。一次失败后核对原文件和暂存文件均仍存在。不能据此确定具体驱动或进程，也不能把单次替换结果推断为跨文件事务。聚焦组合测试串行运行 36 项通过，偶发替换失败风险仍存在。
