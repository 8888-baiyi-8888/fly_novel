# 父故事安排审阅

根故事的拆分由可信应用保存，随后进入多层推进循环。嵌套父故事在子导演拆分后进入同一循环。两者都能在首个子项决定写入前暂停，此时导演作用域已释放。

现有批次暂停保存推进栈，恢复先核对原规划、子项证据和场景结果，再独占领取批次。审阅等待也需要可重读的推进栈，另需展示当时的安排和独立保存的决定。批次领取仍代表开始推进。原拆分和历史暂停继续按所属版本读取。

世界初始化的确认入口由可信应用校验任务归属和用户看到的版本。故事审阅沿用可信调用和版本绑定原则，使用故事记录根、规划、父故事和批次定位。模型作用域只处理故事内容。

核对了故事应用入口、多层推进、暂停恢复、故事查询和世界初始化确认入口。
