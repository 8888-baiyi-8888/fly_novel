# Windows ReplaceFileW 1175 排查

问题：组织和目录等更新调用本机文件后端时，替换已有文件偶发失败并向业务层报告发布结果不确定。项目实现先写入并同步同目录的私有暂存文件，关闭该文件句柄后调用 `ReplaceFileW`；失败路径清理暂存目录。

微软对 `ERROR_UNABLE_TO_REMOVE_REPLACED`（1175）的说明为无法移除被替换文件，原文件及替换文件保留原名；这不指出造成删除失败的具体进程或驱动。参考 [ReplaceFileW](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-replacefilew)。

在隔离临时目录使用独立 C# 包装的 .NET `File.Replace`（无备份文件），不调用项目 TypeScript 文件后端：沙箱内，工作区同目录和子目录暂存各 1000 次，分别出现 16 次和 9 次 1175；系统临时目录对应两组各 1000 次均无 1175。沙箱外相同实验分别出现 15 次、13 次，系统临时目录两组均无 1175。工作区在 D 盘 NTFS，系统临时目录在 C 盘 NTFS，因此这些数据不能区分磁盘与目录影响，也不能确定特定过滤驱动。

附加的沙箱内每组 500 次实验中，工作区同目录 7 次及子目录 4 次返回 1175，所有失败的原文件及替换文件仍存在且内容分别匹配替换前和待发布内容。对 11 次失败各立即重试一次，9 次成功，2 次再次返回 1175；系统临时目录对应两组无 1175。该实验不证明重试次数、等待时间或并发条件下始终安全；生产实现没有增加重试或改变发布语义。

同盘对照：仅为沙箱外测试进程将 TEMP 和 TMP 指向 D 盘根目录下新建的独立临时目录，并核对 .NET 获取到该目录。工作区同目录、子目录暂存各 1000 次分别出现 11 次、13 次 1175；D 盘独立临时目录同样两组各 1000 次均未出现 1175。工作区失败时文件存在且内容未偏离预期，24 次失败的即时重试中 22 次成功、2 次再次返回 1175。该对照不支持整个 D 盘普遍失败，但不能确定目录、权限、过滤规则或其他差异中哪一项是原因。

频率对照：在工作区的三个独立目录中依次执行 .NET 文件替换，每组 300 次，每次创建待替换文件之前分别等待 0、10、50 毫秒；出现 1175 的次数依次为 11、1、10。等待发生在创建暂存文件之前，不等同于替换失败后的重试延迟。该次实验未显示失败随操作间隔增加而稳定减少；样本有限，顺序执行也未控制后台活动，不能排除频率或时间窗口的影响。

已知普通拒绝删除共享句柄的对照曾返回 32，不能由此排除所有句柄或过滤器影响。沙箱内外查询 `fltmc filters` 均返回访问拒绝，无法据此确认过滤驱动；观察到安全和索引进程存在不等于它们是原因。后续若要确定根因，需在具备相应系统权限的环境采集失败时的文件系统事件，并进一步比较同盘目录的权限与过滤规则。发布结果不确定时调用方仍需检查实际成果，不得盲目重新创建。
