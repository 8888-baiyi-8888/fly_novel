# 写作 Agent 的职责与执行边界

## 问题

角色、导演、写作和评估需要独立开发并交由工作流组合。人物成长要求状态能随剧情更新，同时支持不同剧情时点的调用。将人物资料、会话历史、Agent 执行和正式内容提交绑定在一起，会使重演、信息隔离与后续编排难以验证。

## 决定

采用 Deep Agents 承担底层执行，四类业务模板通过显式输入和结构化输出提供独立任务能力。运行状态按调用隔离，长期人物状态由小说业务维护并作为输入提供。导演只产出计划，Agent 不自动互相调度；正式状态提交由外部调用方负责。完整目标契约见[模块设计](../modules/agents/agents.md)。

## 影响

Agent 无需依赖工作流即可开发测试，也不要求每个人物拥有常驻进程。调用方承担资料准备、剧情版本绑定和结果采用。Deep Agents 的默认工具与委派能力必须按业务范围审计，不能把依赖默认行为视为已满足权限边界。不引入通用插件注册中心或自有 Harness。

## 验证

本次交付为设计文档，检查文档链接、空白和职责一致性，不声称通过运行时验证。代码实施按模块设计中的阶段与验收用例验证输入输出、生命周期、默认能力和角色隔离；本轮不修改 Agent 示例、依赖或配置。
