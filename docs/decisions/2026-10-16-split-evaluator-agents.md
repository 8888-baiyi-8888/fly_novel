# 将通用评估 Agent 拆分为审计与内容审查

## 问题

章节流的 `audit` 负责对照 Dispatch、角色模拟和场景材料核对剧情落实与事实一致性；`censor` 负责按平台规范审查正文。通用 `EvaluatorAgent` 的提示词没有表达这两种不同依据和判断边界。

## 决定

提供独立的 `AuditAgent` 与 `CensorAgent`，分别使用章节流现有审计和内容审查职责设计专属提示词。两者沿用原评估 Agent 的构造方式，注入应用创建的模型，并通过 `invoke(content)` 接收调用方准备的材料、返回报告；不自行加载配置、访问小说文件或修改正文。

## 影响

Agent 包公共入口和文档分别导出并描述两种职责，通用 `EvaluatorAgent` 不再作为公共模板。章节节点接线由后续工作完成，调用方仍负责准备各自上下文并处理 `PASS`/`FAIL` 报告。

## 验证

类型检查和正式构建检查两类 Agent 的导出及实现；本次不发起真实模型调用。
