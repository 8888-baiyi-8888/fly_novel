# 世界资料共享与读取设计

本文是世界初始化及后续世界演化使用的共享资料和读取能力设计提案，不表示现有代码已经实现。业务流程见[世界初始化工作流开发计划](../workflows/word-initialization/world-initialization-development-plan.md)；具体 Agent 的提示词、配置和内部执行方式不在本文范围内。

## 目标与范围

同一个世界中的用户、工作流和获授权的 Agent 需要以一致方式查找世界资料。资料既包含已确定的世界事实，也包含发展规划、粗略设想和有意保留的空白。读取能力提供可追溯的内容与上下文，支持按需获取，而不要求调用方了解文件路径或一次读取整个世界。

世界资料按世界隔离，可以服务于同一世界中的多部小说。世界事实、角色认知和小说表达是不同内容；角色可以只看到符合其认知和权限的资料。世界演化、小说组织和角色记忆的完整设计不属于本文。

## 资料组织

世界资料以可识别的资料项组织，每项有明确内容、所属世界、可定位的标识以及可追溯的来源和状态。地区、角色、规则、规划或其他设定都可以成为资料项；类别和层级根据世界的实际内容形成，不预设所有题材的分类。资料项的识别不依赖显示名称唯一，例如同名角色需要能够区分。

资料的详略可以不同。一个地区可以只有名称和概况，另一个地区可以有更深的下级结构；没有展开的部分不等于已经确定为不存在。对重要的未定问题或有意留白，应能明确表达其状态，便于后续继续探索；不要求穷举所有未知内容。

资料应区分已确认的事实与约束、发展规划、待审建议和待定内容。发展规划不自动等于未来已经发生的事实。用户提供的要求与 Agent 提出的建议应可区分；具体状态分类、确认粒度和格式需要结合初始化交互确定。

世界资料与用户对话、Agent 的工作记录和本轮修改建议职责不同。对话可以作为来源或讨论依据，但不会仅因出现在对话中就成为确认的世界事实。已交付的世界方案可以继续修改，修改方式由所属工作流控制。

## 共享与存储

世界资料由共享的世界资料存储提供统一读取入口。调用方获得的是同一世界的相应版本或视图，而不是各自维护的独立事实副本；不同世界不得混读。用户可以通过应用审阅资料，Agent 通过工具访问资料。

底层可以按需要把资料分开保存，并使用总入口、分类索引或分层索引定位；总入口不必逐条列出全部角色和地区，一个索引可以指向多个资料项。索引属于存储实现，调用方不依赖固定文件路径或固定分类。文件布局、索引格式、存储介质和具体检索实现尚未确定。

索引或其他查找结构需要随资料变化保持一致。读取遇到缺失资料、无效索引、损坏或不支持的格式时，返回明确错误或不完整状态，不能伪装成没有相关资料。变更既有持久化格式时须明确版本及迁移或拒绝读取策略，不静默误读或删除用户数据。

## 读取能力

读取工具为获授权的调用方提供以下概念能力；工具名称、参数及结果类型在实现前另行确定：

| 能力 | 输入意图 | 结果 |
| --- | --- | --- |
| 查找资料 | 世界范围、名称、关键词或其他可用线索 | 匹配资料的标识、名称、简要说明、状态与来源，必要时说明结果不完整 |
| 读取资料 | 已定位的资料标识及所需范围 | 内容、状态、来源及可定位的引用；内容过长时说明截取或分页情况 |
| 查看关联 | 资料标识及所需关联方向 | 已记录的上级、下级或其他相关资料；关联不代表完整影响分析 |

调用方可以先查找，再按标识读取；名称不唯一时返回候选项，不自行选择并冒充精确匹配。查询不到资料、资料明确留白和查询未覆盖全部范围是不同结果，需要分别表达。结果引用应足以回到具体资料，避免仅返回无法核对的摘要。

工具可根据请求返回与任务有关的资料，但相关性检索存在遗漏可能，不能据此宣称已经找出全部关联或冲突。查找支持的方式、排序、范围限制和是否提供语义检索，由实际使用场景决定；初期不以语义搜索作为必要前提。

## 调用与信息范围

工作流确定当前世界、可读取的数据视图和调用权限。委派任务时，调用方提供任务目标、用户本轮要求和必要线索；被委派方按需使用读取工具补充信息，而不是只依赖一次性摘要。读取结果提供来源与状态，帮助调用方辨别正式事实和尚待确认的建议。

读取范围由业务层依据用途和身份确定，不由 Agent 自行扩大。世界规划任务可能需要全局资料；角色演化需要遵守角色可见范围，不能将全局事实直接当作角色认知。无法访问的资料不得通过查询结果或错误信息泄露；权限模型与角色认知筛选的具体实现另行设计。

## 草稿、修改与一致性

读取工具本身不修改资料。局部优化产生的建议与当前确认方案分开，不能被其他读取方误认为已经确认的事实；需要查看建议时应明确选择相应视图。具体的草稿保存方式和视图切换方式待定。

冲突检查使用修改建议和可能受影响的世界资料，列出发现的问题和处理建议。用户的选择以及未逐项选择时的处理方式遵循[初始化流程](../workflows/word-initialization/world-initialization-development-plan.md#预期使用流程)。确认后由负责修改的流程更新世界方案及查找结构，并展示实际调整；具体写入接口、版本和并发处理不在读取工具中预设。

一次查找或检查没有发现冲突，不代表世界不存在冲突。结果应说明已检查的范围与无法判断的事项；资料变化后，基于旧资料产生的建议是否需要重新检查，由版本和更新流程设计明确。

## 使用示例

用户希望细化安徽的一个城市。调用方在当前世界中查找安徽，读取其现有资料和上层地区描述，并查询与该地区关联的角色、势力或规则。若结果只包含安徽的粗略概况，调用方保留这一事实，不假设其他城市不存在。优化建议另行提交；检查发现角色经历与新的隔绝规则冲突时，向用户展示冲突与处理建议，确认后更新世界方案。

该示例只说明预期行为，不是已经可运行的工具调用，也不要求每个世界都有地区、角色或势力索引。

## 待确定事项与验证

- 资料标识、状态、来源与引用的具体表示，以及同一资料的局部内容如何定位。
- 查找范围、分页、关联记录和不完整结果的表达；索引建立与更新的实现方式。
- 读取视图和权限如何与世界、小说、角色认知及待审草稿关联。
- 资料更新的版本、并发和恢复语义，以及已有产物迁移或拒绝读取策略。
- 冲突检查如何选择范围、报告未覆盖的部分，以及确认后的修改如何落盘。

实现前应以具体使用示例验证查找、读取、同名候选、明确留白、无结果、权限限制和资料来源；实现后还需验证资料更新与索引一致性、损坏或不支持格式的拒绝路径，以及不同世界的数据隔离。检查覆盖范围应与实际支持的查询能力一致。
