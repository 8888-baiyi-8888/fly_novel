# 写作 Agent 模块设计

本文是开发参考，定义 `src/agents/` 的目标契约，供实现与验收使用，不表示所述接口已经存在。范围限于 Agent 建设；工作流编排、小说数据库、界面和正式内容提交不在本轮实现范围。设计取舍见[决策记录](../../decisions/2026-09-22-writing-agent-boundaries.md)。

## 目标与边界

基于 Deep Agents 构建角色、导演、写作、评估四类可独立调用的 Agent。每类 Agent 接收明确任务与上下文，返回可验证的候选结果，后续由工作流组合调用。

| 所有者 | 职责 |
| --- | --- |
| Agent 模块 | 模板、配置解析、输入校验、提示词组装、模型与工具执行、输出校验、取消与失败传播。 |
| 调用方 | 选择 Agent、准备当前任务、绑定小说与剧情版本、控制调用顺序、选择重试或采用结果。 |
| 小说业务模块 | 人物资料、世界观、正文、角色成长、剧情版本与正式内容保存。 |
| 应用组装入口 | 读取配置、解析凭据、创建模型和受限查询能力，再注入 Agent。 |

导演根据人物性格安排事件和处境，不指定角色选择或心理变化，不启动其他 Agent；评估输出问题与建议，不自行改稿；角色自主决定反应并形成状态变化，由业务程序校验和保存整轮结果。Agent 不内置完整创作工作流，不直接写入正式档案或正文，不管理数据库迁移。

## 模板、配置与任务

| 概念 | 内容 | 生命周期 |
| --- | --- | --- |
| 模板 | 固定职责、输入输出契约、提示词规则和工具能力范围。 | 随代码维护。 |
| 配置 | 模型选择、允许的创作偏好、执行超时与调用预算。 | 创建执行单元时校验并固定。 |
| 运行输入 | 本次任务、人物或作品资料、当前状态、相关材料。 | 每次调用独立提供。 |
| 执行状态 | 本次消息、工具结果和临时工作材料。 | 归属本次运行，不共享给其他运行。 |

角色“林舟”和“苏晴”使用同一角色模板，差异来自各自的资料和状态。角色的长期身份不依赖一个长期驻留的 JavaScript 对象或无限累积的消息历史。角色状态有变化时，通过下一次运行输入体现。

首版提供四个显式工厂入口，暂定名称为 `createCharacterAgent`、`createDirectorAgent`、`createWriterAgent`、`createEvaluatorAgent`。这些名称是设计约定，不是当前可导入的符号。新增模板时增加对应输入输出、工厂与测试，不预建动态插件加载和注册中心。

## 四类模板契约

以下字段表示业务语义，不规定持久化 JSON 格式。实现时由所属模板定义精确类型与运行时校验；禁止把所有模板字段合并为一个大量可选属性的通用输入。

### 角色 Agent

作用：根据人物的认知、动机与经历，完成指定范围内的反应或行动推演。

模板结构、个人记忆、行动反馈、跨轮连续性及性格演变与情境表现见[角色 Agent 详细设计](character-agent.md)。角色具备对自身言语、行动及亲历事件的记忆能力，正式记录由业务侧在采用后保存，并在后续运行中提供。

| 输入 | 要求 |
| --- | --- |
| 任务 | 明确需要回应的情境、运行范围和停止条件，不指定人物必须采取的行动或心理结果，不默认为推进完整剧情。 |
| 人物档案 | 身份与背景。 |
| 性格 | 当前长期倾向、表达习惯及特定关系下的情境表现模式；经历可改变长期倾向，短暂表现不等于整体性格回退。 |
| 当前状态 | 当前目标、信念、关系、能力、身体与情绪状态。 |
| 相关经历 | 与任务有关的事件、角色理解及来源。 |
| 已知信息 | 区分已知事实、个人推测和错误认知。 |
| 场景视图 | 角色能观察到的环境、行动和话语，以及本次行动限制。 |

输出分别包含台词、可见行动、内心活动和角色自主形成的状态变化。每项变化说明原因及依据；没有变化时返回空集合，不为填充结果凭空生成成长。状态变化随本轮经历一致保存，不由导演逐项审批。

内心活动与私有认知不能混入对其他角色公开的台词或行动。角色依据自己的认知作出选择，不依据调用方未向其开放的全局事实行动。输出是创作候选，不保证人物判断符合世界真相。

### 导演 Agent

作用：根据作者目标和剧情约束设计场景，提出可交给工作流执行的创作安排。

功能输入、处理步骤、重规划和调用方式见[导演 Agent 详细设计](director-agent.md)。

输入包括创作任务、剧情进度、相关世界观、参与人物状态、场景边界和作者约束。输出包括场景目标、事件与处境安排、节奏安排、参与人物的反应情境和待确认问题。

导演可获得任务所需的全局信息，但角色输入由调用方按角色知识范围重新组装。导演通过实际发生的事件影响角色，不能用剧情目标直接改写性格、知识、关系或人物目标，也不能规定角色必须原谅、信任或帮助某人。角色反应可能偏离导演预期，导演据此调整后续事件。计划不是已经发生的事件，不直接更新正式剧情。

### 写作 Agent

作用：根据创作材料生成或修改正文。

事实依据、视角约束、局部改稿和调用方式见[写作 Agent 详细设计](writer-agent.md)。

输入包括写作或改稿任务、场景计划、人物表现、相关前文、叙述视角、文风、篇幅要求和必须保留的内容。改稿任务必须提供待改正文与修改范围。

输出包括正文草稿，以及影响采用结果的待确认问题；正文和说明分开。写作 Agent 可以进行符合材料的语言表达和衔接，不擅自改变明确约束；需要新增关键设定或改变剧情事实时列出待确认项。采用限制视角时，不把不可见的其他人物内心直接写为视角人物的认知。

### 评估 Agent

作用：根据指定标准检查创作结果，不直接改写待评内容。

标准绑定、证据定位、修订复评和调用方式见[评估 Agent 详细设计](evaluator-agent.md)。

输入包括待评内容、评估范围、标准、相关事实依据和必要上下文。人物一致性、剧情逻辑、节奏与文风通过评估标准区分，不单独创建模板。

输出包括总体结论、问题清单和无法判断的事项。问题包含位置或引用、对应标准、依据、影响程度及修改建议。影响程度表达修改优先级，不作为未经校准的概率。没有依据的判断标记为待核实，不能当成确定冲突。首版不要求通用总分，也不把无问题清单视为作品质量保证。

## 信息输入与提示词组装

| 通道 | 内容 | 规则 |
| --- | --- | --- |
| 固定系统指令 | 模板职责、行为边界、工具说明、输出约定。 | 随模板维护，不包含某次任务的动态人物状态。 |
| 本次任务材料 | 任务、必要资料、当前状态和明确约束。 | 从输入确定性组装，材料与指令分段。 |
| 查询工具 | 大量历史正文、经历、设定原文。 | 按需读取，结果附来源与版本信息。 |
| 应用运行上下文 | 小说、人物、剧情版本和访问范围。 | 由调用方可信绑定，不由模型自行选择权限。 |

首版必须支持不带查询工具、仅凭显式材料执行。完成任务必需的资料直接输入；补充资料可通过注入的只读查询工具获取。输入缺失必需字段时调用模型前失败；执行所需资料不完整时报告错误。角色对剧情信息的不确定通过自主询问、等待或行动体现，不请求导演决定其反应；其他模板按各自契约返回待确认或无法判断结果。

剧情约束、事实与偏好分开输入。可调文风不覆盖工具权限和模板边界。正文、引文、角色发言中的命令按资料处理，不当成系统指令。提示词分段不能替代工具端访问检查。

角色输入不包含其未知秘密或未来经历。查询工具实施相同的角色、剧情时点及版本限制，不能仅依靠“不要查询秘密”的提示词。独立上下文不能阻止共享文件或查询工具泄露资料，因此运行材料、缓存和工具结果也必须按访问范围隔离。

不把仓库根目录的开发协作 `AGENTS.md` 作为写作记忆加载。首版不依赖 Skills 或模型可自行写入的长期记忆工具；角色个人记忆的读取和采用后记录见[角色详细设计](character-agent.md)。引入其他记忆能力时，单独定义内容来源、可见范围和更新归属。

## 调用契约与生命周期

统一外形为 `run(input, options)`，每类模板保留自身输入输出类型。`options` 提供取消信号；执行超时和调用预算由创建配置归一化，不混入创作正文。此处是接口设计说明，不是可运行 SDK 示例。

一次运行依次执行输入校验、上下文组装、模型与工具执行、结果校验，最终成功、失败或取消。只返回完整且通过校验的成功结果；格式不合法的模型输出不能通过类型断言视为有效对象。

- 配置中的模型引用、超时或预算无效时，在创建或最早可验证的入口失败。
- 输入无效时不调用模型；错误说明具体字段，不包含凭据。
- 模型、工具及结构化输出错误保留可诊断原因，向调用方传播，不返回伪成功文本。
- 首版不对完整任务做隐式重跑；底层提供商重试受执行预算约束，重试策略须在接入时明确。
- 调用前已取消时不启动执行；执行中取消或超时后不再发起工具调用，不发布成功结果。
- 调用方持有取消控制权，Agent 清理自己创建的监听器和定时器。无法物理中止的外部请求，其迟到结果不得重新写回已结束的运行。
- 每次调用拥有独立执行状态；复用执行单元时，不把本次消息或人物资料留作其他调用的隐式输入。

首版以最终结果接口为必需契约，流式进度按展示需要单独接入，不在本轮定义自有事件协议。后续流式部分正文属于执行中的候选内容，不能视为成功结果。

## Deep Agents 接入边界

使用 Deep Agents 的模型循环、工具执行及上下文处理能力。项目只封装业务输入输出和必要执行边界，不重建通用 Harness、模型消息协议、工具协议或子 Agent 调度器。

应用入口按照[配置模块说明](../../../src/config/README.md)解析模型配置与凭据，创建兼容所安装 LangChain 版本的模型对象，再注入 Agent。Agent 内部不读取真实配置文件，不硬编码密钥或供应商。项目现有配置读取不等于完成模型适配；提供商接入必须单独验证工具调用与结构化结果。

四类 Agent 首版均独立调用，不互相注册为自动委派的子 Agent。接入时审计安装版本的默认文件工具、通用子 Agent 和其他内置能力；移除或限制超出模板范围的能力，并通过行为测试验证。不能假定传入空 `tools` 或 `subagents` 就移除了框架默认能力。

运行临时材料不挂载正式小说目录或其他角色私有目录。不开放通用 shell、任意路径写入和正式状态更新能力。需要模型工作文件时，使用本次运行独立的临时后端并明确释放方式。

SDK 的精确参数、导入和构建方式以[Agent 包依赖配置](../../../src/agents/package.json)、锁文件及安装版本的公开类型为准。接入阶段验证 Node.js 模块格式与正式构建入口，不复制未经验证的在线示例作为项目启动代码。

官方参考：[配置](https://docs.langchain.com/oss/javascript/deepagents/customization)、[子 Agent](https://docs.langchain.com/oss/javascript/deepagents/subagents)、[记忆](https://docs.langchain.com/oss/javascript/deepagents/memory)。这些链接用于核对依赖能力，不代替本模块业务契约。

## 角色成长与结果归属

角色运行输入表示某一剧情时点的状态快照。角色根据经历及自身理解形成信念、目标、关系、知识、能力或性格变化，并说明依据。Agent 不直接写入正式档案；业务程序验证字段、依据和版本后，将整轮行为、经历与状态变化一致保存，不由导演挑选心理变化。行动尝试不等于外部结果已经发生。

调用方可以将完整角色结果保存到一次试演的临时版本，再把新快照传给下一次运行。试演整体采用或弃用、版本绑定及并发冲突由小说业务与工作流负责，不能保留事件而删除其引发的角色心理变化。改变影响角色反应的事件时从对应快照重新推演，不直接拼接改写的选择和旧状态。重演不复用已结束运行的消息历史。

Agent 输出携带或关联本次输入依据的版本，版本标识由调用方传入并在应用侧保留，不依赖模型复述。正式采用时由业务层校验依据是否仍有效。角色资料与记忆通过应用侧文件存储保存，文件更新、格式版本、重启恢复和拒绝读取规则见[角色详细设计](character-agent.md)的 F9；模型不直接修改正式文件。

## 计划、草稿与报告的保存

导演计划、写作草稿和评估报告是应用保存的产物，不是人物长期心理记忆。其连续性来自显式提供的旧版本产物和有效剧情材料，不依赖常驻 Agent 对象。模型不修改正式文件，也不自动执行后续 Agent。

业务侧拟提供 `saveAgentArtifact({ kind, artifactId, commitId, expectedRevision, result })`，`kind` 为 `directorPlan`、`writerDraft` 或 `evaluationReport`。应用预先生成稳定标识并绑定小说及分支，首次保存明确使用无前驱状态，更新要求期望修订匹配。返回产物修订和提交标识；未知种类、重复标识但内容不同或版本冲突时拒绝，不回退到其他类型。

文件布局草案为小说分支数据目录下的 `artifacts/<kind>/<artifactId>/revisions/<revision>.json`。每份 UTF-8 JSON 封装包含 `schemaVersion: 1`、所属小说分支、种类、产物及提交标识、修订和前驱、`basis` 与完整输出。正文替换列表保存时还要关联基准正文版本，报告关联待评对象版本；模型不能自行指定这些身份和路径。更新发布新修订，保留旧文件；未知格式版本拒绝读取，不能覆盖或删除旧数据。

文件发布、互斥写入、冻结请求、提交查询及中断恢复复用[角色文件持久化设计](character-agent.md)的 F9 机制，事务范围改为单个产物，不复制角色快照或角色状态变更语义。业务侧对应提供 `getAgentArtifactCommitStatus` 和 `resumeAgentArtifactCommit`，参数为产物身份及稳定提交 ID，返回状态与恢复规则沿用 F9；恢复不重新调用模型。当前均是待实现契约，不能把文档视作已有持久化实现。

保存产物不等于采用：计划成为文件不表示事件发生，草稿成为文件不表示成为正式正文，报告成为文件不表示评估通过。正式采用由应用核对依据版本；依据已失效时拒绝直接采用并要求重新准备材料。旧报告允许作为历史保存，但不能绑定到另一个修订。`blocked` 规划或写作结果可以保存为问题记录，不得发布为可执行计划或可采用正文。

本节仅定义产物保存边界，不建立完整工作流。跨模块验证需要覆盖：计划线索不直接进入角色记忆、写作不改写已提交选择、评估不强制角色服从导演、产物保存不触发其他 Agent，以及修订冲突与中断恢复。

## 代码组织与扩展

代码归属为独立工作区包 `@fly-novel/agents`，包边界与构建方式见[包说明](../../../src/agents/README.md)。测试归属为 `src/agents/tests/`。模板实现按本设计推进，包配置不代表业务工厂已经实现。

基础代码通过抽象 `BaseAgent` 和直接继承它的 `CharacterAgent`、`DirectorAgent`、`WriterAgent`、`EvaluatorAgent` 表达模板关系，由包公共入口导出。基类和子类仅提供骨架，不提供执行方法；上文工厂与详细功能仍为目标契约。各模板后续分别拥有自己的输入输出校验、提示词和工厂，基类仅承载确实共享的职责，不增加多层继承体系。

新增模板的要求：说明独立职责，定义必要输入和可验证输出，声明工具范围，实现独立调用，补充拒绝路径及验收用例，更新文档索引。修改现有模板契约时同步调用方；未知模板标识明确拒绝，不回退到其他类型。

## 开发顺序与验收

本节定义四类模板的实施顺序；独立包基础配置与模板能力分别验收。

| 阶段 | 工作 | 验收结果 |
| --- | --- | --- |
| 1. 契约 | 定义四类输入输出、配置边界和固定测试材料。 | 必需字段与信息范围明确，缺失输入有拒绝用例。 |
| 2. 单次执行 | 接入模型与 Deep Agents，打通一个角色任务。 | 无工作流也能独立运行；取消、失败、结构化输出校验可验证。 |
| 3. 四类模板 | 完成导演、写作、评估及角色模板。 | 每类独立通过有效输入、无效输入和输出约定测试。 |
| 4. 隔离与交付 | 验证工具权限、默认能力、并发隔离与构建入口。 | 可安全交由外部调用方组合，不依赖源码隐式启动或历史构建产物。 |

重点验证如下：

- 两个人物和同一人物的两次并发任务不共享消息、临时文件或状态。
- 角色查询不能访问未来经历、其他人物秘密或其他小说资料。
- 导演不指定角色选择或心理变化；角色结果由程序完整校验与保存，失败或弃用不留下部分状态，重演使用指定快照。
- 写作结果正文与说明分离；评估有问题依据，信息不足时明确无法判断。
- 无效模型输出不会成为成功结果；工具异常、超时、取消及迟到响应均有对应行为测试。
- SDK 默认能力确实符合工具范围，正式构建产物可以通过声明入口运行。

结构与生命周期测试使用固定数据和模型替身，不要求凭据。真实模型验证单独执行并记录供应商、模型、任务和结果；缺少凭据时明确跳过。文学质量通过固定任务的人工评估或专项评测判断，不以易波动的全文精确匹配替代。实际检查命令沿用[项目入口](../../../README.md)，实现阶段按变更范围选择检查，不把文档完成等同于运行测试通过。
