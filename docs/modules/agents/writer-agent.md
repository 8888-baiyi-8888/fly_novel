# 写作 Agent 详细设计

本文定义正文生成与改稿模板的目标契约。公共执行与产物保存规则见[总设计](agents.md)，事件规划见[导演设计](director-agent.md)，人物行为与状态见[角色设计](character-agent.md)。接口及示例为待实现草案。

## 一、需要实现哪些功能

写作 Agent 把已确认的事件与角色表现写成正文，负责语言、叙述和衔接，不通过改写正文替角色重新选择。导演计划只是创作参考，未发生的步骤不能直接写成正式事实。

| 编号 | 功能 | 需要达到的效果 |
| --- | --- | --- |
| W1 | 写作材料与范围校验 | 区分新写和改稿，绑定正文及剧情版本，明确事实与可润色范围。 |
| W2 | 叙述视角与表达约束 | 按视角、文风和篇幅组织叙述，限制私有信息使用。 |
| W3 | 正文生成 | 将有依据的行为、台词和环境写成连贯正文，不新增关键剧情结果。 |
| W4 | 局部改稿 | 在指定段落内修改，保护范围外正文及明确要求保留的内容。 |
| W5 | 结果校验与稿件保存 | 返回正文与问题说明，保存草稿修订，正式采用不回写人物心理。 |

## 二、每个功能如何实现

### W1：写作材料与范围校验

#### 输入信息

| 字段 | 必需信息 | 来源 |
| --- | --- | --- |
| `context` | 小说、分支、剧情版本及正文依据版本。 | 应用绑定。 |
| `task` | `mode` 为 `draft` 或 `revise`，写作目标及场景范围。 | 作者或外部流程。 |
| `events` | 已确认的事件、顺序、环境反馈及来源。 | 场景记录，不能由计划替代。 |
| `characterTurns` | 已保存的台词、动作、可授权使用的内心及对应版本。 | 角色结果，保留行为的完成或待反馈状态。 |
| `contextText` | 相关前文及稳定段落 ID。 | 正文版本，可显式为空。 |
| `narration / style / length` | 视角规则、表达要求、篇幅目标或硬上限。 | 明确输入，不在执行路径隐藏默认值。 |
| `preserve` | 必须保留的引文、事实和段落引用。 | 输入约束，允许空列表。 |
| 改稿专有输入 | `sourceText`、`editableBlockIds` 和修改要求。 | 原稿及指定修订，改稿时必需。 |

可选 `planReference` 仅提供导演的场景目的和节奏参考。角色材料应与实际事件对应，跨版本矛盾不由写作 Agent 自行选择一个当真。

#### 处理逻辑

1. 按任务类型校验输入；改稿缺原稿或范围时在调用模型前失败，不回退为新写。
2. 校验事件、人物表现、原稿及保留引用，区分已经发生的行为与尚待反馈的尝试。
3. 将叙述偏好与剧情事实分开。偏好要求“更亲密”不允许新增告白或把戒备改成信任。
4. 材料完整但事件之间有矛盾，或必须跨过缺失的关键结果才能成文时，返回 `blocked`，不擅自补剧情。

#### 输出与状态影响

得到本轮可写内容与修改边界，不更新剧情或角色。查询只补充本次授权范围内的材料，查不到不是允许编造的依据。

#### 验证

验证改稿必需字段、失效段落引用、计划事实混用及人物与事件版本冲突。

### W2：叙述视角与表达约束

#### 输入信息

`narration` 指定第一人称、限制第三人称或全知视角；受限视角须指定视角人物。`style` 提供文风、节奏和语言要求；`length` 区分目标和硬约束。输入内心材料标明所属人物与可叙述范围。

#### 处理逻辑

1. 应用按视角过滤材料；限制视角不能直接读取他人私有心理，仅凭可观察表现表达推测。
2. 全知叙述可以使用获得授权的多人物内心，但叙述者知道不等于场景中的角色知道，不回写角色认知。
3. 依据文风调节句式、描写密度和停顿，不改变事实、选择和台词含义。首版角色已说出的台词原文保留，语言衔接写在叙述中。
4. 篇幅约束统一按正文去除空白后的 Unicode 码点计数，标点计入、说明不计入；该单位写入接口说明，不混称词数。无法同时满足硬上限和保留内容时返回受阻结果，不删掉关键事实。

#### 输出与状态影响

输出叙述约束供 W3、W4 使用。硬性篇幅由程序复核，文风与视角一致性由固定材料评估，不把结构校验当成文学质量保证。

#### 验证

检查限制视角泄露、全知信息不进入人物记忆、台词原文保留，以及中英文混合篇幅计数的一致性。

### W3：正文生成

#### 输入信息

使用 W1 的事件与角色表现、W2 的叙述约束和相关前文。正文不需要另建人物长期记忆，只读取当前写作范围内的已授权材料。

#### 处理逻辑

1. 按已确认事件顺序组织段落，可调整语言呈现顺序，但不能改变真实发生的因果关系。
2. 将角色台词、可见动作和允许叙述的内心融入正文。允许语言性衔接，不新增会影响因果、资源或人物认知的设定。
3. 对待反馈动作只写已发生的尝试；例如写伸手夺信，不补写对方被制服或信已到手。
4. 固定提示词明确“呈现实际发生的内容，不实现尚未发生的导演目标，不重新选择角色心理”。关键材料不足时返回问题，不写一段看似完整却改变剧情的正文。

#### 输出与状态影响

成功草稿由有序 `blocks` 构成，每项含本轮唯一局部 `id`、`text`、非空 `sourceRefs`。引用可指向事件、角色表现或前文，程序校验引用存在，语义是否忠实另行评估。应用保存时生成正式正文段落标识。输出本身不创建剧情事件或角色记忆。

#### 验证

验证拒绝将计划当成事实、等待结果的动作不被写成成功，以及正文没有擅自增加承诺、能力或秘密披露。

### W4：局部改稿

#### 输入信息

原稿 `sourceText` 提供稳定段落 ID、内容和正文版本；`editableBlockIds` 指定可改段落；`revisionRequest` 描述修改目标；`preserve` 提供必须原样保留的内容。涉及事实调整时还需先提供新版本的实际剧情材料，不接受用改稿直接改人物选择。

#### 处理逻辑

1. 程序冻结原稿及依据版本，验证可修改段落属于原稿，范围不明确时拒绝。
2. 模型只返回指定段落的替换内容，不能返回整本覆盖文本。首版不支持段落插入、删除或重排；扩大范围由外部明确发起新任务。
3. 程序检查所有替换项 ID、重复项和保留引文；将有效替换应用到原稿副本，范围外逐字保持不变。
4. 无需修改时允许空替换列表。正文版本已变化时保存拒绝覆盖，不将替换应用到相似但不同的段落。

#### 输出与状态影响

改稿输出 `replacements`，每项含 `blockId`、完整替换 `text` 和 `sourceRefs`。应用组装新稿后检查视角、保留内容及篇幅约束，验证不通过不发布为可采用稿件。改稿不删除原稿。

#### 验证

验证范围外文本一致、未知或重复段落拒绝、精确保留引文、版本冲突和空修改。

### W5：结果校验与稿件保存

#### 输入信息

创建时注入模型、执行配置及可选受限资料查询器。保存时提供草稿产物 ID、提交 ID 和期望修订，读取与写入权限由应用持有。

#### 处理逻辑

1. 按公共生命周期执行，所有模型输出都通过模板自己的结构校验。
2. 输出区分 `ready` 和 `blocked`：`ready` 的 `draft` 按任务类型含 `blocks` 或 `replacements`；`blocked` 的 `draft` 为 `null`，`openIssues` 非空。问题包含涉及来源、缺失或冲突、受影响范围，不混入正文。
3. 应用按总设计保存草稿修订，明确区分“保存候选稿”和“成为正式正文”。有阻断项时可保存问题报告，但不能发布为正式正文。
4. 正式采用前核对剧情及原稿版本，原样保留角色已提交的选择和状态。文稿需要改变事件时先返回剧情处理，再基于新事实重新写作，不能靠润色反向更改人物经历。

#### 输出与状态影响

返回 `{ basis, output: { status, draft, openIssues } }`。应用保留各稿件版本，写作 Agent 不调用导演、角色或评估 Agent，也不直接写正式文件。

#### 验证

验证正文与说明分离、两种输出分支、取消后无成功草稿、保存冲突、重启加载及采用时依据失效拒绝。

## 三、代码的外部使用方式

以下为设计伪代码，接口尚待实现。`novelService`、上下文和标识由应用提供，不是 Agent 包导出；模型由应用声明的初始化入口创建。

```ts
import { createWriterAgent, type WriterAgentOptions } from "@fly-novel/agents";

async function writeScene(dependencies: WriterAgentOptions, signal: AbortSignal) {
  const agent = createWriterAgent(dependencies);
  const input = await novelService.loadWriterInput({
    storyRef,
    task: { mode: "draft", objective: "写出渡口这段已发生的互动" },
    narration: { kind: "limitedThirdPerson", characterId: viewpointCharacterId },
    style,
    length,
  });
  const result = await agent.run(input, { signal });
  if (result.output.status === "blocked") return result;
  await novelService.saveAgentArtifact({
    kind: "writerDraft", artifactId, commitId, expectedRevision, result,
  });
  // 保存草稿不改变正式正文，不更新角色状态。
  return result;
}
```

改稿时仍调用 `run`，改为 `task.mode: revise`，并提供原稿、`editableBlockIds` 和 `revisionRequest`。应用先按替换列表组装候选稿，再进入保存或评估流程。例如要求“语言更简洁”，可以压缩叙述，不能把林舟拒绝合作改成答应。
