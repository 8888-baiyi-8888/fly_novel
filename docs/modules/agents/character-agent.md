# 角色 Agent 详细设计

本文是模块设计参考，按功能清单、功能实现方式和外部使用方式组织。文中的接口和 TypeScript 示例是待实现的契约草案，不是当前可运行的 SDK。公共执行规则见[写作 Agent 模块设计](agents.md)，公共入口与构建方式见[包说明](../../../src/agents/README.md)。

## 一、需要实现哪些功能

角色 Agent 根据人物设定、记忆和当前场景，生成符合人物认知与动机的反应，并通过后续记忆输入保持跨轮连续性。同一个角色模板适用于不同人物。

| 编号 | 功能 | 需要达到的效果 |
| --- | --- | --- |
| F1 | 人物设定与状态加载 | 使用人物身份、性格、表达习惯、目标、关系及身体情绪状态。 |
| F2 | 分层记忆与线索唤回 | 近期互动完整提供，较远经历以摘要提供，沉寂记忆遇到相关线索才检索加载。 |
| F3 | 任务与场景感知 | 理解本次要回应什么，承接未完成互动，只接收人物可知的信息，并在指定范围内行动。 |
| F4 | 角色反应生成 | 处理目标、关系和底线之间的动机冲突，按顺序生成台词和动作，单独输出内心活动。 |
| F5 | 行动反馈与状态变化 | 区分尝试和结果，由角色自主理解事件、作出选择并形成有依据的关系或状态变化。 |
| F6 | 经历记录与跨轮连续性 | 采用后的言语、行动和经历进入个人记忆，下次调用能够使用；弃用内容不污染正式记忆。 |
| F7 | 执行控制与结果校验 | 校验输入输出，支持取消、超时和预算，隔离不同人物及剧情版本。 |
| F8 | 性格演变与情境表现 | 经历和关系变化影响当前性格；特定情境允许旧有表现逐渐显现，同时保留后来的成长。 |
| F9 | 文件持久化与更新 | 将人物快照、原始经历和派生记忆保存到文件，支持一致提交、重启恢复、去重和版本校验。 |

F1 至 F5、F7 和 F8 中的人物反应及状态变化由角色 Agent 自主产生。导演根据人物性格安排事件和处境，通过经历影响角色，不指定角色必须选择什么、信任谁或产生什么感受。F6 由调用方与小说业务模块保存整轮结果，不审批或挑选角色心理变化。应用侧负责记忆组装、索引及摘要维护。首版不要求向量数据库、概率遗忘或记忆删除机制、完整剧情编排或模型直接写入长期记忆。

## 二、每个功能如何实现

以下按“输入信息、处理逻辑、输出与状态影响、验证”描述每项功能。字段是目标契约，不表示已有代码实现。F1、F2、F3 准备本轮材料，F4 结合 F5、F8 的规则生成角色反应，F7 管理整个运行，F6 定义保存语义，F9 在应用侧实现文件读写。功能划分不要求分别调用模型，也不要求建立九个独立类。

### F1：人物设定与状态加载

#### 输入信息

| 信息 | 必须包含什么 | 来源 |
| --- | --- | --- |
| `context` | 小说、人物、剧情版本、截止时点和状态版本。 | Agent 内部运行时根据初始化身份及已保存快照绑定，不能由模型或调用方场景覆盖。 |
| `profile` | 姓名、身份和背景。过去的性格可以作为经历描述，不作为当前性格覆盖值。 | 初始设定和已保存档案。 |
| `state` | 当前目标及轻重缓急、信念与人物底线、关系、能力、身体和情绪状态；重要判断附依据。 | 当前剧情版本的角色状态。 |
| `knowledge` | 亲历或已知信息、他人转述和个人推测，区分来源与人物理解。 | 角色可知材料，不包含作者掌握但角色未知的真相。 |
| `personality` | 当前性格与关系情境模式，结构见 F8。 | 当前人物快照。 |

以上分组由 Agent 内部运行时明确加载；无记录的集合可以为空，未知信息显式表达，不能把缺少字段当作角色失忆。关系是本人对特定对象的态度，不默认双方对称。调用方不传入这些快照字段。

#### 处理逻辑

1. Agent 内部运行时按初始化身份读取同一剧情版本和时点的档案与状态，拒绝不存在或无权访问的快照。
2. 角色运行入口检查已加载材料的必需字段及类型。不同用途的 ID 使用专用类型；外部来源引用由所属读取入口检查，不能用类型断言替代验证。
3. 保留事实、转述与推测的区别。例如“苏晴说没有拿信”不能归一化为“苏晴没有拿信”，也不能附加角色不知道的真假判定。
4. 为本次运行建立独立材料，不从复用 Agent 实例中继承人物数据，不给缺失背景自动补故事。

#### 输出与状态影响

得到本轮人物快照，交给 F4 使用。加载不改变正式档案；内部资料缺失时在模型调用前失败。人物不知道某件剧情事实属于合法认知状态，不等于调用方输入错误。

#### 验证

验证人物隔离、版本不匹配拒绝、必需字段缺失拒绝，以及转述和猜测没有被转换成客观事实。

### F2：分层记忆与线索唤回

#### 输入信息

| 信息 | 必须包含什么 | 来源与使用时机 |
| --- | --- | --- |
| 访问上下文 | F1 的人物、版本和截止时点。 | 绑定全部记忆读取和来源直读。 |
| 原始经历 | 来源事件、顺序或剧情时点、参与者、内容性质、实际言语和行动、已知结果、私有理解及感受。 | 业务侧已保存且角色可知的事件。 |
| 当前场景和任务 | 正在进行的互动、已识别人物、地点、物件、话语和本次反应范围。 | 应用用于选择材料和提取回忆线索。 |
| 未决事项及当前影响 | 未兑现承诺、未解决冲突、当前关系和信念的依据。 | 当前快照及相关事件，防止只按时间遗漏重要内容。 |
| 组装配置 | 近期范围、远期摘要范围、材料预算及检索容量。 | 应用配置入口校验，不在提示词中隐含固定天数。 |
| 可选 `memoryReader` | 受限查询与按来源读取能力。 | 应用注入，供运行中补充历史；不提供时依靠显式记忆。 |

Agent 内部运行时准备这些材料，并向底层框架组装 `memories.recent`、`memories.summaries`、`memories.recalled` 三组；无内容时各传空列表。原始经历库、完整索引和组装配置不作为全量模型输入，也不作为调用方运行参数。

#### 处理逻辑

1. **先限定范围。** 过滤其他人物私有记录、未来事件和无权访问的剧情版本；摘要、索引及来源直读同样受限。
2. **确定近期完整记录。** 按剧情时间和互动连续性选取当前及紧邻的相关经历，保留人物实际感知的原话、动作顺序与反馈。尚未完成的互动优先保留，不直接按程序时间或消息数截断。
3. **保留仍有影响的事项。** 未兑现承诺和未解决冲突持续提供必要内容，直到事件明确解决。重要关系和信念保留在当前状态，历史细节不必永久加载全文。
4. **生成较远摘要。** 对较远且与任务相关的经历提取参与者、事件、结果、人物理解和影响，附来源版本、覆盖范围与完整性说明。摘要是可重建材料，不覆盖原始记录，不能把推测写成事实或把尝试写成成功。
5. **按线索唤回沉寂记忆。** 从当前可感知材料提取旧称呼、人物、地点、物件或事件主题，通过标识、别名和关键词索引关联旧事，结果放入 `recalled`。默认不加载沉寂正文或全量标题；不要求向量数据库，不保证未知别名或相似处境一定命中。
6. **去重并控制材料量。** 相同来源去重，精确措辞需要核对时读取原文。超长场景仅压缩已经结束且不影响接续的片段；当前互动、未完成动作及必需反馈仍完整保留。必需材料超预算时明确失败，不能要求调用方手工裁剪记忆或静默截断。
7. **运行中按需补充。** 模型可通过 `memoryReader` 提供检索内容或已有来源引用，身份与版本仍由程序绑定。返回来源、线索关联和截断标记；未命中返回空集合，查询失败报错，模糊命中不能强行确认事件或人物相同。

摘要失效时不能跨版本复用。摘要生成失败后，只有原文能在预算内完整提供时才显式回退，否则报告准备失败。模型摘要若被引入，其生成与校验属于应用的记忆准备过程，预算不混入角色 `run`。

#### 输出与状态影响

| 输出分组 | 内容 | 默认加载方式 |
| --- | --- | --- |
| `memories.recent` | 近期完整记录。 | 直接进入上下文。 |
| `memories.summaries` | 较远相关经历及重要未决事项的摘要，必要原话附来源材料。 | 直接进入上下文，细节可查。 |
| `memories.recalled` | 本轮线索命中的摘要或原始片段。 | 命中后进入上下文，不展开所有历史。 |

首版遗忘表示默认不加载，不删除事件，也不制造永久失忆。未检索到不等于没有发生；回忆命中不自动改变性格或永久提高记忆层级。记忆本身形成的信念可以保留，即使人物本轮没有回想起全部细节。采用的回忆表现可作为新体验记录，但旧事件不能被记成再次发生。

#### 验证

验证近期原话与顺序完整、久远承诺不丢失、摘要可追溯且不歪曲认知、无关联线索不加载沉寂记忆、别名检索、查询失败与未命中区分、越界拒绝及超预算明确失败。摘要忠实度与自然回忆表现用固定材料评估。

### F3：任务与场景感知

#### 输入信息

| 信息 | 必须包含什么 | 来源 |
| --- | --- | --- |
| `task` | 需要回应的情境、运行范围和停止条件。 | 调用方安排本轮粒度，不含期望选择或心理结果。 |
| `scene` | 可见环境、人物实际识别出的对象、听到的话、看到的行为、已知行动限制及新增反馈。 | 已发生的场景事件，经调用方按人物视角过滤。 |
| `scene.ongoingInteractions` | 来源事件、已发生部分、当前可知进展、待反馈事项或被打断的位置。 | 已采用事件及已确认反馈；无未完成互动时传空列表。 |
| `scene.observedEvents` | 本轮接收的可知事件列表；每项含稳定 `eventId`、来源版本、顺序、感知内容及可选反馈关联。 | 场景服务提供的角色可见投影，不由模型重写。 |
| 当前认知与相关记忆 | F1、F2 的材料。 | 用于理解场景，不补充人物未知真相。 |

#### 处理逻辑

1. 校验任务和场景完整性，绑定场景反馈与对应互动的来源，剔除人物不可感知的私有内容。
2. 将任务理解为“面对求助作出下一次反应”，而不是“必须帮助苏晴并提高信任”。人物目标来自快照，导演的剧情目标不能写成角色自身目标。
3. 对未完成互动，区分计划、实际尝试和已知结果。例如手已伸向信件不代表夺信成功；被打断的话只把已说出的部分视为他人听见。
4. 根据新增反馈交给角色决定继续、等待、调整或放弃；没有反馈时不自动补结果，不重复已完成部分。
5. 将反应限制在本轮范围内，到需要其他人物或环境反馈的位置停止，不替对方决定回应。

输入结构不提供指定选择或心理变化字段。自然语言中的越界要求仍需行为评估，不能仅凭结构校验声称全部识别。

#### 输出与状态影响

得到本轮可感知场景、可接续互动及停止边界，交给 F4。此步骤不改变角色目标或关系；未知信息保留未知，缺失必需材料报告输入错误。

#### 验证

对照验证夺信等待结果、话语中断、互动放弃、秘密过滤，以及“必须原谅”不能直接变成人物选择。

### F4：角色反应生成

#### 输入信息

| 信息 | 用途 |
| --- | --- |
| F1 的人物快照 | 提供身份、当前目标、底线、认知和情绪。 |
| F2 的分层记忆 | 提供承诺、历史行为及相关经历。 |
| F3 的任务和场景 | 提供本轮刺激、行动限制和停止边界。 |
| F8 的当前性格及适用模式 | 约束表达习惯与特定关系下可能出现的表现。 |
| 模型、可选查询工具和输出结构 | 来自创建配置及模板，负责执行和结构化结果。 |

#### 处理逻辑

1. 将固定系统规则与人物、记忆、任务、场景分段组装。引文和人物发言是材料，不覆盖系统规则。
2. 模型结合人物可知信息理解事件，按 F5 形成感受，按 F8 判断情境表现；这些是同次生成的业务规则，不要求拆成独立模型调用。
3. 存在动机冲突时，结合当前轻重缓急、关系、承诺、人物底线和已知代价选择。允许守约、寻找替代办法或有动机地违约，不采用固定性格标签排序或通用数值打分。
4. 自主生成按顺序发生的台词和动作，单独生成私有心理描写；不把导演预期作为必须满足的选择，不替其他人物决定反应。
5. 需要外部反馈时在尝试处停止。人物不知情时可以询问、沉默或自行承担风险；实际询问写成台词，不生成请求导演决定反应的问题清单。
6. 输出交给 F7 校验，输入依据版本由应用关联，不由模型复述。

人物底线是人物自身的原则，与系统权限和任务边界不同。突破人物底线需要相称的经历与动机，不能只因剧情需要；一次违约不自动删除重视承诺的长期倾向。只表达文学性内心活动，不要求模型公开分析过程。

固定提示词的核心语义如下，精确字段由实现时的输出校验结构提供：

```text
根据人物快照、分层记忆和可感知场景，自主生成本次反应。
导演安排事件，不能指定你的选择、信任变化或感受。
区分亲历事实、他人转述和个人判断，不把未加载记忆当成从未发生。
结合当前目标、关系和底线处理动机冲突，不编造隐藏目标。
按人物对事件的理解形成反应，允许误判、犹豫或言行不一。
特定关系的条件只允许旧有表现出现，不强制全部出现，也不抹去后来的成长。
按顺序输出台词与动作，私有内心活动单独输出。
承接未完成互动，不重复已完成部分，不擅自宣告外部行动结果。
状态变化须有依据；无变化返回空集合，到本轮停止位置即结束。
```

#### 输出与状态影响

| 字段 | 内容 |
| --- | --- |
| `performance` | 有序列表，每项含本轮唯一 `id`、`kind`、`text` 和 `progress`，需要接续时关联 `interactionId`。 |
| `innerActivity` | 私有文学性心理描写列表。 |
| `stateChanges` | 按 F5 产生的变化目标、变化内容、原因与依据，无变化时为空列表。 |

应用包装为 `result.output` 并附 `result.basis`。人物沉默或等待时允许空表现列表。输出不直接写入档案；公开表现也需按观察者的实际感知范围分发，低声交谈不能自动让所有人物知晓。

`kind` 为 `dialogue` 或 `action`；`progress` 为 `completed`、`awaitingFeedback`、`interrupted` 或 `abandoned`。`completed` 只表示描述的本人行为已完成，不能宣告需要外部裁定的结果；`awaitingFeedback` 表示尝试已发生、结果待反馈；`interrupted` 表示被打断；`abandoned` 表示角色放弃已有互动。`text` 只写实际发生或说出的部分，不含未执行计划或未说出口的后半句话。被外部打断须有可知事件依据，不能替其他角色生成打断行为。

接续、放弃或被打断的已有互动必须引用输入中的 `interactionId`。新互动由应用根据本轮提交标识与表现项 `id` 分配稳定 ID；模型不生成全局事件 ID。需要继续的项附 `continuation`，只描述待反馈或待接续内容，不预写结果。输入反馈事件通过 `interactionId` 关联未完成互动；程序据结构化状态更新列表，不从自然语言猜测是否结束。状态与引用不匹配时拒绝整轮结果。

#### 验证

验证动作与台词顺序、私有内容隔离、动机冲突的材料依据和自主选择。自然语言表现采用固定场景对照评估，不以全文精确匹配代替。

### F5：行动反馈与状态变化

#### 输入信息

| 信息 | 必须包含什么 | 来源 |
| --- | --- | --- |
| 变化前快照 | 当前信念、目标、关系、情绪、能力及性格。 | F1、F8。 |
| 本轮可知事件和反馈 | 发生了什么、人物感知到什么、对应来源、哪些结果仍未知。 | F3 及有效记忆。 |
| 本轮角色体验和行为 | 人物对事件的理解、感受和自主反应。 | F4 同次生成，不来自导演指定。 |

#### 处理逻辑

1. 区分实际事件、人物解释和未知结果。伸手夺信是尝试，对方是否躲开需要反馈；不能据此直接生成“夺信成功后放心”的状态。
2. 根据人物经历和当前关系理解事件，再形成感受与反应。同一旧称呼在私下可能令人亲切，在下属面前可能令人难堪，在失信后可能被理解为套近乎；这些是可能解释，不是固定映射。
3. 比较变化前快照，判断本轮是否实际改变情绪、信念、目标或关系。没有变化就返回空集合，不要求每次互动都成长。
4. 对真实变化记录目标、变化内容、原因和依据。只更新本人状态；林舟信任苏晴不代表苏晴也信任林舟。
5. 区分当下情绪、持续关系变化和长期性格变化。短暂放松不能直接写成长期活泼；长期性格与模式变化遵循 F8。
6. 将变化与行为一起返回，由 F7 校验、F6 一致保存。需要尚未知晓的外部结果才能形成的变化，留待收到反馈的下一轮，不预写。

新证据可以修正旧解释，但不删除当时误解及行为的记录。角色可以谅解失约，也可以降低信任，事件不保证产生导演预期的结果。此功能不提供选择采用某条心理变化的入口。

#### 输出与状态影响

输出 `stateChanges`，程序按明确操作应用到快照，不再次调用模型理解“提高信任”等文字后改文件。每项使用以下结构，属于目标接口，不是任意 JSON 路径补丁：

| 字段 | 契约 |
| --- | --- |
| `op` | `add`、`replace` 或 `remove`。 |
| `target` | 封闭集合：`state.goals`、`state.beliefs`、`state.relationships`、`state.abilities`、`state.body`、`state.emotion`、`knowledge`、`personality.currentTraits`、`personality.contextPatterns`。不允许修改身份、历史事件或其他人物。 |
| `entryId` | 集合条目的稳定 ID；关系条目按对方人物 ID 定位。标量 `body`、`emotion` 不带该字段。 |
| `value` | `add`、`replace` 必需，按目标类型完整校验；`remove` 不携带。集合值为完整条目内容，身体及情绪为完整的新值，不是增减指令。 |
| `reason` | 角色形成变化的原因描述。 |
| `evidence` | 非空依据列表；用 `eventId` 引用可见输入或历史事件，用 `performanceId` 或 `innerActivityIndex` 引用本轮表现或私有体验，三种引用使用可辨识类型。 |

集合 `add` 要求条目不存在，`replace`、`remove` 要求条目存在；身体和情绪只允许 `replace`。新条目 ID 必须在本人物范围唯一，同轮重复或冲突地修改同一目标与条目时拒绝。关系的键是关系对象，不表示有权修改对方。替换后仍保留旧提交中的值；删除当前信念或模式也不删除历史。应用在输入版本上校验所有操作，再一次性应用；任一失败不部分更新。每个目标的值类型在实现时定义，禁止任意路径、未知字段和跨类型值。

以下示例表示人物因已知事件形成的信任变化；`character-su-qing` 必须是已有关系条目，`event-rescue` 必须在本轮可见依据中。不是要求导演指定这个变化：

```json
{
  "op": "replace",
  "target": "state.relationships",
  "entryId": "character-su-qing",
  "value": { "attitude": "愿意有限合作，但仍保留戒备" },
  "reason": "她承担风险救了自己，使原来的怀疑有所缓和",
  "evidence": [{ "kind": "event", "eventId": "event-rescue" }]
}
```

业务保存时形成新快照，角色生成阶段不直接修改正式状态。目标值不能包含未验证的模型文件路径或写入指令。

#### 验证

验证未知结果不能作成功依据、同一事件不同理解、关系非对称、误解修正保留历史、无变化为空，以及提交不能丢弃不符合导演预期的心理变化。

### F6：经历记录与跨轮连续性

#### 输入信息

| 信息 | 必须包含什么 | 来源 |
| --- | --- | --- |
| 完整 `result` | `basis`、台词动作、私有体验及全部 `stateChanges`。 | F7 返回的有效角色结果。 |
| 提交上下文 | 目标剧情版本、本轮运行与来源事件标识、期望状态版本。 | 应用绑定，用于去重和冲突检查。 |
| 场景实际进展 | 已发生的事件、可知反馈及未完成互动。 | 场景事件与已有状态，不由保存程序编造。 |
| 本轮输入事件 | 与 `result.basis` 绑定的 `scene.observedEvents` 原始可见投影。 | 应用保留冻结副本，不能提交另一批事件搭配旧结果。 |
| 整轮是否保留 | 正式提交或试演整体弃用。 | 调用方，不是逐项心理审批。 |

#### 处理逻辑

1. 失败、取消、超时或整体弃用的结果不提交；试演需要保留时写入独立临时版本。
2. 检查提交身份、来源和期望版本。重复提交同一结果不生成重复经历；同一标识携带不同内容或并发版本冲突时拒绝覆盖。
3. 将完整角色行为、私有体验与自主状态变化一致保存，生成新事件和新快照。任何一项无效或保存失败时整轮失败，不保存行为后丢弃心理变化。
4. 更新未完成互动：未获得结果的尝试继续等待，完成或放弃的事项移出待处理列表，但历史保留。被弃用的动作不加入列表。
5. 为每个人物保留其实际可知部分，其他人物不能获得私有内心；分发仍需遵守场景感知范围。
6. 后续加载通过 F2 生成摘要和索引，再把新状态、记忆及 `scene.ongoingInteractions` 交给下一轮。摘要失败不抹去已经成功提交的原始事件，下次准备材料时按 F2 报错或回退。

改变输入事件或修改影响角色反应的内容时，从对应快照重新推演，不拼接编辑后的行为与旧心理结果。导演可以据实际反应安排后续事件，不能用反复注入指定选择的方式代替角色自主反应。

本轮提交同时保存尚未记录的输入事件和角色自身反应，即使表现及状态变化都为空，也必须记住本轮听到、看到的内容。`basis` 由程序关联输入事件 ID、来源版本及内容摘要校验值；提交验证冻结输入与其一致，不能信任模型复述。按人物可见事件 ID 去重，相同 ID 不同内容拒绝；新感知或后续纠正使用新 ID 并关联原事件，不覆盖旧认知。重传事件可作为上下文保留，但不重复形成新经历或重复应用同一次已提交反应。运行失败不将输入事件标为已处理，场景方保持可重投递；试演弃用不删除已经在场景中确立的事件。

校验补充：沉默仍记录输入事件，事件重投递不重复入库，输入与结果错配被拒绝，结构化行动反馈能准确接续已有互动，未知目标或冲突状态操作整轮拒绝。

#### 输出与状态影响

成功返回新剧情或状态版本，并保存可追溯事件、记忆和状态。尝试记录不等于结果已知；后续反馈作为后续事件进入。文件提交与格式版本规则见 F9，原始记忆不因摘要或降层删除。

#### 验证

验证幂等提交、版本冲突拒绝、保存失败无部分状态、弃用隔离，以及第二轮获得第一轮承诺但不被强制守约。

### F7：执行控制与结果校验

#### 输入信息

| 信息 | 必须包含什么 | 来源 |
| --- | --- | --- |
| 创建依赖 | 已初始化的模型适配器，可选 `memoryReader`。 | 应用入口完成配置和凭据初始化后，注册给 Agent 内部运行时。 |
| `execution` | 整次运行超时 `timeoutMs`、模型调用预算 `maxModelCalls`。 | 内部运行时创建执行单元时解析并校验，提供商重试计入预算。 |
| 内部执行输入 | F1、F2、F3、F8 定义的人物快照、记忆、场景和输出要求。 | Agent 每次根据初始化身份、调用方 `scene` 及 `responseFormat` 独立组装。 |
| `options.signal` | 可选取消信号。 | 调用方控制。 |
| 模型输出与工具结果 | 待校验的外部数据。 | 本次执行，不信任类型断言。 |

#### 处理逻辑

1. 内部运行时校验已注册依赖与执行配置；角色实例在创建时绑定身份，不在实例中缓存动态人物状态。正式启动遵循应用已声明入口。
2. `run` 先检查取消、场景和输出要求，再加载内部材料；任一步失败时不启动模型，并建立本次独立消息、预算与取消传播。
3. 将材料交给 Deep Agents，按需调用受限查询工具。审计默认能力，不提供通用 shell、正式状态写入或其他角色自动调度。
4. 执行期间累计调用预算，传播工具、模型与取消错误；不隐式整轮重跑，不把查询失败当成无记忆。
5. 校验输出字段、封闭表现种类、本人可变字段及依据引用。字段或引用无效时整轮失败，不静默删除错误条目，不生成伪成功结果。
6. 成功后关联可信 `basis` 返回。无论成功、失败或取消，都清理自己创建的监听器和定时器；超时取消后不再发起工具调用，迟到响应不写回结束的运行。

结构校验不能证明文学表现一定合理。人物自主性、摘要忠实度和性格表现需要相应固定场景评估，不能靠类型检查宣称全部保证。

#### 输出与状态影响

返回完整有效结果，或明确失败、取消；不直接保存正式状态。详细生命周期沿用[公共设计](agents.md)。代码归属 `src/agents/`，测试归属 `src/agents/tests/`；简单实现可集中在角色文件中，只共享实际共用的执行边界。

#### 验证

验证输入失败不调用模型、无效输出不成功、工具异常传播、调用预算、提前取消、执行超时、迟到响应和人物并发隔离。实际命令以[项目入口](../../../README.md)为准。

### F8：性格演变与情境表现

#### 输入信息

| 信息 | 必须包含什么 | 来源 |
| --- | --- | --- |
| `personality.currentTraits` | 当前长期性格倾向、表达习惯及形成依据。 | 初始设定或已保存的角色自主变化。 |
| `personality.contextPatterns` | 特定关系下的相处模式，无模式时为空列表。 | 当前有效快照，不为所有好友自动建立。 |
| 当前关系与情绪 | 对对象的信任、戒备、未解决冲突及本轮情绪。 | `state`，双方关系不假定对称。 |
| 可感知情境 | 已识别对象、场合、称呼、危险及旁人在场情况。 | `scene`，不使用作者知道但人物未认出的身份。 |
| 近期表现及关联旧事 | 当前互动中已发生的表现、相关记忆和本轮唤回材料。 | F2，用于判断触发与连续性。 |

每个 `contextPatterns` 条目需要以下信息：

| 字段 | 内容 |
| --- | --- |
| `id`、`relationshipTargetId` | 模式及具体关系对象标识，不使用“老朋友”作为泛化匹配对象。 |
| `sourceRefs` | 形成模式的有效经历或初始设定。 |
| `activationConditions` | 允许旧有表现出现的必要条件，全部具备也不强制表现出现。 |
| `blockingConditions` | 阻止或打断表现的条件，例如已知背叛或迫近危险。 |
| `manifestations` | 可出现的具体范围，例如语气放松、主动打趣或使用旧称呼。 |
| `retainedBoundaries` | 仍保留的当前边界，例如保守秘密、谨慎许诺。 |

字段为设计语义，不是持久化格式。当前性格只维护一份有效快照，不在 `profile` 另存冲突版本。模式来源引用不意味着把全部沉寂记忆正文加载到上下文。

#### 处理逻辑

1. 程序根据场景中角色已识别的对象筛选关系匹配的模式，并校验结构与来源；未认出旧友不能只凭作者知道身份触发。
2. 模型结合当前关系、情绪与可感知线索判断必要条件。缺少依据时不主动触发，阻断条件优先；安全感等语义判断不伪装成精确数值计算。
3. 条件允许时，自主决定是否表现、表现哪些部分和程度。例如先短暂一笑，再逐渐打趣；不强制完整复现过去。多个模式冲突时，冲突部分沿用当前性格，不为剧情临时编造模式。
4. 保留后来形成的知识、能力、信念与边界。关系模式只影响指定表现，不把整个人物恢复到旧版本。
5. 每轮结合近期已采用表现重新判断持续或退出。称呼可来自本段互动的记忆，不必每轮重复；好友离开、威胁出现或信任受损时自然收敛，不在实例中保持隐藏开关。
6. 经历经 F5 的人物理解后若形成长期变化，通过 `stateChanges` 更新长期倾向或模式。变化范围与依据相称，重大事件可以有明显影响，但不按客观事件类别机械增减性格。

回忆命中只提供依据，不保证触发旧有表现；已有关系倾向可以影响反应，不必每次回忆全部形成过程。一次重逢开玩笑不自动变成长期活泼，一次道歉也不自动恢复全部信任。新模式源自初始设定或角色自主形成的变化，不由导演在运行中指定。

#### 输出与状态影响

短暂表现写入 F4 的台词、动作和内心活动，不新增“切换性格”接口。长期变化使用 F5 的 `stateChanges`，关联有效依据，并由 F6 随整轮保存；弃用剧情或其他分支的经历不影响当前快照。首版不引入性格评分、衰减公式、随机概率或强度数值。

#### 验证

对照检查特定好友与其他好友、私下与公开场合、已知背叛与仍有信任、互动持续与好友离开。允许条件满足但仍只短暂一笑；验证渐进和解、保留成长以及长期变化与剧情版本隔离。结构与来源检查使用确定性测试，自然语言表现使用固定场景评估。

### F9：文件持久化与更新

#### 输入信息

| 信息 | 必须包含什么 | 来源 |
| --- | --- | --- |
| 存储位置 | 应用管理的小说数据根目录，以及小说、分支、人物标识。 | 应用配置和可信上下文，不接受模型提供文件路径。 |
| 初始资料 | 人物档案、状态、认知、性格及初始记忆来源。 | 明确的初始化操作，不能因文件缺失自动创建空人物。 |
| 完整本轮结果 | F6 的结果、提交标识、来源事件及期望人物版本。 | 已校验的角色结果与调用上下文。 |
| 派生记忆 | 摘要、检索索引、覆盖的来源和派生规则版本。 | F2 的记忆准备过程。 |
| 已保存文件 | 当前分支的提交记录及可选派生缓存。 | 文件存储读取入口，全部校验后使用。 |

首版采用本地文件存储，写入器归属于小说业务侧，应用注入读取能力给角色 Agent。模型不执行任意文件修改，也不决定文件名。数据目录是运行时数据，以下布局是设计草案，不在本次文档变更中创建这些目录。

```text
<小说数据根目录>/<小说ID>/<分支ID>/characters/<人物ID>/
  commits/
    00000000.json       初始快照和初始经历
    00000001.json       第一轮经历、完整角色结果及更新后的快照
    00000002.json       下一次提交
  derived/
    summaries.json     带来源版本的摘要缓存
    index.json         带来源版本的检索索引缓存
  pending/
    <commitId>.json    发布前保存的冻结提交请求，用于中断后恢复
```

`commits` 是正式事实来源，已发布文件不可原地改写。每个提交包含完整的当前人物快照及本轮新增经历，不复制全部历史记忆；完整历史从提交链读取。近期、摘要、沉寂是加载策略，不通过移动或删除原始文件实现。无需另建可独立覆盖的 `state.json` 和 `memory.json`，避免只更新其中一份。

分支历史采用固定父版本引用。派生分支的初始化提交复制父版本的人物快照，并保存 `parentRef`（父分支、人物、固定 revision 及对应提交完整性标识），不只复制状态而丢弃经历。读取历史时先读取父链截至该版本的经历，再追加当前分支经历，父分支之后的新事件不可见。分支初始化的快照不重复生成旧事件；各分支的本地 revision 从 0 开始。禁止循环父引用，父记录缺失或损坏时明确失败，不当作没有历史。被引用的父提交不能删除；派生摘要关联完整父版本范围，不能直接使用父分支最新缓存。此机制按人物成立，不引入跨人物分支事务。

#### 处理逻辑

1. **定位并校验目录。** 程序根据可信 ID 生成路径，检查最终解析位置仍处于指定数据根目录，拒绝路径穿越及逃逸目录的链接。首版一个存储根只允许一个写入进程；用进程退出会释放的互斥机制防止第二个写入者进入，进程内按人物分支串行提交，不仅依靠可被误删的锁文件。
2. **加载当前版本。** 读取并校验连续提交链，最新有效提交提供人物快照，历史提交提供经历。检查格式、身份、版本衔接和内容完整性；损坏或缺号时报告错误，不跳过坏记录或自动重置人物。派生缓存不参与决定正式版本。
3. **生成下一轮数据。** 在同一写入临界区内检查期望版本和提交标识。相同标识及相同内容的重试返回原提交版本，不重复记录；相同标识不同内容或版本冲突时拒绝。依据全部 `stateChanges` 计算新快照，将事件、角色输出和快照装入一个提交文件。
4. **完整写入再发布。** 在同一文件系统的目标目录写入唯一临时文件，校验内容并刷入文件，再通过经目标平台验证的原子发布操作形成新的提交文件。禁止覆盖已存在的版本文件。发布是本轮生效点，之前失败不改变有效版本，之后不能返回“确定未提交”并盲目重跑。
5. **处理结果不确定的重试。** 若文件已发布但进程在返回前中断，重启后通过提交标识查询结果。读取方不把临时文件当作提交；残留临时文件经校验确认不属于活动写入后才可清理，不能删除有效历史。原子可见与断电耐久不同，实现须验证目标平台的落盘能力，不能把重命名本身当成断电保证。
6. **更新派生文件。** 正式提交成功后，F2 按需生成摘要和索引，各自写临时文件后替换，并标记覆盖版本及来源。两份缓存不必同时更新；读取时独立检查适用范围，必要时从正式提交重建。缓存失败不回滚已提交事件，不冒充原始记录保存失败；下次材料准备按 F2 回退原文或明确失败。
7. **重启恢复。** 重新打开存储后验证提交链，重建当前快照和查询能力。试演使用隔离分支，重演引用明确起点；不会因重启、遗忘或摘要重建丢失原始经历。首版不自动删除历史或执行压缩清理。

提交文件使用 UTF-8 JSON。首版文件封装固定 `schemaVersion: 1`，包含所属小说、分支和人物标识、单调递增的 `revision`、前一版本引用、唯一 `commitId`、来源依据、本轮完整结果、新增经历以及 `profile`、`state`、`knowledge`、`personality`、未完成互动组成的更新后快照。完整性校验覆盖实际提交内容。初始化版本没有前驱，后续版本必须连续，剧情分支标识、状态修订号与文件格式版本不能混用。

这是文件封装的设计约定，内部精确类型和校验器随实现定义。缺少格式版本或遇到未知版本时拒绝读取并报告路径和版本，不静默按当前结构猜测，不删除原文件。后续格式升级递增版本，必须提供显式迁移或继续明确拒绝的策略。派生缓存也声明格式版本和来源范围，无法使用时可重建。

提交前由应用生成稳定 `commitId`，同一整轮提交重试必须沿用该值和完全相同的冻结请求，不能重跑模型后复用旧 ID。写入器在发布提交前，用同样的完整写入方式保存 `pending/<commitId>.json`，包含目标人物分支、期望版本、输入事件、完整结果及内容校验值；它是恢复材料，不是有效人物经历，也不由记忆查询读取。正式提交记录保存同一标识和请求校验值。成功后可清理对应请求文件；中断留下的请求不自动生成新反应。

`getCharacterCommitStatus({ characterRef, commitId })` 在同一写入同步范围内检查记录，返回 `committed`（附 revision）、`pending`（冻结请求存在但尚未发布）或 `notFound`（无提交也无请求）。查询失败、文件损坏或无法确认时报告错误，不能返回 `notFound`。先检查已提交记录，再检查请求，因此发布成功但请求未清理时仍返回成功。`resumeCharacterCommit` 仅从保存的请求恢复，重新执行版本校验和幂等检查，不再次调用角色模型；无法恢复或版本冲突时保留材料并报告。进程重启可枚举未完成请求供应用恢复，不自动把试演弃用结果提交。

#### 输出与状态影响

提交成功返回新的 `revision` 和 `commitId`。F1 从最新有效提交获取人物状态，F2 从提交历史及有效缓存获取记忆，F6 的整轮一致性由单个正式提交文件保证。每次人物反应形成的新版本保留旧版本，更新意味着发布新提交，而不是由模型覆盖旧资料。

本机制只保证一个人物在一个分支内的整轮一致提交，不声称多个角色文件同时具备跨人物事务。场景向其他人物分发可见事件时以稳定来源 ID 去重，失败后可以补交；不得将一个人的私有记忆复制给另一个人。

#### 验证

使用临时目录验证写入后重启恢复、记忆原文与状态一致、重复提交去重、版本冲突、第二写入者拒绝、路径越界拒绝、未知格式拒绝及损坏文件报告。在临时写入、发布前、发布后返回前分别模拟中断，确认不会读到半轮结果且可凭提交标识恢复。验证摘要或索引单独失败时正式记录仍有效、缓存可重建；目标平台的原子发布与落盘检查必须通过真实文件集成测试。

补充验证派生分支能读取分叉前原话但不能读取父分支后续事件、父链缺失或循环拒绝，以及提交请求保存后崩溃、发布成功但回执丢失、查询异常不伪装未提交、恢复请求版本冲突等路径。

## 三、代码的外部使用方式

### 3.1 对外入口

调用方通过 `@fly-novel/agents` 的公共入口创建一个绑定角色身份的 Agent。应用启动时通过 `configureAgentRuntime({ resolveModel })` 注册模型解析器；`run` 将 `modelId` 解析为 LangChain 模型对象并调用 Deep Agents。

初始化只传入模型和角色定位所需的基本信息：

| 参数 | 用途 |
| --- | --- |
| `modelId` | 已注册模型的标识；省略时由 Agent 运行时选择默认模型。模型对象、凭据和 Deep Agents 创建由运行时处理。 |
| `storyId` | 小说身份，用于定位小说数据与世界规则。 |
| `branchId` | 剧情分支身份；省略时固定为 `main`。该标识不触发文件存储。 |
| `characterId` | 角色身份，用于加载该角色的档案、状态、记忆与性格。 |

运行时只传入当前小说生成所需的内容：

| 参数 | 用途 |
| --- | --- |
| `scene` | 当前角色能看到、听到或已经获知的场景信息，以及本轮实际反馈。 |
| `responseFormat` | 调用方提供的 Zod 4 对象 Schema，定义本轮输出字段、类型、含义、必需项和额外字段处理规则。Agent 不预设字段名或字段集合。Schema 描述表达数据含义，不指定角色必须作出的选择。 |
| `signal` | 可选取消信号。 |

接口为 `new CharacterAgent({ modelId, storyId, branchId, characterId })` 和 `agent.run({ scene, responseFormat }, { signal? })`。`modelId` 可省略。调用方不传人物快照、三层记忆、性格模式、状态版本、查询工具、执行预算或文件提交标识。

`run` 将场景组织为本轮消息，使用 `z.toJSONSchema(schema)` 保留调用方约束，再交给框架 `toolStrategy`，并将 `signal` 传给底层调用。Schema 必须是可转换为 JSON Schema 的 Zod 对象；缺失或类型不符在模型初始化前拒绝。首次运行通过注册的 `resolveModel(modelId)` 解析模型并创建框架实例；后续运行复用该实例，由模型调用中间件设置本轮 Schema，不重建会话。重新注册运行时不改变已创建实例的模型。

结果中的 `structuredResponse` 按调用方 Schema 校验，其余字段保留框架状态。`CharacterAgentRunInput<TSchema>` 接收外部 Schema，`run()` 返回的 `CharacterAgentRunResult<z.output<TSchema>>` 推导对应输出类型，必需字段不会统一退化为可选字段。字段名称、嵌套结构、数组、可选项和描述均属于调用方；F4、F5 的字段是业务设计参考，不是类内置的输出约束。正式业务提交仍未接入。

结构化输出采用工具调用策略，模型需要支持工具调用；未依赖供应商原生 JSON Schema 模式。模型调用中间件显式设置 `toolChoice: "auto"`，避免框架默认强制工具调用与 DeepSeek 思考模式冲突。模型调用中间件将普通工具列表设为空，仅由框架提供本轮结构化输出工具；自动选择不保证模型一定调用输出工具，程序只接受通过校验的结构化结果。违反外部 Schema 或未生成结构化结果会使调用失败，结构化解析错误不自动重试。框架先按转换后的 JSON Schema 校验，再按调用方 Zod Schema 解析；使用 `z.strictObject()` 拒绝额外字段，`z.looseObject()` 允许保留额外字段，不能假定框架会自动剔除 `z.object()` 未声明的字段。每轮清空框架状态中的旧 `structuredResponse`，防止缺失本轮结果时返回上轮内容。结构校验不保证人物一致性、事实正确性或状态变化依据有效。

每个实例拥有独立的框架 `MemorySaver`，调用使用固定 `thread_id` 延续该实例的会话；每轮只传新增消息，由框架读取历史。不同实例不共享会话检查点；程序退出后检查点丢失。同一实例并发 `run` 会立即拒绝，失败或取消后释放运行状态。

框架检查点不等同于 F6、F9 的正式经历提交。调用失败或取消时不回滚检查点，也不隐式重试整轮。返回值经过结构校验，未经过业务校验。框架可能压缩长上下文，检查点不保证最近经历永远完整。

角色类为人物资料、当前状态和性格准备保留统一的 `{ content: string }` 接口。`buildModelPrompt()` 顺序准备这些资料，`combineContext()` 跳过空白片段，再附加外部场景和输出字段；`generateReaction()` 负责调用框架。会话历史不通过 `loadMemory()` 手工检索或拼接。`validateResult()` 与 `saveExperienceAndState()` 是业务校验和正式经历提交接口，直接调用会报告未实现，`run()` 不调用它们。

角色运行不加载记忆摘要，不挂载磁盘存储后端，也不向模型提供文件读写工具。已有角色记忆文件不删除、不读取；业务记忆策略仍由 F2、F8、F9 描述。

执行超时、模型调用预算、检索材料预算和保存重试策略属于应用的 Agent 运行时配置，不暴露在每次角色调用参数中。它们在创建内部执行单元时校验并固定，提供商重试也计入预算，不额外执行隐式整轮重跑。精确 Deep Agents SDK 适配在实现时按安装版本验证。

### 3.2 创建、调用、采用和再次调用

以下 TypeScript 使用当前调用形式。调用代码不接触 `novelService`、`memoryReader`、提交 ID 或快照版本；它们属于 `CharacterAgent` 的内部协作对象。应用启动时一次性完成模型和 Deep Agents 运行时初始化，并注册模型解析器，不能用此简化接口绕过应用初始化。

以下字段仅为调用样例，由调用方在运行时定义；可以替换字段名、类型或整个 Schema，无需修改 `CharacterAgent`。调用方需声明 `zod` 依赖，可运行的应用样例见[character-agent-example.ts](../../../src/app/character-agent-example.ts)。

```ts
import { CharacterAgent, type CharacterScene } from "@fly-novel/agents";
import { z } from "zod";

async function runCharacterExample(scene: CharacterScene) {
  const agent = new CharacterAgent({
    modelId: "default",
    storyId: "novel-river",
    branchId: "main",
    characterId: "character-lin-zhou",
  });
  const controller = new AbortController();

  const result = await agent.run(
    {
      scene,
      responseFormat: z.strictObject({
        dialogue: z.string().describe("角色实际说出的台词"),
        action: z.string().describe("角色实际做出的动作"),
      }),
    },
    { signal: controller.signal },
  );

  // dialogue、action 的类型从调用方 Schema 推导为 string。
  return result.structuredResponse;
}
```

同一实例的下一次 `run` 只提供新场景、实际反馈和输出字段，不需要传回上一轮结果。三层记忆读取、性格模式和正式状态提交属于 F2、F8、F9 的业务接入目标，不是当前会话检查点的功能。行动尝试不能仅因进入会话历史就视为外部结果已经发生。

接入 F9 文件提交时，使用内部稳定提交 ID 和冻结请求恢复；回执丢失、版本冲突或无法恢复应使调用明确失败，不能重新调用模型替代提交恢复。当前 `run` 不执行文件提交。
