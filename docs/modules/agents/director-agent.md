# 导演 Agent 详细设计

本文定义导演模板的目标契约，不表示接口已经实现。公共执行与产物保存规则见[总设计](agents.md)，人物自主反应及记忆见[角色设计](character-agent.md)。本文接口与示例均为待实现草案。

## 一、需要实现哪些功能

导演根据作者创作目标、世界规则和人物实际状态安排事件与处境，观察角色自主反应后调整后续计划。导演不能命令人物信任、原谅、爱上或帮助某人，也不通过改写角色资料达成剧情目标。

| 编号 | 功能 | 需要达到的效果 |
| --- | --- | --- |
| D1 | 创作目标与事实整理 | 区分希望达到的效果、已经发生的事实、世界规则和可调整偏好。 |
| D2 | 场景与事件设计 | 安排冲突、外部事件及节奏，为人物创造需要选择的处境。 |
| D3 | 角色反应情境组装 | 为调用方提供观察与反应范围，不指定角色决策，不泄露全局秘密。 |
| D4 | 根据实际进展调整计划 | 保留已发生事件，依据角色实际选择调整尚未发生的部分。 |
| D5 | 结果校验与计划保存 | 校验结构和来源，由应用保存版本化计划，不把计划直接记成角色经历。 |

## 二、每个功能如何实现

### D1：创作目标与事实整理

#### 输入信息

| 字段 | 必需信息 | 来源 |
| --- | --- | --- |
| `context` | 小说、分支、剧情时点及依据版本。 | 应用可信绑定。 |
| `task` | 本轮要设计或调整的场景范围、希望形成的冲突或阅读效果。 | 作者创作任务。 |
| `facts` | 已发生事件、时间顺序及有效来源 ID。 | 已提交剧情，不包含尚未发生的计划。 |
| `worldRules` | 事件必须满足的世界规则、资源和能力限制。 | 有版本的设定。 |
| `characters` | 参与人物的当前性格、关系、目标、身体状态及可授权参考的经历。 | 对应人物快照。 |
| `constraints / preferences` | 场景边界、不可修改事实及可调整的节奏偏好，分开提供。 | 应用与作者输入。 |

必要分组必须存在，无相关事实可显式提供空列表。导演只获得本次规划需要的全局信息，不默认读取所有人物私有文件。

#### 处理逻辑

1. 校验材料版本与来源，拒绝必需字段缺失及不存在的人物引用。
2. 区分世界事实、人物自身认知与作者期望。例如“希望两人有合作机会”不是“两人已经互相信任”。
3. 将当前人物目标作为事实依据，不把作者目标写入人物状态。若任务要求人物必须作出某种选择，将其标为超出导演权限的冲突，不设计直接改写心理的操作。
4. 结构完整但创作约束相互冲突时，返回受阻结果并指出冲突引用，不静默放弃其中一条；不确定的剧情事实只在有权限时查询，未查到不臆造。

#### 输出与状态影响

得到本次规划使用的事实与约束材料，交给 D2。不会修改角色或世界状态。应用保存 `basis`，模型不生成依据版本。

#### 验证

验证计划和事实分离、冲突约束显式报告、跨分支材料拒绝，以及指定人物心理变化不能成为执行指令。

### D2：场景与事件设计

#### 输入信息

使用 D1 的创作目标、世界规则、人物现状和允许的场景范围；调整已有计划时增加原计划及实际执行进展。人物潜在反应只能用于预判，不能成为已发生事实。

#### 处理逻辑

1. 定义场景位置、时间范围及本轮冲突，例如渡船将离岸而两人仍有未解决的分歧。
2. 安排外部刺激、资源变化和可观察线索。事件须符合世界规则；涉及某个人物主动施救、告白或背叛时，只能安排使其有机会选择的处境，由对应角色决定行为。
3. 按因果顺序形成节奏步骤，标明哪些步骤依赖已发生事件，哪些必须等待角色或环境反馈。依赖图不能循环，不提前兑现尚未满足的条件。
4. 对角色反应预留空间。例如提供合作机会，不写“林舟必然答应”；计划不是自动执行脚本，也不保证达到作者期待。

#### 输出与状态影响

产生 `plan`，结构语义如下：

| 字段 | 内容 |
| --- | --- |
| `scene` | 场景时空、边界及创作目的。 |
| `beats` | 有序步骤，含计划内唯一 `id`、事件描述、依据引用、前置条件及停止点。 |
| 步骤 `kind` | `externalEvent` 表示拟安排的外部变化；`characterSituation` 表示等待角色自主反应的处境。 |
| `reactionContexts` | D3 定义的角色观察线索和反应范围。 |

计划内 ID 不是正式事件 ID。调用方确认外部事件实际发生后才分配来源事件 ID并更新场景；角色动作的尝试及反馈沿用角色设计。导演不负责执行环境裁定或启动其他 Agent。

#### 验证

检查步骤引用、因果顺序、未知步骤和循环依赖；对照评估事件是否合理、是否将角色行为伪装成外部事件，以及是否暗含指定心理结果。

### D3：角色反应情境组装

#### 输入信息

输入 D2 的待处理步骤、参与人物身份和当前可见性依据。世界秘密与人物私有材料保持来源标记，人物是否能听见或看见由实际场景决定。

#### 处理逻辑

1. 为每个参与者生成 `characterId`、可感知线索引用、反应范围和停止条件，不生成期望选择、情绪或信任增减。
2. 将全局创作目的留在导演计划里。例如“制造误会”不能原样成为角色系统指令，角色只看到引起误解的可知事件。
3. 调用方在事件实际发生后重新检查感知范围，组装角色 `scene.observedEvents`、快照和记忆。模型提供的可见性安排仅作规划参考，不能代替应用访问检查。
4. 其他角色的内心和未揭示秘密不传给观察者。事件未发生时不直接把计划作为近期记忆输入。

#### 输出与状态影响

`reactionContexts` 每项含 `characterId`、`cueRefs`、`scope` 和 `stopCondition`，其中 `cueRefs` 指向计划步骤或有效场景材料。外部调用方负责将发生后的线索转换成真实事件，不由导演写入角色记忆。

#### 验证

验证同场不同人物获得不同信息、计划线索未直接入库、未知人物引用被拒绝，以及“必须帮助”不被传成角色任务。

### D4：根据实际进展调整计划

#### 输入信息

`previousPlan` 提供计划产物 ID 和修订；`progress` 提供已发生事件、实际角色结果、未完成步骤及当前快照版本。原计划是参考，实际事件是依据。

#### 处理逻辑

1. 对照实际进展识别已完成、已失效和仍可执行的步骤，不能仅凭计划描述宣告完成。
2. 角色拒绝原本期待的合作时，保留该选择及其状态变化，重新安排后续处境；不能将拒绝改写为答应，也不能剥离不符合目标的心理变化。
3. 重新检查未执行步骤的前置条件，删除或调整失效部分，输出完整的新计划版本及其替代的旧计划引用。
4. 需要改动已发生事件时，标记需要独立分支重演，不在当前版本直接覆盖历史。更新计划不会自动创建分支或重跑角色。

#### 输出与状态影响

新计划关联 `supersedes`，原计划和实际进展保留。角色与正文不随计划调整而自动变化。

#### 验证

验证人物拒绝后的重规划、已发生事件不回滚、旧前置条件失效及新旧计划来源可追溯。

### D5：结果校验与计划保存

#### 输入信息

已初始化模型、执行配置、可选受限资料读取器，以及 D1 至 D4 的输入。保存时应用提供产物标识和期望修订，不把文件路径交给模型。

#### 处理逻辑

1. 按公共生命周期运行并校验步骤、人物和来源引用。固定系统规则强调“只安排事件，不指定角色选择，不把计划当成已发生事实”。
2. 使用可辨识输出：`status: ready` 时含完整 `plan`；`status: blocked` 时 `plan` 为 `null`，并含非空 `openIssues`。
3. `openIssues` 每项含问题描述、冲突或缺失依据及影响范围。它用于作者任务与规划材料的澄清，不能询问导演希望角色产生什么心理以覆盖角色判断。
4. 应用按总设计的产物保存契约保存计划修订。失败、取消或结构无效不发布计划；保存成功也不表示步骤已经执行。

#### 输出与状态影响

返回 `{ basis, output }`，`output` 包含 `status`、`plan`、`openIssues`，无问题时为空列表。导演没有角色式长期心理记忆，连续性来自已保存的计划和真实剧情材料。

#### 验证

验证两种输出分支、无效引用、取消、查询失败、修订冲突及重启读取；创作合理性以固定场景评估。

## 三、代码的外部使用方式

以下为接口草案，不可直接运行。`createDirectorAgent` 与类型尚待实现；`novelService`、人物场景材料及标识由应用提供，业务服务不属于 Agent 包导出。代码位于完成模型初始化的应用流程中。

```ts
import { createDirectorAgent, type DirectorAgentOptions } from "@fly-novel/agents";

async function planNextScene(dependencies: DirectorAgentOptions, signal: AbortSignal) {
  const agent = createDirectorAgent(dependencies);
  const input = await novelService.loadDirectorInput({
    storyRef,
    task: { objective: "提供让两人面对共同困难的机会", scope: "渡口下一场景" },
  });
  const result = await agent.run(input, { signal });
  if (result.output.status === "blocked") return result;
  await novelService.saveAgentArtifact({
    kind: "directorPlan", artifactId, commitId, expectedRevision, result,
  });
  // 保存计划不执行事件。应用另行推进场景，再准备角色可见输入。
  return result;
}
```

后续角色作出反应后，应用加载新的 `facts`、`characters`、`previousPlan` 和 `progress` 再调用 `run`。例如林舟拒绝帮忙，导演可以安排渡口关闭等有依据的后续变化，但不能把计划改成“林舟其实已经同意”。存储和执行预算配置沿用公共契约，角色调用仍由外部组织。
