#### 工具插件

**目标**：参考 DeepSeek Harness 的工具系统，基于 Cordis 构建通用 Tools 插件，使不同 Agent 能通过插件配置获得不同工具能力，并由 Agent Loop 协调模型工具调用。

本阶段先实现原生 Function Calling 的完整闭环，再逐步增强工具定义、运行上下文、生命周期及执行管理。

**开发原则**：

- 以官方实现为学习参考，不要求复制全部官方设计。
- 优先复用项目已有的 LLM、Session、Cordis 和 Agent Loop 契约。
- 每一步先解释原理、最小使用示例及输入输出，再开始实现。
- 每一步完成后进行实际调用验证，并停止等待下一步指示。
- 不提前实现当前步骤不需要的复杂功能。
- 工具插件负责注册与执行，Agent Loop 负责 Turn、Step 和模型交互，Session 负责事件持久化。

**开发步骤**

**1. 理解官方工具架构与确定最小接口**

阅读官方 `dsh-tools` 和 Agent Loop 工具调用实现，理解 ToolDefinition、ToolSchema、Tools Service、ToolExecutor 和 Agent Loop 的关系。

检查本项目现有 LLM、Session 和 Agent Loop 契约是否可以满足工具调用。

明确基础调用形式：

`ctx.tools.register(definition)`  
`ctx.tools.schemas()`  
`ctx.tools.execute(call, context)`

此步骤先确定接口和职责边界，不急于开发完整功能。

**2. 实现最小 ToolDefinition 与本地工具目录**

首先规划通用工具的存储结构，区分 Tools 基础设施插件与具体工具实现。

- `src/agents/plugins/tools/`：存放 ToolDefinition 契约、注册服务和 Cordis 基础插件。
- `src/tools/`：存放具体工具实现，按能力或业务领域划分子目录。
- `src/tools/filesystem/`：存放文件系统工具，第一版实现 `read_file`。

参考 DeepSeek Harness 的 `defineTool()`，建立最小工具定义结构，包含名称、描述、参数 schema 和执行函数。

以 `read_file` 作为首个示例工具：接收相对于授权工作目录的文件路径，读取 UTF-8 文本并返回内容。工具工作目录由运行上下文提供，不允许模型自行指定根目录；实现基本路径边界检查、文件大小限制及明确错误处理。

本步骤重点学习工具如何定义、如何组织代码，以及输入输出契约。可以通过直接调用 `execute()` 验证文件读取功能，暂不接入注册服务、Agent Loop 和模型调用。

完成后说明 ToolDefinition 如何转换为模型可见的 ToolSchema，并停止等待下一步指示。

**3. 建立 Tools Service 与 Cordis 插件**

在 `src/agents/plugins/tools/` 中实现工具服务，接入项目现有 Cordis 插件注册机制及 Agent Preset。

支持工具注册、查询、模型 schema 投影、按名称查找及注销。

验证不同 Agent Context 的工具隔离、重复注册和插件销毁后的清理行为。

**4. 实现工具调用与结果契约**

让 Tools Service 可以直接执行已注册的工具。

增加参数校验、未知工具处理、执行异常捕获和取消信号传递。

区分工具执行的结构化输出、模型可见结果和执行失败信息，避免后续扩展时需要重新设计返回格式。

通过直接调用工具服务进行测试，此步暂不接入模型。

**5. 接入 Agent Loop，完成单工具闭环**

在 Agent Loop 中获取当前 Agent 可见的 ToolSchema，并传递给 LLM Adapter。

模型返回 tool-call 后，Loop 调用 Tools Service，记录 Session 事件，将 tool-result 与原 call ID 关联，随后进入下一次模型请求。

复用现有消息协议，补齐必要的适配器兼容问题。

使用固定 LLM Adapter 验证完整的两步模型调用，确保最终 `agent.run()` 返回模型最终文本，而不是工具原始结果。

**6. 完善工具运行上下文与作用域**

明确工具执行时能够访问的上下文信息，包括 Agent 身份、调用 ID、取消信号及必要的运行作用域。

区分工具注册范围、模型可见范围和执行授权范围。

确保不同 Agent 使用相同工具定义时，仍然能够根据各自上下文执行，不会发生权限或数据串用。

**7. 完善执行结果与 Session 一致性**

明确工具返回值、模型可见内容和 Session 记录之间的转换关系。

检查工具调用与结果事件的关联、执行失败、取消以及异常中断时的记录完整性。

确保工具调用历史能够正确恢复为模型消息，不出现缺失关联结果、重复记录或不可解释的中间状态。

**8. 支持多个工具调用及 Loop 保护**

支持一次模型响应包含多个工具调用。

第一版优先串行执行，按模型调用顺序记录结果，并保证各工具失败相互隔离。

增加最大 Step 数等基本运行保护，明确取消、工具失败和超过执行上限时的 Turn 结束行为。

复杂并发调度、重试和执行策略暂不实现。

**9. 接入小说资料工具与 Agent Preset**

实现一个只读小说资料工具，使用已存在的小说数据。

通过 Agent Preset 决定工具插件的装配，通过 Agent 上下文确定可访问的数据范围。

验证角色 Agent 能读取自身授权的小说资料，而未装配该工具的 Agent 不可见、不可执行。

**10. 完整验收与官方方案对照**

使用固定 LLM Adapter 完整测试工具闭环，再通过真实模型进行受控测试。

检查工具注册、插件生命周期、参数校验、结果映射、Session 关联、上下文隔离、Loop 结束条件及异常处理。

对比 DeepSeek Harness 官方实现，列出已完成能力、设计差异和明确推迟的扩展能力。

基础工具系统完成后停止，不自动进入权限审批、MCP、PTC 或复杂执行策略开发。

**后续扩展方向（仅了解，不在当前阶段实现）**

工具权限审批、动态可见性、执行策略流水线、MCP 工具接入、执行超时与重试、并发调度、工具 UI 展示和后台任务。
