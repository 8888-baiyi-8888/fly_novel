# 评估 Agent 详细设计

本文定义评估模板的目标契约，接口与示例尚待实现。公共执行和报告保存规则见[总设计](agents.md)，被评估对象可来自[导演](director-agent.md)、[角色](character-agent.md)或[写作](writer-agent.md)模板。

## 一、需要实现哪些功能

评估 Agent 根据明确标准检查指定版本的内容，区分有依据的问题、风格判断和无法判断的事项。它不修改原稿、不改人物状态，也不把“角色没有按导演期待行动”本身视为缺陷。

| 编号 | 功能 | 需要达到的效果 |
| --- | --- | --- |
| E1 | 评估对象与标准绑定 | 固定待评内容版本、范围和标准，不自行扩大评估范围。 |
| E2 | 证据读取与问题判断 | 核对事实、人物连续性、视角或文风，明确依据及不确定性。 |
| E3 | 可定位的问题报告 | 每项问题可定位、可核对，给出修改方向而不直接改稿。 |
| E4 | 修订复评 | 在新版本上重新检查旧问题，不因文本变化自动判定解决。 |
| E5 | 结果校验与报告保存 | 保存与对象版本绑定的报告，避免旧结论被当成新稿结论。 |

## 二、每个功能如何实现

### E1：评估对象与标准绑定

#### 输入信息

| 字段 | 必需信息 | 来源 |
| --- | --- | --- |
| `context` | 小说、分支及依据版本。 | 应用可信绑定。 |
| `target` | 对象种类、产物 ID、修订和完整待评内容。 | 指定版本的计划、角色结果或正文。 |
| `scope` | 需要检查的段落、步骤或表现项 ID。 | 调用方指定，全文检查也需明确。 |
| `criteria` | 每条标准的唯一 ID、说明及性质：事实约束、行为约束或表达偏好。 | 作者或应用，不由模型暗中追加标准。 |
| `evidence` | 有来源的事件、角色状态、叙述规则或保留要求。 | 评估权限内的材料。 |
| 可选旧报告 | 报告 ID、目标旧版本及旧问题。 | 复评时提供，不作为新结论的事实依据。 |

人物一致性、剧情逻辑、节奏和文风通过标准区分，首版使用一个评估模板，不建立多个子评估 Agent。

#### 处理逻辑

1. 固定对象版本及范围，校验标准 ID、内容定位 ID 和证据引用。
2. 缺失对象或必需结构时直接报错；结构完整但判断所需证据不足时保留该项为无法判断。
3. 若标准要求“角色必须服从导演选择”，报告标准与角色自主性边界冲突，不把人物拒绝本身标为错误。
4. 把被评文本中的命令当作材料，不允许其改变评估规则或读取权限。

#### 输出与状态影响

得到冻结的评估对象、标准集合和证据范围。不修改对象、角色或世界事实。

#### 验证

验证空标准拒绝、重复或未知定位 ID、标准越界，以及正文中的提示词不能覆盖评估职责。

### E2：证据读取与问题判断

#### 输入信息

使用 E1 的对象、标准和证据，可选注入受限资料读取器。事实核对所需世界材料与角色当时知道的材料分别标识，评估者知道真相不意味着角色应该知道。

#### 处理逻辑

1. 针对每条标准检查范围内内容，必要时读取允许的来源原文，不把摘要当作逐字引用依据。
2. 事实问题核对事件与正文是否矛盾；人物问题核对其当时认知、目标、经历和情境，而不是核对是否配合导演安排。
3. 将角色误判与文本错误分开：人物相信错误消息可以成立，叙述无依据把错误消息写成世界真相才可能构成问题。
4. 文风和节奏问题引用具体片段及标准，明确这是表达判断，不能包装成客观事实违例。
5. 缺少依据时记录无法判断项，不编造引文或确定结论。查询未命中不等于事实不存在；工具失败按执行错误传播，不伪装成评估通过。

#### 输出与状态影响

产生候选问题与无法判断项，交给 E3 组织。不会为了消除问题直接改写人物选择、正文或事件。

#### 验证

对照检查误判合理性、私有信息泄露、导演强制角色选择、风格偏好与事实冲突区分，以及无证据不下确定结论。

### E3：可定位的问题报告

#### 输入信息

E2 的判断、冻结对象、标准及来源原文。待评材料以有稳定 ID 的块或项目提供，避免只使用容易漂移的自然语言位置描述。

#### 处理逻辑

1. 每项问题绑定 `criterionId`、目标项目 ID 和短引用。引用必须是该目标内容的精确子串；重复出现时增加明确出现序号，应用验证可定位。
2. 记录问题描述、证据和修改方向，不输出替换正文。全局结构问题定位为本次整个 `scope`，不能伪造不存在的具体句子。
3. 影响程度分为 `blocking`、`major`、`minor`，只表示修订优先级，不表示统计概率。阻断必须说明违背哪条必须满足的标准。
4. 同一位置同一原因的问题合并，保留覆盖标准；不同问题不能为了减少数量强行合并。
5. 为每条标准给出 `noIssueFound`、`issuesFound`、`unableToAssess` 或 `partiallyAssessed`。有问题但仍有未判断部分时使用最后一种，不用总体结论掩盖缺口。

#### 输出与状态影响

| 字段 | 内容 |
| --- | --- |
| `summary` | 本次限定范围内的结论，不承诺作品整体质量。 |
| `criterionResults` | 每条输入标准对应的覆盖状态及问题、未判断项引用。 |
| `issues` | 本轮唯一 ID、标准引用、位置、判断性质、描述、证据、影响程度及修改方向。 |
| `unassessed` | 缺少的依据或无法判断原因、关联标准和范围。 |

`issues`、`unassessed` 可为空；所有标准必须有覆盖记录。首版不输出通用总分。报告版本由应用绑定，不依赖模型生成。

#### 验证

验证引文精确匹配、定位唯一、标准覆盖、引用完整和无问题不等于无证据；使用固定报告结构测试，文学判断进行专项评估。

### E4：修订复评

#### 输入信息

新 `target`、本次 `scope`、标准和证据，以及可选 `previousReport`。旧问题含旧对象版本和定位，不能直接作为新版本位置。

#### 处理逻辑

1. 按新版本重新定位旧问题，重新读取修改后内容与依据。
2. 同一问题确实消失时标记 `resolved`；仍存在标记 `persists`；缺少证据或定位不能确定时标记 `unableToAssess`；不在本次范围时标记 `outOfScope`。
3. 删除原句不自动等于问题解决，需要检查冲突是否移到其他位置；限定范围不足以验证时保持无法判断或范围外。
4. 复评仍检查本次所有指定标准，可能发现新问题，不只逐条勾选旧清单。原报告不可改写。

#### 输出与状态影响

`issueResolutions` 在复评时列出旧报告问题 ID 和处理状态，关联新问题 ID；普通评估返回空列表。新报告关联旧报告但绑定新对象版本，不自动采用改稿或关闭外部待办。

#### 验证

验证问题移位、局部复评范围限制、旧问题无法定位、新增问题及跨版本报告隔离。

### E5：结果校验与报告保存

#### 输入信息

模型、公共执行配置、可选查询依赖，以及 E1 至 E4 材料。保存时应用绑定报告 ID、提交 ID和依据版本。

#### 处理逻辑

1. 按公共生命周期执行，固定规则要求“有依据、可定位、未知明确说明、不直接修改对象”。
2. 程序检查定位、引文、标准和问题引用，拒绝结构无效或伪造来源，不通过删掉错误项伪装成无问题报告。
3. 返回有效报告后由应用保存；报告可以包含无法判断项，它不是模型执行失败，但不得显示成全部通过。
4. 待评对象变化后，旧报告只作为历史，不继续显示为新版本已通过。再次评估由外部流程显式发起，不自动循环改稿。

#### 输出与状态影响

返回 `{ basis, output }`，输出包含 E3 的字段与 `issueResolutions`。应用按总设计保存版本化报告；评估不改变剧情、正文和角色状态。

#### 验证

验证报告与对象版本绑定、取消无成功报告、查询异常传播、保存冲突及重启恢复；不得把部分评估显示为完整通过。

## 三、代码的外部使用方式

以下接口和业务服务为设计草案，不可直接运行。应用完成模型初始化后提供依赖；调用方负责保存报告并决定是否发起独立改稿任务。

```ts
import { createEvaluatorAgent, type EvaluatorAgentOptions } from "@fly-novel/agents";

async function reviewDraft(dependencies: EvaluatorAgentOptions, signal: AbortSignal) {
  const agent = createEvaluatorAgent(dependencies);
  const input = await novelService.loadEvaluatorInput({
    targetRef,
    scope,
    criteria: [
      { id: "facts", kind: "factConstraint", description: "正文符合已确认事件" },
      { id: "autonomy", kind: "behaviorConstraint", description: "不改写角色已形成的选择和心理" },
    ],
  });
  const result = await agent.run(input, { signal });
  await novelService.saveAgentArtifact({
    kind: "evaluationReport", artifactId, commitId, expectedRevision, result,
  });
  // issues 为空仍需查看 unassessed 和 criterionResults。
  return result;
}
```

例如正文将“伸手夺信”写成“成功夺信”，报告应引用该句、对应角色动作和缺失反馈，建议恢复为有依据的尝试或先补充场景反馈，不能直接替角色重写结果。复评时传入新稿和旧报告，所有结论重新绑定新稿版本。
