# 世界发展规划：联合资料契约

本文确定[联合开发计划](world-initialization-stage-6a-world-development-plan.md)的首版契约；实际格式、受控存储和工具见[世界发展规划插件](../../../src/agents/plugins/world-development/README.md)。示例是规划格式，保存或目录登记不代表用户确认，也不代表未来事件发生。

## 身份、存储与版本

三个模块共用世界发展规划负责人目录及专用插件，按宏观规划、故事线、人物成长蓝图分开维护权威正文。每个需要独立定位的规划对象一份 JSON；总览按世界和类型各一份，方向、事件构想、故事线、角色成长线和跨人物规划项使用程序生成的小写 UUID。名称只用于显示，允许重名；世界、负责人目录和权限由可信应用绑定，不由模型决定。

目录使用 `macro-development/`、`storylines/`、`character-growth/` 及 `candidates/`，各类对象独立子目录；确切路径由[插件说明](../../../src/agents/plugins/world-development/README.md)给出。文件包含 `formatVersion: 1`、可信 `worldId`、类型、ID、名称、待审状态和内容。JSON 必须是 UTF-8 严格对象：拒绝未知版本、重复键、额外字段、非法 ID、跨世界身份、类型不匹配和损坏文件；不能修改或删除原文件。此前的 Markdown、人物及其他模块数据不自动转换、覆盖或迁移。文件版本是并发控制凭据，不是世界时间或用户确认。

初始化创建均为待审（`suggested`）。未确认资料按读取的文件版本完整更新，版本不匹配拒绝；格式允许读取 `confirmed`，已确认资料仅可独占创建带原文基线的候选，候选读取时报告基线是否变化，不实现用户确认或候选提交。已有候选、无法核对版本或发布结果不确定时不能盲目覆盖；查询与目录登记不等于确认。世界演化后的历史留存、规划实际采用与结果记录留给后续世界运行。

## 对象和内容

| 对象 | 最小正文 | 必要身份或关联 |
| --- | --- | --- |
| 宏观蓝图 | 名称、世界规划概况、覆盖范围及留白。 | 世界内一个总览；方向和事件通过独立文档定位。 |
| 发展方向 | 名称、概况、可能变化、条件 / 影响及未知。 | 可按局势方案分别记录适用说明，可关联事件构想和故事线。 |
| 重大事件构想 | 名称、概况、可能发生的变化、条件 / 影响及未知。 | 与历史事件分属不同类型；可由多个方向、故事线引用。 |
| 故事线 | 名称、持续主题、按需阶段或分支、留白。 | 可关联方向、构想、角色、组织和其他故事线；多个故事线可引用同一构想。 |
| 角色成长线 | 名称、角色的成长方向、按需阶段或可能转折、未知。 | 每个已关联人物在一个世界最多一条成长线；可以关联多条故事线。不同方向在该线内表达。 |
| 人物成长蓝图 | 名称、世界范围内的人物成长规划重点和留白。 | 世界内一个总览；引用跨人物规划项及角色成长线，不复制每人详细成长内容。 |
| 跨人物规划项 | 名称、多个人物成长的呼应、张力、可能影响和留白。 | 按需引用多个角色成长线、宏观方向及故事线；不自动成为人物事实。 |

正文允许按需使用文字与少量结构化列表，不要求生成全部类型或固定数量；留白为可读文字列表。阶段 / 分支可以先在各自正文中有明确标题与适用说明，不强制每个阶段单独建文件。程序不解析自然语言判定条件是否成立，也不自动排序、推断因果、触发事件或执行故事。

## 单角色成长线和未关联线索

已关联角色使用 `{"kind":"linked","id":"角色UUID"}`。创建或更新成长线须通过可信同世界人物读取核验角色 ID，并在已记录成长线中检查一个人物最多一条；修改时也检查其他成长线，禁止通过更换关联绕过唯一性。一个世界可以有尚未建立成长线的人物，不能强制为所有人物创建。

尚未建档角色可使用 `{"kind":"unresolved","description":"可读线索"}`。不同线索不能根据姓名自动合并或判断人物不同；解析线索后须取得实际人物 ID，检查该人物是否已有成长线，若已有则拒绝关联并保留原线索与既有文件，由用户或负责 Agent 比较后处理。线索不证明人物存在，也不授予访问权限。相同角色的不同候选局势和可能方向应写在同一成长线中并标明适用范围，不创建重复成长线。

## 局势适用范围

每个方向、事件构想、故事线、角色成长线和跨人物规划项均可分别说明适用性；建议使用以下三种表达，互不混同：

- `unknown`：尚未判断适用的方案；不表示适用于所有方案。
- `general`：经规划者明确声明为不依赖特定候选的通用规划，并提供说明；不是从缺少引用自动推断。
- `scoped`：一条或多条不同的同世界局势方案关联，每条包含方案 ID、适用说明，以及按需引用的局势条目 ID；同一方案不可重复。

写入时由可信应用读取方案及条目，验证真实世界和条目属于该方案；不因名称相似、文件路径或候选顺序自动匹配。多个方案分别保存说明，互相不继承条件。查询方案 A 时分别返回明确适用于 A、明确声明通用，以及尚未判断的候选；仅适用于 B 的对象不进入 A 的适用结果。无法读取或核验方案时报告原因，不将其当作不适用或已确认。`unknown`、缺失资料和明确留白各有含义。

## 关联与来源

单项文档维护其主动声明的关联，使用目标类型、稳定 ID 和说明；反向查询扫描实际文档并显示来源及方向，不额外维护一份反向权威数据。至少支持方向与构想、构想与故事线、故事线与成长线、成长蓝图项与成长线或世界发展方向；同一目标可以被多个对象引用，名称相同不自动关联。不同类型的先后、因果、依赖、相关和互斥只在明确记录时成立，程序不从引用或反向查询推断新的关系。关联目标不存在、跨世界、类型不匹配、权限不足或尚未核验时分别报告，不能自动重写外部资料。

引用历史、地点、组织、人物及其关系时，由可信应用绑定相应存储句柄并核验世界和负责人；基础信息若只有授权文档，使用实际文档路径或明确线索，不伪造对象 ID。需要追踪来源变化时保留实际读取可用的版本 / 摘要并可重新比较；未配置、缺失、无权、读取失败、版本未知和版本变化不能混同。模型自己提供的版本不证明读取过原始内容。跨模块逐个读取不是原子快照；程序不声称能自动裁决复杂语义矛盾。

## 范围与拒绝路径

本契约只覆盖初始化规划和可核查引用，不建立角色权限系统、导演安排、事件自动触发、世界时钟或剧情执行。规划者可读取完整授权资料，但此读取不代表角色已知；普通文件、目录和搜索的角色视角隔离留给后续角色运行。

第三步必须通过实际文件和工具测试：两个候选方案互不串用、同人物重复成长线拒绝及线索关联冲突、单线多方向、跨世界引用拒绝、反向查询、版本冲突、无权 / 缺失 / 未配置、损坏与未知格式、取消、已确认候选和发布结果不确定。实际实现不能把可见范围之外当作不存在，也不能在失败后删除已有资料。
