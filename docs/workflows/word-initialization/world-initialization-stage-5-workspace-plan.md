# 世界初始化第五阶段：共享工作区与资料读取详细计划

本计划细化[世界初始化开发计划的第五阶段](world-initialization-development-plan.md#5-最小方案工作区与资料读取)。目标是在同一世界中为主、子 Agent 提供共享读取、各自的修改范围和可维护的资料目录，为后续方案生成提供基础。工作区的最终根路径由后续业务决定；本阶段由可信应用显式提供测试工作区，不预设世界数据的最终存储位置。

## 已商议的目标

- 一个世界有一个主 Agent 和若干由用户决定的特殊子 Agent。特殊子 Agent 有持续身份；运行实例可按需创建、销毁和重新创建，实例结束不删除其成果文件。
- 特殊子 Agent 基于现有通用子 Agent 机制实现，由用户装配为主 Agent 可调用的专用工具；主 Agent 调用对应工具使用该子 Agent 的能力。运行时世界工作区的最终根目录留待后续业务开发时确定。
- 装配主 Agent 时，可信应用向专用工具提供对应子 Agent 的稳定身份、所属世界和工作区配置；模型调用时提供本次任务所需的业务参数，不通过调用参数授予世界或目录权限。重新创建实例时沿用对应身份和目录；稳定身份与目录的具体表示方式待确定。
- 同一世界的主、子 Agent 可以读取该世界工作区内全部获授权的资料；每个 Agent 只能修改分配给自己的子目录，不能直接修改其他 Agent 的目录。不同世界的工作区相互隔离。
- 工作区有一份资料目录，记录成果文件的位置、用途简介、负责的 Agent，以及简介对应的文件版本。普通文件工具不能直接修改该目录；Agent 通过专用工具登记和更新简介。
- 主 Agent 和特殊子 Agent 通过资料目录专用工具登记、修改和删除自己负责的记录，不能处理其他 Agent 的记录；同一世界内获授权的其他 Agent 可以查找和读取。主 Agent 发现子 Agent 的记录有问题时，调用对应子 Agent 处理。
- 程序检查目录记录与文件实际版本，发现不一致时标记过期，由主 Agent 委派负责该文件的子 Agent 更新。子 Agent 未运行时可按其持续身份重新实例化，继续使用原有目录；不能假定记忆模块已经存在。
- 不预建独立的 Agent 身份与目录映射管理系统。优先复用用户提供的 Agent 配置和明确的目录约定；如实施中发现无法安全表达对应关系，先记录实际问题并确认所需方案。

以下仅用于说明关系，目录名和实际格式尚未确定：

```text
世界工作区/
├── 资料目录                 # 由专用工具维护
├── 主 Agent 的目录/         # 主 Agent 可写
├── 子 Agent A 的目录/       # A 可写；实例销毁后保留
└── 子 Agent B 的目录/       # B 可写；实例销毁后保留
```

第五阶段以工作成果和目录读取为中心：普通成果、用户要求、建议、明确留白与已确认资料不能混为一谈。已确认资料的保护仍须维持，不能因为某个 Agent 拥有目录就自动获得改写已确认事实的权限。完整世界业务模型、用户确认提交、长期持久化和记忆恢复仍按后续阶段设计；本阶段不声称这些能力已经实现。

## 尚待确定的事项

- Agent 稳定标识、目录命名或显式配置方式，以及同一身份重复启动时等待、拒绝还是复用；不提前固定特殊子 Agent 的类型、数量或职责。
- 文件版本使用内容摘要还是后端版本，以及目录的记录格式、版本号和恢复策略；若写入持久文件，必须定义未知版本拒绝或迁移规则，不静默误读或删除用户数据。
- 何时执行对齐：任务结束前、查询时、显式检查或组合；未登记、过期、缺失、读取失败和检查中变化如何向主 Agent 报告。此项暂留，后续结合实际流程讨论。
- 目录中登记的简介与用户要求、建议、明确留白和已确认内容的关系；资料目录是导航信息，不能仅凭简介或登记动作将建议确认为事实。
- 本阶段真实模型验证是否需要具体特殊子 Agent；缺少实际 Agent 或记忆模块时，使用固定替身验证身份复用和任务交付，不能虚构记忆恢复。

## 1. 核对现状并确定工作区契约

1. 阅读第四阶段文件后端、沙箱、观察策略、搜索、工具上下文、主子 Agent 创建与作用域实现，核对现有读取根、修改根、事件路由、取消和释放行为；列出与共享读取、各自可写目标之间的差距。
2. 用至少两个世界、一个主 Agent 和两个用户指定的特殊子 Agent 的具体例子，确定可信应用如何提供世界根、持续身份和可写子目录；确认重新实例化及并发实例的权限归属，不从模型参数授权。
3. 明确资料目录的职责、可访问方式和登记权限；区分导航记录、成果文件、已确认资料和未来业务确认流程。明确绝对路径、相对路径、目录链接、路径别名及平台临时可写根对授权的影响。
4. 与用户确认上节仍影响实现的选择；在本计划记录可验证的决定、错误和清理语义。现有应用层路径检查不能保证抵御恶意本地并发替换、硬链接和所有平台差异，生产装配前须按实际环境评估。

### 现有能力与差距

- [受控应用入口](../../../src/app/agents/world-initialization.ts)为主 Agent 配置草稿写权限，为通用子 Agent 配置只读工具；委派工具固定使用一个子 Agent Preset，尚不能选择用户指定的持续身份。主、子 Agent 的读取和搜索以可信应用提供的读取视图为工作目录。
- [工作区校验](../../../src/app/agents/world-initialization-workspace.ts)要求读取视图、草稿根和已确认资料根是已有的真实目录，草稿和已确认资料位于视图内，且已确认资料不与上游可写根重叠。[草稿文件后端](../../../src/app/agents/world-initialization-draft-fs.ts)额外限制修改目标，避免上游允许的系统临时目录扩大修改范围。当前配置尚不表达各 Agent 的独立可写目录或世界之间的配置关系。
- [读取授权](../../../src/agents/plugins/fs/tool-fs/read-access.ts)以可信工作目录为根解析模型提供的路径并检查包含关系；搜索复用读取授权。[文件观察策略](../../../src/agents/plugins/fs/fs-observation-policy/index.ts)按工具所属 Agent 和 Session 路由观察及修改意图，Session 关闭时清理观察。观察记录不等于持续身份或记忆恢复。
- [子 Agent 服务](../../../src/agents/plugins/subagent/subagent/runtime.ts)取消并等待尚未交付的启动，已交付运行由句柄持有方释放；[进程内创建](../../../src/agents/plugins/subagent/subagent-in-process-driver/create.ts)在启动期间取消时释放迟到的句柄。持续身份与目录复用、同一身份并发运行及其失败清理仍需确定并实现。
- [通用创建器](../../../src/agents/runtime/subagent-in-process-creator.ts)为每次启动生成新的 Agent 实例 ID 和运行 ID；[Agent Manager](../../../src/agents/runtime/agent-manager.ts)拒绝同一 Manager 内重复的实例 ID，包括创建和清理期间，但这不会自动限制使用不同实例 ID 的同一业务身份。通用子 Agent 服务也不登记已交付的运行；基于通用机制实现的特殊子 Agent 应结合这些现有能力设计持续身份与并发策略，不能直接假定已有按业务身份的互斥。
- 通用创建器通过可信的 Preset 插件配置装配子 Agent，Spawn Provider 也接受可信创建函数；专用工具可以在装配时接收工作区配置并通过既有创建扩展点传入子 Agent。现有通用委派工具本身只配置 Preset ID，具体注入方式仍待设计。
- [本机文件后端版本](../../../src/agents/plugins/fs/fs-local/fsio.ts)由文件身份、大小和时间元数据组成，用于文件修改时的新鲜度检查，不是内容摘要。资料目录长期保存时能否使用该后端版本，或使用文件内容摘要，仍需结合存储与恢复要求决定。
- 资料目录、专用登记工具与简介版本对齐尚无实现。目录是导航信息，成果文件和已确认资料仍是各自独立的内容；登记不会触发未来的业务确认流程。

### 待商议的身份与目录示例

以下是讨论用示例，不是已批准的配置格式或授权契约。世界 A、世界 B 使用隔离的工作区；世界 A 的主 Agent 和用户指定的 `history`、`geography` 子 Agent 各有独立目录，世界 B 即使也有 `history` 身份，其目录和权限也属于世界 B。各 Agent 读取本世界获授权内容，只修改自己的目录；已确认资料和资料目录仍受独立保护。实例结束后保留成果，重新实例化时使用对应身份原有目录。实际根目录留待后续业务决定，本阶段由可信应用提供测试工作区。

特殊子 Agent 的专用工具在装配时接收可信应用提供的身份、世界和工作区配置，调用时接收任务参数。具体配置形式、目录别名与链接的处理、同一身份重复启动时拒绝、等待或复用，以及跨进程并发范围仍须与用户确认。

**验收**：共享读取、专属修改、已确认资料保护、世界隔离和重新实例化边界有具体例子和可验证规则；未决定事项不冒充已批准的契约。

## 2. 角色创建专用子 Agent 与工具

详细开发步骤见[角色创建子 Agent 与专用工具计划](world-initialization-stage-5-character-creator-plan.md)。

1. 核对现有通用子 Agent、委派工具和角色相关实现，明确角色创建子 Agent 的职责、任务输入和结果；该子 Agent 用于协助创建世界中的各种角色，不将示例角色或角色分类固定为所有世界的必需内容。
2. 基于现有通用子 Agent 机制创建角色创建专用子 Agent，由可信应用将其专用工具装配给主 Agent；主 Agent 通过工具提交角色创建任务，子 Agent 的职责和配置由应用确定，不由模型自行创建或授权子 Agent。
3. 明确工具的任务参数、结果、失败、取消和资源释放语义，复用现有 Spawn 和生命周期能力；为后续注入所属世界及工作区权限保留实际需要的装配位置，本步不预设世界数据的最终根目录，也不实现虚假的记忆恢复。
4. 使用固定模型替身通过真实主子 Agent 和工具链验证角色创建任务的传递、结果返回、失败、取消和释放；验证不同角色任务可以交给该专用子 Agent，不将替身结果描述为真实模型能力验证。

**验收**：主 Agent 能通过可信装配的专用工具调用基于通用机制的角色创建子 Agent，并获得任务结果；调用失败、取消和清理行为可验证，为下一步注入工作区配置提供入口。

## 3. 工作区装配与各 Agent 文件边界

1. 沿现有 Harness 和文件后端扩展点建立最小工作区配置与校验，工作区根由可信应用提供；不自动选择最终数据位置，不覆盖或删除已有用户数据。
2. 为每个 Agent 装配相同世界的读取和搜索范围及自己的修改范围。明确主 Agent 与子 Agent 的授权、受保护的资料目录和已确认资料；必要时在现有沙箱外增加更严格的应用约束，不能将上游平台临时根误认为专属目录。
3. 让持续身份对应的目录在实例销毁后保留，并验证再次实例化仍使用同一目录。实施所需的并发实例约束、启动失败回滚和作用域清理；记忆恢复保持独立，不创建虚假记忆实现。
4. 验证同世界交叉读取、跨 Agent 写入拒绝、跨世界读取和写入拒绝、绝对路径与遍历、目录链接、目录别名、已确认资料及资料目录的普通写入拒绝。采用受控测试目录和固定替身。

**验收**：真实工具执行链证明共享读取与专属修改，Agent 销毁和重新创建不丢失成果，越权路径及失败清理有反例；平台和并发限制如实记录。

## 4. 资料目录与受控登记工具

1. 按第 1 步确认的契约定义最小目录记录，包括文件位置、简介、负责 Agent 和简介对应的版本；文件格式及版本规则在持久化前确定。登记、查询和删除或移动记录的权限依已确认方案执行。
2. 实现专用工具及后端，校验调用者身份、世界范围、目标位置和文件状态；对目录文件启用单一受控写入口。并发登记不同文件不得丢失彼此更新，同一记录冲突须明确报告或按契约重试，不静默覆盖。
3. 将文件版本与登记时读取到的文件内容关联。文件在登记前后发生变化、目录写入失败或部分操作完成时，返回真实状态；禁止将陈旧简介标为最新。明确事务范围，不把无法原子完成的多文件操作描述为整体回滚。
4. 实现按需查找与读取，结果说明来源及状态；验证同名候选、不存在、明确留白、读取失败和未覆盖范围的区分，不要求调用方依赖宿主绝对路径。

**验收**：真实工具和受控并发测试证明目录写入口、授权、版本关联及失败语义；已确认资料不能通过登记被提升或改写。

## 5. 版本对齐与对应子 Agent 更新

1. 按已确认的触发时机检查目录，明确区分一致、内容变化、未登记、文件缺失、读取失败以及检查期间继续变化；不能将失败伪装成无结果或过期处理成功。
2. 将需要更新的记录及其负责 Agent 交给主 Agent；主 Agent 使用用户配置的对应身份委派，实例未运行时重新创建。相同身份的并发执行遵循第 1 步决定，避免并行写入同一目录。
3. 子 Agent 读取保留的成果文件，通过专用工具更新简介并携带或关联实际版本；最终再次核对，若文件再次变化则保留未对齐状态，不宣称更新成功。更新失败、取消、负责人不存在或不可启动时明确返回并保留可恢复状态。
4. 使用固定模型和受控并发替身验证任务结束、实例销毁、重新实例化、正常更新、再次修改竞争和失败清理；不把重新实例化描述为已经恢复记忆。

**验收**：过期发现、主 Agent 委派、对应身份更新及最终对齐形成可观察的闭环，异常和并发情况下不丢失成果或误报一致。

## 6. 集成、文档与交付

1. 通过真实主子 Agent 注册、工具执行和 Session 链路验证两个 Agent 共享读取、各自修改和目录登记；至少覆盖两个世界隔离、用户指定子 Agent 重启以及资料不存在、明确留白和读取失败。
2. 保持第四阶段文件能力的授权和观察保护；更新相关模块 README、架构、应用入口和 Agent Note。说明文件路径与资料业务接口的关系、持久化格式及迁移或拒绝读取规则、记忆模块尚未实现的边界。
3. 运行变更对应的聚焦测试、类型检查和必要构建产物冒烟，检查文档链接、许可证及 Git 空白；记录实际平台、跳过项、并发与安全限制。真实模型测试单独说明是否执行及结果，不将固定替身测试当作真实模型通过。

**验收**：调用方可按照已验证入口装配和查找资料，真实权限与版本对齐可复验；长期持久化、记忆恢复和用户确认提交的未完成部分明确保留。
