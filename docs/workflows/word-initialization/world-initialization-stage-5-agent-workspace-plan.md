# 世界初始化第五阶段：工作区装配与各 Agent 文件边界详细计划

本文细化[第五阶段工作区计划第 3 步](world-initialization-stage-5-workspace-plan.md#3-工作区装配与各-agent-文件边界)的实施顺序。世界、Agent 身份、授权范围及资料目录的首版契约见[工作区计划第 1 步](world-initialization-stage-5-workspace-plan.md#1-核对现状并确定工作区契约)；角色创建能力及其当前边界见[角色创建计划](world-initialization-stage-5-character-creator-plan.md)。本文是开发计划，不表示下述共享文件边界已实现。

## 目标与范围

可信应用显式装配世界读取范围、主 Agent 和用户指定的特殊子 Agent 身份及各自可写目录。同一世界的 Agent 读取和搜索获授权的世界资料，只修改自身目录；不同世界隔离。普通文件工具不能修改已确认资料或工作区资料目录，Agent 销毁和重新创建不删除成果，也不将 Session 恢复说成长期记忆恢复。

本步建立和验证工作区装配及文件边界，并在受控测试中接入角色创建 Agent；第二个特殊子 Agent 使用固定测试职责和现有通用机制，不提前开发新的业务 Agent。资料目录的登记工具、文件版本对齐及整体确认流程仍分别按工作区计划后续步骤实施；本步只保护其预留目录，不创建虚假的目录服务。最终世界根路径由可信应用提供，不固定生产数据位置。

## 现状与实施约束

- [受控入口](../../../src/app/agents/world-initialization.ts)为主 Agent 装配草稿写权限、为通用子 Agent 装配只读工具；角色创建工具通过 `persistent` Provider 启动独立 Agent。入口检查角色目录与草稿、已确认根不重叠，但尚未表达通用的每 Agent 可写根及多个世界之间的配置关系。
- [工作区校验](../../../src/app/agents/world-initialization-workspace.ts)和[草稿文件后端](../../../src/app/agents/world-initialization-draft-fs.ts)保护当前主 Agent 草稿与已确认目录；上游沙箱的 `workspace-write` 还包含系统临时目录，不能把它直接作为 Agent 专属写权限。
- [文件读取授权](../../../src/agents/plugins/fs/tool-fs/read-access.ts)和搜索复用可信读取根；[文件观察策略](../../../src/agents/plugins/fs/fs-observation-policy/README.md)记录当前 Agent 和 Session 的观察，并不提供目录授权或持久身份。
- [角色创建入口](../../../src/app/agents/character-creator.ts)使用可信目录、角色资料服务及持久 Session；角色资料服务直接执行文件操作，必须纳入本步的目录和受保护资料检查，不能只给普通文件工具加限制。
- [`persistent` Provider](../../../src/agents/plugins/subagent/subagent-persistent-in-process/README.md)复用已有运行驱动，同一个创建绑定在运行期间独占；跨绑定及跨进程的身份和写入互斥不能假设已由它保证。可信应用负责为持续身份提供一致的目录和 Session 配置。

## 1. 核对实际文件路径及装配链

1. 阅读受控主 Agent 入口、角色创建入口、文件后端、读取和搜索工具、观察策略、`persistent` 创建函数及其测试；核对工具使用的读取基准、所有可写操作、实际事件来源及释放顺序。
2. 分别列出主 Agent 草稿工具、通用只读子 Agent、角色资料工具和测试用特殊子 Agent 的读写路径。检查直接文件操作、文件移动的源与目标、系统临时目录，以及模型是否能自行提供授权根。
3. 保留现有第四阶段的读取授权、观察和已确认资料保护；明确尚无资料目录服务时，目录预留路径由可信配置提供并由普通文件工具保护。

**验收**：依据实际代码和测试指出可复用入口、当前差距及直接文件访问路径；不把提示词或观察策略当作授权机制。

### 第 1 步核对结论

| 调用方 | 实际读取路径 | 实际修改路径与授权 |
| --- | --- | --- |
| 主 Agent | [受控入口](../../../src/app/agents/world-initialization.ts)将 `viewRoot` 作为可信工作目录；文件读取和搜索由文件后端解析并检查读取根。 | `tool-fs` 经[草稿后端](../../../src/app/agents/world-initialization-draft-fs.ts)修改 `draftRoot`；写入、编辑、补丁、删除分别检查目标，移动检查源和目标。 |
| 通用只读子 Agent | 同一入口用 `spawn` 装配相同的 `viewRoot`、只读文件工具和搜索工具。 | 文件后端使用只读策略；没有装配普通修改工具。 |
| 角色创建 Agent | [独立入口](../../../src/app/agents/character-creator.ts)从可信配置取得 `readRoot`；当前 `read_file` 是[直接读取实现](../../../src/tools/filesystem/read-file.ts)，自行检查相对路径和真实路径，不经过第四阶段文件观察策略；当前入口没有装配搜索工具。 | [角色工具](../../../src/tools/character/character-tools.ts)绑定 `CharacterStore`，由服务直接操作可信 `characterRoot`，不经过草稿后端或普通文件工具的观察策略；模型不能传入授权根。 |
| 第二个特殊子 Agent | 当前没有该工作区测试装配。 | 后续使用通用机制和真实文件工具建立测试实例，不能把只读子 Agent 当作第二个可写实例。 |

角色资料服务在角色根下直接维护 `index.json`、`requirements.md`、角色 ID 目录中的 `profile.md`、`pending.md` 和 `pending.json`；可信确认、恢复和重建还会使用 `backup.md`、`operation.json`、索引备份以及同目录临时文件。服务使用程序生成的角色 ID，按根目录在进程内排他并串行执行操作；确认提交和恢复不是模型工具。其直接文件访问必须与普通文件工具一起纳入后续边界验证，不能仅检查工具参数。

当前工作区配置只表达 `viewRoot`、`draftRoot` 和 `confirmedRoot`；入口对可选角色根检查它与草稿根、已确认根不重叠，并要求角色 Session 根与读取视图分离。它尚未统一表达世界 ID、多 Agent 专属目录、资料目录保护根及多个世界的相互关系。通用 `workspace-write` 包含平台临时目录，但当前草稿后端另行限制所有修改目标必须在草稿根内；后续装配不能只依赖通用沙箱根。资料目录登记服务尚不存在，预留保护根应由可信配置提供。

文件观察按工具调用的 Agent 身份和 Session 路由，不提供路径授权；角色服务和 `read_file` 的直接文件调用不产生这条观察链。`persistent` 创建绑定在启动到释放期间独占；角色创建入口另按世界与 Agent 身份、Session 和角色根进行进程内占用检查，但这些机制不构成统一的跨 Agent 或跨进程工作区锁。角色入口先释放框架和 Session 后端，再关闭角色服务并解除占用；委派工具等待任务结果和释放，任务与释放同时失败时保留两个错误。启动取消由现有运行驱动清理迟到实例。

现有验证入口包括[工作区与草稿边界测试](../../../src/app/tests/world-initialization-workspace.test.ts)、[角色持续委派测试](../../../src/app/tests/world-initialization-persistent-delegation.test.ts)、[角色 Agent 集成测试](../../../src/app/tests/character-creator-integration.test.ts)、[角色资料服务测试](../../../src/world-init/tests/character-store.test.ts)、[文件沙箱边界测试](../../../src/agents/tests/fs-sandbox-boundary.test.ts)、[真实文件观察集成测试](../../../src/agents/tests/fs-observation-local-integration.test.ts)及 [persistent 生命周期测试](../../../src/agents/tests/subagent-persistent-in-process.test.ts)。这些测试覆盖各自局部行为，尚不能替代本计划要求的两个世界、多个可写 Agent 和全部文件访问路径的组合验证。

## 2. 实现可信工作区配置与校验

1. 在应用或世界初始化业务层提供工作区配置：可信应用显式提供世界 ID、已有世界读取根、已确认资料根、资料目录保护根，以及各 Agent 的稳定 ID 与已有专属目录。目录名称和最终根位置不写死；模型任务参数不提供或扩大这些授权。
2. 按[首版工作区契约](world-initialization-stage-5-workspace-plan.md#首版工作区契约与示例)校验绝对路径、真实目录、世界内包含关系、世界之间不重叠，以及同世界内专属目录、已确认根和资料目录根两两不重叠。重复身份、缺失目录、重叠和无法判断的路径立即报错；不自动创建、清理或迁移用户目录。
3. 对符号链接、junction、目录别名、大小写和不存在目标进行实际平台验证；现有路径检查不能阻止恶意并发路径替换和所有硬链接情形，记录限制并在生产装配前按宿主环境评估，不声称操作系统级隔离。
4. 使用两个世界、一个主 Agent 和至少两个特殊子 Agent 的受控目录夹具检查正常装配与冲突拒绝；同名 Agent 在不同世界的身份及目录分别绑定。

**验收**：有效配置形成明确的读取根和各 Agent 专属写入根；越界、别名重叠、缺失及身份冲突在启动前被拒绝，原目录数据未被改变。

## 3. 装配共享读取与各自修改边界

1. 沿现有文件服务和沙箱扩展点装配相同世界的读取及搜索范围；按当前 Agent 的可信身份装配其专属修改根，不从模型提供的路径或参数推导权限。
2. 对写入、编辑、补丁、删除和移动分别执行边界检查；移动的源与目标均须获授权。普通文件工具拒绝跨 Agent、跨世界、已确认资料、资料目录和平台临时目录的修改；读取和搜索也须拒绝跨世界及越界路径。
3. 将角色创建 Agent 使用的角色资料根绑定到该 Agent 的专属目录；核对角色资料服务、索引、待审文件和备份的直接访问路径，使其不能借助独立文件调用越过目录或确认边界。角色 Session 根仍由可信应用装配，不暴露为模型可读世界资料。
4. 为第二个测试特殊子 Agent 装配同一世界读取和独立写入权限，验证其通过真实文件工具操作；无需为测试创建新的业务角色或提前实现资料目录登记。
5. 验证文件观察和取消行为继续按所属 Agent 与 Session 路由，授权拒绝不依赖提示词；不扩大其他现有入口的权限。

**验收**：真实工具链证明同世界交叉读取与各自写入；跨 Agent 修改、跨世界读取和修改、已确认资料及资料目录普通写入被拒绝；角色服务不能绕过同样的目录边界。

## 4. 持续身份、并发与清理

1. 可信应用以世界和稳定 Agent 身份绑定专属目录及对应 Session 配置；使用现有 `persistent` 创建机制和运行驱动，不将每次运行 ID 当成持续身份。重新实例化沿用原目录，实例释放不删除成果。
2. 按工作区契约实现同一应用内相同世界与身份从启动到释放期间独占，重复启动明确报忙；不同身份和世界可并行。协调不同创建绑定对同一业务身份的访问，不能只依赖某一个 `persistent` 创建函数内部的互斥。
3. 明确启动中取消、创建失败、父作用域关闭、已交付运行释放以及清理失败的责任；等待未交付资源回滚和已交付运行结束后再解除占用。清理失败时保留错误并阻止不安全重入；任务和清理同时失败时保留两个原因。
4. 首版遵循单个可信应用进程持有同一世界写入的部署前提；无法保证该前提时不启用写入。进程内互斥不能证明跨进程互斥，跨进程锁及其崩溃恢复不在本步假装实现。

**验收**：使用受控门闩验证重复启动、取消、失败和释放；销毁并重新创建后保留原目录成果及按配置恢复的 Session，不宣称恢复长期记忆。

## 5. 文件边界与跨世界集成验证

1. 使用两个世界，每个世界至少包含主 Agent 和两个可信配置的特殊子 Agent；通过真实注册、文件工具和 Session 链路验证同世界交叉读取、自身修改、跨 Agent 修改拒绝和跨世界读写拒绝。
2. 覆盖相对路径、绝对路径、`..`、目录链接或 junction、目录别名和大小写、目标尚不存在、系统临时目录、已确认资料及资料目录。测试明确区分不支持的平台行为，不以跳过项冒充通过。
3. 验证角色创建 Agent 的资料服务和通用文件工具均受各自授权约束，主 Agent 不能通过自己的草稿写权限改写子 Agent 目录；读取权限不等于写入权限。
4. 验证子 Agent 正常结束、取消、父 Agent 销毁、创建及清理失败后的成果保留与占用释放；Session 恢复仅证明对话历史可继续，不证明长期记忆已经存在。

**验收**：正常路径和越权反例均经实际工具链验证；记录测试平台、未覆盖的本机并发替换和硬链接限制，以及任何跳过原因。

### 第 5 步验证记录

在 Windows x64、Node.js 24.20.0 下，使用[双世界装配测试](../../../src/app/tests/world-workspace-assembly.test.ts)分别启动主 Agent、角色创建 Agent 和通过测试 Provider 委派的第二个特殊 Agent；第二个特殊 Agent 使用真实进程内运行驱动、文件工具、观察策略和 Session，但并非新的生产业务 Agent。测试验证两世界内相互读取、各自写入、角色资料创建及会话恢复，并检查跨 Agent、跨世界、已确认目录和资料目录的修改拒绝。相对路径遍历、绝对路径、尚不存在的目标、平台临时目录、目录 junction、Windows 大小写别名及移动源和目标均有反例。

[工作区生命周期测试](../../../src/app/tests/world-workspace-lifecycle.test.ts)验证启动竞争、不同世界并行、创建失败、清理失败和父 Agent 销毁时取消角色任务；已创建角色保留，随后可以重新打开资料和恢复 Session。启动中取消和清理失败还由 [persistent Provider 测试](../../../src/agents/tests/subagent-persistent-in-process.test.ts)验证。相关文件沙箱和观察策略回归测试同时运行，共 35 项通过、无跳过。固定模型替身不构成真实模型验证。

测试不证明跨进程独占、恶意本机进程在检查后并发替换路径或硬链接安全；Windows 8.3 短文件名别名未单独验证。其他操作系统的链接和大小写行为未在本次运行中验证；链接创建不受支持时测试会明确报告跳过。

## 6. 文档与交付

1. 更新受影响的应用、Agent 和世界初始化模块 README，以及必要的架构说明、目录登记和 Agent Note；清楚说明可信配置、资源归属、文件限制、失败清理和单进程部署前提。
2. 运行受影响的聚焦行为测试、类型检查和必要构建；若交付构建入口，显式构建后执行入口冒烟。检查文档链接和 Git 空白；真实模型测试单独报告，不将固定替身视为真实模型验证。
3. 不将本步完成描述为整个第五阶段完成；资料目录与受控登记、版本对齐、完整确认流程和长期记忆按后续步骤继续。

**交付验收**：可信应用能够按世界和身份装配主 Agent 与角色创建 Agent 的文件范围，受控测试证明共享读取、专属修改、已确认资料保护、世界隔离和实例重建；第二个特殊 Agent 的范围通过测试用 Provider 验证，其通用生产装配不在当前入口内。失败清理与实际限制有可复验说明。
