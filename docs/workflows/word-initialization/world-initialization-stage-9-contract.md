# 初始化状态、恢复与交付契约

本文记录依据[盘点和用户同意的推荐方案](world-initialization-stage-9-inventory.md)拟实施的业务契约；具体代码与格式以各步实现和验证为准。现有第七、八阶段文件按其所属格式读取，不因为本文出现新的业务对象就自动迁移。

## 身份与记录

可信应用选择已校验的完整世界配置和业务记录根。初始化任务有程序生成的稳定 ID，绑定世界 ID 与完整负责人配置；同名世界、同名成果和不同用途的 Session ID 不混用。记录与世界根、Session 根及其他业务记录根隔离，调用方必须给出全部相关根并保证单可信写入进程。模型不选择这些根，也不能创建用户决定或交付授权。

拟新增严格版本 1 的任务记录、第一版判断、交付审阅及交付记录：任务记录标识世界和会话关联，不承载当前正文；第一版判断引用用户或可信业务流程实际核验的成果及版本；交付审阅固定将向用户展示的内容、来源、检查结果、留白、活动候选的逐项处理和未覆盖范围；交付记录绑定审阅版本、用户明确完成动作及实际结果。文件名、Session 文本、目录摘要和保存时间不代替身份或证据。具体字段以各自实现和测试为准。

未知版本、重复键、身份不匹配和损坏保留原文件并拒绝受影响的自动操作。旧工作区缺少任务或第一版判断时先只读接入并展示缺失依据；用户可显式建立新任务和重新审阅，但不得补造过去的判断、选择或交付。新增格式不重写已有候选、报告、确认、发布或 Session；确需改变既有格式时先明确按版本读取、可验证迁移或拒绝读取并覆盖中断路径。

## 第一版与任务进度

第一版总览保存、Session 恢复和资料目录登记只说明各自操作结果。完整性判断由可信应用接收用户或可信业务流程的明确动作，绑定被核验的成果身份、正文版本和范围说明；需要的成果未保存、不可读或判断依据发生变化时不能使用旧判断。重新判断形成新记录，不覆盖原始依据。业务进度从可核查记录派生，不能因为模型说完成或某个阶段产生文件就跳转为已完成。

恢复时首先展示发现范围、每项来源及读取结果。能按现有 API 核对的讨论、候选、报告、审阅、确认、单项 / 批次发布、人物恢复标记、目录和 Session 分别列出；没有可靠发现能力的部分标为未覆盖或需要调用者提供身份。未发现记录、目录不存在、读取失败、格式未知及分页未完成分别表示。任何辅助索引不能成为正文或用户决定的唯一证据。

## 未完成工作与恢复

活动候选按目标和版本展示，用户可以明确选择继续处理或暂留；暂留保留候选并列入交付审阅，不自动放弃或提交。发布中、正文 / 索引不一致、未知版本和结果不确定与普通活动候选区分；影响已选范围的此类问题先核查，不能靠暂留豁免。已放弃和已提交候选保留历史，不自动重新激活。

单项与批次记录分别读取并核对讨论、候选、目标、正文、索引、目录和所绑定确认。恢复可调用现有 `reconcile`、`stopAfterInterrupt`、`reconcileItem` 等能力，但先展示当前情况；有结果不确定时，只有可信应用收到用户针对实际版本的明确选择才能提供相应决定。已开始的发布不盲目重放，已完成项不声称回滚，未开始或失败项需要重新检查、审阅和确认。业务记录损坏或结果无法辨别时保留文件和占用，不自动修复或覆盖后续修改。

恢复和交付复用已有世界协调：在协调边界内重查已读取版本、范围凭据及相关写入口；未接入或不支持的路径不能被视为受保护。此契约不增加跨进程锁、跨文件原子事务、断电持久性或系统级隔离的承诺。清理失败保留资源占用和必要证据。

## 交付审阅与明确完成

交付审阅提供当前世界、第一版依据、所选正文的可追溯版本及实际内容、已接受的局部结果、已知冲突、未覆盖范围、暂留候选、留白和目录状态。重要冲突先处理；检查失败、未完成发布、结果不确定或无法读取的必要资料阻止完成。明确未覆盖和普通留白可以经用户逐项知悉后保留，不能描述成已检查。活动候选若暂留，必须针对每个候选取得明确选择并记录其版本；用户未选择、取消或关闭界面不完成。

审阅生成后和完成前必须检查第一版依据、正文和候选版本、已读取依赖、可重放范围及相关发布状态；变化或不能可靠复核则拒绝旧审阅并要求重新检查。用户点击完成是独立可信动作，须带实际审阅版本、已展示范围与选项；模型工具、Session、过期确认和超时不能代替该动作。局部发布或交付不会自动把全部模块改为 `confirmed`。

交付以版本化记录保存用户所确认的范围、版本、决定与可核对正文内容或可靠的不可变内容引用；若现有正文可能被覆盖，仅保留路径和旧摘要不能重建历史，必须提供能验证且可恢复的内容快照。快照的体积限制、写入和失败策略在实现中明确；清单、正文、目录和业务记录不伪称跨文件原子。完成记录使用稳定的审阅 / 操作身份防止同一动作重复生效；发布结果不确定时先读记录及实际状态，未能区分则保留证据并拒绝自动推进。

交付后的修改进入新的待审流程，保留既有交付及其可核对版本；不得静默改写已交付记录。如何开启后续修订由可信应用显式处理，不提前实现世界演化或故事推进。

## 验收样例

- 已有总览但地图结果未知：不自动产生第一版完整判断；补做或重新核对后由可信应用接收明确判断。
- 地点已发布、人物结果未知、成员未开始：展示逐项结果并保持未决占用；人物核查和用户选择后，成员须重新检查、审阅及确认。
- 城门活动候选暂留：先展示实际候选与版本并取得用户逐项决定；未知发布或重要冲突不能用此方式跳过。
- 交付审阅后新增关联或目标变化：旧范围凭据或正文版本失效，拒绝完成并重新审阅；未覆盖范围逐项知悉。
- 用户确认后响应丢失：用操作标识读取已保存记录并核对实际内容；记录缺失或无法区分时不重复产生业务效果。
- 旧世界只有正文和 Session：保留文件并展示缺失依据，可新建可信任务重新审阅，不能虚构已有确认或最终交付。
