# 局部讨论与候选契约设计

本文规定第 7 阶段拟实现的讨论和候选行为；不是现有 API。现状和用户确认的业务选择见[盘点](world-initialization-stage-7-inventory.md)。

## 身份和范围

可信应用提供世界配置和第一版完整判断。判断不完整时拒绝进入讨论并提示继续补做；判断完整只允许进入讨论，不表示第一版已确认。判断由调用方为本次装配显式提供，重启后重新提供；不从 Session、目录或总览推断，也不作为完整初始化恢复记录。

讨论 ID 由程序生成并绑定世界；每个讨论绑定用户选定的主目标和独立 Session 线索。用户切换时选择或创建另一讨论，返回时由可信应用选择原讨论并恢复对应会话与候选；Session 和业务记录分别读取。名称或描述只作为查找线索，同名须由用户选定真实目标。

已有目标使用所属模块、对象类型及模块真实 ID；受控文件使用可信应用校验归属后的成果标识，模型不能提供任意路径或选择世界、负责人和权限。单例目标使用所属模块明确的单例类型。一个讨论可关联多个目标；每个候选独立保存目标、归属及结果。新增意图不冒充已存在的正式 ID；跨候选引用和正式 ID 转换在所属模块支持前明确拒绝。

## 候选与并发

候选包含格式版本、世界 ID、候选 ID、讨论 ID、目标、修改意图、基线版本、候选正文和简要说明。修改或删除意图以实际读取的当前正文版本为基线；删除只保存意图。新增意图没有当前正文或基线，必须明确标识为新增。正文由所属模块校验和序列化，不用通用摘要替代正文。候选版本来自候选文件的实际版本，不能使用查询分页版本代替。

讨论记录包含 `formatVersion: 1`、`worldId`、程序生成的 `id`、主目标和用于恢复的 Session 标识；讨论本身不记录已完成或确认状态。候选记录包含 `formatVersion: 1`、`worldId`、程序生成的 `id`、`discussionId`、目标、`intent`（新增、修改或删除）、`status`（有效或放弃）、基线、正文及说明。目标的模块和类型决定 ID 的校验规则；单例目标不接受外部 ID。修改和删除必须具有基线；新增明确没有基线，删除没有替代正文。记录格式在实现时使用严格解析，拒绝额外字段和不合法组合。

每个世界同一已有目标最多有一个有效候选。创建前检查既有候选和已有模块候选；发现其他讨论的有效候选或无法识别的旧候选时拒绝并提示，不接管、不覆盖。候选更新要求所属讨论匹配、基线仍有效且提供上次读取的候选版本；任何不一致均拒绝，要求重新读取。读取返回当前正文、当前版本、完整候选、基线及过期状态；读取失败、目标不存在和版本变化分别报告，不能转换为空正文。

明确放弃将候选状态持久化为放弃，保留正文和版本供查看；成功放弃后目标可由新讨论占用。放弃操作需要当前候选版本，不能恢复为有效候选而绕过新的占用检查。停止生成、切换、失败及退出不等于放弃。发布结果不确定时返回可核查标识，重新读取确认实际状态后才能重试。

## 存储与兼容

讨论记录与候选放在可信应用指定的世界级受保护目录，和当前资料、Session、其他世界目录隔离；应用校验真实路径、归属及不重叠关系。根下 `discussions/` 和 `candidates/` 分别以程序生成的 UUID 为文件名存放版本 1 JSON；讨论记录只保存定位和会话线索，不复制当前正文；每个候选以单个独立版本化记录保存状态和完整建议。所有标识由程序生成并验证，目录或文件名不由模型选择。未知格式版本、损坏、越权、超限或身份不一致时拒绝读取并保留文件。

候选文件是有效占用的权威记录；查找索引不得独立证明候选存在或允许覆盖。创建在同一世界的串行队列中扫描并校验候选后独占发布，扫描不完整或发现无法识别文件时拒绝创建。写入使用独占创建和按版本替换；多文件操作不宣称原子性。中断或结果不确定时按文件实际状态核查，不自动清理未知文件。单可信写入进程、进程内串行化和受保护目录是前提，不提供跨进程锁或对不可信进程的系统级隔离。

讨论引用候选通过按世界和讨论 ID 查询候选文件得到，不依赖另一次写入来维护候选列表。创建先保存讨论再保存候选；候选发布失败时讨论仍可读取。放弃以候选文件的条件替换作为生效点，发布结果不确定时禁止假定目标已释放。

人物已有 `pending.md` / `pending.json` 不自动迁移、删除或关联讨论；只要任一遗留文件或未完成操作存在，该人物的新讨论候选须拒绝并报告需要处理。历史、局势、规划和专有内容已有候选同样不得自动接管或覆盖。旧格式及未知版本保留原样；后续若需要迁移，须另行规定可验证的迁移及失败策略。

## 样例验证

曲水城已有地点和文件版本。讨论 A 读取后创建候选，第二轮按候选版本更新；讨论 B 请求同一地点时获得占用提示。切换到青云宗并返回 A 后，重新读取当前正文、候选和基线；正文变化时报告过期，不更新候选或当前资料。A 明确放弃后保留候选，B 才能创建新候选。

林岚已有角色正文和摘要版本。若旧人物候选存在，讨论不能覆盖它；没有旧候选时，人物适配使用人物格式校验隔离候选。讨论涉及青云宗成员职务时，人物和组织成员关系各自读取版本、各自保存并展示结果。一个候选失败或发布状态未知不影响对另一个结果的如实报告，也不表示整体完成；提交和影响检查由第 8 阶段处理。

以上为契约层面的样例走查；实际装配、重启、竞争、权限绕过和模型行为需在后续实现中通过测试验证。
