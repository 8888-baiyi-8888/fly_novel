# 世界专有模块资料契约

本文定义[世界专有模块计划](world-initialization-stage-6a-world-specific-content-plan.md)的初始化 JSON 版本 1；实际能力以[插件说明](../../../src/agents/plugins/world-specific/README.md)为准。保存、目录登记或 Agent 返回不代表用户确认。

## 文件与身份

世界专有内容负责人目录包括 `topics/<主题ID>.json`、`items/<内容ID>.json` 和 `candidates/<原ID>.json`。可信应用提供真实目录、世界及负责人身份；主题和条目使用程序生成的小写 UUID，名称与 ID 分离，允许同名。不同世界资料不能混用。每个主题及需要独立维护的内容项一份文件；主题文件不维护一份必须同步的全部条目清单。

每份 JSON 包含版本 `formatVersion: 1`、世界 ID、对象 ID、`kind`（`topic` 或 `item`）、`contentStatus`（`suggested` 或 `confirmed`）、名称、别名、展开程度、概况、正文、明确留白、主题归属、已记录关联和外部引用。正文可容纳长规则；不要求按题材套用动态字段或固定栏目。展开程度使用 `unexpanded`、`overview`、`detailed`，只描述该份资料，不能推断其他资料或世界完整；审核状态与其独立。

JSON 须为 UTF-8 严格对象；未知版本、重复键、损坏、额外字段、非法 ID、跨世界或文件身份不符拒绝读取并保留原文件。旧 Markdown 和其他模块已有资料不自动导入、覆盖或删除；后续改变格式前须确定迁移或拒绝读取策略。

## 多主题、关联与规则留白

内容项的 `topicIds` 至少包含一个当前同世界主题 ID，允许多个且不能重复；主题自身 `topicIds` 为空，不借此强制主题树或单一父级。灵石可以用同一个 ID 和正文同时关联修炼、交易两个主题；按任一主题查询时返回完整 `topicIds`，不能把它误认为只属于当前查询的主题。更新归属只更新该内容文件，不能要求维护反向条目总表。

`links` 按源文档记录已存在的目标类型、目标 ID 和说明，可用于主题或内容之间的实际关联；重复目标和自关联拒绝。反向查询由记录推导并保留原始方向；关联不自动意味着父子、因果或相互知情。未创建的主题、内容及子规则不等于不存在；`reserved` 记录明确留白，主题与各条目独立维护自身展开程度。

内容可通过 `references` 关联现有历史、地点、组织、人物、局势与世界发展规划的实际对象：已关联项包含类型、ID、说明和可空的已记录版本；未关联项包含类型和非空文字线索，基础信息可用未关联线索或按现有授权文件机制读取。写入时已关联对象须通过可信解析器核验真实世界与 ID；未配置、无权、未找到和读取失败不可当作同一种情况。模型填入的已记录版本不证明其曾读取来源；显式核验才比较实际版本。角色是否知情不由规则、引用或组织身份自动决定。

## 修改与安全

初始化新建默认为待审；未确认文件按读取版本更新，过期版本或已有候选时拒绝覆盖。已确认文件只能独占保存一个含基线版本的待审候选，读取候选时报告基线是否过期；确认提交及世界演化后的规则历史留存不由本阶段实现。发布结果不确定时返回可核查的相对路径，先检查文件与版本，不盲目重复创建。目录登记与保存分别报告。

存储依赖调用者保证单可信写入进程，并限制真实目录与文件路径；进程内占用不构成跨进程锁或系统级隔离。跨文件读取不是原子快照，目录简介不是权威正文，Session 仅恢复对话；专有规划完整内容不能直接作为故事角色的认知。
