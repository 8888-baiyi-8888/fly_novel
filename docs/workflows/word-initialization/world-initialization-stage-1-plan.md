# 世界初始化第一阶段：使用场景与最小业务契约

本文规划[世界初始化开发计划的第一阶段](world-initialization-development-plan.md#1-使用场景与最小业务契约)。本阶段通过具体场景讨论预期行为和最小业务概念，为后续主 Agent 开发提供依据。本文中的示例和建议均为讨论稿，不表示接口或实现已经确定。

## 阶段目标与边界

从用户提供零散构想开始，描述第一版方案如何供审阅、用户如何选择局部进行讨论、修改如何检查影响，以及用户如何确认处理结果。讨论应说明各方看到和操作什么，并区分用户输入、Agent 建议、当前方案和待审修改。

本阶段的成果是经过讨论的使用示例、最小业务概念、确认边界和未决问题清单。它不实现 Agent、工具或存储，不设计完整世界数据模型、固定题材分类、具体接口字段或持久化格式。主 Agent 如何委派、资料如何检索和保存等技术细节在对应后续阶段确定。

## 讨论顺序

1. **整理输入与第一版**：以示例讨论用户想表达什么、Agent 如何识别重点，以及第一版需要让用户看到什么。
2. **选择局部并讨论**：明确用户如何指向方案的一部分，多轮交流中的提议如何与当前方案区分。
3. **检查影响与处理冲突**：明确需要展示的影响、检查范围和处理建议，以及未发现冲突的含义。
4. **选择、确认与展示结果**：讨论明确选择、未逐项选择而确认、取消和失败时的行为。
5. **归纳最小业务契约**：从示例提取必须区分的概念和状态，检查是否能解释整个过程，再列出尚需决定的事项。
6. **核对阶段成果**：按本文验收项检查示例和契约，确认后等待指示进入下一阶段。

## 主场景：零散构想到局部调整

以下是用于讨论的虚构交互，不规定界面文案、输出格式或固定的世界设定栏目。

### 1. 用户提供构想

> 我想写非常规修仙小说，角色智商在线。法无好坏，人有好坏。希望世界不只围着主角转，有不同势力和各自的利益。

输入同时包含创作要求、价值取向和尚未确定的内容。Agent 先理解用户意图，对模糊或冲突的地方可以反复询问用户；用户没有想好的内容保持未定，不补充世界设定。不能把“法无好坏”直接改写成用户已经指定的完整力量规则；用户没有提供地图，也不意味着世界没有地图。

Agent 整理并展示自己对构想的理解，请用户确认是否符合想法。用户提出修正时，Agent 继续澄清或调整理解并再次展示，直到用户确认，或系统配置的等待时间内用户没有回复等行为；超时按该次展示的理解符合用户想法处理，然后继续生成第一版。理解结果应区分用户原意与 Agent 的归纳，不加入额外设定。

超时默认确认只适用于当次展示的理解结果，不代表用户确认之后生成的世界方案、Agent 建议或世界事实。等待时间由系统配置；具体时长及等待、回复与恢复的交互细节在实现前确定。

### 2. 生成第一版供审阅

Agent 根据确认后的用户构想，主动识别规划重点，生成一份可整体审阅的完整世界方案。用户即使只提供零散想法，也应能看到具体的世界、参与者和局势，并在此基础上提出修改；Agent 负责主要构思与规划，不把补全方案的工作交给用户。

第一版的组织由 Agent 根据构想决定。以下说明各类内容可能承担的职责，不是所有世界必须具备的固定栏目或必须填满的字段：

- **创作方向**：引用前一步对用户输入的理解结果，包括用户希望体现的主题、风格、关注重点和约束。该结果经用户确认或按约定超时后，作为生成第一版的依据，也供用户审阅方案时对照；它不是 Agent 在第一版中另行规划的世界设定。
- **世界与规则**：说明世界的基本性质、运行规则及其对世界运转的影响；具体规则由当前构想决定。
- **地区**：以地图式的空间关系规划世界，用坐标表达地区的大致位置，并说明坐标所对应的世界范围和大致尺度；分别描述地区的环境、地貌等特点，以及重要地区之间的通行方式、障碍和难易程度。表达大地区与其内部小地区的层次关系，同时区分可能相互交叠的地理区域、行政区域和势力活动范围。结合已确定角色的位置、合理活动范围及计划中的故事可能涉及的地点，决定重点地区及周边的规划深度；其他地区可以只有大致方位、概况或留白。区分已经确定与粗略、待定的空间信息，不要求第一版精确测绘或穷举所有地区，也不因此固定角色行动路线或故事过程。
- **历史**：初始化重点说明世界中广为人知的重要历史及其对当前局势的影响；隐藏历史可以留白，在后续故事创作和世界演化中逐步补充。历史需要有统一的记录体系，表达事件的大致时间、地点、参与者、主要经过，以及事件之间的先后和必要因果关系；区分广为人知的说法、已确定的世界事实和未确定内容，不把传闻直接当作事实。新增或修改历史时，检查其与已有历史事件、角色经历和世界规则是否冲突；具体记录和检查方式在相关能力设计时确定。
- **势力**：初始化时只规划与当前世界局势、重要角色和计划中的故事密切相关的主要势力，分别说明其性质、目标、利益、活动范围及与其他势力的关系。内部结构、成员、资源和历史等按当前需要决定详略；随着故事和世界演化，根据实际发生的事件逐步补充和调整，也可以加入新出现或变得重要的势力。
- **角色**：根据角色参与的故事范围、对世界及其他角色的影响程度划分重要性，不按男一号、女一号等小说角色位次判断。初始化时第一梯队的重要角色以大约 10 人以内为参考，不设严格上限；后续可随故事和世界发展增加角色、调整梯队和补充资料。角色越重要，规划越深入；普通角色按当前需要粗略规划或留待后续出现。

  对重要角色分别规划身份、经历、性格、目标、动机、能力、关系、当前处境及成长线，并可关联所属势力和活动地区。成长线描述角色的初始性格与认知、重视和畏惧的事物、自身局限、可能遇到的挑战及其可能带来的变化；同时考虑较稳定的核心特质、与其他角色的相互影响，以及成长可能是成熟、退缩或产生新弱点。角色拥有自己的目标和变化，不只为推动其他角色而存在；角色认知与世界事实分开，其选择与成长基于自身经历和掌握的信息。

  第一梯队角色的重要经历及与成长有关的故事需要在后续演化中展开，不要求逐一模拟日常琐事。多个角色共同参与的故事作为同一组世界事件演化，并分别记录各角色的经历、认知和受到的影响。成长线是发展参考，不预先固定全部遭遇、选择和结局；实际演化与规划不同时，应根据已发生事件重新审视成长方向，区分原规划与实际变化，避免为达到预定结果强行安排不合理的行动。
- **世界初始状态**：以准备演化的第一个故事为重点，规划故事开始时涉及的地区、角色、势力及其关系和潜在矛盾，同时保留理解整个世界所需的基本背景。初始状态描述世界开始演化时的情况；后续故事发生后，相关地区、角色和势力的状态随事件结果更新，已发生的事件作为历史记录。
- **世界推进规划**：规划世界重大故事线，说明可能影响整个世界或多个重要地区的重大变化、背景、参与者及潜在矛盾，作为后续推进的最高层级故事规划；其他故事不必都从属于它。根据世界需要规划地区、势力等其他重要故事线，以及故事之间可能的联系、影响和发展条件。说明重要角色可能参与的故事及其与成长线的关系；角色成长线本身由角色规划管理。明确第一个要演化的故事的背景、参与者、处境、目标和起始矛盾，并与世界初始状态对应。规划中的故事和可能发生的变化不视为已发生事实，具体过程、角色选择和结果由后续演化产生；规划随实际演化调整。暂时没有确定或不需要的内容先不写，后续需要时再补充。
- **待补充的其他内容**：Agent 根据世界构想识别并规划上述内容以外的重要设定。例如，玄幻或修仙世界可能需要规划修炼体系，其他世界可能有不同的重点。需要补充什么以及规划深度由具体世界决定，不使用固定题材清单；当前不需要或尚未确定的内容可在后续讨论和世界演化中补充。

完整指方案具备整体审阅和继续优化的基础，不要求所有部分详略相同，也不要求提前确定所有事件及角色结局。不同构想需要规划的重点可能不同；不同对象分别组织和存储，以便独立定位、审阅与修改，并通过关联表达角色所属势力等关系。用户明确提供的要求、Agent 对其意图的理解、Agent 补充的建议和留白需要可区分，建议不因出现在第一版就成为已确认事实。


### 3. 选择局部并多轮讨论

用户在前端选中一个需要完善的资料项，并提出具体的修改要求。系统将所选资料的定位信息和用户要求交给 Agent；具体标识和存储方式在接口设计时确定，用户不需要了解底层存储位置。

一次局部讨论默认只处理用户选中的一个资料项。Agent 围绕该资料项与用户多轮讨论，形成待审修改；如果修改可能影响其他资料项，在后续影响检查和冲突处理时考虑，不在本次局部讨论中直接修改其他资料项。

例如，用户选择一个边境地区的资料，并提出：

> 我希望这里更封闭一些，普通人很难穿过边境，但也不想完全切断交流。

Agent 可以先讨论“普通人”的范围和通行条件，再提出修改：边境平时限制通行，特殊通行需要凭证。用户每次提出修改要求后，Agent 返回对应的修改内容，形成可供检查的待审修改；用户继续提出要求时，Agent 相应调整待审修改。待审修改与原内容分开展示，不直接覆盖原内容；待后续影响检查和冲突处理完成，并经过相应确认后，再更新原内容及需要联动调整的资料。

用户切换话题或中途离开时，暂存当前待审修改和相关对话。用户没有提出明确修改要求，或话说到一半就离开时，保持当前内容原样，并保存已有对话。

### 4. 检查影响并展示建议

Agent 检查待审修改对其他资料的影响，尽可能识别相关冲突，并优先寻找兼顾各方内容的解释或调整方案。对多个相互关联的冲突，Agent 综合考虑处理方案，检查方案之间是否会产生新的冲突；确实无法兼容的对立选择汇总后交给用户，而不是发现一项就立即要求用户选择。汇总时说明选项之间的依赖、兼容的方案组合及其影响，并提供 Agent 的建议。用户明确选择优先；用户确认继续但未对某项逐项选择时，采用已展示的对应建议。用户在规定时间内没有进行任何操作时，默认选择展示的第一个对应选项；相互依赖的冲突按展示的第一个兼容方案组合处理。

消除冲突不能悄然改变用户的明确要求。若坚持用户要求需要调整其他设定，Agent 列出这些调整；若无法兼顾，应向用户展示对立选项。用户选择后，Agent 再检查组合后的调整；发现新冲突时继续处理，无法消除的再交由用户选择。检查或资料读取无法完成、资料不足或检查范围受限时，说明未能判断的内容，不能声称已经没有冲突。

世界事实、传闻和角色认知可能不同。发现说法不一致时，先判断是否真正冲突；对于可以并存的差异，可在世界资料或影响检查结果中说明差异及原因。说明应限制在有权了解的资料视图中，不写入角色认知，不向角色暴露其不知道的事实或其他角色的认知。

Agent 找到的消除冲突方案和对其他资料的联动调整均作为待审内容，不直接覆盖原资料。处理后向用户展示选中资料及其他受影响资料的完整拟议调整，按后续确认流程提交。

例如，假设待审修改规定“边境在过去十年完全封闭”，而当前方案中角色在同一时期曾多次往返。Agent 查阅有关地区规则和角色经历，并检查其他相关影响后，向用户展示：

- **拟议修改**：过去十年边境完全封闭。
- **发现的问题**：角色的多次往返经历与拟议规则相矛盾。
- **处理建议**：若没有改变用户明确要求，且资料允许，提出兼顾双方的解释；否则列出维持完全封闭并调整角色经历，或修改封闭规则等选项，说明各选项涉及的调整及推荐理由。
- **检查范围**：说明实际查阅的地区规则与角色资料，以及尚未检查或无法判断的范围。

此处“完全封闭”是讨论中的修改示例，Agent 不应把用户希望保留交流的原意悄然替换成完全封闭。若拟议修改与用户要求不一致，也应将这一点呈现出来。未发现其他冲突只表示在所述范围内没有发现，不代表世界不存在冲突。

### 5. 用户选择并确认

影响检查和冲突处理完成后，系统向用户展示本次完整调整，包括用户选中的资料项和因消除冲突需要联动修改的其他资料，并等待一次最终确认。

- 用户确认，或在规定时间内没有任何操作时，系统提交这批调整，并展示实际结果。
- 用户明确要求取消时，系统不提交本次调整，保留修改前的资料。
- 相互关联的调整作为一个整体提交；提交失败时保留修改前的资料，向用户说明失败，不将部分调整当作已完成提交。

### 6. 继续优化或完成初始化

本次调整成功提交并展示结果后，用户可以继续选择其他资料项进行讨论和优化，也可以选择完成初始化。用户明确取消本次调整时，系统保留修改前的资料，用户同样可以继续优化或完成初始化。提交失败时，系统说明失败并保留修改前的资料，由用户决定下一步操作。

用户选择完成初始化后，交付当前世界方案，作为后续世界演化的基础。方案的交付判断见[开发计划](world-initialization-development-plan.md#第一版内容与交付标准讨论稿)。

## 最小业务概念

下表归纳前述流程需要区分的概念和职责，不预设它们各自必须成为独立数据类型或固定字段。

| 概念 | 职责与关系 |
| --- | --- |
| 世界 | 确定资料和讨论所属的世界；同一个世界可以为多部小说提供素材，世界事实、角色认知和小说呈现相互区分。 |
| 用户构想与理解结果 | Agent 可以反复澄清用户构想，展示理解结果供用户确认；按约定超时后也可继续。理解阶段不补充世界设定，理解结果作为生成第一版的依据。 |
| 世界方案与资料项 | 世界方案供用户整体审阅；地区、角色、势力等不同对象分别组织并可相互关联。用户通过前端选择需要完善的资料项，一次局部讨论默认只处理一项。 |
| 世界事实与规划 | 已发生的世界事实与尚未发生的发展规划相区分；世界初始状态和推进规划可随实际演化更新。 |
| 对话与待审修改 | 用户提出修改要求后，Agent 返回待审修改；继续讨论时可以调整，切换话题或离开时暂存修改和对话。待审修改不直接覆盖原资料。 |
| 影响与冲突 | 检查待审修改对其他资料的影响，优先寻找消除冲突的方案；无法兼容的选择及其相互依赖汇总给用户。不同角色的认知可以与世界事实不同，不应泄露角色未知的信息。 |
| 用户选择与最终确认 | 冲突处理遵从用户明确选择；未逐项选择而确认继续时采用对应建议，规定时间内无操作则默认选第一个选项或兼容方案组合。随后展示完整调整，等待用户最终确认；最终确认同样可按约定超时继续。 |
| 调整结果与交付 | 关联调整整体提交，成功后展示结果；取消或提交失败时保留修改前的资料。用户可以继续优化，也可以选择完成初始化并交付当前世界方案。 |

上述区分不预先规定枚举值、数据结构或存储方式；用户要求、Agent 理解和建议的具体展示方式暂不确定。本阶段不设计角色记忆或小说叙事模型。

## 补充场景与边界

使用主场景之外的例子检验契约，避免将修仙世界或地区规划当成通用模板：

- **不同重点**：用户只想构思一座漂浮城市中的代际关系，Agent 可以重点规划社会关系和资源约束，不必补齐大陆地图或力量体系。
- **构想澄清与确认**：输入有歧义或冲突时，Agent 可以反复询问并展示理解结果；用户修正后继续澄清。用户确认或在系统配置的等待时间内没有回复等行为时，继续生成第一版。
- **局部讨论中断**：用户提出修改要求后返回待审修改；切换话题或离开时暂存修改和对话。没有明确修改要求或话说到一半就离开时，保持当前内容原样并保存对话。
- **不同认知**：世界事实、传闻和角色认知不一致时，先判断是否真正冲突；可以并存的差异及其原因不写入角色认知，也不向角色暴露未知信息。
- **关联冲突与用户选择**：Agent 优先尝试消除冲突，无法兼容的选项汇总展示。用户明确选择优先；确认继续但未逐项选择时采用对应建议；规定时间内没有操作时默认选择第一个选项或兼容方案组合。选择后再次检查，发现新冲突时继续处理。
- **最终确认、取消与失败**：展示完整调整并等待一次最终确认；用户确认或规定时间内没有操作时整体提交，明确取消时保留原资料。检查受限或失败时说明无法判断的范围；提交失败时保留修改前的资料并说明失败。

## 阶段成果与验收

阶段讨论结束时，应形成可供用户审阅的成果：

1. 用示例走通从零散构想、反复澄清和理解确认，到完整第一版、局部讨论、影响检查、最终确认和展示结果的过程；用不同世界构想检验规划重点可变。
2. 说明最小业务概念及其关系，区分世界事实、角色认知和发展规划，以及原资料、对话和待审修改；不预设存储形式。
3. 说明用户明确选择、确认继续但未逐项选择、无操作超时、取消，以及检查或提交失败时的预期行为；确认角色未知信息不会因冲突说明而进入角色认知。
4. 说明调整成功、取消或失败后用户如何继续，以及用户选择完成初始化时交付当前世界方案。
5. 形成后续主 Agent 阶段所需的输入、输出和预期行为提纲，不提前确定具体实现；仍需设计的细节明确列出，不伪装成已决定。

本阶段以示例走查和文档一致性检查为主要验证，不以实现代码或调用真实模型作为完成条件。讨论完成后等待用户指示，再进入下一阶段。
