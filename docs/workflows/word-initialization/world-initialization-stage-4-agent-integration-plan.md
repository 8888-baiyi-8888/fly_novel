# 文件能力第九项：主、子 Agent 装配与端到端计划

本计划细化[第四阶段第 9 项](world-initialization-stage-4-file-tools-plan.md#9-主子-agent-装配与端到端验证)。由可信应用提供工作视图和草稿修改范围，真实主 Agent 按需委派独立子 Agent，验证读取、搜索、草稿修改和释放。按步骤验证并分别提交，不将文件工具当作世界资料业务存储或用户确认机制。

## 现状与安全边界

现有世界初始化主 Preset 注册 Tools 和 Skill，应用入口另注册 `read_file`，工作目录默认为进程目录；通用子 Preset 当前没有文件工具。Spawn 创建器由可信应用为固定 Preset 提供插件配置和独立 Session，`delegate` 固定委派 `generic-subagent`。世界资料的状态、持久化及确认流程仍属后续设计，不能凭文件名把内容自动视为已确认事实。

文件读取和搜索共用 Loop 的可信工作目录作为读取根；沙箱只限制修改，并按上游语义额外允许平台临时根。已确认资料必须由可信应用明确标识并隔离于所有可写根之外；子 Agent 可采用只读策略，主 Agent 的修改仅用于明确的草稿范围。实际部署配置若无法证明这些路径关系，须拒绝装配，不能假设两个不同的路径字符串彼此隔离。路径检查后的恶意本地替换与硬链接不受当前应用层沙箱保证，搜索子进程亦非内核沙箱；适用范围为可信本地工作区，生产启用前按实际部署风险重新评估。

## 1. 核对装配与授权方案

核对主应用入口、主与通用子 Preset、工具服务、Spawn 创建和销毁链、Skill 来源与现有 `read_file` 调用方，确认真实依赖和可独立配置的 Agent 作用域。设计由可信应用显式提供的读取视图、草稿根和已确认资料根；规范化并检查目录包含与上游平台临时写入根，确定缺失、重叠、链接和无效配置的拒绝语义。确定子 Agent 使用独立只读权限、Session 和可信创建配置；工具参数不得修改授权。

**验收**：工作区配置、初始化失败清理、可信数据来源与现有入口迁移方案可验证；对当前无法提供的系统级隔离不作超出事实的保证。

### 第 1 步核对结果

现有应用通过 `factory.create` 创建主 Agent，自行注册 `read_file`，而 Spawn 子实例由同一框架的 `manager` 创建和释放；`delegate` 固定请求 `generic-subagent`，其可信插件配置由创建器闭包提供，不由模型指定。主、子均须有各自的 Tools、文件后端、观察策略和 Session；文件观察事件按 Agent 身份路由，子 Agent 使用只读文件策略。主 Agent 继续使用 Skill 来源的独立根，文件工具启用时使用新 `read`，避免重复开放两套读取接口。

可信应用显式提供三个现有绝对目录：读取视图、草稿根和已确认根。先通过真实路径解析并验证目录，要求草稿根与已确认根都位于读取视图内且彼此不包含；检查已确认根与 `writableRoots` 中每个根在两个方向上均不重叠，包括平台临时根。路径比较采用文件沙箱相同的目录身份检查，不能只比较字符串。若要求草稿是唯一业务写入范围，还须在应用装配的文件后端增加草稿范围检查：上游 `workspace-write` 自身另外允许平台临时根，不能仅靠传入草稿根声称只写草稿。子 Agent 使用 `read-only`，不会继承父 Agent 的写入授权。

配置校验发生在创建 Agent 前；注册与实例初始化失败须清理已建立的作用域和子运行。配置仅来自可信应用，模型工具参数不得传入或修改路径根；不凭进程工作目录隐式授权新文件工具。保留无参数旧入口的现有行为，新增显式受控装配入口及配置；是否启用由调用方选择，不能在缺少真实世界工作区信息时擅自创建或覆盖用户数据。确认资料格式和提交仍由后续业务工作区实现，路径保护仅保证在已声明根与当前应用层约束下的修改拒绝。

## 2. 受控工作区与插件装配

工作区校验子步骤：读取视图、草稿根和已确认根必须是现有真实绝对目录；校验其包含关系，并拒绝已确认根与上游可写根（含平台临时根）任一方向重叠。Windows 聚焦测试覆盖有效目录、重叠、缺失目录、目录链接和系统临时根，2 项通过；草稿专用后端和 Agent 装配仍待完成。

草稿后端子步骤：应用专用后端继承文件沙箱，并在修改前重新解析目标、检查目标身份和草稿根；包括上游允许的系统临时根在内的草稿根外修改均被拒绝。Windows 聚焦测试验证草稿内写入成功、已确认目录及系统临时目录写入被拒绝；主子 Agent 装配与其他修改操作的端到端验证仍待完成。

受控入口子步骤：新增显式工作区创建入口，按独立 Preset 装配主 Agent 文件工具、搜索及只读子 Agent；旧无参数入口保持原状。内置 Skill 来源由应用单独授权，加载 Skill 不扩大文件工具读取根，其资源仍须通过文件工具授权。该分离解决内置 Skill 不在工作视图下时的初始化冲突，真实主子工具链仍须在下一步验证。

按第 1 步方案建立受控配置和工作区检查，并为主 Agent 显式装配文件后端、观察策略、读取／修改／补丁、子进程及搜索插件。将 `read_file` 的保留或替换方式明确落实；Skill 来源仍由可信应用单独配置。建立专用子 Agent 装配及 Spawn 配置，权限不可从模型任务或父 Session 中扩大；补丁删除需显式启用。

**验收**：缺少或冲突的路径配置在最早阶段失败并清理资源；已确认根不在主 Agent 的可写范围内，子 Agent 无写权限；现有无文件工具入口行为和文档同步更新。

## 3. 真实主子链路验证

固定模型替身经真实主 Agent Loop 调用搜索、读取、创建／编辑／删除草稿及 `delegate`；子 Agent 使用自己的 Session 与权限读取和搜索，尝试修改已确认资料及草稿均被拒绝。覆盖根外读取和修改、上游临时根与已确认根冲突、目录链接、重复配置、主子作用域销毁、失败与取消；验证已确认文件内容保持不变，结果如实进入 Session。

**验收**：主子工具和资料边界在真实调用链上有正反例，子运行和进程释放可观察；测试不依赖真实模型或持久化工作区。
