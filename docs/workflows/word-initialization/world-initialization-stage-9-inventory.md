# 第 9 阶段现状盘点与样例决策

本文记录第九阶段实施前核对的入口、业务数据和恢复范围；实施顺序见[详细计划](world-initialization-stage-9-persistence-recovery-delivery-plan.md)。用户要求按计划推荐方案连续开发，各步骤分别验证和提交。

## 入口、身份与发现

| 对象 | 当前可核对的能力 | 尚需开发或由调用方提供 |
| --- | --- | --- |
| 世界及负责人 | [配置校验](../../../src/world-init/workspace/config.ts)接收已有真实目录、世界 ID、主 / 专用 Agent ID，校验权限边界并冻结快照；进程内按世界和 Agent 占用身份。 | 可信调用方提供完整世界配置和选定世界；没有持久化世界清单、用户任务发现或跨进程锁。 |
| 主 / 子 Agent Session | [世界初始化入口](../../../src/app/agents/world-initialization.ts)从世界、主 Agent 和 Session ID 派生持久化身份；子 Agent 各自装配。Session 可恢复对话与未完成工具事件。 | 恢复时必须重新提供配置、模式、目录和身份；不能从 Session 判断业务完成，也不能盲目重放结果未知的工具。 |
| 第一版总览 | `save_first_world_plan` 创建独立待审文件；`firstVersionComplete: true` 是可信调用方对讨论装配的显式输入。 | 没有绑定成果清单及版本的持久化第一版完整判断；总览、目录或模型回答不能补造该判断。 |
| 讨论和候选 | [讨论服务](../../../src/world-init/discussion/service.ts)按 ID 读取讨论 / 候选，按讨论列出候选；内部扫描候选校验身份、格式及独占。候选 v1 为活动 / 放弃，v2 为发布中 / 已提交。 | 没有统一的世界级任务发现及跨记录恢复视图；发布中的候选必须与具体操作核对，未知格式保留并拒绝。 |
| 报告、审阅、确认 | [影响检查](../../../src/world-init/impact/service.ts)按讨论和报告 ID 读取及复核；[审阅服务](../../../src/world-init/impact/review.ts)按 ID 读取审阅及其确认。报告 / 审阅 / 确认为严格版本 1。 | 没有完整的世界级跨目录发现与孤立记录分类；旧报告或确认必须按实际版本及范围重新验证，不能视为永久授权。 |
| 发布及恢复 | [单项发布](../../../src/world-init/impact/commit.ts)和[批次发布](../../../src/world-init/impact/batch-commit.ts)按操作 ID 查看和核查；批次支持标记中断、单项核查和目录复查。记录各为严格版本 1。 | 现有入口依赖调用者知道 ID，未形成发现、展示、用户选择和重建的一体化流程；两类记录及候选占用须共同检查，不能以文件名推断结果。 |
| 人物、目录和其他模块 | 人物保留独立旧候选、索引和初始化恢复记录；目录可分页核对，成果和目录分开保存。局势、规划和其他模块各自校验格式、引用和版本。 | 不能把目录当正文清单或确认；人物恢复要匹配记录摘要。缺少的资料、旧候选、无法读取的目录与未配置的模块必须分别展示。 |
| 最终交付 | [第八阶段交接](world-initialization-stage-8-handoff.md)记录已验证的局部提交及限制。 | 尚无面向用户的完整初始化状态、最终审阅、明确完成动作和交付记录。 |

## 按用户同意的推荐方案处理

- 曲水城候选仍活动时，不静默提交或放弃；用户可明确选择继续处理或暂留，暂留必须列入待办并与实际候选版本绑定。发布中、结果不确定或读取失败不能作为普通待办静默跳过。
- 重要冲突先处理；未覆盖范围和普通留白如实展示，明确知悉后的处理与第八阶段已确认的规则保持一致。不能把“没有查到”当作没有冲突。
- 第一版完整由可信应用接收用户或可信业务流程的显式判断，并绑定可核验的成果清单和版本；单个总览、Session 或目录登记不足以证明完整。
- 已有世界先只读发现和核验，缺失的确认、任务或交付依据不补造；格式未知、损坏或身份冲突时保留原数据并拒绝受影响的自动写入。
- 最终交付优先保留可核查的版本引用与历史记录；后续修改形成待审版本并重新审阅。是否复制正文不预设，依据实际版本可追溯能力与存储验证决定。
- 无法区分发布结果时保留证据及候选占用，阻止相关自动写入；不假设完成、回滚或用户同意。经展示实际结果后的明确选择仍要绑定版本，未完成目标重新检查和确认。

上述方案是用户同意的开发方向，不将测试样例中的用户动作替换为真实用户授权；最终完成仍需要针对具体世界、内容版本和范围的明确动作。

## 走查与下一步

总览已保存但地图工具中断：显示总览与未知任务，不推断第一版完成。地点已发布、人物结果未知、成员未开始：保留地点结果，核对人物和索引，成员不自动重试。新增关联或正文变化：旧影响报告和确认须复核。两个世界存在同名地点：世界配置、目标 ID 和 Session 分别绑定，不按名称合并。交付后再次修改：保留原交付记录，重新进入待审流程；旧资料缺少交付决定时不回填历史确认。

上述能力和缺口由源码、[模块说明](../../../src/world-init/README.md)、[应用说明](../../../src/app/README.md)及相关测试交叉核对。下一步形成严格状态、版本、迁移及交付契约，不能先把拟议方案当作已存在的数据格式。
