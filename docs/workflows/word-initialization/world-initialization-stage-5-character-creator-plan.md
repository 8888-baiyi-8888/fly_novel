# 世界初始化第五阶段：角色创建子 Agent 与专用工具计划

本计划细化[第五阶段工作区计划的第 2 步](world-initialization-stage-5-workspace-plan.md#2-角色创建专用子-agent-与工具)。角色创建 Agent、资料工具、持续 Session 和主 Agent 委派已在受控测试目录中完成集成验证；共享工作区的各 Agent 文件边界按[工作区计划第 3 步](world-initialization-stage-5-workspace-plan.md#3-工作区装配与各-agent-文件边界)实施。实际装配方式见[应用说明](../../../src/app/README.md)。

## 场景与边界

角色创建 Agent 是可独立运行的 Agent，负责根据世界背景创建一个或多个角色设定，也负责根据用户要求修改角色设定。世界初始化主 Agent 可通过专用工具委派这些任务；子 Agent 是该场景下的运行关系，不是其唯一运行方式。

角色按参与故事的范围及对世界和其他角色的影响划分重要性，规划深度随重要性变化；第一梯队约十人以内是参考，不是所有角色的数量上限。Agent 主动设计角色之间的关系，普通角色也按世界和任务需要创建。分层及初始化规划依据见[世界初始化角色规划](world-initialization-stage-1-plan.md#2-生成第一版供审阅)。

用户在修改入口指定现存角色，Agent 围绕该角色形成修改，不在此步骤修改其他资料；整体影响检查和修复属于后续流程。角色资料使用独立文件和角色 ID，名称可以重复，通过角色工具按名称和分类查找。资料格式和受控读写见[角色资料模块说明](../../../src/world-init/README.md)；主 Agent 可依据文档内容或子 Agent 的回复作答。

修改期间原资料与待审修改分开保存；可信提交入口校验确认所绑定的候选和基线，并处理备份。整体影响检查和用户确认流程仍属于后续工作，不能仅因 Agent 返回成功而覆盖已确认资料。

Agent 可在获授权的共享范围内读取所需资料；作为子 Agent 时，资料不足则告知主 Agent 缺少的内容，并根据后续回复处理。共享工作区与授权尚未完成，实际可读取范围由可信应用装配。Agent 使用自然语言回复，不要求固定结构化回复格式。

生成角色时，用户有明确数量或其他要求的，按用户要求处理；未指定数量时，系统提示词使用可信应用提供的默认数量，不内置统一数值。

同一世界中的角色创建 Agent 可使用一个持续 Session 处理创建和修改任务，重新实例化时继续该会话。Session 可提供对话上下文，但不是已确认角色档案或长期记忆。随着会话增长，需要考虑上下文压缩或记忆化；触发条件、保留内容及实现范围尚待确定，不能假设现有实现已提供这些能力。

例如，用户希望构思一位在宗门中调查失踪事件的角色。主 Agent 把用户要求及当前任务所需的世界背景交给角色创建专用工具；子 Agent 依据任务形成角色设定建议，并返回给主 Agent。另一项任务可以要求创建与该角色立场不同的人物；不预设所有世界必须有相同的角色分类、字段或数量。具体角色内容和工具输入输出格式须结合示例与用户确认。

子 Agent 的生成结果是建议，不因工具执行成功而成为用户已确认的世界事实。工作区最终根目录由后续业务决定；模型不通过参数授权目录。长期记忆恢复和工作区资料目录仍按[第五阶段工作区计划](world-initialization-stage-5-workspace-plan.md)及后续业务阶段处理。

## 现有实现与可复用能力

- [通用子 Agent Preset](../../../src/agents/generic-subagent/preset.ts)装配标准 Loop、SystemPrompt、LLM 和独立 Session；[通用职责提示词](../../../src/agents/generic-subagent/system-prompt.ts)只要求完成任务并返回结果。角色创建需要明确的专有职责，不能只改工具名称就声称已有角色创建能力。
- [通用委派工具](../../../src/agents/plugins/subagent/tool-subagent/index.ts)接收非空任务，可信装配选择 Preset，模型不能选择 Preset；工具等待结果和释放，并保留任务与清理同时失败的原因。[测试](../../../src/agents/tests/tool-subagent.test.ts)覆盖可配置 Preset、父 Agent 作用域、失败和取消。
- [Spawn Provider](../../../src/agents/plugins/subagent/subagent-spawn-in-process/index.ts)接收可信创建函数；[通用创建器](../../../src/agents/runtime/subagent-in-process-creator.ts)按允许的 Preset 提供插件配置，每次创建独立实例和运行 ID，不允许通过现有配置指定持久化 Session ID。[运行驱动](../../../src/agents/plugins/subagent/subagent-in-process-driver/run.ts)负责执行、取消和等待释放。这些机制可复用，但本身不提供持续业务身份或记忆恢复。
- 现有 [角色 Agent Preset](../../../src/agents/character/preset.ts)及[角色提示词](../../../src/agents/character/plugins/system-prompt/plugin.ts)面向根据角色资料和场景进行角色扮演；[角色委派工具](../../../src/tools/character/delegate-character.ts)接收已有角色的 `characterId` 并选择该 Preset，当前也不会按 ID 加载角色资料。它们与创建角色设定的职责不同，不能直接当作角色创建功能使用。
- [世界初始化受控入口](../../../src/app/agents/world-initialization.ts)将通用 `delegate` 绑定到只读子 Agent；可选装配的 `delegate_character_creator` 使用 [`persistent` Provider](../../../src/agents/plugins/subagent/subagent-persistent-in-process/README.md)及角色创建 Agent 的持续 Session。读取范围与角色目录由可信应用指定，完整共享工作区隔离仍须后续验证。

## 待商议的业务契约

### 角色重要性分层讨论稿

依据[第一阶段角色规划](world-initialization-stage-1-plan.md#2-生成第一版供审阅)，以角色实际参与的故事范围、对世界和其他角色的影响判断重要性，而非按主角、配角等叙事位次划分。梯队用于决定初始化的规划深度和后续关注范围，不是角色的固定身份；世界演化后可调整。

| 梯队 | 判断依据 | 初始化规划深度 |
| --- | --- | --- |
| 第一梯队 | 影响多个重要故事或世界局势，其目标和行动对多个角色、势力产生持续影响。 | 深入规划身份、经历、性格与认知、目标动机、能力、关系、当前处境和可能成长方向；保留未来选择和结局的空间。第一版约十人以内仅作参考，不设硬上限。 |
| 第二梯队 | 对一个重要地区、势力或故事有显著影响，或与第一梯队角色有持续且重要的互动。 | 规划支撑其自主行动的身份、性格、目标、处境和重要关系；根据实际需要补充经历、能力与可能变化。 |
| 第三梯队 | 主要影响局部事件、场景或少数角色，但有独立的处境和行动理由。 | 先记录辨识角色及参与当前事件所需的要点和相关关系；后续变得重要时再扩充。 |
| 普通或暂未展开角色 | 对当前规划的影响有限，可能是世界日常运行的一部分。 | 按需要简要提及或留待后续出现，不要求预先逐一建档。 |

这些梯队不要求每个世界都配置固定人数或涵盖全部层级；用户指定人数、角色或规划深度时优先遵循用户要求。角色之间的关系由 Agent 主动构思，结合各自立场、认知和目标表达，不预设关系必须对称。

第二、第三梯队不在初始化时一次创建完整：只创建近期故事需要的角色，后续故事需要新角色时再按需创建。普通或暂未展开角色同样根据实际需要补充。

### 任务示例讨论稿

**生成第一版角色**：用户提供修仙世界背景、几个主要势力和近期故事，希望规划第一版角色。Agent 围绕世界局势和近期故事，构思若干不同重要程度的人物，设计他们各自的目标、处境和相互关系，并按梯队决定详略。第一梯队约十人以内是整体规划参考，不限制其他梯队；第二、第三梯队只创建近期故事需要的人物，后续按需补充；用户指定数量时按用户要求。生成结果写入规范角色资料文档供审阅，其中 Agent 补充的内容仍是建议；世界资料不足处标明假设或留白。

**修改现存角色**：用户在修改入口选择一名已有宗门长老，要求其更重视宗门稳定，但保留其与弟子的既有关系。Agent 基于该角色现有资料和用户要求，形成只涉及该角色自身的待审修改，并在规范文档中表达；不直接修改弟子或宗门资料。关联资料的整体影响检查和修复由后续流程处理，用户继续讨论时可调整待审内容。

以上分层和示例用于说明角色规划，不规定所有世界的角色数量或内容；实际资料格式与实现范围见下文链接。

### 角色资料和读取设计

角色文件、名称索引、多维分类、批量读取和修改备份的设计见[角色资料与分类读取设计](character-information-design.md)，实际能力以[角色资料模块说明](../../../src/world-init/README.md)为准；完整确认流程和共享工作区装配仍须后续实施。

## 开发步骤

### 1. 确定职责与示例

1. 与用户讨论根据世界背景创建一个或多个角色，以及按要求修改角色设定的场景，列出用户提供的信息、主 Agent 传入的任务与上下文、Agent 返回的建议及未确定事项；说明用户要求和 Agent 补充建议如何区分。
2. 据示例确认工具最小输入和输出、空任务及资料不足时的行为；不为已有角色档案设计虚假的 ID 查找，不假设子 Agent 可以看到父 Session。
3. 明确角色创建职责与角色扮演职责的边界，确定提示词和可用工具的实际范围；对尚未确定的字段和世界业务规则保持开放。

**验收**：示例覆盖不同角色任务，能够说明输入、结果、待定内容和确认边界；影响实现的业务选择得到用户确认。

### 2. 建立角色创建子 Agent

详细实施顺序见[建立角色创建子 Agent 的详细开发计划](world-initialization-stage-5-character-implementation-plan.md)。

1. 通过 Preset 和 SystemPrompt 插件装配角色创建职责，复用标准 Loop、LLM 和 Session；该职责与角色扮演分开。
2. 可信应用提供模型路由、角色资料根与读取范围；角色创建 Agent 接收任务及必要上下文，不继承父会话。提示词不替代程序授权。
3. 用固定模型替身检查专有职责提示词实际进入请求、不同任务可以复用该职责，以及持续 Session 与父会话隔离；不能用固定输出证明真实模型生成质量。

**验收**：通过独立入口和 `persistent` 委派链路创建角色创建 Agent，验证职责、输入、独立持续 Session 和作用域清理；无模型凭据也可运行常规测试。

### 3. 建立专用委派工具并装配主 Agent

1. 可信应用向[世界初始化入口](../../../src/app/agents/world-initialization.ts)提供角色创建配置，入口按需注册 `delegate_character_creator`；模型只提供任务，不授予身份、Session 或目录权限。
2. 工具通过 `subagents.start('persistent', ...)` 和共享运行驱动等待结果、释放句柄；失败与取消行为见[工具说明](../../../src/tools/README.md)。通用 `delegate` 仍使用 `spawn`，角色扮演 `delegate_character` 保持独立。
3. 角色根须位于读取视图内，并与主 Agent 草稿根及已确认根分离；完整的每 Agent 文件边界和跨世界隔离按工作区计划第 3 步实施。

**验收**：主 Agent 的模型工具调用经过专用工具、`persistent` Provider 和子 Agent，结果返回主 Agent；无效输入、不可用 Provider 和释放行为有明确结果。

### 4. 集成验证与交付

1. 使用固定模型替身通过主 Agent Loop、工具注册、`persistent` Provider、子 Agent Loop 和 Session 验证创建与修改；检查职责提示词、资料工具结果和主 Agent 收到的内容，不依赖真实模型或密钥。
2. 聚焦验证空输入、子 Agent 启动或模型失败、运行中取消、父 Agent 销毁、工具卸载和清理失败；确认子实例和注册按所有权释放，任务与清理同时失败不丢失原因。必要时复用现有测试夹具，不以测试替身声称实现记忆或文件持久化。
3. 更新实际受影响的 Agent、工具和应用 README、目录登记及 Agent Note；说明专用工具与现有角色扮演工具的区别和尚未接入的工作区能力。运行聚焦测试、类型检查和必要构建，检查文档链接与 Git 空白；真实模型验证单独报告是否执行及凭据限制。

**验收**：可信应用可装配并调用角色创建专用工具，自动化测试覆盖成功、失败、取消和清理；文档准确说明职责与边界。完成后再按第五阶段计划接入共享工作区，不将本步完成描述为整个第五阶段完成。
