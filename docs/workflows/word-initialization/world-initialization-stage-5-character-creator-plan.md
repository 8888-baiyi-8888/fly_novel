# 世界初始化第五阶段：角色创建子 Agent 与专用工具计划

本计划细化[第五阶段工作区计划的第 2 步](world-initialization-stage-5-workspace-plan.md#2-角色创建专用子-agent-与工具)。目标是在接入共享工作区之前，让世界初始化主 Agent 通过专用工具委派角色设定创建，并取得子 Agent 的结果；任务由用户选择装配的专用子 Agent 处理。本文是开发计划，示例和候选接口不表示现有能力或已确定的业务格式。

## 场景与边界

例如，用户希望构思一位在宗门中调查失踪事件的角色。主 Agent 把用户要求及当前任务所需的世界背景交给角色创建专用工具；子 Agent 依据任务形成角色设定建议，并返回给主 Agent。另一项任务可以要求创建与该角色立场不同的人物；不预设所有世界必须有相同的角色分类、字段或数量。具体角色内容和工具输入输出格式须结合示例与用户确认。

子 Agent 的生成结果是建议，不因工具执行成功而成为用户已确认的世界事实。本步先验证委派与结果交付，不实现角色档案存储、用户确认提交、共享资料目录或记忆恢复；这些能力按[第五阶段工作区计划](world-initialization-stage-5-workspace-plan.md)及后续业务阶段处理。工作区最终根目录由后续业务决定，本步不要求模型提供路径或通过模型参数授权。

## 现有实现与可复用能力

- [通用子 Agent Preset](../../../src/agents/generic-subagent/preset.ts)装配标准 Loop、SystemPrompt、LLM 和独立 Session；[通用职责提示词](../../../src/agents/generic-subagent/system-prompt.ts)只要求完成任务并返回结果。角色创建需要明确的专有职责，不能只改工具名称就声称已有角色创建能力。
- [通用委派工具](../../../src/agents/plugins/subagent/tool-subagent/index.ts)接收非空任务，可信装配选择 Preset，模型不能选择 Preset；工具等待结果和释放，并保留任务与清理同时失败的原因。[测试](../../../src/agents/tests/tool-subagent.test.ts)覆盖可配置 Preset、父 Agent 作用域、失败和取消。
- [Spawn Provider](../../../src/agents/plugins/subagent/subagent-spawn-in-process/index.ts)接收可信创建函数；[通用创建器](../../../src/agents/runtime/subagent-in-process-creator.ts)按允许的 Preset 提供插件配置，每次创建独立实例和运行 ID，不允许通过现有配置指定持久化 Session ID。[运行驱动](../../../src/agents/plugins/subagent/subagent-in-process-driver/run.ts)负责执行、取消和等待释放。这些机制可复用，但本身不提供持续业务身份或记忆恢复。
- 现有 [角色 Agent Preset](../../../src/agents/character/preset.ts)及[角色提示词](../../../src/agents/character/plugins/system-prompt/plugin.ts)面向根据角色资料和场景进行角色扮演；[角色委派工具](../../../src/tools/character/delegate-character.ts)接收已有角色的 `characterId` 并选择该 Preset，当前也不会按 ID 加载角色资料。它们与创建角色设定的职责不同，不能直接当作角色创建功能使用。
- [世界初始化受控入口](../../../src/app/agents/world-initialization.ts)当前将通用 `delegate` 绑定到只读子 Agent。新增角色创建工具时须核对与现有工具的名称、Preset、注册和权限关系；不能声称第四阶段入口已经具有角色创建职责或专属可写目录。

## 待商议的业务契约

1. 角色创建任务需要主 Agent 明确传递哪些上下文：先用实际示例确定最小必需信息；缺少资料时子 Agent 如何表达假设、疑问和待定内容。
2. 结果是否先采用自然语言建议，还是要求结构化字段；若需固定字段、一次创建多个角色或角色之间的关系，先结合使用场景确认，不能把示例字段当成已批准的模型。
3. 主 Agent 在什么情况下调用该工具、是否需要用户明确指定某次委派，以及结果如何呈现给用户。用户已决定可装配的特殊子 Agent；工具的装配不代表每个任务都必须委派。
4. 专用工具在本步如何接收持续身份及未来工作区配置、是否需要在本步使用身份；目录具体形式、同身份并发策略和共享工作区权限按工作区计划继续确认，不把随机运行 ID 当作持续身份。

## 开发步骤

### 1. 确定职责与示例

1. 与用户讨论至少两个不同的角色创建任务，列出用户提供的信息、主 Agent 传入的任务与上下文、子 Agent 返回的建议及未确定事项；说明用户要求和 Agent 补充建议如何区分。
2. 据示例确认工具最小输入和输出、空任务及资料不足时的行为；不为已有角色档案设计虚假的 ID 查找，不假设子 Agent 可以看到父 Session。
3. 明确角色创建职责与角色扮演职责的边界，确定提示词和可用工具的实际范围；对尚未确定的字段和世界业务规则保持开放。

**验收**：示例覆盖不同角色任务，能够说明输入、结果、待定内容和确认边界；影响实现的业务选择得到用户确认。

### 2. 建立角色创建子 Agent

1. 沿现有 Preset、SystemPrompt 和插件注册机制，为角色创建职责提供专有提示词及装配；复用通用子 Agent 的 Loop、LLM、Session 和 Spawn，避免混入角色扮演提示词。具体文件和包归属以现有模块组织及实际依赖为准，不预建不需要的包。
2. 通过可信应用提供模型路由和允许的 Preset 配置；验证子 Agent 接收任务及必要上下文，并且不继承父会话。尚无工作区配置时不授予文件权限，后续由可信应用接入，不把提示词作为权限控制。
3. 用固定模型替身检查专有职责提示词实际进入请求、不同任务可以复用该职责、各次 Session 相互独立；不能用固定输出证明真实模型生成质量。

**验收**：通过真实 Spawn 链路创建角色创建子 Agent，验证职责、输入、独立 Session 和作用域清理；无模型凭据也可运行常规测试。

### 3. 建立专用委派工具并装配主 Agent

1. 基于步骤 1 确认的契约定义专用工具；可信装配确定该工具对应的子 Agent Preset 和必要配置，模型仅提供完成本次任务所需的参数，不能提供模型适配器、Preset、身份授权或工作区路径。
2. 复用 `subagents.start('spawn', ...)`、Provider 和运行驱动，将任务交给专用子 Agent，等待结果并释放句柄；依据实际契约处理启动失败、执行失败、取消及清理失败，任务与清理同时失败时保留两个原因。
3. 将工具显式注册到世界初始化主 Agent 的作用域，随作用域清理；核对已有 `delegate` 和角色扮演 `delegate_character` 的用途与工具名冲突，明确是否同时装配，不因新增能力改变其他入口的权限。
4. 让可信装配位置能够在下一步提供世界和目录配置；具体形式在工作区设计确定后接入，不在本步声称完成世界隔离或身份重建。

**验收**：主 Agent 的模型工具调用经过专用工具、SubAgent、Spawn 和子 Agent，结果返回主 Agent；无效输入、不可用 Provider、工具冲突及释放行为有明确结果。

### 4. 集成验证与交付

1. 使用固定模型替身通过主 Agent Loop、工具注册、Spawn、子 Agent Loop 和 Session 验证至少两个不同任务；检查子 Agent 的职责提示词、输入上下文、工具结果及主 Agent 后续收到的内容，不依赖真实模型或密钥。
2. 聚焦验证空输入、子 Agent 启动或模型失败、运行中取消、父 Agent 销毁、工具卸载和清理失败；确认子实例和注册按所有权释放，任务与清理同时失败不丢失原因。必要时复用现有测试夹具，不以测试替身声称实现记忆或文件持久化。
3. 更新实际受影响的 Agent、工具和应用 README、目录登记及 Agent Note；说明专用工具与现有角色扮演工具的区别和尚未接入的工作区能力。运行聚焦测试、类型检查和必要构建，检查文档链接与 Git 空白；真实模型验证单独报告是否执行及凭据限制。

**验收**：可信应用可装配并调用角色创建专用工具，自动化测试覆盖成功、失败、取消和清理；文档准确说明职责与边界。完成后再按第五阶段计划接入共享工作区，不将本步完成描述为整个第五阶段完成。
