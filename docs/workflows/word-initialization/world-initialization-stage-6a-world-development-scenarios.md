# 世界发展规划：现状与联合场景走查

本文是[世界发展规划联合开发计划](world-initialization-stage-6a-world-development-plan.md)第一步的核对结果，用于确定后续资料契约与验收场景。示例中的名称和关系仅用于说明，不是世界模板；数据结构、工具和实现方式仍由契约步骤确定。

## 已有能力与本次缺口

| 能力 | 实际情况 | 联合规划的使用边界 |
| --- | --- | --- |
| 初始局势 | [局势存储和工具](../../../src/agents/plugins/initial-situation/README.md)记录一个世界起点、多个待审方案和各自的局势条目；通过总览 ID / 条目 ID 读取，条目包含所属方案 ID。 | 可读取实际方案与条目并检查归属；尚无方案选择 / 确认入口，不得从名称、返回顺序或目录记录推断哪个方案已选。 |
| 来源与版本 | 局势读取返回文件版本；引用核验可比较可用版本，并分别报告未配置、未找到、版本未知和变化；模型提供的历史版本不证明实际读取过来源。 | 提示来源变化并重新读取实际正文；多文件读取不是原子快照，版本一致不证明规划语义正确。世界基础信息按现有文档 / 目录读取，不虚构其结构化对象 ID。 |
| 历史、地点、组织与人物 | [历史](../../../src/agents/plugins/history/README.md)、[地图](../../../src/agents/plugins/map/README.md)、[组织](../../../src/agents/plugins/organization/README.md)和[人物](../../../src/agents/plugins/character/README.md)各自提供存储与查询，格式、版本和接口并不相同。 | 规划引用真实资料及稳定身份，不复制其完整正文或修改原模块；人物名称与 ID 分离。无法读取时保留原因或线索，不把无权当成不存在。 |
| 可信装配 | [局势引用绑定](../../../src/app/agents/initial-situation-references.ts)借用实际模块句柄并核验世界和负责人；[局势 Agent 入口](../../../src/app/agents/initial-situation-agent.ts)按配置注册读取能力。 | 这些代码是可参考的实现，并不是已有的通用世界发展规划引用服务；局势方案和条目的读取、版本及归属核验仍需为新 Agent 明确绑定。 |
| 委派和生命周期 | 主 Agent 可配置初始局势 Agent、Session 和专用委派；现有[固定替身走查](../../../src/app/tests/initial-situation-agent-e2e.test.ts)覆盖两个世界及多个方案。 | 世界发展规划专用 Agent、规划文件和工具尚不存在；固定替身不证明真实模型能正确组织三类规划，也不证明世界运行已经实现。 |

## 内容对象及职责

| 对象 | 内容与需要关联的对象 | 归属与限制 |
| --- | --- | --- |
| 宏观蓝图 | 世界级规划入口与范围，可关联多个发展方向。 | 属于世界；可引用不同局势候选，但不选定候选或生成历史事实。 |
| 发展方向 | 如资源协调或争夺扩大，说明可能条件、影响及适用局势方案。 | 每个已关联方案的适用条件单独表达；没有关联时不能推断适用所有方案。 |
| 重大事件构想 | 如未来可能举行的多城谈判；按需单独定位。 | 可被多个方向或故事线引用，但不是已发生历史，也不固定参与者行动或结果。 |
| 故事线 | 如持续围绕水源分配展开的故事；可关联宏观方向、事件构想、角色成长线和局势。 | 表达持续主题及按需阶段；不只是事件清单，地区线不必都从属一条世界线。 |
| 角色成长线 | 一个角色的一条成长线，维护其成长方向、阶段、可能转折及相关故事。 | 用户确认每个角色只保留一条成长线；建议在该线内按需表达不同可能发展与适用条件，而不是为每个候选另建一条。具体阶段和分支表示留待契约步骤确定。 |
| 人物成长蓝图 | 跨人物的成长重点、相互影响、与世界发展方向的呼应和留白；引用角色成长线。 | 具有独立规划职责，不重复维护单个人物成长阶段或替人物决定实际选择。 |

规划对象是否都要独立文件、如何表达阶段与多重关联，在下一步按真实查询和版本需求确定；不能把表格中的每个对象一律视为必须生成的文件或固定字段。

## 城邦群：一个世界、两个候选局势

假定授权可读的世界中有林岚、顾青、城邦组织与水渠地点：方案 A 表示上游封渠、下游抗议；方案 B 表示暂时通水、协议不稳定。历史记录青河战争已结束；它与当前是否敌对、未来是否再发生冲突是不同问题。

| 对象 | 规划与关联示例 | 预期核对 |
| --- | --- | --- |
| 宏观方向 | “协商与共同管理”可关联 A 和 B；A 下需考虑恢复供水条件，B 下需考虑维持协议的条件。 | 一项方向可以关联两个真实方案，并保留每个方案各自条件；不自动让 A 和 B 同时为真。 |
| 宏观方向 | “冲突扩大”适用于 A，前提可能是封渠持续且协调失败。 | 查询 B 的适用内容时不得把它当成 B 已有条件；可能发生不等于一定爆发战争。 |
| 事件构想 | “多城谈判”与协商方向相关，也可关联不同故事线。 | 一份构想可被多方引用；谈判是否举行、由谁参与及结果均可未知。 |
| 故事线 | “河谷水源分配”可关联协商方向及“多城谈判”，另有一条“城邦边境压力”线也可能引用该谈判。 | 两条故事线各自维护主题与发展内容，不复制构想；关联不等于谈判已发生。 |
| 林岚成长线 | 同一条成长线可规划林岚可能更重视多城合作，也可保留她继续优先本城利益的可能方向。 | 角色只对应一条成长线；其中如何区分方案、阶段或不同可能性需在契约步骤细化，不能因为有 A、B 就创建两条同角色成长线。 |
| 顾青成长线 | 同一条成长线可描述其逐渐形成独立判断的可能阶段，并关联相关故事线。 | 成长线引用顾青真实 ID；与林岚的不同规划不自动变成两人已经知道或已经发生的事情。 |
| 人物成长蓝图 | 以单独的跨人物规划项表达二人在水源矛盾中的可能张力及与世界发展方向的呼应，引用两条成长线。 | 保留蓝图自己的跨人物规划正文；林岚、顾青各自的详细阶段只由各自成长线维护。 |

同一世界存在多个待审局势时，故事线、成长线及跨人物蓝图规划也可能只适用于其中一些方案。建议每项按需表达适用方案及分别说明，未限定时明确是尚未判断还是经说明的通用规划；该表示属于契约提案，不能因为没有字段就默认它适用于所有方案。

## 修仙世界：不同重点和留白

历史记录宗门因灵脉变化迁徙，当前山门附近灵气紧张。宏观蓝图可以概述“寻找替代资源”和“资源争夺扩大”两个方向；故事线按需细化宗门内部协调和散修探索，二者可以并行，不要求所有故事线属于同一世界主线。

需要规划成长的散修人物有一条详细成长线，可在其中按需讨论对宗门态度的不同可能变化；宗门弟子也有自己的成长线。人物成长蓝图可规划两人可能形成的张力，以及个人成长与资源矛盾的呼应。远方是否有灵脉、二人是否相遇、真实选择和结局均可未知；缺少人物档案时保留待关联线索，不用姓名充当人物 ID。

## 查询与失败验收场景

| 场景 | 验收要求 |
| --- | --- |
| 按局势方案查询 | 指定 A 时能找到明确适用 A 的方向、故事线和成长规划；区分适用性未定的内容，不把只适用 B 的内容当成 A 的结果。关联 B 时反之。 |
| 从构想查询故事线 | 从“多城谈判”找到两条引用它的故事线，保留各自关联说明；删除或修改规划关联不自动更改历史或实际事件。 |
| 按人物查询成长规划 | 以真实人物 ID 找到该人物唯一成长线及引用它的人物成长蓝图项；同名人物不自动合并。不同可能方向在同一线中表达。 |
| 方案与条目错配 | 企图把属于 A 的局势条目登记为 B 的依据时拒绝或明确报告错配；同世界两个待审方案不因有关联就合并或自动确认。 |
| 来源变化 | A 的局势正文或人物资料更新后报告相关规划的来源版本变化或无法比较；需要重新读取并讨论，不宣称程序已判定业务冲突或自动重写规划。 |
| 找不到、无权与未配置 | 已关联目标缺失、未配置读取句柄、访问拒绝或正文损坏分别报告；未建档对象保留文字线索。不能把目录简介或 Session 当作正文、不能把失败变成无结果。 |
| 审核与写入 | 初始化未确认资料按版本更新；已确认资料修改形成候选并保留基线，确认提交流程仍未实现。过期版本拒绝覆盖；发布结果不确定时先核查实际文件。 |
| 跨世界与身份 | 绑定或引用其他世界的方案、人物或负责人目录时拒绝；相同姓名不构成同一角色。 |
| 可恢复运行 | 主子 Agent 取消或中断后保留已完成成果；同一 Session 恢复只提供对话历史，先核实文件和版本，不能盲目重复创建。 |

## 下一步契约需要解决的技术细节

1. 如何在单条成长线内表示长期规划、阶段及不同候选局势下的可选方向，同时维持一个角色只对应一条成长线；并明确未建档人物线索转为真实人物 ID 时如何核验唯一性和保留原线索。
2. 一个规划对象如何分别绑定 A、B 方案及各自说明；查询如何区分明确适用、明确不适用、尚未判断和无读取权限，精确的字段和状态仍待契约设计。
3. 一个事件构想与多条故事线、成长线和成长蓝图项的关联由哪一侧保存及怎样反向查询；明确删除、无效引用、版本变更和不完整扫描的语义，不预建通用图服务。
4. 总览、条目、阶段和候选的文件粒度、ID 与版本规则，以示例实际的读取、修改与定位需求为依据。三类规划共用插件和 Agent，但分别维护自身权威内容。

本步只核对现状与场景，不新增业务代码或实现世界演化、故事执行、角色行动及用户确认流程。
