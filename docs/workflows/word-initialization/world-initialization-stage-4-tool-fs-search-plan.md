## 1. 核对依赖与搜索授权

逐项核对上游 schema、argv、错误、超时、结果裁剪和实际运行依赖，检查 ripgrep 包版本、许可证、平台二进制及构建安装方式。梳理可信工作目录、文件后端解析、搜索目标和结果路径的映射；对绝对路径、父目录、目录链接、显式文件链接、路径重定向、错误输出及并发替换进行威胁分析。确定不跟随目录链接及对结果逐项验证的可执行方案，不假设进程 cwd 是授权沙箱。

**验收**：来源、实际依赖与授权数据流可追溯；无法通过路径检查避免的并发窗口和进程后端限制有明确说明。

### 第 1 步核对结果

官方搜索 `glob` 使用 `rg --files`、按修改时间排序、搜索隐藏及忽略文件并排除 VCS 元数据；`grep` 使用 `--json`、`--regexp=<pattern>` 和可选正向 `--glob=<include>`。用户路径置于 `--` 之后，上游在 `search-core` 固定前置 `--no-config` 并直接执行打包二进制。无匹配对应退出码 1；其他非零退出、信号、启动失败和不完整原始输出均为明确错误。项目不提供上游展示卡片和结果 spill，因此应报告截断并提示缩小范围，不声称已保存完整结果。

`@vscode/ripgrep@1.18.0` 在 npm 注册表声明 MIT，仓库为 `microsoft/vscode-ripgrep`，平台二进制为同版本可选依赖；主包完整性为 `sha512-ns5lWe44tSfbTMbVUsyB+I1819PVSw4AdpgK0RNkzfWfwy6+3IUNSxwSrfTno1/oWaS/hERNz+XLWVyga2aJBQ==`。该版本满足上游 `^1.18.0`，本项目固定精确版本并由锁文件校验；实际安装后核验 Windows 二进制和随包许可证，其他平台需各自在其环境验证。

工具执行上下文的可信 `workingDirectory` 是与 `read` 共用的根和路径基准。调用前通过文件后端解析根与目标并检查包含关系，将规范目标的进程路径传给 ripgrep；不启用跟随目录链接。解析每个搜索结果后再次使用同一文件后端解析并检查根，全部通过后才渲染模型结果。对于 `glob` 使用 NUL 分隔路径，避免文件名中的换行拆分成伪路径；`grep` 解析 JSON 路径字段，不能识别的路径拒绝结果。模型值只进入 argv 元素，失败时不回传可能含越权路径的原始 stderr。

上述检查只约束检查时的路径身份，外部进程仍可能在检查与搜索之间替换目录或文件；搜索进程并未受到内核读取沙箱限制。返回前再次解析不能证明搜索期间读取的内容对应同一文件，检查也不解决硬链接或宿主级恶意并发。生产装配时须结合可信工作区和已确认资料保护重新评估；当前方案不能声称抵御恶意本地进程。

## 2. 包及受控搜索执行

执行基础进展：已固定安装 `@vscode/ripgrep@1.18.0`，核实 Windows x64 平台包及其 MIT 许可证；真实打包二进制的根内搜索、无结果、根外目标拒绝、原始结果超限、失败信息和预取消已纳入聚焦测试。工具注册、结果逐项授权和集成尚未完成。

引入并固定实际使用的 `@vscode/ripgrep`，建立独立工作区包及显式插件，适配项目 Tools、文件后端、期限和子进程服务。由可信调用方提供读取根，解析模型搜索目标并拒绝越界；只执行包内可信二进制和固定参数模板，使用 `--no-config`，模型参数作为独立 argv 元素，路径置于 `--` 后。适配上游退出码、错误、输出溢出与取消语义，不传递未授权的 stderr 路径或内容。

**验收**：包独立构建、注册和清理；启动失败、无结果、非零退出、取消、期限和原始输出溢出行为可验证。

## 3. glob 与 grep

移植上游路径匹配、正则搜索、JSON 解析和有限结果格式，配置上限在入口校验；明确忽略文件、隐藏文件、VCS 目录及符号链接的实际行为。对每条待返回路径重新验证读取授权，结果需可在同一视图读取；不使用未经授权的 spill 文件保存结果。覆盖常规匹配、无结果、截断、非法模式、非 UTF-8、输入前导横线、特殊路径及路径越界。

**验收**：真实工具服务返回有界、可解释的路径与内容；范围外路径或内容不进入模型结果，错误不泄露范围外信息。

初步结果：`glob` 与 `grep` 已显式注册并使用真实工具服务验证；匹配、无结果、截断、非法模式、包含过滤、根外目录、目录链接及返回前目标变更均有受控测试。返回前逐项重新解析路径并确认普通文件，任一结果越界时整次拒绝；上述测试不消除搜索过程中路径被替换的窗口。真实 Loop、多 Agent、取消和交付验证仍在第 4 步进行。
