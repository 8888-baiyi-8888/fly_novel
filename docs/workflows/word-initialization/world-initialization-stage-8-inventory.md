# 第 8 阶段现状盘点与样例决策

本文记录影响检查与受控提交开发前对实际代码的走查，以及用户确认的近期业务选择。具体类型和错误以对应源码为准；这里的检查与提交缺口不是已实现的接口。

## 共同边界

[讨论服务](../../../src/world-init/discussion/service.ts)以世界和讨论 ID 定位版本 1 记录。候选只有 `active` / `abandoned`，包含目标、基线和候选全文；`readCandidate` 另返回当前正文、当前版本、候选文件版本、`update` 和基线过期状态。候选更新、放弃均比较候选版本，服务没有已提交状态、检查报告、用户选择、确认、发布或提交恢复。人物及其他模块既有候选分属各自存储，不等于讨论候选。

[应用讨论工具](../../../src/app/agents/discussion-tools.ts)由可信应用绑定世界、讨论及授权目标，只提供当前资料 / 候选读取和候选准备；专用子 Agent 的讨论装配不持有初始化写工具。应用仍可通过其他可信入口创建初始化 Agent；[身份占用](../../../src/world-init/workspace/agent-lease.ts)按世界与 Agent 身份而非全世界统一协调。[共享存储](../../../src/world-init/storage/world.ts)按需借用各模块句柄，各存储和讨论服务各有队列。现有队列、身份占用及 `singleWriterProcess` 声明不构成检查、确认到跨模块发布的一体化协调，也不防护其他进程。

第 7 阶段的 `validateCandidate` 等接口校验所属模块的格式、身份、已记录图及部分引用，并不判断语义冲突、用户选择或整个世界的影响。检查范围版本、用户确认凭据和提交记录均需新建；不能把查询版本直接当目标写入版本，也不能只靠提示词控制写权限。

## 各目标的读取、检查线索与发布缺口

| 目标 | 当前读取与检查线索 | 初始化写入 / 既有恢复；第 8 阶段缺口 |
| --- | --- | --- |
| 地点 | [地图存储](../../../src/agents/plugins/map/store.ts)读取地点正文及文件版本，`validatePlaceCandidate` 检查现有地点图；[地图查询](../../../src/agents/plugins/map/query.ts)提供按名称、层面、父级、空间及连通的查询，分页版本基于实际扫描和筛选。 | 地点创建后没有地点更新或提交接口；连通有按文件版本的直接更新。需要地点受控发布、确认绑定与结果恢复，不能借连通更新代替。地图概览和连通尚无讨论候选。 |
| 人物 | [人物存储](../../../src/agents/plugins/character/store.ts)的 `readVersioned` 返回正文和 SHA-256 摘要；`query` 按姓名 / 分类筛选，不是地点引用的完整反向索引。 | `updateInitialization` 只更新未确认人物，检查旧候选和摘要并有初始化操作恢复；既有 `prepare` / `commit` 使用角色目录内独占候选、摘要和操作日志，提交后将角色标为 `confirmed`，可通过 `recover` 核对实际文件与索引。它们不能直接确认讨论服务的独立候选，也不实现跨模块提交。 |
| 人物关系 | [关系存储](../../../src/agents/plugins/character/relationship-store.ts)按 ID 或人物查询，文件摘要作为版本；查询分页版本反映匹配关系。候选校验已有关系及人物引用。 | 初始化 `update` 仅允许未确认关系并直接替换；发布不确定时返回可核查路径。没有讨论候选确认 / 提交及跨模块恢复；新增关系条目在讨论候选中不支持。 |
| 组织、组织关系、成员 | [组织查询](../../../src/agents/plugins/organization/query.ts)可按组织或人物查询成员，规划者视图包含文件版本；查询版本绑定过滤条件及可见资料，组织存储扫描复核文件和目录清单。未关联人物只作为线索。 | 三类初始化更新均按文件版本直接覆盖，候选校验可核验组织、成员引用及统属图；没有用户确认绑定或跨文件恢复。角色视图版本属于过滤结果，不是规划者写入版本。 |
| 历史事件 | [历史查询](../../../src/agents/plugins/history/query.ts)可按已关联人物、地点或组织及关键词查找；未关联线索会使引用结果不完整，时间无法比较时标记未知。分页版本绑定已记录事件快照和查询条件。 | 未确认事件初始化直接更新；已确认事件可独占准备旧候选并检查基线，无候选提交。讨论适配拒绝已有旧候选；需要受控发布和恢复。 |
| 世界起点、局势总览 / 条目 | 局势存储按对象返回文件版本；[局势查询](../../../src/agents/plugins/initial-situation/query.ts)的搜索版本绑定方案和快照，关联 / 一致性检查明确限定已记录范围。 | 世界起点有按版本直接更新，且不自动检查历史相对时间；未确认总览 / 条目可直接更新，已确认对象使用独占旧候选。均缺讨论候选的确认提交与恢复。 |
| 世界发展规划 | [规划查询](../../../src/agents/plugins/world-development/query.ts)可按类型、人物或局势方案搜索，分页版本绑定规划扫描及条件；未判断的局势适用性单独返回。关联检查不覆盖未记录关联及语义因果。 | 未确认资料直接按版本更新，已确认资料使用独占旧候选；需要讨论候选受控发布、原线索与外部引用重验及恢复。 |
| 世界专有主题 / 内容 | [专有内容查询](../../../src/agents/plugins/world-specific/query.ts)按主题、关键词和已关联引用查询，分页版本绑定扫描与条件；未关联线索和 `coverage: unknown` 不能当作无影响。 | 未确认资料直接更新，已确认资料使用独占旧候选；需要讨论候选受控发布、主题 / 引用校验和恢复。 |
| 受控文件成果 | [文件适配](../../../src/world-init/discussion/file-adapter.ts)以可信负责人和规范真实路径读取，正文 SHA-256 作为版本；目录登记只提供查找线索。 | 需要可信应用受控发布及路径、摘要重验；正文成功与目录登记 / 刷新分别报告，现有目录服务不承担候选确认或跨文件事务。 |

地图、组织、历史、规划和专有内容查询中的快照或分页版本可作为各自已记录范围的重查线索；应逐项确认其筛选条件、分页行为及是否覆盖新增记录。局势关联查询与一致性检查的返回并不都提供可直接重放的范围版本。每种查询返回的范围只覆盖其实际数据和能力；这些版本不是跨模块原子快照。

## 按样例走查

1. **城门与林岚。** 讨论服务可读取曲水城当前正文、候选和基线。地图查询能找地点层级和连通，历史可按已关联地点 ID 查事件；人物正文中的地点经历并没有通用的结构化地点反向查询。组织成员查询针对人物 / 组织，不能仅凭城门地点推断成员。检查需要实际读取命中正文，并把未关联线索、未展开资料和人物正文反向检索缺口报告为不确定或未覆盖；现有代码没有语义冲突裁决或确认提交。
2. **林岚与青云宗成员。** 人物正文和组织成员各有独立候选、当前正文及各自版本；组织查询可按已关联人物 ID 查成员。两个候选可以同属一个讨论，但一个候选保存成功不证明另一项完成。没有现成的跨模块检查 / 用户选择 / 协调发布能力；人物 `commit` 的独立候选和 `confirmed` 副作用不能直接代替该流程。
3. **发布结果不确定。** 地图、组织、历史及其他模块在可能发布后失败时提供相应错误 / 可核查路径；人物旧提交有备份和操作阶段，可依据摘要判断恢复。讨论服务的候选发布也会报告不确定路径。现有能力不提供把用户确认、目标实际发布和讨论候选占用结束绑定起来的统一记录；不能从一次异常推断未写入，或从 Session 推断已经提交。

上述是源码与既有测试的路径走查，并非第 8 阶段的端到端运行结果。第 8 阶段必须先补齐可证明的跨入口协调；对无法重放或版本不可靠的范围不能凭一次扫描宣称后续未变化。

## 已确认的近期业务选择

- 用户选择优先；只有用户明确确认继续且某项没有单独选择时，才使用确认前已展示、具体且仍有效的该项建议。没有可执行建议时重新询问；建议涉及其他目标时先逐项展示并确认。
- 已知重要冲突或只提交部分目标会导致已知不一致时，阻止提交并先处理冲突；不能由 Agent 自行豁免。
- 检查的实际读取失败阻止提交；明确列出未覆盖范围后，允许用户明确确认继续。未覆盖不等于不存在影响，用户确认不能被模型或缺省行为代替。
- 多目标发布中途失败时保留并展示实际结果，停止后续写入；重新检查后由用户明确选择如何继续，不自动回滚或重复发布。
- 接受局部修改不自动等于确认整个第一版；人物既有提交将人物标为 `confirmed` 的副作用需在契约设计中处理，不能把两种确认混同。

第 8 阶段不决定最终初始化是否允许未解决的重要冲突；按照上述近期选择先处理已知重要冲突，并将未覆盖范围和实际结果交给后续阶段。
