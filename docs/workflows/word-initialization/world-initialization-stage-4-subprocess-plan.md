# 文件能力第七包：子进程基础开发计划

本计划细化[第四阶段第 7 项](world-initialization-stage-4-file-tools-plan.md#7-dsh-subprocess-及本地提供方搜索执行基础)，为后续搜索提供受管理的前台子进程。按步骤完成验证并分别提交，继续后续步骤；未验证的平台和能力如实记录。

## 来源和范围

依据用户提供的 DeepSeek Harness 官方下载快照，`dsh-subprocess`、`dsh-subprocess-local` 和 `dsh-tool-fs-search` 均为 `0.2.2-rc.1`，采用 MIT 许可证；快照没有已核验的 Git 提交标识。初步核对的 SHA-256：子进程契约 `src/index.ts` 为 `19e3fde571d0cd1f76e95696477a7d38677529aaf51b07c429965f2e4330065f`、`src/types.ts` 为 `e65166444ff791994a7198a86ac4a821e8329120bd551f342913623c87e5a715`；本地提供方 `src/index.ts` 为 `0839baefcbc7562ac73562cc7c5c3f1f983a8693bf3b76e0c956a5f93b4548ce`；搜索调用 `src/search-core.ts` 为 `d642c99286faff7cb6e70a24b0c4743184b3f83e8c6620bc9537c426987b198f`。实际移植的其他源码与测试在实施时补充哈希和本地调整。

上游搜索使用 argv 数组、`--no-config`、可信工作目录、有限 stdout/stderr 捕获和取消信号；退出码 1 表示无匹配。上游本地提供方还包含终端、平台原生进程组、溢出文件、网络代理和执行环境等能力，依赖 timeout、lazy-require、Win32 原生接口、koffi 和 node-pty。应核对真实调用后选择搜索必需的能力，不能把简化实现声称为完整上游进程树隔离，也不能通过 Shell 拼接模型参数。

## 1. 核对契约、依赖和生命周期

阅读搜索、契约、本地提供方、超时和相关测试，梳理启动失败、退出、输出上限、取消、超时、进程及后代所有权和作用域销毁的语义。核对 Node 与现有 Cordis 版本、上游许可证、依赖和可用构建方式；区分实际搜索路径与终端等非必需能力。明确 Windows 和其他平台进程树清理保证及不能保证的情况，并选择可测试的适配范围。

**验收**：来源和依赖可追溯，搜索调用接口、资源归属、竞争与平台限制明确；必要的辅助包分别规划，不假设服务作用域天然清理子进程。

## 2. 子进程契约与本地提供方

按第 1 步核对的必要范围分别建立工作区包、公开入口与显式服务注册，适配项目 Harness 和类型；使用参数数组直接启动进程，限制输出并保持错误和退出结果可区分。明确调用取消和作用域销毁的幂等性，保持运行中进程的所有权直至清理完成。同步来源、许可证、构建、目录说明和 Agent Note。

**验收**：包可独立构建和清理；导入无启动副作用，缺少提供方或配置时明确失败；能力与上游的差异有文档和测试依据。

## 3. 超时、取消和资源清理

按实际设计实现超时策略与取消传播，验证预取消、运行中取消、自然退出竞争、启动错误、非零退出、输出超限、重复关闭以及销毁等待。固定测试程序不可依赖外部模型或系统搜索工具；分别验证直接进程和适用平台的后代进程，无法证明的进程树边界单独记录。

**验收**：已启动任务在对应所有者销毁后不再运行，输出内存受限；测试只声称实际平台和进程范围的保证。

## 4. 集成和交付

以真实 Agent 作用域和固定子进程验证多个实例隔离与销毁，检查公开入口、构建产物、冻结锁文件、类型及聚焦测试；检查许可证、链接和空白。记录跳过原因、平台边界和搜索接入所需前置条件，然后进入第 8 项；本项不注册模型可直接调用的任意命令工具。

**验收**：搜索所需执行基础与生命周期有可复验的证据，限制如实记录，后续搜索授权另行验证。
