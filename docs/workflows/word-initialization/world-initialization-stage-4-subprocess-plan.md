本计划细化[第四阶段第 7 项](world-initialization-stage-4-file-tools-plan.md#7-dsh-subprocess-及本地提供方搜索执行基础)，为后续搜索提供受管理的前台子进程。按步骤完成验证并分别提交，继续后续步骤；未验证的平台和能力如实记录。

上游搜索使用 argv 数组、`--no-config`、可信工作目录、有限 stdout/stderr 捕获和取消信号；退出码 1 表示无匹配。上游本地提供方还包含终端、平台原生进程组、溢出文件、网络代理和执行环境等能力，依赖 timeout、lazy-require、Win32 原生接口、koffi 和 node-pty。应核对真实调用后选择搜索必需的能力，不能把简化实现声称为完整上游进程树隔离，也不能通过 Shell 拼接模型参数。

## 1. 核对契约、依赖和生命周期

阅读搜索、契约、本地提供方、超时和相关测试，梳理启动失败、退出、输出上限、取消、超时、进程及后代所有权和作用域销毁的语义。核对 Node 与现有 Cordis 版本、上游许可证、依赖和可用构建方式；区分实际搜索路径与终端等非必需能力。明确 Windows 和其他平台进程树清理保证及不能保证的情况，并选择可测试的适配范围。

**验收**：来源和依赖可追溯，搜索调用接口、资源归属、竞争与平台限制明确；必要的辅助包分别规划，不假设服务作用域天然清理子进程。

### 第 1 步核对结果

搜索只使用普通前台 `spawn`：可执行文件及参数组成 argv，stdin 忽略，stdout 和 stderr 分别按调用方指定字节数保留内存尾部，不创建 spill；`done` 返回直接进程的退出码与信号，启动和提供方错误拒绝。输出 `readFrom(0)` 若已丢失前缀，搜索必须报溢出，不能解析不完整结果。搜索固定添加 `--no-config`，防止宿主 ripgrep 配置注入预处理命令；目标路径还必须在第 8 项单独授权，不能依靠进程工作目录形成读取隔离。

上游调用方通过信号提供取消和超时，进程服务负责触发终止，超时原因由调用方分类；`graceMs` 用于终止升级和进程退出后管道排空的上界。`done` 只反映直接进程结果，`waitForExit` 单独等待提供方可观察的管理范围为空。服务销毁需主动终止所有仍归属的范围并等待清理，启动失败、自然退出与取消竞态均需验证。上游 timeout 是独立无运行时依赖包；搜索只需要期限信号与清理，按需移植该行为并单独记录来源，不把超时当作自动终止机制。

本地提供方上游优先使用 Windows Job 或 Linux systemd scope，其他情况回退至 POSIX 进程组或 Windows `taskkill`；回退不能保证脱离进程组或父子树的后代被观察、等待或终止。原生路径涉及独立 helper、平台探测及构建产物，终端又需要 node-pty；项目采用 CommonJS、Node 24 和 Cordis 4.0.2，上游快照为 ESM 和 Cordis 4.1 系列，不能直接视为同一运行时。先移植与搜索有关的普通进程契约、输出和上游回退管理路径；不得把回退范围标称为 Job 或 scope，也不实现终端、溢出文件或代理服务。若可用平台的回退不能满足搜索的终止和销毁测试，则补齐相应原生管理路径或保留交付未通过状态。

子进程默认环境沿用上游对含 `KEY`、`PASSWORD`、`SECRET`、`TOKEN` 及 `DSH_` 名称的过滤规则，显式可信覆盖另行校验；上游代理环境叠加依赖项目尚无的代理服务，不为搜索提前引入。取消和销毁期间必须保留管理句柄到观察结束；Windows 回退只能观察上游所能观察的直接进程，进程树逸出、强制宿主退出与其他平台能力需据实际测试报告。

## 2. 子进程契约与本地提供方

进展：已建立搜索所需的普通进程契约，并开始适配上游回退路径。Windows 首次取消测试发现 `taskkill` 可能失败而未产生启动错误，直接进程仍需执行终止回退；修复后重新运行固定子进程测试。范围退出、销毁竞态和平台后代测试仍须在本步骤及下一步完成后验收。

按第 1 步核对的必要范围分别建立工作区包、公开入口与显式服务注册，适配项目 Harness 和类型；使用参数数组直接启动进程，限制输出并保持错误和退出结果可区分。明确调用取消和作用域销毁的幂等性，保持运行中进程的所有权直至清理完成。同步来源、许可证、构建、目录说明和 Agent Note。

**验收**：包可独立构建和清理；导入无启动副作用，缺少提供方或配置时明确失败；能力与上游的差异有文档和测试依据。

## 3. 超时、取消和资源清理

期限子步骤：`@fly-novel/timeout` 复用上游期限信号与原因识别，释放期限时清除定时器；固定 Node 进程测试验证期限触发终止及调用方取消原因，2 项通过。该信号只通知，进程清理由本地提供方负责。

按实际设计实现超时策略与取消传播，验证预取消、运行中取消、自然退出竞争、启动错误、非零退出、输出超限、重复关闭以及销毁等待。固定测试程序不可依赖外部模型或系统搜索工具；分别验证直接进程和适用平台的后代进程，无法证明的进程树边界单独记录。

**验收**：已启动任务在对应所有者销毁后不再运行，输出内存受限；测试只声称实际平台和进程范围的保证。

## 4. 集成和交付

以真实 Agent 作用域和固定子进程验证多个实例隔离与销毁，检查公开入口、构建产物、冻结锁文件、类型及聚焦测试；检查许可证、链接和空白。记录跳过原因、平台边界和搜索接入所需前置条件，然后进入第 8 项；本项不注册模型可直接调用的任意命令工具。

**验收**：搜索所需执行基础与生命周期有可复验的证据，限制如实记录，后续搜索授权另行验证。
