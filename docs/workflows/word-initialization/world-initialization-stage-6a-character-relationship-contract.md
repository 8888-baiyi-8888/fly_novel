# 人物与关系：存储契约设计

本文细化[人物与关系开发计划](world-initialization-stage-6a-character-relationship-plan.md)第二步的存储契约。角色初始化更新和关系存储的实际接口及限制见[世界初始化模块说明](../../../src/world-init/README.md)；人物关系工具、Agent 装配及世界演化能力不由存储自动提供。

## 现有数据和兼容

保留角色根的 `index.json`、`requirements.md` 和各角色 UUID 目录；`profile.md` 继续使用版本 1 YAML 元数据及 Markdown 正文，ID、状态和自由正文不自动改格式。现有 `pending.md`、`pending.json`、`backup.md`、`operation.json` 和索引备份均是用户数据或恢复依据；升级不得删除、覆盖或静默迁移。未知格式版本、损坏的资料、未完成操作和索引与正文不一致时拒绝正常更新，保留原文件并报告原因。

角色的个人感受和当时所知继续写入本人正文；公共关系由独立文档维护，只保存初始化时已经存在的关系。正文中已有的关系叙述不自动解析、迁移或删除；提供读取及核对手段，避免将角色的错误认知当成程序可自动修复的错误。

## 关系文档和身份

可信应用可在角色负责人专属根下建立 `relationships/`；每个文件为关系文档 UUID 加 `.json`，一个文档维护一对人物的多项公共关系。关系存储接收已存在的真实目录，不创建目录或初始化角色索引；测试覆盖角色根下新增子目录后既有索引和角色读取。文件与目录路径为应用授权配置，不由模型指定。

关系文档采用严格版本 1 JSON：`formatVersion`、可信绑定的 `worldId`、程序生成的 `id`、两个 `participants`、`relations` 和 `contentStatus`。已建档端点表示为 `kind: linked` 与角色 UUID；只存 ID，不保存当前姓名副本。未建档端点使用 `kind: unresolved`、程序生成的线索 UUID 和可辨认描述；至少一端须为已建档人物，同一文档不能两端引用同一角色。字符串名称不是角色身份；角色改名不会修改关系 ID。

每条关系具有稳定条目 UUID、非空名称、方向（端点 A 到 B、B 到 A 或双向）及文字说明。方向只表达该条明确含义，不从名称推断双方态度，也不要求枚举所有世界的关系类型。多个条目可以表达师徒、亲属及合作；更新提交完整文档，调用方须保留不需要修改的条目。同一对角色的已关联文档必须唯一，配对按两个 UUID 的无序组合判重；条目的方向相对于文档端点，排序展示不能改变语义。状态与角色资料一样区分方案和确认。

尚未关联的线索不能只凭相同姓名合并。核验并将线索关联到角色时在已关联端点的 `previousClue` 保留线索 ID 和原描述；关联操作须保留文档 ID，并由调用方保留现有条目 ID。若对应的已关联角色配对已有文档，拒绝自动创建第二份或静默合并，报告冲突供核对处理。两个未关联线索是否为同一人未知，不能当作不同角色已被核实；当关联后形成自关联或跨世界引用时拒绝。角色解析由可信应用提供，核验角色根属于目标世界且角色实际存在，不能仅凭 UUID 格式或目录简介判断。

## 初始化更新与中断恢复

初始化直接更新只适用于可信应用判定仍在初始化且当前 `profile.md` 状态为 `suggested` 的角色；已确认角色仍走现有待审候选。模型不能通过工具参数授予阶段或确认权限。读取返回正文和原始文件摘要；更新必须提供该摘要，并在单可信写入进程内按角色根串行检查。已有 `pending.md`、`pending.json`、`backup.md`、`operation.json` 或无法判定的状态时拒绝并保留全部文件，避免覆盖或误清理。索引损坏、角色 ID 不符或内容未知版本均拒绝。

人物更新需要同时处理 `profile.md` 与索引，不能声称跨文件原子。使用独立版本化 `initialization-operation.json` 和不可覆盖的 `initialization-backup.md`，保存基线和新资料摘要及恢复阶段；先写恢复依据，再替换当前资料并更新索引，最后清理本次操作产生的记录。中途失败或发布结果不确定保留恢复依据；恢复根据实际摘要和索引判断是否尚未发布、资料已发布但索引未完成，无法唯一判断时停止，不覆盖或删除未知文件。该记录不改变现有确认操作的 `operation.json` 格式。

关系创建使用程序生成 ID 与独占创建，更新携带读取摘要并保护同一对唯一性；初始化更新仅作用于未确认方案。发布出现异常时返回可核查的目标路径，不假定成功或失败。已确认关系拒绝直接覆盖；关系候选与确认入口尚未实现，世界演化后的历史留存属于后续工作。单可信写入进程内串行检查配对与写入；现有路径校验不提供跨进程锁、系统级隔离或跨模块事务。保存、更新和目录登记不代表用户确认。

## 查询、授权和失败

查询读取文档正文及两端 ID，通过已绑定角色服务解析当前名称；角色缺失、身份不一致、无权限和读取失败应分别报告，不能把未查询或未建档称为不存在。规划者和未来角色的读取范围须由可信应用绑定；原始角色文件、关系目录、搜索和资料目录均不可绕过授权。完整角色认知与世界运行机制不在本阶段预建。

文档损坏、未知字段或版本、重复 JSON 键、重复文档 ID、重复已关联配对、非法 ID 和无效方向均拒绝处理，保留原文件。索引如引入只能作为可重建的查询辅助，不得替代正文权威；扫描范围、分页版本、限额和失败语义在查询步骤实现。模型不能以本步骤获得任意角色目录的写权限。

## 实现与验证顺序

1. 在真实角色根建立可重放夹具：旧版角色、同名人物、候选、操作记录、未知版本和损坏索引；验证未修改的旧数据及既有读取行为。
2. 实现初始化角色按摘要更新、索引一致性与中断恢复，注入各阶段故障；覆盖旧版本冲突、已确认拒绝、已有候选拒绝、取消及不确定结果，不清理不属于本操作的文件。
3. 实现关系格式、单对唯一性和受控存储，覆盖双端、多个条目、角色改名、同名、线索关联冲突、跨世界和未知版本。真实目录验证失败后文件保留，建立与关闭的并发和取消边界。
4. 运行角色存储与关系的聚焦测试和构建；角色查询工具、Agent 委派、角色权限和真实模型按后续步骤验证，不因本设计文档视为已完成。
