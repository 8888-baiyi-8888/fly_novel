# 地图与空间模块首版数据和工具契约

本文细化[地图与空间开发计划](world-initialization-stage-6a-map-space-plan.md)的第 1 步，供后续插件实现和验证使用。文中的文件、字段和工具是实施设计，不表示插件已存在；JSON 示例仅用于说明，不是实际世界资料。世界、目录和权限始终由可信应用绑定，不接受模型通过工具参数指定。

## 一、数据范围和文件归属

每个世界的地图负责人目录有一份世界地图 JSON、多份地点 JSON 和按需创建的连通 JSON：

```text
地图负责人目录/
├── map.json
├── places/
│   └── <地点ID>.json
└── connections/
    └── <连通ID>.json
```

每个文件是一个 UTF-8 JSON 对象，`formatVersion` 为 `1`，带 `worldId` 以核对可信装配的世界。地点和连通的 ID 由服务生成，文件名与 ID 一致，名称不是身份；同一地点跨层面和父级只使用同一文件。用户决定的连通设定单独维护在连通文件，不复制进两端地点。地点子列表、父级反查和连通反查从各自权威文件派生，不能将缓存视为另一份事实。

无目录记录不代表文件不存在；共享资料目录是可选导航能力，登记状态不替代地图插件自身读取。现有角色、目录、Session 和基础信息文件格式不变；没有既有地图格式时只能新建，不能把其他 JSON 或未版本化文件静默当成 v1。未知版本、重复对象键、未知必要结构或损坏文件须明确拒绝并保留原文件；普通 `JSON.parse` 本身不检测重复键，实现时需选择能严格识别重复键的解析方式，验证依赖兼容性和许可证，不将该能力写成现有实现。

## 二、世界地图 `map.json`

| 字段 | 类型及规则 |
| --- | --- |
| `formatVersion` | 必需，整数 `1`。 |
| `worldId` | 必需，非空字符串，必须等于可信绑定的世界 ID；不由模型指定。 |
| `name`、`description` | 世界地图名称和描述，名称非空；内容按世界需要组织。 |
| `reviewStatus` | 本阶段的地图概览为 `suggested`；不从工具暴露模型确认。 |
| `scale` | 单一世界比例：正数 `width`、`height` 及非空 `unit`，分别表示世界画布覆盖的物理宽高；例如公里。创建时由地图 Agent 根据世界构想设置，不为局部地图另设物理比例。 |
| `layers` | 世界内至少一个层面定义；每项 `id` 在世界地图内唯一，`name` 为显示名称，按需有 `description`。例如行政与山水层面；不固定全部世界使用相同层面。 |
| `orientation` | 描述画布上方对应的世界方位；未知时使用明确的文字说明，不把上方自动等同北方。 |
| `reserved` | 用户明确要求暂不设定的范围或内容的文字列表；没有要求时为空数组，不能从其他未知内容推断。 |

画布横纵均为 `0..1000`、左上原点、x 向右增大、y 向下增大；世界坐标 `[x,y]` 的物理相对位移按 `x / 1000 × width`、`y / 1000 × height` 换算。横纵各自归一化，不表示世界物理范围一定是正方形。两点由此得到的仅是平面直线距离，不能代替连通资料里的实际路线距离和时间。

```json
{
  "formatVersion": 1,
  "worldId": "city-world",
  "name": "河谷世界",
  "description": "群山之间的城邦和河流。",
  "reviewStatus": "suggested",
  "scale": { "width": 10000, "height": 4000, "unit": "km" },
  "layers": [
    { "id": "administrative", "name": "城市划分" },
    { "id": "geography", "name": "山水地理" }
  ],
  "orientation": "画布上方为北方。",
  "reserved": ["外海暂不设定"]
}
```

上例的宽高是虚构的 Agent 设定，不从 `0..1000` 反推出公里。世界比例应在创建时设置；输入不足时 Agent 可根据任务构思比例并明确它是本次地图方案内容，不应伪称用户已指定。比例更新及其对已有坐标、距离的影响不属于本步新建接口。

## 三、地点 `places/<id>.json`

| 字段 | 类型及规则 |
| --- | --- |
| `formatVersion`、`worldId`、`id` | 必需；版本为 `1`，世界 ID 与绑定相同，ID 为程序生成的 UUID，并与文件名一致。 |
| `name`、`aliases`、`description` | 名称非空，别名为字符串数组，描述为自然语言；名称和别名允许与其他地点重复。 |
| `reviewStatus` | 本阶段创建使用 `suggested`；该状态与展开程度独立。 |
| `detailLevel` | `unexpanded`、`overview`、`detailed`，只描述本地点，不随父子地点状态自动变化。 |
| `parents` | 非空数组；每项标识层面、父级及本地点在父画布中的实际矩形范围与画布映射。同一层面可有多个父级，同一地点跨层面共用文件和 ID。 |
| `reserved` | 用户对该地点明确要求保留空白的内容；没有时为空数组，不能将未知自动写成用户留白。 |

每个 `parents` 项使用 `layerId`、`parent`、`localBoxes`、`frameBox` 和 `coverage`：

- `layerId` 必须存在于 `map.json` 的 `layers`。`parent` 用 `{ "kind": "world" }` 表示该层面顶层，或 `{ "kind": "place", "id": "…" }` 引用同世界、同层面已存在的父地点；不能自为父级或在该层面形成循环。一个子地点需要先有父地点概况，不创建引用缺失父级的子地点。
- `localBoxes` 是地点在此父画布内实际占据的矩形数组。每个矩形是 `[left, top, right, bottom]`，四个数均为有限数，实际覆盖框位于 `0..1000`，`left < right`、`top < bottom`；多个框的并集是记录范围，重叠不能重复计数，空隙不能当作实际范围。数组为空表示该关系的范围尚未给出，不能推断地点没有面积。
- `frameBox` 是完整地点局部画布在此父画布内的映射框；使用同一数组形式和正宽高，可以超出父画布以表达跨父级。无法可靠确定时为 `null`；此时不依据已知片段猜测整幅画布，依赖该映射的坐标换算报告无法计算。画布框与实际范围不同，不能用它判定地域归属。
- `coverage` 为 `partial` 或 `complete`：表示这条父级关联中给出的 `localBoxes` 是部分还是完整记录。`complete` 仅表示这一关联的记录范围已列出，不证明所有父级、其他层面或整个世界已规划完整；不能根据文件数量自动设定。`localBoxes` 为空时只允许 `partial`。
- 同一地点不得重复登记相同的 `layerId` 和父级组合；同一个地点可以在不同层面引用同一父级，或者在同一层面有不同父级。路径定位和区域查询按层面明确区分；几何重叠不自动等于行政归属。

### 城邦群：多父级示例

假设 `city-world` 的行政层面中，甲、乙地区都是世界地图顶层；甲在世界画布覆盖 `[0,0,500,1000]`，乙覆盖 `[500,0,1000,1000]`。城市完整世界画布范围为 `[400,200,600,600]`，横跨两区。以下是城市文件，两个父 ID 分别对应已创建的甲、乙地区文件：

```json
{
  "formatVersion": 1,
  "worldId": "city-world",
  "id": "11111111-1111-4111-8111-111111111111",
  "name": "曲水城",
  "aliases": [],
  "description": "河谷中的跨区城邦。",
  "reviewStatus": "suggested",
  "detailLevel": "overview",
  "parents": [
    {
      "layerId": "administrative",
      "parent": { "kind": "place", "id": "22222222-2222-4222-8222-222222222222" },
      "localBoxes": [[800, 200, 1000, 600]],
      "frameBox": [800, 200, 1200, 600],
      "coverage": "complete"
    },
    {
      "layerId": "administrative",
      "parent": { "kind": "place", "id": "33333333-3333-4333-8333-333333333333" },
      "localBoxes": [[0, 200, 200, 600]],
      "frameBox": [-200, 200, 200, 600],
      "coverage": "complete"
    }
  ],
  "reserved": []
}
```

两个 `frameBox` 都描述完整城市画布在各自父坐标系中的映射，因此允许超出 `0..1000`；两个 `localBoxes` 只描述各自父级内的城市部分。它们分别映射到世界的 `[400,200,500,600]` 与 `[500,200,600,600]`，合并得到城市已记录范围。查询甲地区的子地点时，结果须标明曲水城还属于乙地区；查询乙时返回同一 ID。已知父级片段覆盖不全时使用 `partial`，不能仅凭缺少其他记录认定完整。

### 修仙世界：分离范围示例

群岛在大陆局部画布的范围为 `[100,200,300,400]` 和 `[700,200,900,400]`。群岛完整画布参考框为 `[100,200,900,400]`；反向换算后两个岛分别为 `[0,0,250,1000]` 和 `[750,0,1000,1000]`，中间为空隙。左岛港口若在群岛画布为 `[50,200,150,400]`，经群岛的 `frameBox` 换算到大陆画布为 `[140,240,220,280]`。区域搜索落入 `x=250..750` 的空隙时，不能仅因为群岛的参考框覆盖它而判定与岛屿范围相交。宗门和人物资料只引用地点，不复制群岛地点正文。

## 四、连通 `connections/<id>.json`

连通是写入即生效的当前地图设定，不设用户 / Agent 来源字段或审核状态。字段包括 `formatVersion`、`worldId`、程序生成的 `id`、`fromId`、`toId`、`direction`（`one-way` 或 `two-way`）、非空 `mode` 和 `description`；距离、耗时与条件按需填写，未知时省略。`mode` 由 Agent 使用具体文本表达道路、水路等，不预先限定所有世界的类型。两端必须是同世界存在的地点，不能指向自身；方向从 `fromId` 指向 `toId`，双向表示两边均可通行。不同路线用不同 ID，一条连通只保存一份。

```json
{
  "formatVersion": 1,
  "worldId": "city-world",
  "id": "44444444-4444-4444-8444-444444444444",
  "fromId": "11111111-1111-4111-8111-111111111111",
  "toId": "55555555-5555-4555-8555-555555555555",
  "direction": "one-way",
  "mode": "沿河道路",
  "description": "枯水期可通行。"
}
```

反向查询可以发现这条记录，但仅当 `direction` 为 `two-way` 才可说明反向通行；未找到记录不等于不可通行。创建使用独占写入；更新读取当前版本后用完整的新对象覆盖同一 ID 文件，版本变化时拒绝，避免覆盖其他修改。连通关系文件不要求同时改写两端地点，不承诺跨文件事务。

## 五、坐标计算和查询边界

- **变换。** `frameBox = [L,T,R,B]` 时，局部点 `[x,y]` 映射到父画布为 `[L + x × (R-L)/1000, T + y × (B-T)/1000]`。矩形分别变换两个角，多个框逐一变换；逐层组合变换，不能把所有框先合为单一包围框。参考框可以越出父画布，不能自动裁掉完整地点。
- **比较和精度。** 采用有限数计算，计算过程中不逐层取整；向调用方输出时统一保留至多 6 位小数。比较前换算到同一画布并以 `0.000001` 画布单位为误差容限；超出容限的共同范围差异报告冲突，不自动覆盖。精度只用于数值比较，不代表测量精度；地点范围的概略程度以内容描述为准。不同父级仅保存各自片段时，只比较实际能对应的共同部分，不要求两个片段完全相同。
- **区域交集。** 以矩形集合计算正面积交集，边缘或角点仅接触时单独报告 `touching`，不当作面积相交；两个范围重叠的重复部分只算一次。`frameBox` 不参与地点实际占地查询。该规则只判空间相交或接触，不推断行政归属、道路或可通行。
- **有限查询。** 多父级图需要检测循环和去重；后代查询按层面指定深度，结果说明命中路径和该地点其他可见父级。不可读取的父级不泄露名称、ID 或数量，但结果标明父级信息不完整。父级片段、文件或授权不完整时，查询结果说明局限，不把未覆盖当作不存在。
- **版本与分页。** 文件版本用于检测读取后变化，不是世界事实的确认。查询版本基于所扫描范围和实际内容建立；同版本分页期间任何相关文件新增、删除或变化时拒绝后续页并要求重查。扫描失败、取消、受限或超上限须报告不完整或失败；该校验不提供跨文件原子快照，单可信写入进程限制仍然适用。

## 六、工具契约

以下工具名用于后续开发；权限和可信根由插件装配固定，输入不包含世界 ID、磁盘路径或授权参数。分页统一输入 `offset`、`limit`、后续页 `version`；返回 `items`、`nextOffset`、`version` 和完整性 / 未覆盖说明。精确 schema 和错误码在实现时随插件接口及测试确定。

| 工具 | 主要输入 | 最小结果 |
| --- | --- | --- |
| `map_overview_read` | 无。 | 世界概览及文件版本。 |
| `map_overview_create` | 名称、描述、世界宽高 / 单位、层面、方向和留白。 | 保存后的路径和版本；创建已存在的概览时拒绝覆盖。 |
| `map_place_create` | 名称、别名、描述、展开程度、父级关系及留白。 | 生成的 ID、路径和版本；先校验父级、画布、世界身份及无环。 |
| `map_place_search` | 名称 / 别名、可选层面、父级和展开程度；分页。 | ID、名称、状态和匹配父级线索；同名返回多个候选。 |
| `map_place_read` | 地点 ID。 | 地点完整 JSON、相对路径和内容版本。 |
| `map_place_ancestors` | 地点 ID、层面、深度和分页。 | 所有可见父级路径与祖先，标记截断或断链；不以名称代替 ID。 |
| `map_place_children` | 父地点 ID 或世界顶层、层面、深度、可选展开程度和分页。 | 子地点及匹配路径、可见的其他父级 / 层面、展开程度和完整性；不让结果暗示只有当前父级。 |
| `map_coordinates_convert` | 地点 ID、明确的父级路径、目标祖先或世界画布，以及完整范围 / 父级内覆盖的选择。 | 换算后的矩形集合、路径、文件版本和完整性；不能换算或多路径不一致时报告原因。 |
| `map_area_search` | 层面、参考画布、一个或多个查询框及分页。 | 与查询范围有正面积交集的地点，按需区分仅边界接触；不凭外包框推断实际占地。 |
| `map_connections_read` | 地点 ID、入 / 出方向或连通类型及分页。 | 连通 ID、两端、方向、方式、条件、文件版本；无记录不等于不通。 |
| `map_connection_create` | 两端地点 ID、方向、方式和按需描述 / 条件。 | 连通 ID、路径及文件版本；独占创建，成功写入即为当前设定。 |
| `map_connection_update` | 连通 ID、完整新内容和读取版本。 | 原 ID 对应文件的新版本；旧版本冲突拒绝覆盖，结果不确定时先核实。 |

地图专用 Agent 的写工具限于可信应用配置的地图负责人；其他 Agent 可仅装配读取工具。目录登记复用现有身份绑定，文件写入和登记分别报告。地点和地图概览的后续待审修改及确认仍由第 7 阶段设计；这些工具不自动授予确认能力。

## 七、验证和下一步

1. 对 JSON 解析覆盖重复键、未知版本、未知层面、重复 ID、无效父级、越界覆盖框、零面积框、非法 `frameBox` 和环；错误时保留原文件，不跳过损坏资料冒充无结果。
2. 对城邦样例检查同 ID 多父查询、跨父级坐标及多条路径一致性；对群岛样例检查分离范围、空隙搜索和逐层换算。覆盖精度阈值边界、边缘接触和物理尺度换算。
3. 对工具和装配检查只读 / 写权限、跨世界拒绝、目录未配置、版本冲突、文件变化、取消、身份占用和部分成功；确认写入结果不确定时返回可核查线索，不删除现有用户数据。
4. 用固定模型替身验证调用与文件状态；真实模型验证 Agent 是否按场景创建地图、保留留白和正确使用工具，报告实际质量与平台限制。两者不能互相替代。
