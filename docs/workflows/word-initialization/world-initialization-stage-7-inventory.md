# 第 7 阶段现状盘点

本文记录局部讨论开发前对现有实现的走查；业务选择尚待确认，不能作为已实现的讨论接口。源码是具体工具与格式的权威来源。

## 目标、版本与候选

| 目标 | 当前读取和版本 | 初始化写入与候选缺口 |
| --- | --- | --- |
| 地图概览、地点、连通 | 地图存储按 ID 读取完整地点和连通及文件版本；搜索分页版本绑定查询结果。 | 可创建概览、地点和连通，只有连通有按版本直接更新；没有地点待审候选或地点更新工具。 |
| 人物 | `character_initialization_read` 返回正文摘要版本；普通读取不返回该版本。 | 可创建、直接更新未确认人物；`character_prepare` 保存独占候选与正文基线，重复准备会覆盖同一候选，未检查调用方持有的候选版本。 |
| 人物关系 | 按关系 ID 或人物查询；读取提供关系版本。 | 初始化创建和按版本直接更新未确认关系；没有待审候选。 |
| 组织、组织关系、成员关系 | 规划者查询可读取完整记录及文件版本；角色视图经授权过滤，其版本不能用于写入。 | 三类对象分别支持创建和按版本直接更新；没有待审候选。成员关系归组织模块，不由人物正文代替。 |
| 历史事件 | 读取事件及文件版本，查询分页版本绑定扫描结果。 | 未确认事件直接更新；已确认事件可独占创建候选，记录基线及候选文件版本，读取报告过期；不提供候选更新或提交。 |
| 世界起点、局势总览和条目 | 起点及各文档可读取文件版本。 | 起点可直接按版本更新且没有候选；已确认总览和条目可独占创建候选，未确认资料直接更新；候选没有更新或提交入口。 |
| 世界发展规划 | 按类型与 ID 读取文档和文件版本。 | 已确认规划可独占创建候选，未确认规划直接更新；候选没有更新或提交入口。 |
| 世界专有主题和内容 | 按 ID 读取主题、内容及文件版本，内容保留全部主题归属。 | 已确认资料可独占创建候选，未确认资料直接更新；候选没有更新或提交入口。 |
| 世界基础信息、主 Agent 总览及补充文件 | 文件通过可信读取范围访问；目录登记是线索，不能替代读取正文。 | 基础信息和总览保存工具创建独立文件；主 Agent 普通文件工具可修改草稿根。尚无按可信成果绑定的讨论候选。 |

历史、局势、发展规划和专有内容的候选只接受已确认正文，因此不能直接满足对未确认第一版也隔离修改的要求。各模块的文件版本与查询分页版本用途不同，不应混用。来源分别见[地图](../../../src/agents/plugins/map/README.md)、[人物](../../../src/agents/plugins/character/README.md)、[组织](../../../src/agents/plugins/organization/README.md)、[历史](../../../src/agents/plugins/history/README.md)、[局势](../../../src/agents/plugins/initial-situation/README.md)、[规划](../../../src/agents/plugins/world-development/README.md)和[专有内容](../../../src/agents/plugins/world-specific/README.md)。

人物候选的 `pending.json` 和 `pending.md` 分别保存基线及正文；可信 `commit` 检查基线与候选摘要，将人物标记为 confirmed，并通过备份和操作记录支持中断恢复。保存状态与正文分开，失败时必须核查实际文件；既有恢复针对提交及初始化更新，不等于跨模块事务，也没有讨论身份或候选版本条件更新。

## 装配与隔离

[世界入口](../../../src/app/agents/world-initialization.ts)按可信世界配置绑定身份和专用 Agent，使用持久子 Agent 路由与可选 JSONL Session。主 Agent 的普通文件修改受限于草稿根，但草稿本身包含当前成果；通用子 Agent 文件工具只读。基础信息 Agent 通过专用保存工具写入自己的目录。其他专用 Agent 的普通文件工具只读，但业务插件以初始化读写权限注册，能够直接创建或更新所属资料。

[共享存储](../../../src/world-init/storage/world.ts)由世界装配持有并按需打开，专用 Agent 借用句柄；跨模块引用通常以只读工具或解析器公开，但借用的底层存储本身可写，工具只读配置不能替代受限句柄。所有者负责关闭，现有单可信写入进程声明不提供跨进程锁或跨文件原子快照。Session 的世界、身份和 Session ID 由应用绑定，恢复对话不证明第一版完成或候选已保存。

讨论装配需要同时限制主 Agent 草稿写入、专用 Agent 业务写工具、基础信息保存工具、委派路径及共享句柄，并验证恢复 Session 不重新引入初始化写权限。不能把提示词作为隔离边界。

## 样例走查

- 曲水城：地图搜索选择真实 ID，`map_place_read` 读取正文与文件版本；现有工具无法为地点保存候选。两轮修改、切换到青云宗及返回需要新的讨论记录与地点候选适配；不能用新建地点或连通更新替代。
- 林岚：人物读取和版本化读取定位当前正文，既有 `prepare` 可保存并重复覆盖单份人物候选，但不能判断候选属于哪个讨论，也不能阻止旧候选版本覆盖新版本。切换与返回还需要讨论和 Session 的独立关联。
- 林岚的青云宗职务：人物正文与组织成员关系分别读取实际记录和版本；组织成员关系没有候选，`organization_membership_update` 会直接覆盖当前记录。需要分别保存、展示两份候选；一方成功不能证明另一方成功，也不能声称跨模块原子完成。

以上是依据源码与已有测试的路径走查，尚非可运行的第 7 阶段端到端验证。

## 已确认的近期业务选择

- 同一目标已有有效候选时，拒绝其他讨论创建新候选并提示已有候选，不能覆盖；同一讨论内的更新仍需候选版本保护。
- 明确放弃候选时保留记录并标记放弃；停止本轮生成保留先前候选。放弃后如何重新取得目标占用，以及已有人物候选如何归属，在契约设计中明确，不能静默删除已有数据。
- 可信应用显式接收第一版完整判断；不完整时提示继续补做，不以总览、目录或 Session 单独推断完成。具体输入及持久化边界在契约设计中确定。
- 一次讨论涉及多个模块时逐项展示候选和归属；整体或部分提交及影响检查留给第 8 阶段。
