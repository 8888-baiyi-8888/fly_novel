# 文件能力第二包：`dsh-fs` 文件系统契约开发计划

本文细化[第四阶段的 `dsh-fs` 步骤](world-initialization-stage-4-file-tools-plan.md#2-dsh-fs文件系统契约)。目标是复用官方文件系统服务契约，让后续本地后端、观察策略和文件工具有共同接口。逐步核对依赖、接入服务和类型，再用受控替身验证；本计划不表示该包或后端已经实现。

## 范围和边界

本包计划放在 `src/agents/plugins/fs/fs/`，作为独立工作区包；测试放在 `src/agents/tests/`。前置补丁库见 [`fs-patch`](../../../src/agents/plugins/fs/fs-patch/README.md)，整体目录和逐包顺序见[第四阶段计划](world-initialization-stage-4-file-tools-plan.md#包的目录安排)。

本阶段只提供契约、类型、错误和事件，不实现本地磁盘访问、路径授权、文件观察策略、沙箱或 Agent 文件工具。不因注册契约就声称已有可用文件系统；实际后端负责资源、取消、原子性和真实文件行为。

## 已核对的上游基线

- 固定提交为 [`fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`](https://github.com/deepseek-ai/deepseek-harness/tree/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/fs/fs)，包版本 `0.2.2-rc.1`。源码主要为 `src/index.ts` 和 `src/types.ts`，上游测试为 `tests/service.spec.ts`。
- 上游通过 Cordis `Service` 定义抽象 `FileSystem` 和 `ctx.fs`，声明 `fs/write-intent`、`fs/edit-intent`、`fs/delete-intent` 和 `fs/observed` 事件；具体存储和观察策略由其他包提供。
- 契约包括目标解析、路径及包含关系、元数据、文本和字节读取、单层列表、监听、写入、编辑、补丁、删除和移动；监听和宿主路径转换存在基类默认行为，具体签名以固定提交源码为准。
- 包清单将 `dsh-fs-patch` 列为直接依赖，Cordis、`dsh-brand`、`dsh-llm` 和 `dsh-sandbox` 列为 peer；源码中 `PatchHunk`、品牌类型及沙箱类型为类型导入，`FsError` 运行时继承上游 `HarnessError`。声明依赖与实际运行时依赖需分别处理。
- 上游包清单声明 MIT；引入前核对固定提交的仓库许可证和具体源码文件的版权声明。不可假设其他包的许可证条款必然相同。

## 1. 核对依赖与确定接入方式

1. 逐项核对固定提交的包清单、公开导出、源码、上游测试和许可证；确认后续 `fs-local`、观察策略及 `tool-fs` 实际消费的符号和事件。
2. 对照本项目 Cordis 版本、`@fly-novel/fs-patch`、品牌类型、LLM 错误和现有服务作用域。检查上游 `HarnessError` 的构造、错误码和行为，不能仅因存在项目错误类就认为兼容；检查沙箱类型的结构及其被调用方使用的方式。
3. 对每项依赖确定直接引入、复用项目等价契约或单独同步上游包的方式，并记录理由与潜在行为差异。若发现必需的上游包无法兼容，先将其作为独立前置任务，不以空类型或忽略检查绕过。
4. 比较使用官方发布包与固定提交源码同步的模块格式、工作区和更新影响，按已确定的逐包复用方向选择具体方式。固定提交源码与已发布包版本号相同不等于内容已经验证一致。

**验收**：形成依赖和接口映射清单，区分类型与运行时依赖，确定需要同步或适配的内容以及后续消费者如何接入；无法确认的问题明确记录。

## 2. 建立工作区包和来源记录

1. 在 `src/agents/plugins/fs/fs/` 建立包，按第 1 步选择的方式引入官方源码和所需许可证；尽量保留公开契约与实现，逐项记录本地修改。
2. 配置包入口、声明文件、TypeScript 构建和所需依赖，更新工作区清单、锁文件、根 TypeScript 配置中必要的路径及构建边界；确保源码检查和构建产物检查的前置条件明确。
3. 在包 README 记录固定提交、许可证、接口入口、本地修改和更新步骤；同步 `AGENTS.md`、`src/agents/README.md` 及受影响的架构说明，并按项目规则记录重要工程决定。
4. 保证包导入不创建后端、不访问文件系统；不得通过关闭类型检查或宽泛断言掩盖依赖不匹配。

**验收**：冻结锁文件安装、包构建与类型检查可执行；公开入口可由独立调用方导入，来源、许可证和本地修改可追溯。

## 3. 契约与类型适配

1. 对照上游逐项保留服务方法的参数、返回值、取消信号、失败条件及资源归属，特别是字节读取上限、可选版本保护、移动的目标发布与源删除结果、监听初始化与异步关闭。
2. 保留目标标识与版本的专用类型及其不透明语义；确认 `FsError` 与错误码的运行时行为与所选错误基类一致，不能静默丢失错误信息或改写错误码。
3. 将补丁参数接到本项目 `fs-patch` 类型，确认消费者不依赖具体后端路径；为沙箱相关类型和未提供后端时的行为保留明确契约。
4. 对确需修改的接口记录差异，并检查固定上游 `fs-local`、观察策略和工具的调用点，避免把简单导入修改演变成不兼容的契约变更。

**验收**：类型检查覆盖项目实际导出和下游使用所需的类型；补丁、身份、版本、错误和可选参数语义与确定的契约一致。此步不测试本地文件操作。

## 4. Cordis 服务、事件和生命周期

1. 核对项目 Harness 的 Context、服务注册及作用域清理方式，确认 `ctx.fs` 声明、服务所有者和依赖启动行为；不在根作用域隐式暴露未经授权的全局文件系统。
2. 保留各意图事件的 waterfall 继续调用和短路语义，以及观察事件的同步通知行为；观察策略的具体实现留给对应包。
3. 使用受控内存替身验证服务装配、访问、隔离和作用域销毁；覆盖重复清理、依赖缺失或启动失败中实际可能发生的路径。确认替身只用于验证契约，不假装验证磁盘安全性或文件原子性。
4. 对基类默认监听不支持、取消传播和监听句柄归属进行聚焦验证；具体监听实现及关闭竞态由后端阶段覆盖。

**验收**：按项目实际入口创建和释放服务，事件与作用域行为可复现；未装配后端时无可用文件访问，失败不留下可访问的残留服务。

## 5. 构建、测试和交付

- 将与契约和本地适配有关的上游测试按项目测试框架移植到 `src/agents/tests/`，保留适用版权声明；补充服务装配、错误、事件和清理的行为测试，不复制与本阶段无关的后端测试。
- 执行包类型检查、构建、项目类型检查和聚焦测试；先构建再从公开入口做消费冒烟，验证类型与运行时导出。涉及构建入口的变化检查干净工作区和实际构建产物，不依赖残留产物。
- 检查许可证、依赖清单、锁文件、模块文档和 `git diff --check`；记录实际运行命令、结果与未完成项。
- 交付稳定的契约包和测试，为下一步 `fs-local` 提供明确的接口、依赖及已知差异。文件访问权限、磁盘 I/O、搜索、Agent 工具和真实后端并发行为由后续阶段分别验证。
