# 世界初始化第五阶段：版本对齐与对应子 Agent 更新详细开发计划

本计划细化[第五阶段工作区计划第 5 步](world-initialization-stage-5-workspace-plan.md#5-版本对齐与对应子-agent-更新)，衔接[资料目录与受控登记计划](world-initialization-stage-5-catalog-plan.md)。目标是让主 Agent 发现资料目录记录与成果不一致后，委派负责该成果的子 Agent 更新简介，并通过程序重新检查实际文件和记录。本文是开发计划；尚未实现的工具、检查和自动处理不表示当前可用。

## 范围与现状

- [资料目录服务](../../../src/world-init/workspace/catalog/service.ts)按文件实际字节计算 SHA-256；查询或读取记录时返回 `current`、`stale`、`missing`、`unreadable`、`changing` 或 `forbidden`。`catalog_read` 的 `not_registered` 是请求路径没有登记，不等于成果文件缺失；当前没有自动发现所有未登记成果的能力。
- 目录记录含负责人、世界相对路径、简介、`contentSha256` 和记录 `revision`；目录分页使用整个目录文件的版本。三种版本用途不同：内容摘要描述成果字节，记录 revision 控制记录更新冲突，分页版本固定目录记录快照。状态检查和登记不会确认世界事实。
- [目录工具](../../../src/tools/catalog/catalog-tools.ts)只允许负责人更新或删除自己的记录，主 Agent 可查询其他 Agent 的记录但不能代改。`catalog_update` 当前在提交前自行读取文件摘要，但不验证该摘要是否对应 Agent 写简介时实际阅读的内容；不能仅凭更新成功或 `fileStatus: current` 证明简介基于所读版本。
- [世界入口](../../../src/app/agents/world-initialization.ts)可装配主 Agent、角色创建 Agent 和一个共享目录服务；现有 [角色委派工具](../../../src/tools/character/delegate-character-creator.ts)固定指向角色创建职责。`persistent` 支持可信创建绑定和路由，但当前生产装配并不提供按任意负责人选择的通用特殊 Agent 工具；第二个特殊 Agent 仅有测试装配。不能把配置中的任意 ID 假定为可调用 Agent。
- 角色 Agent 的资料由专用工具和直接文件访问维护；不能依靠普通文件观察事件捕捉所有成果变化。已有 Session 按可信配置恢复对话历史，长期记忆、自动压缩和跨进程写锁不在本步实现。

## 首版处理设计

### 触发与发现

按已确定的工作区契约，负责人可在任务结束前显式登记或更新自己成果的简介；目录查询继续逐项检查成果摘要；主 Agent 还可显式发起世界范围全量检查。本步为全量检查提供真实工具或受控入口，并在主 Agent 的工作指引中说明何时可检查；不把每次普通文件写入、每轮对话或子 Agent 退出当作已实现的自动触发。

全量检查只遍历已登记记录，并逐条返回路径、负责人、记录 revision、记录内容摘要和检查状态；某路径是否登记可通过现有 `catalog_read` 查询。它不通过扫描目录推断全部未登记文件，也不因找不到记录而替用户自动登记。`current` 保留为无需更新；`stale` 可以进入更新流程；`missing`、`unreadable`、`changing`、`forbidden`、负责人缺失和目录损坏分别报告，不能当作空结果或自动删除记录。请求取消或全量检查不完整时保留已检查部分与未完成范围，不能报告全部一致。

检查按确定顺序分页，使用现有目录版本防止页面混合不同目录快照。先完成扫描、再处理记录；扫描期间目录变化时返回明确冲突，主 Agent 可重新发起检查，不在后台无限重试。文件内容可能在不同记录的检查之间变化；每条结果只说明其检查时刻。处理某条记录前重新读取记录、revision 和文件状态，避免用旧扫描结果直接委派。

### 主 Agent 与负责人分工

主 Agent 读取检查结果，决定是否需要处理及如何向用户说明。对于主 Agent 自己负责的记录，主 Agent 使用自己的目录工具更新；对于特殊子 Agent 的记录，主 Agent 通过可信装配的对应专用委派工具提交更新任务。主 Agent 不直接改写其他 Agent 的目录记录或成果文件，也不能通过模型参数赋予世界、负责人、目录或 Session 权限。

可信应用根据用户提供的世界与特殊 Agent 配置，将稳定业务身份映射到实际可调用的专用工具及 `persistent` 创建绑定；模型可见的负责人及工具说明用于选择，实际工具绑定仍由可信应用固定。不要让模型通过字符串指定任意 Provider、创建参数或授权路径，也不把运行实例 ID 当成业务 ID。角色创建 Agent 继续复用现有专用工具与 `persistent` 驱动；第二个负责人使用可控测试替身验证配置、路由和拒绝路径，不提前开发新的业务 Agent。

不存在可用绑定、负责人不属于本世界、对应工具未装配、身份忙、启动或执行失败时，明确返回该记录的未处理原因并保留原记录；不能改由主 Agent 接管或将结果标记为完成。相同 `(世界 ID, Agent ID)` 的实例使用现有进程内身份占用；实例未运行时按可信配置重建并恢复原目录及 Session，不能宣称恢复了长期记忆。已有正在运行的负责人如何接受下一项任务遵循现有运行和忙碌语义，不新建绕过互斥的并发写入通道。

### 绑定实际读取版本

为避免简介基于旧文件、但更新时被错误地关联到新摘要，新增由目录服务提供的受控成果读取能力，并由专用工具暴露给**该记录负责人**。读取时检查世界、负责人、规范目标和记录 revision，按原始字节读取并计算摘要；读取前后核对文件真实目标和版本，变化或缺失时失败。模型获得完整可用文本、对应记录 revision 和由服务签发的短期读取凭据；输出限制由可信配置决定。文件过大、非支持的文本编码或无法完整读取时明确报告并交由负责人处理，不对截断内容签发可用于更新的凭据。

读取凭据由服务生成并绑定世界、稳定负责人、规范路径、记录 revision 和此次读取的实际字节摘要；调用者不能自行指定这些绑定内容。凭据由可信应用作用域管理，不能跨世界、跨负责人、跨路径、跨记录版本或跨服务重启复用；Agent 实例关闭时撤销其未使用凭据，取消、释放和并发使用的行为在实现时用测试固定。凭据仅证明服务向该 Agent 提供了对应版本内容，不能证明模型理解了内容或简介语义正确。

更新工具要求携带所读取记录的 revision、读取凭据和新简介；服务在串行更新中重新验证身份、凭据、记录 revision、真实路径和当前文件摘要。任何一项不一致则拒绝发布并保留原记录；不能用模型传入的摘要直接充当授权或替代服务重新计算。目录文件发布前再核对成果，发布后再次检查并返回实际状态；发布后成果改变或复核失败时报告已提交但未对齐，不声称回滚。一次成功更新后凭据失效；文件再次变化或 revision 冲突后须重新读取并生成新凭据。

现有 `catalog_register` 的创建流程保持原有语义；现有 `catalog_update` 调用方、角色 Agent 指引及测试须同步迁移到带读取凭据的更新契约。项目尚未正式发布，不为旧模型工具接口添加静默兼容分支；如果实现阶段发现其他持久数据或外部接口受影响，先明确迁移或拒绝策略，不能删除用户数据。目录 JSON 现有格式没有新增持久字段时维持版本 1；若实际实现需要改变持久格式，须先明确版本与迁移或拒绝读取策略。

### 最终核对和结果

委派返回只是 Agent 的任务结果，不作为文件已对齐的证明。主 Agent 或可信检查入口在每次处理后重新读取该路径，核对负责人、记录 revision、内容摘要与实际文件状态；仅在**最终检查时**记录存在、负责人一致、预期更新已生效且 `fileStatus: current` 才报告该条对齐。若期间发生记录删除、重建、负责人变化、成果再次改变、读取失败或检查取消，按实际结果标记未对齐、无法确认或不确定，保留原有数据和已完成的其他结果。

本步设计逐项结果，至少区分：无需更新、已对齐、仍过期、未登记、成果缺失、不可读、检查期间变化、越权或负责人不匹配、负责人未配置、身份忙、委派失败、取消及提交结果不确定。完整检查报告包含实际检查范围与是否完成；不以模型自由文本、退出码或一次成功工具调用推断全世界已经一致。失败条目允许后续重新检查，首版不自动循环重试、后台轮询或创建持久任务队列。

## 开发步骤

### 1. 核对调用链与固定对齐契约

1. 阅读目录服务与工具、主 Agent 和角色 Agent 的系统提示词及装配、`persistent` Provider 和驱动、身份占用与现有测试。梳理检查、主 Agent 决策、可信专用工具选择、子 Agent 源文件读取、目录更新及最终复查的真实链路。
2. 使用两个场景固定输入输出：主 Agent 自己的世界构想过期；角色 Agent 成果过期且其实例已经销毁。另覆盖负责人未配置、记录或成果被移除、文件读取后再次变化。明确检查触发、逐项状态和处理前后的版本比较。
3. 核对现有文件读取工具对完整内容、大小上限、编码、取消和文件版本的保证；确定专用读取凭据的表示、生命周期、撤销时机、并发和错误码。按真实代码确认 `catalog_update` 的现有调用方，列出需要同步的迁移与测试。
4. 确定用户配置到专用工具的可信装配方式及主 Agent 可见的能力说明，验证不能通过模型参数改变世界、业务身份或权限。根据实际代码明确世界服务、凭据、父子 Agent 和作用域关闭顺序；发现上述设计无法由公开扩展点实现时先修正文档，不伪装为现有能力。

**验收**：两种场景有具体调用和状态示例；明确所读版本如何贯穿到更新和最终检查，以及负责人不存在、实例未启动和各类错误的处理。

### 2. 实现读取凭据与受控简介更新

1. 在工作区目录服务中提供完整成果读取及临时凭据，绑定可信世界、负责人、路径、记录 revision 和实际内容摘要；只允许负责人读取用于更新的成果，继续保留普通共享读取能力。
2. `catalog_update` 增加必需的读取凭据并在服务端核对；服务自行计算成果字节摘要，检查读取、更新和发布后的真实版本。实现凭据过期、重复使用、实例撤销、服务关闭、跨负责人和跨世界拒绝；不修改成果文件和用户确认状态。
3. 在 `src/tools/catalog/` 实现相应读取工具并更新目录工具输入、结果与模型说明；同步现有调用方、角色创建 Agent 的指引和测试。模型收到的错误不能泄露宿主路径；取消和发布结果不确定时保留真实状态。
4. 使用受控门闩验证读取前后变化、读取到更新之间变化、更新期间变化、发布后变化、记录 revision 冲突、凭据复用及错误身份；验证旧接口明确拒绝、不删除原目录与成果。

**验收**：不能用旧内容摘要或其他身份的凭据提交简介；已提交但成果再次变化时如实返回未对齐状态。

### 3. 实现全量检查与逐项结果

1. 复用目录服务的记录读取、分页版本与单项检查，建立显式全量检查入口；按世界授权和受控分页遍历，完整区分所有状态及未完成范围。
2. 处理空目录、未登记路径、损坏目录、状态读取失败、取消和检查期间目录变化；不自动扫描、注册或修改任何成果。
3. 验证大于单页的记录、跨页变化、文件变化、缺失、读取失败、负责人失效和取消；检查结果不得伪装成全量完成。

**验收**：主 Agent 可获得可追踪的检查范围、负责人及逐项状态；失败项和未检查项可重新处理。

### 4. 可信装配负责人委派与主 Agent 指引

1. 沿现有世界入口、专用工具及 `persistent` 机制装配用户配置的负责人能力；为主 Agent 提供负责人到对应专用工具的可信可见说明。角色创建 Agent 作为实际负责人，第二种职责只在测试中装配。
2. 在主 Agent 和负责 Agent 的提示词或现有 Skill 中明确：先检查、主 Agent 自己处理本人的记录、其他记录委派负责人、负责人读取实际文件后更新并提交凭据、最后重新检查。提示词不替代服务端权限和版本检查。
3. 对负责人未配置、身份忙、启动失败、取消和清理失败提供可观察结果；委派等待任务和释放，执行与清理同时失败时保留两者。未经可信配置的身份不能被模型调用或获得目录权限。
4. 测试不同世界同名负责人、跨世界与跨负责人伪造、实例销毁后重新创建、同身份并发及子任务失败。不得把角色创建工具固定当成任意其他 Agent 的委派工具。

**验收**：主 Agent 能在真实工具链中将过期记录交给正确负责人，未经装配或无权的负责人无法被调用。

### 5. 最终复查与端到端验证

1. 通过真实主子 Agent、目录工具和 Session 验证两种场景：原记录过期、主 Agent 发起检查、对应负责人读取并更新、最终重新核对为 `current`。另验证主 Agent 处理自己记录及两个世界隔离。
2. 使用门闩制造负责人读取后成果变化、更新后再次变化、记录被删除或重建、并发更新、身份忙、不可读、未配置负责人、任务取消及清理失败；逐项报告保留已完成和未完成结果，不虚构完整成功。
3. 验证子 Agent 结束和实例重建后复用原目录及已配置 Session；凭据随实例或服务关闭失效，不将 Session 重新加载描述为长期记忆恢复。

**验收**：发现、正确委派、可信版本绑定和最终复查形成可观察闭环，失败和竞争均能重试或由用户处理，不丢失成果。

### 6. 文档与交付

1. 更新目录服务、工具、主子 Agent、工作区装配和持久化相关说明，以及必要的架构、目录登记和 Agent Note；描述凭据、生命周期、取消、版本迁移和部署限制。
2. 运行受影响的聚焦测试、类型检查和正式构建；若交付构建入口，显式构建后运行入口冒烟。检查文档链接和 Git 空白；记录测试平台、跳过原因及是否运行真实模型，固定替身不能冒充真实模型验证。
3. 不将本步完成当作第五阶段整体完成；第 6 步的最终集成、后续业务确认、跨进程锁和长期记忆仍按各自范围推进。

**交付验收**：可信配置下主 Agent 能检查过期资料、委派正确负责人并据实际最终状态报告；未配置、失败与竞争结果清晰，限制可复验。
