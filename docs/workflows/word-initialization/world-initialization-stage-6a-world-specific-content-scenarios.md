# 世界专有模块：现状与场景走查

本文是[世界专有模块详细开发计划](world-initialization-stage-6a-world-specific-content-plan.md)第一步的核对结果。示例用于开发与验收，不是必须创建的世界主题；文件、字段和工具以资料契约及实际实现为准。

## 当前可复用的能力

| 范围 | 实际能力 | 世界专有模块的边界 |
| --- | --- | --- |
| 世界基础 | [基础信息 Agent](../../../src/app/README.md)将成果保存为待审 Markdown，授权范围内可读取原文及资料目录。 | 引用可访问的文件或线索，不凭名称编造基础信息 ID；目录简介不是正文。 |
| 地图、组织、人物、历史 | 各自的插件维护文件、读取及查询；已有可信引用绑定会核对世界和负责人。 | 专有规则按需引用实际地点、组织、人物和历史，不改写它们的权威正文；规划者读权限不等于角色知情。 |
| 初始局势 | [局势插件](../../../src/agents/plugins/initial-situation/README.md)维护一个起点、多个待审方案及所属条目，没有方案选用流程。 | 引用具体方案及其条目，不将不同候选当作同时成立，也不把规则中可能发生的变化当作当前状态。 |
| 世界发展规划 | [联合规划插件](../../../src/agents/plugins/world-development/README.md)维护宏观方向、故事线、成长线与成长蓝图，并区分未知、通用和按局势方案的适用性。 | 对未来变化引用对应规划；不预定角色行为，不将未来构想写成已经成立的专有规则。 |
| 工作区与 Agent | 现有专用 Agent 通过可信应用绑定世界、身份、负责人目录、Session 及授权工具；目录用于导航，Session 不能证明业务完成。 | 可复用装配与生命周期模式，但当前没有世界专有内容插件、存储、引用服务或 Agent，不能将提示词当作已实现能力。 |

## 修仙世界

输入是用户构想“力量本身无善恶”，基础信息已给出世界概况；地图有青云山及灵脉位置，组织有青云宗，历史有一次因灵脉变化产生的迁徙。根据可访问的实际资料，专有 Agent 可以识别需要补充的修炼体系与灵脉规律，并按近期需要表达力量来源、功法适用条件或灵脉恢复机制；更远的境界和罕见功法可以留白。

“灵石”同时涉及修炼规则、组织交易及特殊设施供能时，用户确认维护一份独立内容并允许从多个主题查询；从任一关联主题查询都显示全部归属，同一规则被引用时不复制多份权威正文。青云宗的资源配置由组织模块维护，灵脉坐标由地图维护，历史迁徙原因若未知则不能由规则推定。每项内容应能标明本身是否展开、相关资料及未知；主题的概况不能替代条目正文。

## 城邦群与航海世界

城邦群已有水源地图、供水组织和初始局势。若世界需要解释提水设施及运行限制，专有 Agent 可自主补充水利技术规则；若已有成果足以支持用户构想且没有必要深入，可报告未新增主题，不强制生成修炼、科技等固定栏目。地点、联盟协约、成员与当前供水状态仍由各自模块维护。

航海世界有“特定潮汐期间穿越迷雾海域”的用户构想；专有 Agent 可识别潮汐航行规则和相关技术限制，未知的迷雾成因明确留白。地图负责真实海域及航线，历史负责已经发生的事故；未来可能开发的导航技术属于世界发展规划，不写成当前已存在的事实。

## 后续验收场景

| 场景 | 核查内容 |
| --- | --- |
| 自主补充 | 根据已有世界背景和已授权资料识别适用主题、创建必要成果、报告依据和留白；用户不必先逐条提供主题清单。 |
| 按需不新增 | 城邦已有设定足够时，可读取并报告无需新主题；未创建不代表世界中不存在任何水利技术。 |
| 继续完善 | 已有主题时先查询正文与版本，再按需新增内容或更新本人资料；结果不确定时先核查文件，不能盲目重复创建。 |
| 多主题与不重复维护 | “灵石”只保留一份正文，能从已关联主题查询并显示其他归属；具体关联结构待契约确定，不按同名自动合并。 |
| 外部资料变化 | 地图或组织来源改变、缺失或不可读取时分别报告变化、缺失、未配置、无权或读取错误；不依据目录摘要自动重写专有规则。 |
| 不同世界与同名 | 不同世界的同名主题相互隔离；同世界同名时列出候选，由实际身份确定目标。 |
| 保留旧数据与失败恢复 | 新格式不覆盖已有 Markdown 或其他模块成果；版本过期、损坏、取消、发布不确定及会话恢复均保留原数据并明确报告。 |

## 契约前需明确的选择

- 用户确认使用 JSON，主题及按需拆分的内容项各自有身份和版本；具体字段和文件层级在契约步骤确定。
- 用户确认允许一个条目关联多个主题，反查显示所有已关联主题；不要求一个主题只有一个父主题或建立统一的手工总表。具体层级及关系语义在契约步骤按场景细化。
- 不同地区规则、公开说法与未知可先通过正文和明确范围表达；不预建任意动态 Schema 或角色未来知识授权系统。展开等级、用户确认状态及可计算约束须分开设计。

本步仅核对现状和示例，不实现业务代码或世界运行。
