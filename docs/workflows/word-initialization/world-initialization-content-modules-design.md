# 世界初始化内容模块与子 Agent 设计（讨论稿）

本文在第六阶段与局部讨论阶段之间设计十个世界初始化内容模块的职责、资料和协作方式。十个模块及其职责来自用户提出的设计说明；具体数据表示、Agent 分工和阶段顺序是待确认提案，不表示代码已实现，也不要求每个世界填满全部内容。整体流程见[开发计划](world-initialization-development-plan.md)。

## 项目现状与设计原则

- [世界工作区与资料目录](../../../src/world-init/README.md)提供世界隔离的文件范围、按负责人登记的目录、版本检查及受控读取；目录简介不是成果正文，也不代表用户确认。不存在统一的十模块对象存储、跨模块关联服务或路径无关读取接口。
- [角色创建入口](../../../src/app/agents/character-creator.ts)提供角色资料、待审修改、独立 Session 和可信身份装配；[世界入口](../../../src/app/agents/world-initialization.ts)生产装配的专用子 Agent 目前只有角色创建。通用只读子 Agent 能协助分析，但不是其他九类专用 Agent。
- 十个模块是内容职责边界，不自动要求十个 Agent、十种数据库表或十份固定模板。Agent 根据构想和用户要求确定深度；明确留白可以保留，不用无结果或缺文件冒充留白。
- 每一资料项只设一个正文归属；其他模块通过引用、必要的简短上下文和来源访问，避免复制另一模块完整事实。用户要求、已有事实、Agent 建议、未来方向和待定内容需要区分；生成、登记或保存不等于用户确认。
- 现有角色文件及目录格式已有版本与数据，任何格式变更均须先设计版本、迁移或明确拒绝读取策略，保留原数据。Session 是对话历史，不是世界事实或长期记忆。单进程写入和路径检查的限制见[应用说明](../../../src/app/README.md)。

## 十个模块的职责、输入与输出

“基础数据”是设计需要表达的信息，不是所有项目必填的固定字段。每个输出可由一项或多项资料承载，包含足够的定位、来源及状态信息；具体格式和拆分粒度由示例及后续接口设计确定。

| 模块 | 职责和边界 | 输入 | 输出与基础数据 | 关联 |
| --- | --- | --- | --- | --- |
| 历史设定 | 故事开始之前发生的历史，包含公开叙述与隐藏真相；不把未来规划当成既成历史。 | 世界基础、用户要求、已有历史和人物等资料。 | 事件、时间或顺序、经过、原因、影响、公开说法与真相的区分，允许时间和细节待定。 | 引用地点、组织、人物；由初始局势引用历史影响。 |
| 初始局势 | 故事开始时的整体处境与正在发生的情况；不替代未来事件规划。 | 历史、世界基础、地区、组织和人物的当前资料。 | 起始时间或参考时点、局势、关系、矛盾、危机及正在发生的事件，按需保留未定项。 | 引用历史、地点、组织和人物，并为未来规划提供起点。 |
| 宏观发展蓝图 | 规划重大变化、事件条件和可能影响，不提前锁死具体行动与结局。 | 创作方向、初始局势、历史和相关资料。 | 发展方向、重大事件构想、先后关系、条件、影响及确定程度。 | 引用初始局势和其他内容；供故事线关联，不重复维护完整故事线。 |
| 故事线组织 | 维护持续发展的叙事线路及其关联，不将故事线等同于重大事件清单；角色成长内容由角色成长线维护。成长线为后续导演安排相关故事提供引导，不替角色决定具体行动或实际成长结果。 | 创作方向、宏观蓝图、角色及相关资料。 | 核心故事线、角色成长线及其长期或阶段性发展内容、方向、分支与合流。 | 引用人物、组织和事件构想；成长蓝图关联角色成长线。关联不是实际事件已发生的证明。 |
| 人物成长蓝图 | 规划重要人物可能的变化和阶段性方向，为安排相关故事提供创作参考，不代替角色当前设定或决定未来选择。 | 人物当前资料、相关关系、世界背景、创作方向及角色成长线。 | 角色长期和阶段成长规划的组织与关联；成长目标、认知和价值变化、可能经历、关系变化与可选终态的规划内容由成长线维护，不等于实际结果。 | 关联角色及其成长线；蓝图如何组织规划和成长线待结合示例确认。 |
| 世界基础信息 | 建立世界的整体概念、基本构成、文明和时代背景；不取代具体地图、组织或角色。 | 用户构想、约束与已有世界资料。 | 世界名称、整体概念、时代与文明背景、核心特征等按需表达。 | 为其他模块提供上下文；专有内容引用对应扩展模块。 |
| 地图与空间 | 表达地点、空间层级、包含和空间关联，不要求一开始画完整地图。 | 用户对空间的要求、世界基础与已有地点。 | 地点身份和描述、层级、空间关系、距离或通行信息；按需提供坐标与尺度。 | 历史、局势、组织和人物引用地点；地图不维护其完整资料。 |
| 组织 | 维护组织自身的背景、目标、结构、资源及组织关系，适用于宗门、国家、公司等。 | 世界背景、历史、地点和相关人物资料。 | 组织资料、成员或岗位线索、控制区域、内部派系及组织间关系。 | 引用历史、地点和人物；成员角色正文仍归人物模块。 |
| 人物与关系 | 维护人物当前身份、经历、性格、目标及人物关系，不把未来变化写成当前事实。 | 世界背景、历史、组织、地点、用户约束及近期需求。 | 人物资料和关系描述；重要角色按需深入，不要求统一填满全部字段。 | 引用组织、地点、历史；成长规划归人物成长蓝图。复用现有角色创建能力。 |
| 世界专有模块 | 承载特定世界需要的专有内容，如修炼或科技体系，不预设所有世界相同。 | 用户要求、世界基础及其他相关资料。 | 每个世界按需定义的专有主题、内容和必要关联；具体数据结构可因主题不同而异。 | 引用世界基础、历史、地点等；不因题材名称自动创建模块。 |

## 内容模型与关联（建议，待确认）

1. **资料项与范围。** 每项具有稳定标识、所属世界、内容归属、正文、来源与状态；名称可重复，引用使用标识而非名称。用户确认宏观发展蓝图、故事线和人物成长蓝图归属于世界，同一世界可服务多部小说。类型、具体字段及持久化格式暂不锁定；格式中的可机读字段仅覆盖真实需要校验的身份、版本、关系与状态。
2. **来源与状态。** 区分用户明确要求、已有资料和 Agent 建议；区分待审、已确认、未来规划及明确留白，但不预先把这些不同维度压成一个枚举。引用可携带来源版本；无法核实时标注范围，不能把摘要或会话当作权威正文。
3. **关系。** 关系记录应说明起点、终点和含义；例如组织成员、地点包含、历史事件影响局势。方向性、时间范围和多种关系按实际语义确定，不因存在引用就推断完整的影响分析或双向关系。
4. **层级与动态扩展。** 地点可表示包含和空间关联，避免假设所有关系都是单一行政树。世界专有模块以世界内的主题标识和内容项组织，允许按需增加、修改主题；具体 Schema 或自由正文由主题的实际验证需求决定。扩展主题不是新增顶层模块，也不能借主题名称获得权限。
5. **修改与确认。** 以当前资料和单独的待审建议区分讨论成果；保存、目录登记或 Agent 回复均不触发确认。用户审阅、影响检查与提交分别属于后续阶段；现有角色待审修改只能证明角色领域当前能力，不能推广为所有模块已具备同等能力。

## Cordis 与子 Agent 组织（建议，待确认）

内容归属、Agent 职责和存储权限分开设计：主 Agent 负责识别重点和整合；专用 Agent 在确有独立职责、工具或持续身份需要时使用。每个专用 Agent 可独立运行，也可作为子 Agent；可信应用决定世界、身份、Session、读写目录和工具，模型只提供任务和必要背景。工具按已配置的能力暴露，不因为内容模块存在就默认装配。沿用现有 Preset、SystemPrompt、Tools 和持久子 Agent 扩展点；不把十模块业务知识放入通用 Harness。

建议的第一批职责划分如下；这是待确认的设计，不代表对应 Agent 已实现，也不强制每次委派。

| 负责者 | 负责的内容 | 输出与协作边界 |
| --- | --- | --- |
| 主 Agent | 世界基础信息与初始局势的整体整合。 | 根据其他资料形成整体建议，需要专门分析时可委派；不自行冒充其他负责人的成果已核实。 |
| 历史设定 Agent | 历史设定。 | 维护历史建议，引用人物、组织和地点，并说明历史对初始局势的影响线索。 |
| 地图与空间 Agent | 地图与空间。 | 维护地点及空间关联建议，提供其他内容可引用的地点线索。 |
| 组织 Agent | 组织。 | 维护组织及组织关系建议；成员人物的正文仍归人物与关系。 |
| 角色创建 Agent | 人物与关系。 | 复用现有职责和角色资料工具；人物成长线及蓝图不自动写入当前人物事实。 |
| 世界发展规划 Agent | 宏观发展蓝图、故事线组织及人物成长蓝图。 | 分别维护三类内容的边界；角色成长内容归成长线，蓝图的组织职责仍待确认。未来若确有独立演进或工具需求，再考虑拆分。 |
| 世界专有内容 Agent | 世界专有模块。 | 根据实际主题执行任务；是否采用单一通用职责或针对主题装配专用 Agent，需以具体世界验证，不能由模型通过主题名称获得权限。 |

实施时先选一个尚未实现的职责，验证输入、资料读取、成果保存、可信身份和可恢复会话，再逐项增加；本表不表示要一次创建所有 Agent，也不规定所有世界都必须启用它们。

专用 Agent 在授权范围内读取原文、维护自己的建议并返回可核实线索；跨模块内容通过读取与引用协作，不直接修改其他负责人的成果或已确认资料。失败、取消和重新运行要保留已有成果；主 Agent 可恢复会话并核查工具结果，不假定 Session 自动恢复世界状态。现有目录、角色工具和共享读取能复用的部分以实际接口为准；缺少的角色以外的存储和写入权限须在各模块实现前单独设计。

## 边界示例

三百年前两组织发生战争：战争记录归历史设定，地点和组织使用引用；故事开始时双方仍敌对的状态归初始局势，引用该历史。未来可能爆发新战争归宏观发展蓝图；有关两组织冲突如何持续展开的叙事线归故事线组织。一个人物目前谨慎且自私归人物与关系；其可能学会承担责任的方向由角色成长线维护，人物成长蓝图关联该成长线。后续导演可据此安排需要角色作出选择的故事，但角色实际如何选择、是否发生这种变化，由角色在故事中的认知和行动决定；实际结果可以偏离规划。以上内容即使互相关联，也不能因为引用或生成就成为已确认事实。

### 两种世界构想走查

以下是讨论用的虚构构想与建议规划重点，不是题材模板或必须生成的内容。细化、概况、留白和暂不使用均针对本例，实际世界由用户构想和主 Agent 判断。

| 模块 | 开放式修仙世界：法无好坏，世界不围绕单一主角 | 资源有限的城邦群：水源紧张，各城利益不同 |
| --- | --- | --- |
| 历史设定 | 概述影响宗门格局的旧事，隐秘历史可明确留白。 | 细化争夺水源的旧战争及其影响。 |
| 初始局势 | 细化宗门、散修和资源之间的矛盾。 | 细化供水紧张、城邦关系和当前危机。 |
| 宏观发展蓝图 | 概述灵脉变化可能带来的不同方向。 | 规划缺水可能引发的合作或冲突，结果留待发展。 |
| 故事线组织 | 按需构思宗门利益与散修探索等持续线索。 | 重点构思资源分配与城邦协商的持续线索。 |
| 人物成长蓝图 | 按重要人物的规划需要组织；与成长线的分工待确认。 | 按重要人物的规划需要组织；不预定角色实际选择。 |
| 世界基础信息 | 概述世界性质、文明背景和创作方向。 | 概述城邦社会、资源约束和时代背景。 |
| 地图与空间 | 细化重点地区，远方可只有概况或明确留白。 | 重点描述城邦、水源与交通的关系。 |
| 组织 | 按需细化宗门及其他势力。 | 重点细化城邦及其联盟。 |
| 人物与关系 | 按需深入重要人物及其各自目标，其他人物可概述。 | 按近期需要设计水源管理者、城邦代表等人物。 |
| 世界专有模块 | 可深入设计修炼体系。 | 可按需要设计水利或运输体系；本例也可暂不单列专有主题。 |

例如，灵脉衰竭曾导致宗门迁徙属于历史；迁徙后的宗门目前争夺资源属于初始局势；灵脉未来可能进一步衰竭属于宏观发展蓝图。城邦旧战争、目前的水源争议和未来可能的合作同样分别归属历史、初始局势和发展蓝图。地点、组织和人物的完整资料由各自内容负责，其他内容引用其资料并保留必要上下文；相关资料尚不存在时保留未定线索，不把引用当作已经实现的关联服务。

## 待用户确认的业务边界

1. 用户已确认宏观发展蓝图、故事线和人物成长蓝图均归属于世界；角色成长内容由成长线维护，供后续导演安排相关故事以引导角色发展，角色在具体故事中的实际发展由角色自身决定。以水源管理者可能从维护本城利益转向考虑多城合作为例，建议成长线维护个人成长方向和可能的阶段、转折；成长蓝图规划多个人物的成长重点、呼应或张力及暂不规划的范围，并引用各成长线。蓝图的独立职责仍待用户确认；本阶段不实现导演安排或角色自主行动。
2. 十个模块是否作为可用的内容职责分类，而每个世界可按需要留空或不使用某些分类？例如城邦群可以暂不单列专有主题；建议按构想选择细化、概况、明确留白或暂不使用，缺少文件本身不表示用户决定留白。具体采用规则待确认。
3. 历史真相和人物秘密的读取范围如何区分？例如公开记录称水源枯竭是天灾，另一资料记载人为破坏。建议在有权访问的世界资料中区分公开说法与真相，不预设所有角色 Agent 可读取全局真相；现有共享读取是工作区范围，细粒度角色认知和授权另行设计。该方案待确认。
4. 组织成员关系及角色关系的权威归属和双向展示如何管理？例如人物既是宗门长老，又秘密属于另一个组织。建议成员关系只维护一份权威关联，组织与人物两侧按授权读取或展示；谁能提出和确认修改、秘密关系的权限与一致性规则需在具体模块设计时确认。该方案不表示现有代码已有关系服务。

## 建议开发顺序

先确认上述业务边界和两个不同世界构想中的资料归属，再确定最小内容模型及引用方案；随后逐个设计专用 Agent 的输入、输出、身份、可用工具、保存与待审边界，并以单个有代表性的模块验证现有扩展点。逐项实现前确定相应数据格式版本、用户资料保留和错误处理；按需扩展，最后再进入局部讨论与待审修改。此阶段不实现故事级工作流、世界运行或角色自主行动。
