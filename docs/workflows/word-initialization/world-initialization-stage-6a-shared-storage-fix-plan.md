# 第 6A 阶段：跨模块存储共享修复计划

本文细化[跨模块整合与交付计划](world-initialization-stage-6a-integration-delivery-plan.md)第二步，解决同一世界的专用 Agent 维护资料时，其他 Agent 无法可靠使用结构化查询的问题。本文为开发计划，所列代码布局和接口是实施方向，不表示已经实现。

## 问题与目标

地图、组织、历史、初始局势、世界发展规划和世界专有内容存储按世界或目录进行进程内独占，不区分只读和读写实例。人物资料根及人物关系存储也分别独占，但接口和一致性规则不同。专用 Agent 创建时自行打开所属存储并负责关闭；其他 Agent 的 `references` 由可信应用提供已打开句柄。若应用为引用长期持有地图句柄，再委派地图 Agent，后者重复打开地图存储会失败。地图的只读 / 只读、只读 / 读写、读写 / 只读和读写 / 读写组合均已通过复现测试确认；其他模块的相同占用规则以源码核对为依据，须在实施时验证。

修复目标是：同一个世界内，每类实际需要的结构化存储由可信应用统一管理一个实例；所属专用 Agent 能通过授权工具维护资料，其他 Agent 能同时发起只读查询。实例已有的队列可继续串行执行读取和写入；同时发起查询不要求底层并行读取。主 Agent 根据世界构想按需委派，不强制生成模块或改变生成顺序。

## 范围和业务边界

- 首先完成地图写入与组织、人物查询的纵向样例，再按相同的所有权原则接入其余有实际跨模块引用的存储；人物资料和人物关系沿各自既有接口适配，不假定它们与地图接口相同。
- 组织、历史、局势、发展规划和专有内容维持各自的业务规则、文件格式和引用校验；世界基础信息与主总览仍沿现有文件机制处理。专有内容当前没有其他专用 Agent 对它的结构化引用配置，验证其自身装配与关闭，不为此额外发明引用需求。
- 独立专用 Agent 仍可独立运行。世界入口使用共享所有者时借用存储；独立入口没有提供共享所有者时由自身打开并关闭。两种模式不得同时各自打开同一存储，不允许 Agent 关闭外部拥有的句柄。
- 应用明确 `singleWriterProcess: true`；进程内占用不是跨进程锁。共享只保证已有实例内的执行顺序和既有单文件检查，不宣称跨模块事务、跨文件原子快照或系统级隔离。
- 模型不能选择世界、存储路径、负责人或权限。初始化规划者的读取范围不等于故事角色的知识范围。
- 不修改持久化数据格式；若实施中发现格式必须变化，先确定版本及迁移或拒绝读取策略，保留原数据，再调整计划。

## 预期代码布局

| 位置 | 计划职责 |
| --- | --- |
| [`src/app/agents/world-initialization.ts`](../../../src/app/agents/world-initialization.ts) | 世界入口创建可信共享所有者，按世界配置连接专用 Agent；主 Agent 关闭时先结束子运行，再释放共享资源与目录服务。 |
| `src/world-init/storage/`（计划新增） | 世界资料共享存储装配：管理同一世界按需获取、去重打开、失败回滚及统一关闭；从已校验的世界和负责人目录构造存储，明确底层文件后端归属。该目录不放 Agent 定义。 |
| [`src/app/agents/`](../../../src/app/agents/) 各专用 Agent 入口及 `*-references.ts` | 在可信装配中区分自有与借用存储；保留世界、负责人和目录核验，将已有只读工具或引用解析器绑定到正确实例。独立入口的创建和释放契约同步验证。 |
| [`src/agents/plugins/`](../../../src/agents/plugins/) 各业务插件 | 保留数据格式、业务规则、存储和工具定义。仅在现有公开接口不足时做最小修改；不将 Agent 专用工具拆到插件外，也不删除防止不安全重复写入的占用检查。 |
| [`src/app/tests/`](../../../src/app/tests/) | 覆盖真实工作区、主子 Agent、共享存储、引用权限和生命周期；测试使用固定模型替身验证执行路径。 |
| [`src/agents/tests/`](../../../src/agents/tests/) | 若业务插件接口或底层行为变化，在所属测试中覆盖实际读写、错误和拒绝路径。 |
| [`src/app/README.md`](../../../src/app/README.md)、[`docs/architecture.md`](../../architecture.md) 及相关插件 README | 实现后记录实际装配、生命周期、授权和限制；涉及新的源码路径时同步根目录 `AGENTS.md` 与源码目录说明。 |

共享所有者放在 `src/world-init/` 下的独立目录，由可信应用创建并持有；`src/app/agents/` 只保留 Agent 创建与装配入口，不把跨模块存储管理器放入其中，也不把跨模块装配逻辑放入地图等单一业务插件。该能力可以供后续其他流程复用，但本次只实现初始化所需行为；各业务存储是否支持世界演化仍需各自设计。可参考已有目录服务的世界级持有与身份绑定模式，但不要求复制其实现或构造没有实际用途的通用框架。

计划从 `src/world-init/storage/` 的管理入口开始，负责共享存储的获取和关闭；地图、人物、组织等存储的装配适配代码根据实际职责和代码量拆分到该目录内。不要提前建立无实际用途的空文件。各业务存储及工具仍由所属插件维护，Agent 入口仅接收可信应用提供的能力。

## 可信装配与权限

1. 可信应用先校验世界和 Agent 身份，从配置取得各负责人根目录及必需子目录；共享所有者的键必须区分世界、业务类型和可信负责人，不能用模型输入构造目录或身份。
2. 对需要读写的业务存储，每个世界的共享所有者只创建一个实例。同一存储的并发首次获取必须合并或安全拒绝，不能并发打开两个实例；创建失败时不留下一个被当成可用的半成品。
3. 所属 Agent 获得它本来就拥有的写工具；其他 Agent 只获得有实际需要的只读工具或只读查询函数。不能将共享存储的写方法、关闭方法或可变授权直接暴露给模型。可信应用内部即使持有读写实例，也必须为每个消费者注册受限工具。
4. 引用解析器继续检查同世界、目标负责人和根目录，保留已验证、目标不存在、引用能力未配置、无权及读取失败之间的区别。未配置其他 Agent 不自动创建目标资料，也不编造引用 ID。
5. 显式外部 `references` 与世界入口自动共享的关系须在实现前明确：优先避免同一目标存在两个所有者或覆盖调用方配置；不兼容配置应尽早拒绝并说明原因。独立入口原有外部借用模式及调用方关闭责任需保持明确。
6. 按需打开是资源装配策略，不是固定世界规划顺序。解析器需要其他存储时应避免在持有队列或启动锁期间反向等待自身；实现时列出跨模块依赖和获取顺序，并以有界测试覆盖循环等待风险。

## 生命周期与失败处理

共享所有者区分正在打开、可用、关闭中、已关闭和失败状态；这是内部资源状态，不引入新的持久化业务状态。可用存储、底层文件后端和目录绑定的归属必须明确。

- **创建与取消：** 并发获取同一目标时只建立一个实例；打开中取消某个等待方不能关闭仍被其他使用方需要的实例。部分初始化失败时释放已创建资源，保留原始错误；回滚失败同时报告清理错误，不宣称资源已释放。
- **子 Agent 结束：** 先停止并等待其运行和工具调用，释放其 Agent / Session / 目录绑定；借用的共享存储继续有效。独立 Agent 自有存储仍由该入口关闭。
- **主 Agent 结束：** 禁止新的借用，取消并等待所有子任务及已受理的读取或写入，再按依赖关系关闭共享存储、文件后端和目录服务，最后释放世界 / Agent 身份。重复关闭应返回同一次关闭结果；清理失败时保留必要占用并报告，不绕过错误重开。
- **结果不确定：** 保留各存储已有的提交结果不确定语义和目标路径；恢复同一 Session 时先核查实际文件与目录，不自动重复创建或覆盖。
- **循环依赖：** 写入中执行跨模块引用可能调用另一存储，人物与组织也存在相互查询需求。不得在共享所有者的全局锁内等待业务操作，也不得让持有单实例队列的操作通过引用回到自身队列；按实际调用链验证，必要时限制获取顺序或调整调用边界。

## 场景与验收

| 场景 | 验收结果 |
| --- | --- |
| 地图、组织、人物联合 | 地图 Agent 创建地点后，组织和人物可用真实 ID 查询；它们不暴露地图写工具，地图 Agent 可再次运行并修改地图，不出现重复打开错误。 |
| 多查询者与读写交错 | 多个 Agent 同时发起查询均有结果；同一实例的读写顺序和版本冲突遵循存储契约，不返回半写入文档；不声称跨文件快照。 |
| 未配置、缺失和错误 | 没有配置对应负责人、目标不存在、无权、文件损坏或版本未知分别反馈；未提供引用时不将其伪装成已核验。 |
| 生命周期 | 并发首次获取、单次子 Agent 结束后继续查询、取消 / 打开失败 / 部分回滚、主 Agent 关闭、重复关闭及关闭后重建均有确定结果；另一个仍使用共享实例的 Agent 不被提前关闭。 |
| 身份和隔离 | 其他世界、错误负责人或目录、未授权写入均被拒绝；相同 Agent 身份并发占用仍受控。 |
| 已有独立入口 | 各专用 Agent 单独运行、释放后恢复 Session 和原有显式引用模式不回归；外部所有者及 Agent 不重复关闭同一实例。 |
| 其余模块 | 依次覆盖组织、人物及关系、历史、局势、发展规划的代表性跨模块引用；专有内容自身按需装配并释放。不同业务模块的格式和单写入约束保留。 |
| 实际文件和目录 | 查询以真实文件及返回 ID 为准；目录与正文状态分别核查，保存或目录登记不代表用户确认。 |

## 分步实施与提交

1. **固定复现与契约。** 保留地图四种访问组合和外部引用阻止地图 Agent 启动的复现，补充共享所有者需要满足的行为与实际跨模块依赖。检查现有未提交测试后再修改，不覆盖用户工作。完成聚焦测试并单独提交。
2. **地图纵向修复。** 在 `src/world-init/storage/` 建立最小的世界级共享和借用机制，由可信应用持有并接入地图 Agent、组织和人物只读能力；覆盖真实 ID 查询、同实例读写、独立入口、权限、并发获取与释放。更新相关接口说明和决策记录，验证后单独提交。
3. **扩展其他业务存储。** 依据真实依赖接入组织、人物资料和人物关系、历史、局势、世界发展规划和世界专有内容；逐项保持现有业务校验与独立入口。按可独立验证的模块组拆分提交，每组完成并通过相应检查后提交，不为了凑一次提交跨越未验证的中间状态。
4. **失败、取消和多世界验证。** 覆盖共享资源的并发获取、初始化失败回滚、取消与关闭竞态、资源清理失败、不同世界隔离、同身份占用以及恢复会话。验证实际引用调用链不会因锁或队列相互等待而挂起；完成后单独提交。
5. **整合验证与交付。** 运行受影响的应用和插件聚焦测试、类型检查、构建与文档链接 / Git 空白检查；检查现有真实模型配置后按需开展真实模型样例，缺少配置或失败须如实报告。更新架构、应用说明、源码目录登记和 Agent Note，整理未覆盖限制，完成后单独提交。固定模型替身不证明模型的规划质量。

本修复完成后回到[跨模块整合与交付计划](world-initialization-stage-6a-integration-delivery-plan.md)的后续步骤；本文件不替代第一版方案完整性、失败恢复、双世界端到端及真实模型的阶段验收。
