# 世界基础信息专用 Agent 开发计划

本计划细化[内容模块逐项开发计划](world-initialization-stage-6a-content-modules-plan.md#1-世界基础信息)的首个模块。计划中的新增入口和工具均为待实施方案；两个世界样例和未决业务问题见[内容模块讨论稿](world-initialization-stage-6a-content-modules-design.md#边界示例)。

## 目标与职责

单独建立世界基础信息专用 Agent，负责根据用户构想及授权资料开发世界的整体概念、基本构成、文明与时代背景等基础信息。它可由可信应用独立运行，也可接受主 Agent 委派。不同世界的内容和详略可以不同；世界名称等候选内容不是强制字段，允许明确留白。

主 Agent 对用户确定的十个模块负责协调和整合，不负责开发这些模块的信息；对十个模块之外、用户尚未想到但世界实际需要的内容，主 Agent 仍要主动补充。本文只规划基础信息专用 Agent，不要求修改主 Agent 模块。将来接入协作时，主 Agent 可以引用、概述和核对专用 Agent 的成果，不把自己的总结当作该模块的独立正文，也不以自行补写代替缺失的模块成果。

修炼规则或水利体系的深入内容按需要归世界专有模块；基础信息可以概述世界整体特征并引用相关成果，不替代地图、组织或人物的完整资料。具体引用形式和基础信息与专有内容的边界仍需结合实际成果确定，不将十个模块之外的补充自动视为新的顶层模块。

## 现有能力与待开发部分

- [世界入口](../../../src/app/agents/world-initialization.ts)可配置共享读取、主 Agent 草稿目录、角色创建 Agent、可选目录与 Session；生产装配的专用子 Agent 当前是角色创建。基础信息专用 Agent 尚无独立入口或委派工具。
- [角色创建入口](../../../src/app/agents/character-creator.ts)及[角色创建委派工具](../../../src/tools/character/delegate-character-creator.ts)可作为可信身份、独立 Session、持久委派和释放的参考。角色资料格式及工具服务于角色，不直接作为基础信息契约。
- [资料目录与共享读取](../../../src/world-init/README.md)可按世界和负责人登记文件并读取已登记成果正文；目录简介是导航线索，目录可以不装配，也不提供跨文件快照。现有草稿文件与独立总览保存能力不等于已有基础信息专用存储。
- 当前[主 Agent 提示词](../../../src/agents/world-initialization-main-agent/plugins/system-prompt/plugin.ts)包含自行规划内容的指引。本文只记录与目标分工的差异，不在本步改变主 Agent 模块；协作接入范围按后续明确指示处理。

## 输入、成果与权限

| 项目 | 方案 |
| --- | --- |
| 任务输入 | 用户构想、明确要求、必要的理解结果和任务目标，以及授权资料线索。受托 Agent 不继承父会话，委派方提供足够背景；缺少关键背景时说明不足。 |
| 可信装配 | 应用确定世界、稳定 Agent 身份、专属写入目录、共享读取范围、Session 和可选目录绑定。模型提供任务及背景，不能通过任务参数选择或扩大权限。 |
| 资料读取 | 按需要读取授权范围内的正文；目录简介只用于定位。分别说明未登记、未找到、无权、内容过期、读取失败和资料中明确的留白，不以缺少某模块成果推断世界不存在该内容。 |
| 结果 | 形成可审阅的基础信息建议，返回成果的可核对线索、来源、待定内容、发现的矛盾和未覆盖范围。区分用户要求、已有资料和 Agent 建议；保存、登记或返回均不等于用户确认。 |
| 写入归属 | 仅维护本 Agent 负责的成果；不直接改写其他负责人的资料或已确认资料。授权调用方可读取正文并引用，目录未配置时不能宣称已登记。 |
| 再次生成 | 创建独立成果，保留旧成果；结果不确定时先检查实际文件和目录，再决定是否重试。局部讨论、确认提交和完整影响检查属于后续阶段。 |

建议以专属目录内的文本成果和现有文件能力建立最小链路，不预建十模块统一对象存储。底层文件服务已有 `createIfAbsent`，但通用 `write` 工具可创建或替换，不能单靠它保证不覆盖；保存成果时需显式使用前者。若新增可机器解析的持久化格式，先确定版本、旧数据保留及未知版本拒绝或迁移策略；不擅自改变角色、目录或 Session 格式。

### 第一步：最小成果契约（实施建议）

以下方案用于后续实现，不把未实现的接口当成现有能力，也不预先规定所有世界相同的内容章节。独立入口与受托入口使用同一成果契约。

1. **内容。** 每次成果是一个可独立审阅的 UTF-8 Markdown 文本文件，明确标为基础信息建议；按构想组织世界整体概念及必要的文明、时代或其他背景。只写有助于理解本世界的内容；未提供世界名称或时代时不要求虚构字段。区分用户明确要求、基于已有资料的内容、Agent 补充建议、明确留白和无法判断的内容；未来方向不写成已发生事实。
2. **来源。** 能定位的已有文件以世界内授权相对路径引用，并在可取得时记录所依据的目录记录版本或正文摘要；不能取得版本时明确说明，不能伪造稳定版本。用户直接提供但没有资料路径的要求标明来自用户输入，不虚构文件或将整个 Session 当作世界事实。明确说明尚未读取、不可访问或无法核实的来源。
3. **保存。** 建议由专用受控保存工具在可信装配的专属目录内为每次成果生成独立名称，以底层 `createIfAbsent` 写入；文件已存在时拒绝覆盖，具体名称不作为业务身份或用户提供的权限。普通文本正文无需新增机器解析的持久化 Schema；若实施时引入有版本的结构化元数据，先确定版本和旧数据策略。工具将实际世界内相对路径返回调用方。
4. **读取与引用。** 目录已配置且成果已登记时，使用记录定位并读取实际正文；目录共享读取返回记录 revision、正文摘要和 `current` / `stale`，调用方记录实际依据，过期不自动等于内容无效或已确认。目录未配置或未登记时，按授权范围使用返回的实际相对路径读取；路径只在对应世界及授权视图内有意义，不是路径无关标识。目录简介不能替代正文；单次摘要或版本不构成跨文件快照。
5. **结果和恢复。** 保存成功返回路径及成功状态；发布结果不确定时返回可核查路径和不确定状态，先检查实际文件再决定后续操作。文件保存与可选目录登记分别报告；登记结果不确定时核查目录记录。读取失败、无权、无记录和明确留白各自报告，不用缺失代替留白，也不把 Session 或成功回复当作成果存在的证明。

以下片段仅说明内容及来源如何辨认，不是固定模板、机器 Schema 或已保存的成果：

- **修仙世界。** 用户要求：力量本身无善恶，世界不围绕单一主角。Agent 建议：不同修行群体对力量使用形成不同社会规范。留白：远方地区尚未展开；修炼机制的深入规则另待设计。
- **城邦群。** 用户要求：多个城邦的资源有限。已有资料：读取授权范围内的水源概况并引用其实际路径及可获得的版本线索。Agent 建议：城邦之间可能形成不同的供水协作方式。明确留白：外海暂不设定。

**核对依据。** [受控草稿文件系统](../../../src/app/agents/world-initialization-draft-fs.ts)限制修改根，[通用写入工具](../../../src/agents/plugins/fs/tool-fs/mutation.ts)允许创建或完整替换；[总览保存工具](../../../src/app/agents/world-initialization.ts)使用 `createIfAbsent` 并在结果不确定时返回核查路径。[总览文件测试](../../../src/app/tests/world-initialization-files-e2e.test.ts)覆盖独立文件和结果不确定；[持久委派测试](../../../src/app/tests/world-initialization-persistent-delegation.test.ts)及[工作区生命周期测试](../../../src/app/tests/world-workspace-lifecycle.test.ts)覆盖已有角色委派、会话恢复、取消和身份占用的部分路径。它们是可复用能力的证据，不是基础信息 Agent 已实现或已通过测试的证据。

## 场景走查

| 场景 | 输入和已有资料 | 期望结果 |
| --- | --- | --- |
| 开放式修仙世界 | 用户要求力量本身无善恶、世界不围绕单一主角；无既有资料。 | 给出世界概念和文明背景建议，标明用户要求与新增建议；修炼体系细节可留待专有内容，未确定区域明确留白。 |
| 资源有限的城邦群 | 用户要求多个城邦资源有限；有一份授权水源概况，外海明确留白。 | 重点描述城邦社会及资源约束，引用实际水源正文，保留外海留白；与修仙世界的重点和详略不同。 |
| 读取与复用 | 已有基础信息建议，另一获授权任务需要背景；目录可能未装配。 | 调用方可依据实际路径或目录线索读取成果正文并保留来源；目录简介不替代正文，不将建议视为已确认。 |
| 再次生成和失败 | 目录内已有成果，保存或登记失败、结果不确定。 | 新成果不覆盖旧成果；分别报告文件和登记状态，不确定时核实后再继续，保留已完成内容。 |
| 权限和中断 | 尝试跨世界或跨负责人写入，或在运行中取消。 | 越权操作被拒绝；取消传播并等待释放，已完成写入不假定回滚；恢复时核查实际成果。 |

## 装配与执行方案

1. 可信调用方校验世界配置、目录及身份，取得进程内身份占用；装配 Preset、专有 SystemPrompt、LLM、Tools、Session、授权读取与专属写入能力，以及可选目录绑定。
2. 独立入口接收任务和背景；受托入口使用现有持久子 Agent 扩展点提供相同职责。委派工具只接收任务内容，固定使用可信应用装配的世界、身份、Session 和目录，不让模型授予权限。
3. Agent 按需读取授权资料，提出来源可辨的基础信息建议，以可靠不覆盖方式保存成果；可选登记时使用本人目录绑定。返回成果线索、留白、矛盾与失败信息。
4. 调用方按实际权限核对正文及状态。文件保存成功而目录登记失败时分别报告；读取受限、过期或缺失时说明范围，不把摘要或成功回复当作正文及确认。
5. 调用取消信号传递给子运行，完成后等待释放；启动失败回滚已取得资源，执行和清理同时失败时保留两者。Session 只恢复会话历史，恢复后仍须检查实际成果。身份占用及单可信写入进程边界沿用现有约定，不声称跨进程锁或系统级隔离。

## 开发步骤

1. **核对契约。** 复核现有工作区、文件工具、持久委派及相关测试；以两个样例确定本模块成果的最小内容、来源和引用方式。模块可选程度等未决业务问题保持待确认，不用假设替代用户决定。
2. **专用职责。** 创建基础信息专用 Preset 与 SystemPrompt，表达世界整体背景、输入来源、留白和模块边界；不固定题材字段，不让建议冒充事实。必要时按实际新增目录更新项目结构说明。
3. **独立应用装配。** 复用现有应用与工作区机制，装配独立身份、Session、受限读写及可选资料目录；核验创建不覆盖的保证，确定保存失败及不确定结果的处理。必要的新持久化格式先明确版本和数据保留。
4. **受托能力。** 复用持久 Provider 设计专用委派工具与可信绑定，验证任务参数、身份、取消及资源释放；本计划不要求调整主 Agent 模块，实际接入主 Agent 的范围按后续指示确定。
5. **验证和文档。** 测试独立运行及受托运行，核对实际文件、读取和可选登记；覆盖未配置、越权、身份占用、取消、保存失败、结果不确定、重建和不同世界隔离。同步专用入口和模块说明、必要架构说明及工程决定记录。

## 验收

- 两个世界通过专用 Agent 形成重点不同、来源可辨的待审基础信息，保留明确留白，生成或保存不确认事实。
- 可信应用可独立运行专用 Agent，也可通过受托入口使用同一职责；模型任务不能选择世界、身份、Session 或写入权限。
- 获授权调用方能读取实际成果，重复生成不覆盖旧成果；缺失、越权、失败与结果不确定能区分并保留已有数据。
- 固定模型替身配合真实工具验证执行路径、文件和生命周期；它不证明真实模型规划质量。真实模型验证和跨平台结果按实际情况报告。
- 完成并验收本模块后等待用户指示，再进入下一模块；不实现完整世界初始化工作流或其他模块。
