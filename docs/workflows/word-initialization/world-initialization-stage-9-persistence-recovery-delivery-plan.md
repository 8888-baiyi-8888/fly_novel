# 第 9 阶段：持久化、恢复与最终交付开发计划

本文细化[世界初始化总开发计划](world-initialization-development-plan.md#9-持久化恢复与最终交付)的第 9 阶段，承接[第 8 阶段验证与交接](world-initialization-stage-8-handoff.md)。本文是实施计划：示例、拟议状态和推荐方案不是现有接口，也不代表所有业务规则已经用户确认。实施从第一步盘点开始，涉及近期行为的业务问题结合具体例子与用户确认；工程问题依据现有约束自行处理。

## 目标与边界

1. 在可信应用重启后，重新定位世界、配置、当前方案、对话和未完成业务，展示实际可恢复状态，让用户选择继续的内容。不能仅凭 Session 恢复、目录登记或某个文件存在推断初始化任务已完成。
2. 为初始化过程和最终交付建立可核查、版本化的业务记录。保留当前正文、待审候选、检查报告、审阅、用户确认、发布结果及各自关系；不把不同对象合并为一个未经核验的完成标志。
3. 用户审阅具体版本后才能明确选择完成初始化；交付展示实际方案、已接受的局部修改、主要留白和未解决事项，能够核对引用和版本。第一版总览、局部候选或某批发布成功均不单独代表最终交付。
4. 对中断、部分发布、写入结果不确定、记录丢失或损坏、外部资料变化及旧版本，区分可以安全恢复、需要用户判断和必须阻止的情况。恢复不盲目重放有副作用的操作，不自动替用户确认或补偿。
5. 通过可信应用装配世界、身份、工作区、Session、现有业务服务及权限；主 Agent 协助解释和协调，专用 Agent 按需处理所属内容，但模型输出不能代替可信用户动作或程序核验。
6. 本阶段不实现世界演化、故事推进、导演安排或角色自主行动。交付给后续阶段的是明确版本和限制，不声称后续运行已经接通。第一版完整性、交付完整性和局部修改确认是不同判断。

## 业务样例与恢复边界

### 第一版尚未完成时中断

用户要求规划河谷世界，主 Agent 保存了总览，但地图 Agent 正在生成曲水城，组织资料尚未核查。重启后展示已保存总览、各模块可核实成果及未完成或结果未知的任务；允许用户继续检查或调整，不因为总览存在、Session 可恢复或模型曾说“完成”就进入最终交付。可信应用接收的第一版完整判断须绑定当时可核对的内容与依据；判断方式先结合样例与用户确认。

### 多目标发布中断

曲水城修改已发布，林岚候选的发布结果不确定，青云宗成员候选尚未开始。重启后逐项读取发布记录、候选状态、实际正文 / 索引和目录状态；已发布结果保留，未开始项不自动执行。人物文件与索引不一致时仅使用能匹配记录和摘要的所属模块恢复能力；无法辨别结果时保留证据并阻止自动推进。用户核查后作出的选择要绑定实际版本，剩余修改重新检查、重新审阅并取得明确确认。

### 用户审阅后资料发生变化

用户审阅最终交付清单后，新增组织成员或其他写入口修改了曲水城。即使总览和原有单个命中项未变，原有范围或版本凭据也可能失效。交付前复核实际目标、检查依赖和可重放范围；无法可靠比较、读取失败或发生变化时停止并要求重新检查或审阅。未接入的反向查询必须作为未覆盖范围呈现，不能声称世界不存在其他冲突。

### 完成动作中断或重复

用户明确选择完成，应用开始保存交付记录后进程退出；重启可能看到准备记录、结果不确定或已核实的交付。先核对同一操作标识、已记录版本和实际文件，展示真实结果；重复请求不得产生第二次业务效果或覆盖之后的修改。若无法区分是否完成，保留原记录并要求用户在核实后选择，不自动报告成功。文件系统的单文件替换、目录登记和 Session 刷新不构成跨文件事务。

## 需要先确定的业务契约

### 业务对象与版本

区分世界身份与工作区配置、初始化任务、当前正文及其版本、第一版完整判断、会话与目标绑定、候选、影响报告、审阅和选择、单项 / 批次发布记录、待解决事项及最终交付。每个对象有明确的所有者、可信创建入口、引用关系、可读取版本与失败语义；名称、目录摘要和 Session 文本不能代替业务身份。新增状态及字段先定义严格版本和读取边界，不因便利复制并维护第二份正文权威来源。

已有讨论、候选、报告、确认、发布、模块资料和 Session 文件按各自格式读取。格式变化前确定逐版本兼容矩阵，明确原地兼容、可重复验证的迁移或保留原文件并拒绝读取；迁移前核验身份、准备可恢复依据并测试中断，不静默覆盖、批量重写或删除已有数据。旧数据没有的用户确认、第一版完整性或最终交付决定不得推断或补造；未知版本、重复键、损坏和身份冲突保留证据并阻止受影响的自动写入。若引入数据库，模式版本单调递增，是否使用数据库须先根据实际恢复和维护需求决定。

### 恢复清单与结果

可信应用恢复前核验世界配置、根目录、Agent / Session 绑定和服务所有权，列出实际发现的业务记录与未能读取的范围。恢复状态至少能够分别表达可继续、需要重新检查、等待用户决定、部分完成、结果不确定和无法读取；上述名称是设计需求，不预设持久化枚举。记录应指出来源、目标、版本、关联、下一步所需动作和无法保证的范围，不以更新时间或文件名猜测先后及成功。

先确认如何发现已有单项 / 批次操作、讨论和 Session；现有按 ID 读取或已有目录不能自动等同于完整扫描。设计发现机制时处理孤立候选、缺失确认、多个记录指向同一目标、记录和正文不一致及目录分页不完整。新增索引若只是加速线索，损坏时不能覆盖正文或伪造空结果；需要重建时先定义只读核验、条件写入和保留旧文件的策略。

恢复期间继续遵守世界写入协调。检查、用户决定、实际发布和恢复记录各有明确边界；若不能保证本进程所有相关写入口参与协调，就不开放受影响的自动写入。跨进程写入、恶意进程替换、硬链接和断电保证不因本阶段增加记录而自动成立；是否扩大支持范围需另行设计和验证。

### 最终审阅与交付

最终审阅应让用户看到当前世界与范围、第一版完整性依据、实际正文或可追溯引用及版本、局部发布结果、已发现的冲突、未覆盖范围、留白、目录状态和仍需处理的事项。需要分页或按需加载时，清楚标出未加载和读取失败，不用摘要替代正文，不将未覆盖描述为已检查。

用户明确选择完成前，可信应用重新核验清单、版本、已读取依赖和可重放范围，并检查未完成发布和结果不确定项。显式选择、取消、关闭界面与无回复分别处理；模型建议和等待超时不是确认。完成动作与用户实际审阅的版本、范围、待定事项和最终决定绑定；写入中断或响应丢失按实际记录核查，不自动重复发布或承诺整体回滚。

交付物的具体表示先走查：可考虑版本化清单引用已有正文并记录摘要及来源，必要时提供用户可读的总览；清单和总览的生成方式、是否需要独立不可变副本，以及之后修改如何形成新版本，均须先结合业务和现有存储确定。交付不自动把各模块全部标记为 `confirmed`，也不将尚未开发的世界演化状态写入资料。

## 可信应用与代码归属

优先复用[世界初始化业务模块](../../../src/world-init/README.md)、[应用装配](../../../src/app/README.md)、既有 Session 持久化及各所属模块的校验 / 恢复入口。按实际职责补充业务状态、恢复编排、交付和用户交互；不要让模型拿到用户确认凭据、任意文件写句柄或能够跳过检查的提交入口。界面形态与正式入口先核对项目现有启动方式和用户需求；本计划不预设已有前端，也不新增绕过初始化、配置和授权校验的隐式入口。

明确资源的创建者、借用者和释放顺序：恢复中失败或取消时停止新操作，等待已受理工作，按已保存的实际状态保留占用与恢复依据；关闭需可重复且不删除用户资料。跨世界和多 Agent 的配置、Session 根、业务记录根及可写范围由可信应用绑定和核对。需要用户作出决定时展示具体对象及后果；后台超时、模型输出或对话恢复不构成决定。

## 分步开发与验收

第一步的现状、样例与用户同意的推荐方案见[现状盘点](world-initialization-stage-9-inventory.md)。

第二步的状态、恢复与交付规则见[业务契约](world-initialization-stage-9-contract.md)。

实现入口、可重复验证及尚未覆盖的边界见[恢复与交付验证](../../cookbook/world-initialization-delivery-validation.md)。

1. **盘点与样例决策。** 先检查 Git 状态、现有入口、数据格式、写入路径、版本凭据、恢复 API 和相关测试；用第一版未完成、多目标中断、未知版本、交付后修改及两个世界走查。列出可自动发现、只能按 ID 读取、需要用户提供和目前无法核查的对象；区分现有能力、缺口与用户尚未确认的业务规则。对影响近期实现的问题给出具体例子和建议，与用户讨论。
2. **确定状态、版本与交付契约。** 明确任务 / 第一版 / 候选 / 发布 / 交付的身份、状态转移、来源与权威位置；确定用户最终动作、未解决事项及旧数据处理策略。用样例核对第一次创建、取消、重复确认、版本失效和中断，不把计划建议作为已经确认的契约。
3. **实现可信发现与状态读取。** 依据盘点建立世界和任务的可信发现 / 打开方式，按需连接 Session 与现有业务记录，展示来源和无法读取范围；处理同名世界、孤立记录、未知版本、损坏、分页和身份冲突。发现或打开不得创建虚假完成记录、删除文件或自动恢复写入。
4. **实现初始化过程持久化。** 按已确认契约保存用户决定、第一版完整性依据及必要的任务进度，绑定实际成果版本；为旧工作区提供有证据的接入、迁移或拒绝策略。覆盖保存前后失败、重复请求、用户数据不被覆盖及重启后的状态复核。
5. **实现中断核查与恢复编排。** 对接已有单项 / 批次、人物索引和 Session 的实际恢复能力，识别已发布、未开始、候选占用和结果不确定；让用户核查并选择受支持的下一步。注入多个持久化边界的进程退出、响应丢失、后续修改和重复恢复，验证不盲目重放、不错误解锁、不伪称整体回滚。
6. **组装完整应用入口。** 以可信世界配置和显式身份装配从新建、第一版、讨论、检查、选择到恢复的统一入口及必要的用户交互；覆盖加载、成功、失败、取消、关闭和资源清理。验证模型、普通文件工具、子 Agent 和跨世界路径不能绕过用户动作与受控发布；构建产物使用声明的正式入口启动。
7. **实现最终审阅与交付。** 展示清单、正文或可追溯引用、未覆盖范围和待定事项；用户明确选择完成后，在受协调的边界复核并记录可核查交付。测试版本或范围变化、重要冲突、未完成候选、用户取消、重复完成、写入结果不确定及交付后的再次修改；按用户确认的业务规则处理，保留既有数据和实际结果。
8. **端到端验证与交接。** 使用真实临时工作区和固定模型替身覆盖两个世界及完整流程、不同中断点、部分失败、恢复和最终交付；另在获授权的隔离合成样例中验证真实模型，区分程序断言与人工审阅。运行相关测试、类型检查、正式构建及构建产物冒烟、文档链接和 Git 空白检查；对照 DeepSeek Harness 的相关 Session / 工具能力，记录适用差异、未覆盖和后续世界演化的交接边界。

每完成一步，运行与该步相关的验证并按仓库既有格式单独提交，然后继续下一步；提交本身不构成暂停。真实模型调用需遵守已有授权的具体端点和发送范围；涉及新的端点或不同数据范围时先明确授权。固定替身只证明受测路径和状态，真实模型样例不证明其他世界的生成质量。

## 需要结合示例与用户讨论的问题

- **完成与待解决事项。** 如果地图存在未覆盖的人物反向查询，或有明确的重要冲突尚未解决，用户能否在知悉后完成初始化？建议分别展示未覆盖、待定事项和重要冲突；第 8 阶段已确认的重要冲突处理规则继续有效，最终交付是否允许保留重要冲突需要用户决定。
- **活动候选。** 城门还有一份有效候选时，用户选择完成初始化：是要求先处理 / 明确放弃，还是允许保留并列入交付的待办？建议不静默放弃或提交，展示候选并让用户明确选择；最终允许哪些状态需要确认。
- **第一版完整判断。** 总览已保存但某个专用 Agent 的结果未知时，如何由可信应用取得“第一版完整”的判断并绑定成果版本？建议先提供可核对清单，由用户或可信业务流程显式作出判断；不从总览或 Session 自动推断。
- **交付形式与后续修改。** 用户完成后再次修改曲水城时，原交付保留为历史记录、创建新的待审版本，还是采用其他方式？建议保留原交付及版本引用，新修改重新经过审阅；是否需要独立正文副本、导出格式和保留周期需要用户决定。
- **不确定结果的处理。** 发布记录和当前文件不足以证明写入是否发生，且用户无法确认实际结果时如何继续？建议保持该项未解决、保留证据并阻止受影响的自动写入；是否允许用户选择人工修复或以新方案替代，须先说明后果并获得明确决定。
- **已有世界接入。** 旧世界只有部分资料和 Session，没有第一版完整判断或最终确认时，如何接入？建议先只读发现并展示缺失依据，由用户逐项补充或重新审阅，不补造历史确认；具体迁移范围与保留方式结合真实数据确定。

## 后续阶段的交接

后续世界演化或故事工作流只能接收经核查的世界身份、交付版本、可追溯正文或引用、用户确认的范围、留白和未解决事项，以及检查覆盖与访问权限限制。具体消费接口、角色认知过滤、世界状态推进和交付后修改规则由后续阶段另行设计；本阶段不把建议、未覆盖范围或 Session 叙述包装成已确定世界事实。
