# 世界初始化第 6A 阶段：人物与关系详细开发计划

本文细化[内容模块逐项开发计划的人物与关系步骤](world-initialization-stage-6a-content-modules-plan.md#4-人物与关系)。以现有角色样例和实际资料为基础，保留可复用能力；以下方案和工具名称均为待讨论的设计，不是已确认契约。世界、人物和关系服务多部小说，不按主角或单一故事预设角色行动与结局。

## 目标与边界

角色创建 Agent 根据用户构想、世界资料和近期需要，创建或完善初始化时已经存在的人物及人物间关系；角色资料记录初始化时角色自身的基础信息和已知情况。未来才建立或发生变化的关系，在未来实际出现时再处理，不提前当作初始事实。主 Agent 识别需要、协调委派和整合，不代替专用 Agent 开发本模块。重要人物按需深入，其他人物允许概况、未知和明确留白，不要求固定数量或填满字段。成果供用户整体审阅；保存、目录登记和工具成功均不等于用户确认。

人物模块负责人物自身和人与人关系。人物与组织的成员关系由[组织模块](world-initialization-stage-6a-organization-plan.md)维护，人物侧按权限查询同一条记录；组织、地图和历史各自维护自己的权威内容，人物只引用或标明未核实线索。角色成长线负责详细成长规划；人物当前目标和关系不是未来必然发生的成长结果。世界演化、角色自主行动和完整记忆工作流不在本阶段实现。

## 场景走查与关系语义

以林岚和顾青为例：初始化时林岚已是顾青的师父，顾青信任林岚；林岚属于青云宗，另有一位尚未建档的师父。另用初始化时两名城邦代表既是亲属又因取水利益竞争的例子，检查不同类型关系共存，不把职位和组织归属混同为两人之间的私人态度。若顾青未来才认识其他人物，不在初始化时预先建立那条未来关系。

同一对人物的公共关系由本模块维护一份可定位的关系文档，按两端人物检索；其中可按需记录师徒、亲属等多个关系条目，并明确各条关系的方向或对称语义。林岚是顾青的师父，只需维护一份师徒事实；从顾青一侧查询可展示其师父是林岚，不由此推断双方态度。各角色的个人感受和认知写在其现有角色资料中，例如顾青信任林岚、林岚关心顾青；认知可能与事实不一致，也不能由一人的态度自动推断另一人的态度。

公共关系文档中的已建档人物只引用角色 ID，不保存当前姓名副本；查询展示时按 ID 读取角色资料和当前姓名。同名由 ID 区分，角色改名不需要修改关系文档。角色资料正文可以从该角色视角描述关系，但公共关系事实以关系文档为准；需要核对正文一致性，现有系统没有自动同步。关联关系不意味着角色知道所有事实或有权读取对方资料。

未建档师父可作为明确线索保留，不能虚构人物 ID；后续出现同名候选时读取资料并核对，再确定是否关联。未找到、未建档、无权读取、未知和明确不存在分别表达；来源不足、历史过期或关系两端不存在时报告实际情况，不静默删除或编造结论。

## 存储、查询和安全设计

1. **人物资料。** 先评估现有 Markdown 正文、元数据、索引与需求清单是否满足角色按 ID 查找及按需展开。保留自由正文和已有文件；新增字段、分类或读取权限若影响版本 1，明确迁移、备份、回滚和未知版本拒绝策略，验证旧数据可读且不静默丢失。不要因地图或组织使用 JSON 就自动转换人物正文。
2. **关系记录。** 同一对人物使用一份公共关系文档，包含双方 ID 和按需建立的多个关系条目；已建档人物只保存 ID，姓名从角色资料读取。优先评估版本化 JSON 与现有角色根目录的受控集成；字段、文件位置、条目身份、未知语义和更新方式在契约步骤细化。未建档人物以线索表示，核实后关联实际 ID；不能用姓名充当 ID。读取和写入使用同一权威内容，索引如有则可由文件重建，不维护两份权威正文。
3. **检索和引用。** 设计按人物 ID、关系 ID、方向及关键词的查询、两端读取与分页；区分角色正文、关系、组织成员、地图地点和历史资料的负责人。关联 ID 由可信应用核验同世界与实际身份；缺少解析器、过期、不可读、同名或不存在分别报告。复用已打开的角色和地图句柄时，明确所有者、访问范围、取消与关闭顺序，不通过重复打开绕过占用。
4. **初始化已知信息。** 人物资料记录初始化时该角色自身知道的基础信息，公共关系文档记录初始化时已经存在的关系；不为未来可能认识、信任或敌对的人物提前建关系。人物之间已有关系不要求双方态度相同或自动了解对方的全部信息。用户明确提供初始化时的秘密或认知差异时如实保留，但不强制每对人物设计秘密。后续角色运行如何取得信息、维护记忆和控制完整读取范围属于后续工作；在相关授权能力建立前，不将未过滤的人物资料直接作为角色可见视图。
5. **更新和历史。** 用户确认人物资料与公共关系按[修改方式](#人物和关系的修改方式)区分初始化、已确认内容和世界演化；现有角色正文的待审候选机制须与初始化直接更新明确衔接。演化后的具体版本、触发、恢复和迁移机制须在世界运行入口实现前设计，不能以 Session 或文件版本冒充世界历史。
6. **职责与工具。** 优先复用角色创建 Agent；评估是否为人物关系增加专用插件，并按需要定义创建、读取、搜索、关系查询、版本修改、引用核验等工具。工具名称、参数及是否单独插件均待设计；模型不能指定世界、目录、身份或授权。主 Agent 通过现有专用委派提交任务，不能直接使用人物模块写工具。

## 人物和关系的修改方式

用户确认采用以下方向；这是开发要求，当前角色服务和人物关系服务尚未全部具备这些能力。

| 阶段或内容 | 人物资料 | 公共关系 |
|---|---|---|
| 初始化第一版尚在构建的未确认方案 | 读取当前版本后直接更新当前人物方案；仍为待整体审阅的方案。 | 读取当前版本后直接更新公共关系方案。 |
| 已确认内容的设定修改 | 保留当前资料，形成待审候选；确认前不替换。 | 保留当前关系，形成待审候选；确认前不替换。 |
| 世界已经向前演化后的实际变化 | 更新当前状态，同时保留变化前信息及必要的时间、事件依据。 | 更新当前关系，同时保留之前的关系状态及必要依据。 |

可信业务流程确定当前所处阶段及资料确认状态；模型不能通过工具参数自行宣布确认或绕过限制。初始化直接更新采用版本或摘要检查，过期时拒绝覆盖并重新读取；保存不等于用户确认。一个初始化世界中若存在已经确认的资料，对该资料使用待审候选，不因为其他内容尚未确认而直接覆盖。

现有 `CharacterStore.prepare` 对修改创建 `pending.md` 和基线，当前并不提供上述初始化直接更新入口；实现时须在已有版本化资料和工具基础上设计受控入口、索引一致性及失败恢复，不擅自把现存候选当作可删除草稿。遇到已有待审候选、提交中断、基线变化或未知状态时，保留文件并明确报告；具体如何继续由可信流程处理。公共关系的待审和确认能力也需另行实现，不因本计划视为已有功能。

公共关系变化可能使角色正文中的描述需要核查；正文也可能有角色自身的错误认知，不能自动判为错误或批量覆盖。分别报告人物、关系及目录登记的实际结果；跨文件操作不假设整体事务，结果不确定时先核实再继续。世界演化的历史快照、时间依据、触发及恢复机制留待对应工作流实现，不能用初始化覆盖或 Session 冒充历史留存。

## 实施前需细化的内容

人物初始化以角色当时已知的基础信息和当时已存在的关系为范围，不把未来关系预设为当前资料。用户明确提供的已有秘密和认知差异应保持原意；本阶段不预建完整的角色知识、记忆或未来关系演化机制。

人物关系文档的条目标识、未关联线索升级、查询实现和索引维护属于具体设计：基于上述方向及现有角色资料细化，避免将常规实现细节重新列为用户必须决定的问题；发现会改变业务语义的例外时，再结合实例讨论。

这些问题影响近期数据与接口，先提供具体例子和推荐方案与用户讨论；其余可由项目现状解决的技术细节不逐项打断用户。

## 开发步骤与验收

1. **核对现状与业务决策。** 复核角色文件、索引、角色创建与角色 Agent、现有测试及组织关系接口；走查初始化已有的师徒、单向信任、多重关系、同名与未建档线索，以及用户明确提供的已有认知差异。确定首版职责和验收后再实现。
2. **存储契约与兼容策略。** 明确人物及关系的权威内容、数据格式和版本、身份引用、审核与初始化修改语义；制定旧角色文件、索引和待审候选的兼容、迁移或拒绝读取方案。用真实目录验证旧数据保留、损坏及未知版本拒绝、失败恢复和同名。
3. **关系查询与工具。** 实现经确认的存储和查询，复用现有角色工具；测试双向检索、单向态度、多重关系、未关联线索、引用失效、版本冲突、取消和写入结果不确定。规划者读取和后续角色读取的授权边界须明确；角色知识、记忆与完整过滤能力不因本步骤自动成立。
4. **Agent 与跨模块装配。** 扩展角色创建 Agent 的实际职责及工具，保持独立运行和主 Agent 专用委派；明确组织成员和地图引用的只读绑定、共享服务所有权及会话恢复。验证同世界角色、组织、地图 Agent 共存、跨负责人写入拒绝、跨世界隔离及失败后释放。
5. **端到端验证。** 使用固定模型替身分别走查修仙世界和资源有限城邦群，从主 Agent 委派到实际文件、双向查询和成果核对；另行用真实模型检查工具使用及规划质量。覆盖旧数据、待审候选、目录登记与过期、引用失效、取消、恢复和结果不确定；替身不证明真实模型会遵循指引。验收后等待用户指示，不自动进入下一模块。

**验收：** 现有角色能力和数据得到保护；人物与人物关系能够按确认的语义定位、查询和修改，单向态度、未关联线索与组织成员归属明确；用户能够审阅建议及未覆盖范围。角色权限、历史留存及角色自主运行只按实际完成和验证范围报告。
