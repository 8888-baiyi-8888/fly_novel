# 历史设定：事件格式与时间契约

本文细化[历史设定详细计划](world-initialization-stage-6a-history-plan.md)第二步的数据契约。版本 1 格式与完整事件集合的图校验由[历史包](../../../src/agents/plugins/history/README.md)提供；文件存储、查询工具、候选提交及 Agent 尚未实现。历史事件资料归世界所有，保存不等于用户确认。

## 文件、身份和版本

规划每个事件一个 JSON 文件，文件名使用程序生成的事件 UUID，位于可信应用绑定的历史负责人目录内的 `events/`；子事件也是单独事件，不将同一子事件复制到多个上级文件。目录是运行时世界资料，与源码目录不同。角色、地点、组织及历史事件名称允许重复；名称不是 ID，不能因同名合并。ID 使用小写 UUID 字符串，事件 ID 与显示名称分离。

版本 1 使用严格 JSON，拒绝未知版本、额外字段、重复键、非法 ID 和损坏数据，不静默迁移或修改原文件。此前以 Markdown、人物或组织正文、目录记录保存的旧叙述仍是原资料；版本 1 不自动识别、转换、覆盖或删除。目录简介用于导航，不是事件正文或确认依据。可信应用负责单进程写入及目录保护，路径检查不提供跨进程锁或完整系统隔离。

## 事件字段

| 字段 | 版本 1 表达及含义 |
| --- | --- |
| `formatVersion`、`worldId`、`id` | 固定版本 `1`，世界身份及事件 UUID；世界由可信应用绑定，模型不能选择。 |
| `name`、`aliases` | 非空名称及可空别名数组；同名允许存在。 |
| `detailLevel` | `unexpanded`、`overview`、`detailed`；仅表示该事件自身的展开程度，不推断子事件或世界已填满。 |
| `contentStatus` | `suggested` 或 `confirmed`；表达用户审阅状态，与公开、隐藏和时间不确定分开。格式允许读取这两种状态，当前没有确认提交入口。 |
| `summary`、`body` | 概述与正文；允许空字符串，不能据此判断事件不存在或已经穷尽。 |
| `time` | 时间表达数组；空数组表示时间未提供，不代表事件没有发生；可并存多个带参考的表达，详见下文。 |
| `parents` | 由子事件维护的上级事件数组，每项含上级 `id` 和非空关系说明；可有多个上级，不得指向自身或重复同一上级。 |
| `childrenCoverage` | `unknown`、`partial`、`complete`，表示记录者对该事件子事件覆盖范围的声明；不是程序自动推断的世界事实，也不能由 `detailLevel` 推导。 |
| `relations` | 从当前事件指向目标事件的关系；`before`、`causes`、`overlaps`、`related` 分别表达先于、导致、重叠、相关，说明可为空。禁止自关联和同类型同目标重复；不能因名称或先后推断其他关系。 |
| `references` | 类型为 `person`、`place`、`organization`，已关联端点保存 ID 和说明，未关联端点保存非空线索；不保存姓名作为身份，不自动核验或关联。 |
| `publicAccounts`、`hidden`、`reserved` | 多条公开说法各含非空内容和来源说明；隐藏内容为 `known` 加非空正文，或 `unknown` 加备注；明确留白为非空文字数组。不维护角色知情名单。 |

空集合只代表文档没有记录相应条目；`childrenCoverage` 才表达记录者对直接子事件覆盖的声明。真实关联对象存在、负责人、权限和世界一致性由可信应用及后续存储核验，单文件格式校验不证明这些事实。历史 Agent 和世界规划者可读取完整内容；角色的已知信息来自自身初始化资料或后续实际经历，不靠历史文件中的角色授权等级。

## 时间表达

`time` 支持多种表达并存，每一条都保存 `original` 原文：

| `kind` | 字段与规则 |
| --- | --- |
| `text` | 只有原文；适合“某王朝末期”“大战之后”等尚不能转换的说法，不据文字自动比较或换算。 |
| `point` | 带 `basis`、`unit`、有限数值 `value` 和 `precision`；`exact` 表示精确，`approximate` 表示约略。初始化起点为零，之前为负，例如约三百年前可记 `value: -300`、`unit: "year"`、`precision: "approximate"`。约略点没有隐含误差范围。 |
| `interval` | 同样指定基准、单位及精度，`start`、`end` 可各为有限数值或 `null`；至少一端已知，两端均有值时开始不得大于结束。`null` 表示该端未知，不能视作零或无穷。 |

`basis` 为 `{"kind":"initialization"}` 或 `{"kind":"era","id":"纪年标识"}`。纪年标识是世界内由可信设计赋予的稳定标识，不能以文字自动建立或假设与其他纪年可互换。多个表达共存只表示记录者写下了这些表达，不证明它们可换算或彼此一致；比较至少需要相同基准、相同单位和足够精度，约略、未知及重叠仍需原样说明。初始化时点与其他模块如何统一、纪年定义及换算服务均未实现。自然语言先后和因果需要明确关系记录；不得从文件时间、Session 时间、数组顺序或近似值推断精确世界时间。

## 子事件与其他关系

子事件用 `parents` 保存全部已记录上级，反向查询由未来查询服务从实际文档计算；多上级关系只维护在子事件中，每个上级说明其具体含义。`validateHistoryEventGraph` 接收调用方提供的完整同世界事件集合，拒绝重复事件 ID、不同世界、缺失的上级或其他事件关系目标，以及上级关系循环；只有上级关系执行无环校验。它不扫描文件、不补全缺失资料、不校验外部模块引用、不自动检查时间或因果矛盾，也不能把局部集合当作全世界历史已完成。

`relations` 中的 `before` 和 `causes` 均从当前事件指向目标，`overlaps` 和 `related` 表示已经记录的关联；文件中的单向记录不自动创造第二份权威正文。未来查询工具可以从两端发现关联，但必须保留记录方向和说明，不把反向查找视为反向因果。重复或矛盾的时间、说法和因果是否符合世界设定需要结合完整资料检查；格式层不作语义裁决。

## 修改、失败和后续步骤

已确认的业务方向：初始化期间未确认事件按读取版本直接更新，旧版本拒绝；已确认事件修改应保存待审候选，确认前保留原文。候选文件的精确布局、确认时的多文件恢复与用户确认入口须在实现前完成设计，不能将建议当作已实现。世界演化造成的变化需保留旧状态与世界时间依据，具体机制属于未来世界运行。未知版本、损坏、现存候选或无法判断发布结果时必须保留已有数据，不静默删除或覆盖。

本步骤的测试使用真实临时目录存放多个 JSON 和旧 Markdown，验证格式、同名、多上级、未知时间、未展开、缺失引用、跨世界和上级环，以及未知版本拒绝后文件保留。第三步再实现受控文件存储、事件检索、工具、版本冲突与发布恢复；图校验及临时目录样例不是持久化服务，也不能证明 Agent 或真实模型会正确使用。
