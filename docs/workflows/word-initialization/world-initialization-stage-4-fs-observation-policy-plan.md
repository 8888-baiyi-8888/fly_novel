# 文件能力第四包：`dsh-fs-observation-policy` 观察策略开发计划

本文细化[第四阶段的观察策略步骤](world-initialization-stage-4-file-tools-plan.md#4-dsh-fs-observation-policy文件观察策略)。目标是复用上游观察状态与修改意图策略，对接项目文件事件，在独立测试和真实本机后端集成中验证状态、隔离与释放。本文是开发计划，不表示策略已接入。

## 范围与已知接入点

计划在 `src/agents/plugins/fs/fs-observation-policy/` 建立独立工作区包，测试放在 `src/agents/tests/`。前置契约为 [`@fly-novel/fs`](../../../src/agents/plugins/fs/fs/README.md)；[`@fly-novel/fs-local`](../../../src/agents/plugins/fs/fs-local/README.md) 仅用于集成验证，不是策略的运行时必需依赖。按下列编号逐步实施，每步验收后再进入下一步。

本包通过文件观察和意图事件产生版本或创建保护，不读写磁盘、不注册模型工具、不提供路径授权或沙箱。策略只对调用方实际触发事件并将返回保护传给后端的修改生效；直接调用未受保护的后端方法可绕过它。本阶段不把本机后端或策略加入生产 Agent，不提前开发文件工具或通用沙箱。

用户提供的 DeepSeek Harness 官方下载快照中，本包为 `0.2.2-rc.1`，包括 `src/index.ts`、`src/types.ts` 和 `tests/policy.spec.ts`；源码快照没有可核验的 Git 提交标识，实施时记录文件哈希及许可证，不宣称其属于先前固定提交。上游通过 `actor.agent.session` 的对象身份作为观察所有者；项目 [`ToolRunContext`](../../../src/agents/plugins/tools/contracts.ts) 的 `agent` 只有身份字段，Session 出现在工具批次日志而非执行上下文中，不能假定两者兼容。

项目文件事件共用 Cordis 总线，而意图事件采用首个决策者获胜的 waterfall。上游监听器不按 Agent 匹配且不调用 `next()`；若多个实例直接注册，一个实例可能截获其他 Agent 的事件。必须先验证并确定事件归属、稳定所有者和监听器路由，再决定最小适配；不能仅凭服务作用域隔离声称事件已隔离。

## 1. 核对上游、契约与归属方案

1. 核对指定官方快照的包清单、全部源码、公开入口、测试、仓库及文件级许可证，记录版本、源文件哈希、版权和更新来源；区分运行、peer、类型、构建及测试依赖。比较官方发布包与快照的依赖、模块格式和适配成本，不将相同版本推断为内容相同。
2. 逐项对照项目 `fs/observed`、`fs/write-intent`、`fs/edit-intent`、`fs/delete-intent` 的参数、返回类型、异常及同步／异步语义，核查项目 `FsError`、品牌类型与 Cordis 版本的运行时身份。列出与项目契约不兼容之处及必要导入调整。
3. 对照真实 `ToolsService`、`ToolRunContext`、Agent Loop 和 Session 的调用关系，确定可稳定代表同一会话的对象从何产生、如何跨调用传递、何时释放以及恢复和 Fork 时如何区分。核查未提供所有者的独立调用语义；不以每次新建的调用对象或可复用字符串 ID 直接替代稳定身份。
4. 对实际共享事件总线验证多个 Agent、多个策略实例及无策略实例的事件路由，明确第一个监听器何时处理或调用 `next()`、事件从哪里发出、未知或失效所有者如何处理。先形成避免跨 Agent 观察污染与决策截获的方案；如果需要修改 Tools、Loop 或事件契约，将其范围、兼容性与测试列为明确前置任务，不用空类型、静默回退或扩大注册范围绕过。
5. 明确策略与读取、写入、编辑、补丁、删除、移动调用方的边界：策略仅决定保护，后端执行版本及创建检查；当前没有文件工具时，使用明确的事件驱动集成测试，不把测试适配器描述为生产工具。

**验收**：形成来源、依赖、事件和所有者映射及可验证的隔离方案；必需的跨包前置变更有明确处理方式，不进入实现时留下无法识别真实调用方的问题。

## 2. 建立包和受控装配

1. 按第 1 步选择引入上游源码或官方包，建立独立包、公开入口、类型声明及 CommonJS 构建；只做必要的导入、所有者识别和事件路由适配，记录每处改动和适用许可证。更新工作区清单、锁文件、源码路径映射和构建边界。
2. 通过项目 Harness 公共插件注册接口定义显式装配方式；该策略是事件监听插件而非 `ctx.fs` 服务，不伪造服务依赖或依赖本机后端。明确安装、重复安装、初始化失败和作用域销毁时监听器与状态的归属。
3. 完成第 1 步确定的所有者及事件路由前置适配；真实工具链暂不能提供所需所有者时，明确限制并阻止将测试中的临时 actor 当成生产接入。不得修改生产 Preset 或赋予 Agent 文件访问能力。
4. 编写包 README，记录来源、许可证、公开接口、调用方契约、作用域、错误、无授权边界、本地改动及更新方法；同步实际受影响的 `AGENTS.md`、Agent 说明和架构文档，并记录重要决定。

**验收**：包可独立类型检查和构建，导入无注册副作用；只有显式装配才注册监听器，作用域释放后监听器与状态不再生效，生产 Agent 未获得新能力。

## 3. 观察状态与意图决策

1. 对每个有效所有者和目标标识验证未观察、观察缺失、观察存在及更新观察的状态转换；覆盖同一对象的跨调用复用、不同所有者及不同目标互不污染，别名使用后端给出的相同 `targetKey`。
2. 对照上游验证写入：未观察或确认缺失得到 `createIfAbsent`，观察存在得到携带所见版本的 `replaceIfVersion`。验证编辑及删除：未观察返回 `FS_NOT_OBSERVED`、观察缺失返回 `FS_NOT_FOUND`、观察存在返回版本保护；检查无所有者调用及异常代码、类身份。
3. 验证 `fs/observed` 同步记录、意图决策的异步拒绝与事件协议；验证注册顺序、`next()` 继续和短路，覆盖不属于本实例的事件与未知 actor，避免一个 Agent 的监听器截获另一 Agent 的意图。
4. 检查策略自身不执行文件 I/O；通过受控事件和后端替身验证传入保护，不把事件决策的成功误认为磁盘提交已成功。

**验收**：状态表、错误与事件语义有聚焦行为测试；所有者和目标隔离有正反例，事件不会因多个实例或未知调用方而误授权或互相污染。

## 4. 真实后端与并发集成

1. 在独立临时目录中，以可信测试适配器调用真实 `@fly-novel/fs-local`、发送观察与意图事件并把决策交给后端；验证读取存在后修改、确认缺失后创建、未观察已有文件拒绝覆盖，以及直接无策略调用的边界。
2. 使用受控同步点验证观察后文件被外部修改、删除或竞争创建时的版本／创建保护；覆盖成功修改后的新版本观察、失败时不记录错误状态、补丁和移动源使用编辑意图、移动目标使用写入意图、删除使用删除意图。按实际调用顺序验证部分成功，不假设移动或多文件操作整体原子。
3. 对两个真实 Agent 实例及相同路径安排独立所有者和事件发起方，验证观察、修改意图及销毁不互相影响；覆盖仅一个 Agent 装配策略、注册顺序变化和监听器销毁。未来文件工具接入时，再通过真实工具执行链重复跨 Agent 验证。
4. 覆盖取消、后端错误和事件监听器错误对结果及已记录状态的影响；不将 `cwd`、观察记录、共享事件总线或版本检查表述为授权与跨进程事务。

**验收**：真实后端的保护条件和竞争结果可重复，跨 Agent 测试证明所选路由方案，未覆盖的外部写入竞争与平台限制明确记录。

## 5. 生命周期和交付

1. 验证销毁前后的事件处理、监听注销、状态清理、重复释放、初始化失败和重新装配；验证新会话、恢复会话与 Fork 不继承旧观察，除非后续明确设计持久化并另行验证。检查销毁期间待决事件不再修改已释放状态。
2. 按行为移植与本包有关的上游测试及适用版权声明；测试使用固定替身或独立临时目录，不依赖网络、模型凭据或真实用户文件。记录与上游不同的隔离行为及尚未验证的竞争。
3. 验证冻结锁文件安装、包类型检查和构建、项目类型检查及聚焦测试；清理本包与必要依赖的构建产物后重建，从公开入口验证类型和运行时导出，检查无导入副作用、许可证、清单、文档链接与 `git diff --check`。
4. 汇总实际命令、平台、结果和限制；明确策略仅提供观察状态保护，不替代路径授权、后端并发保证或真实文件工具的事件接入。

**验收**：作用域清理、隔离和当前平台集成有可复现结果；来源及本地适配可追溯，真实工具链缺口和未验证行为明确，生产 Agent 保持未装配。
