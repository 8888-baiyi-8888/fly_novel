# 世界初始化第五阶段：资料目录与受控登记工具详细开发计划

本计划细化[第五阶段工作区计划第 4 步](world-initialization-stage-5-workspace-plan.md#4-资料目录与受控登记工具)。[工作区首版契约](world-initialization-stage-5-workspace-plan.md#首版工作区契约与示例)规定世界隔离、持续身份和各自目录；[资料目录契约](world-initialization-stage-5-workspace-plan.md#资料目录版本与对齐)规定负责人、内容摘要、受控登记和对齐。本文记录首版设计、开发步骤与验证范围；当前接口和使用限制以[世界初始化模块](../../../src/world-init/README.md)及[工具说明](../../../src/tools/README.md)为准。

## 目标与现状

为每个世界建立一份资料导航目录，让同世界获授权的 Agent 查询成果文件的位置、用途、负责人及简介对应的内容版本；由专用工具受控登记、更新和删除记录。目录记录是导航信息，成果内容和确认状态以原文件及业务流程为准；登记、搜索或对齐均不确认世界事实。

[世界工作区配置](../../../src/world-init/workspace/config.ts)提供读取根、资料目录保护根和各 Agent 专属目录；[工作区装配入口](../../../src/app/agents/world-initialization.ts)按可信配置为主 Agent 与角色 Agent 装配目录服务和工具。角色创建 Agent 由[独立应用入口](../../../src/app/agents/character-creator.ts)创建，拥有独立的框架和 Session；角色资料服务[角色索引](../../../src/world-init/character/store.ts)负责角色 ID、名称和分类，与跨成果文件的世界资料目录不同。角色服务和旧 `read_file` 使用直接文件访问，不能假设它们会发出普通文件工具的观察事件。

主 Agent 当前运行实例 ID 随创建生成，角色 Agent 有可信业务 ID；通用工具的执行上下文绑定实例身份。目录服务必须由可信应用把 `(世界 ID, 稳定 Agent ID, 专属目录)` 绑定到实例及工具作用域，不能用运行 ID 代替业务身份，也不能接受模型传入的世界、负责人或授权根来授予权限。现有生产入口只装配主 Agent 和角色创建 Agent；第二个特殊 Agent 用现有机制及固定测试职责验证，不提前实现新的业务 Agent。

## 首版设计

### 文件、记录和版本

- 可信应用为每个世界提供现有的 `catalogRoot`；首版在其中使用固定文件 `catalog.json`。此名称仅相对于可信提供的保护根，不固定世界根、宿主路径或其他目录名称。服务不把根目录当成角色索引，也不自动扫描文件建立记录。
- 文件使用 UTF-8 JSON，顶层包含 `formatVersion: 1`、`worldId` 和 `records` 数组；每条记录包含 `path`、`ownerAgentId`、`summary`、`contentSha256` 和 `revision`。`path` 是相对于世界读取根的规范路径，统一用 `/` 表示；`contentSha256` 是实际文件字节的 SHA-256 小写十六进制；`revision` 是程序生成的 UUID，用于该记录的乐观并发检查，不是文件内容版本。以下仅为格式示意，路径与简介不是世界必需字段或角色分类：

```json
{
  "formatVersion": 1,
  "worldId": "world-a",
  "records": [
    {
      "path": "agents/history/timeline.md",
      "ownerAgentId": "history",
      "summary": "历史事件草案与待确认事项",
      "contentSha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
      "revision": "123e4567-e89b-42d3-a456-426614174000"
    }
  ]
}
```

- 一个规范目标对应一条记录；严格校验版本、世界身份、路径、非空负责人和简介、摘要与 revision，以及规范目标重复。解析目录文档不要求成果文件仍然存在：缺失、不可读或失去有效归属的成果保留原记录并在查询时报告，不能导致目录被误判为空。文件损坏、未知版本、世界不匹配或记录无效时拒绝读取和写入，保留原文件；不自动修复、重建或迁移。未来格式变化须另定版本和迁移或拒绝策略。
- 显式初始化只在可信调用方请求且 `catalog.json` 不存在时以独占创建方式建立空目录文件；已存在时拒绝初始化，不覆盖任何数据。常规打开要求文件存在且有效；不把缺失或损坏当成空目录。初始化不创建世界根或 Agent 目录。
- 第一次登记要求目标未登记，服务生成 revision；更新和删除必须携带读取到的该条记录 revision，成功更新重新生成 revision，已变化或已删除时报告冲突。删除只删除记录，不删除成果文件；同一路径重建时生成新 revision，避免旧请求误删新记录。

### 授权与工具边界

由可信应用在 Agent 装配时建立世界级目录服务，并为每个允许登记的 Agent 创建绑定其稳定业务身份和专属目录的受限工具句柄。模型可以提交成果路径、简介、查询条件和已有记录 revision；不能指定或修改世界 ID、负责人、专属根、目录根、运行身份或确认状态。工具执行上下文须匹配装配时实际工具服务的 Agent 身份；业务 ID 来自可信绑定，不根据模型传参、实例名称或文件正文推断。

登记或更新只允许指向调用者专属目录内的现有普通文件；服务先从世界读取根解析模型路径，拒绝绝对路径、空路径、`..` 越界、链接或 junction 越界，以及解析后落在其他 Agent、已确认根、目录保护根或其他世界的目标。目录记录中不保存宿主绝对路径。对同目标的大小写、短名称或链接别名按真实目标识别，无法可靠确认时拒绝；不将字符串前缀当成包含关系。服务不允许通过重设负责人接管记录，配置变更导致负责人或目录不再可解析时报告问题并保留记录，不自动迁移或删除。

同世界 Agent 可按路径、负责人或简介关键词查找记录并读取详情，结果包含记录及文件检查状态；路径未登记与目标文件缺失分别报告。查询输入中的负责人只是过滤条件，不是授权来源。首次按路径或条件查询返回明确的分页结果与目录版本；继续翻页必须携带上页版本，目录发生变化时报告冲突并要求重新查询，不能静默混合不同快照。对多个条目的检查逐项返回状态，单项缺失或读取失败不伪装成整体成功或空结果。

首版计划在 `src/tools/` 下提供目录专用工具定义，在 `src/world-init/` 下实现格式和世界级服务，由 `src/app/agents/` 负责可信装配。工具按实际操作拆为登记、更新、删除、查询和详情读取；工具名、参数与错误码在第 1 步结合现有工具模式固定。普通文件工具依旧只能读目录保护根，不得写目录文件；只读通用子 Agent 是否获得查询工具由可信装配明确选择，不继承登记权限。

### 内容关联、并发和失败

登记和更新由服务读取实际文件字节并计算 SHA-256，模型不提供或决定摘要。读取前后核对真实目标与文件版本；调用目录文件发布前再次检查目标与摘要，发布完成后再核对成果状态。发布前发现变化则不写入目录；发布后发现变化时保留已提交记录并明确报告过期或检查失败，不能声称未提交或自动回滚。状态以检查时刻为准：`current` 表示摘要一致，`stale` 表示内容不同，`missing` 表示目标不存在，`unreadable` 表示读取或权限失败，`changing` 表示检查期间变化；不把错误当作不存在，也不宣称检查与外部写入是跨文件原子事务。可识别的目标改指其他 Agent、世界或受保护目录时报告越权，而不是读取其内容计算摘要。

同一世界的所有绑定共享一个世界级服务及串行写队列：不同记录的并发登记依次读取最新目录并合并；同记录通过 revision 拒绝过期更新或删除。目录文件按同目录独占临时文件写入并原子发布；发布前检查目录自身版本，不能无条件覆盖外部修改。尽量复用现有文件后端的单文件发布与版本保护，先验证其跨 Windows 和其他目标平台的实际能力；若不能保证所需语义则明确失败并保留原文件，不自行声称已经实现安全替换。服务关闭拒绝新操作并等待队列结束，Agent 工具释放不关闭其他 Agent 共用的世界服务；世界作用域关闭后才释放服务。

取消在提交前停止并保留原目录；发布已经发生时返回实际提交结果或明确的不确定状态，不能宣称回滚。暂存、校验或发布失败保留已有目录及必要的可恢复信息；清理失败和操作失败同时发生时保留两个原因。任何临时文件清理须限定为本次服务创建的文件，不清理用户目录。目录替换只保证单文件发布，不承诺跨成果文件事务、断电持久性或可抵御外部恶意并发替换及硬链接。

沿用单个可信应用进程持有同一世界写入的部署前提。服务在同一进程内对相同世界和目录进行共享或排他管理，不能因两个不同 Agent 框架各自打开目录而丢失更新；不同世界独立。跨进程锁和崩溃恢复不在本步虚构实现，不能满足单写入进程前提时不启用目录写入。

## 开发步骤

### 1. 核对职责、调用链与接口

1. 阅读世界工作区、主 Agent、角色创建 Agent、文件后端、观察策略、角色资料服务、工具执行上下文和相关测试。画出主 Agent、角色 Agent、第二个测试 Agent 的目录工具注册与释放链，核对实例 ID、业务 ID、Session、目录根分别从哪里取得。
2. 结合“主 Agent 登记自身世界构想”“角色 Agent 登记自己的角色成果，主 Agent 查询但不能代改”两个场景，固定工具名称、输入输出、分页和错误语义；区分首次登记、更新、删除、未登记及缺失成果。角色 Agent 的角色索引与本目录保持独立，目录无需为每个角色额外创建固定分类。
3. 设计世界级共享服务、受限身份句柄、主子 Agent 生命周期和旧入口处理。特别检查主 Agent 实例 ID 随创建变化、角色 Agent 独立框架、不同绑定共用同一世界服务，以及实例销毁和恢复时的句柄注销；不允许模型自行选择身份或世界。
4. 核实现有文件服务的目标解析、文件版本、同目录原子替换、取消和 Windows 行为；明确实际可复用接口、不能覆盖的外部并发及失败状态。如果首版设计与既有契约或实际能力冲突，先修正文档并说明原因，再进入实现。

**验收**：登记、查询和权限边界有具体工具调用示例；服务所有者与释放顺序明确；实现计划不把文件观察或提示词当作授权，也不假设通用特殊 Agent 生产装配已经存在。

#### 第 1 步核对结论：实例与服务

以下记录开发时核对的实例身份和服务装配设计；当前实现以模块说明和源码为准：

| 对象 | 当前入口和身份 | 本步后续装配设计 |
| --- | --- | --- |
| 主 Agent | [世界入口](../../../src/app/agents/world-initialization.ts)校验世界集合后，按 `(worldId, mainAgent.agentId)` 占用业务身份；底层 Agent 实例 ID 为随机值。 | 世界服务管理器从可信世界配置取得目录及业务身份；主 Agent 创建成功后，以其 `context.tools.agent` 的对象身份绑定目录句柄，并注册五个目录工具。 |
| 角色 Agent | [角色入口](../../../src/app/agents/character-creator.ts)使用稳定 Agent ID、独立框架和持久 Session；由 `persistent` 创建函数在任务时启动。 | 可信创建回调把同一世界服务的受限句柄传入角色入口；角色实例创建后以该实例 `context.tools.agent` 绑定，角色工具可维护自己的记录。 |
| 第二个特殊 Agent | [双世界测试](../../../src/app/tests/world-workspace-assembly.test.ts)通过测试 Provider、独立实例和现有进程内驱动验证；没有通用业务生产装配。 | 测试中由可信应用绑定另一业务 ID 和目录，使用同一目录服务及实际工具链；不增加虚构的生产 Agent。 |

`ToolsService` 在构造时冻结自己的 Agent 身份副本，并在每次执行时将该**同一对象**放入 `exec.agent`；工具注册时捕获所属 `tools.agent` 并要求 `exec.agent === capturedAgent`，缺失或不匹配时拒绝。业务 `ownerAgentId`、世界和目录由可信闭包提供；不与可重复或随机的实例 ID 混用。`exec.workingDirectory` 是工具批次提供的运行上下文，不作为目录授权来源；目录路径始终以受信世界根解析。Session 可用于执行与日志关联，不决定目录负责人；Session 恢复也不恢复工具权限，必须重新可信装配。

世界服务由可信应用持有，按已校验的世界 ID、真实读取根及 `catalogRoot` 在当前进程复用同一服务和写队列；同世界但路径、Agent 绑定或目录配置不一致时拒绝，不另开并行写服务。服务为主、角色和测试 Agent 生成各自受限句柄并计数；销毁某个 Agent 只撤销其注册和句柄。世界所有者关闭时先阻止新绑定，取消并等待所属子运行和主 Agent 释放，再等待已提交目录操作及全部句柄退出，最后关闭后端和释放世界服务占用；清理失败传播错误并阻止不安全重入。启动失败逆序清理已创建资源；任务与清理均失败时保留两者。

旧的 `createWorldInitializationAgentWithWorkspace` 不具备可信世界身份和资料目录配置，默认不注册目录工具；独立 `createCharacterCreator` 未获得世界服务时也不注册。不能从工作目录猜测世界或自动开启目录访问。只读通用子 Agent 首版不装配目录工具；需要查询时通过主 Agent 或后续明确的可信装配提供。

#### 第 1 步核对结论：工具契约

首版在 `src/tools/` 建立 `catalog/` 工具实现；具体持久化格式、目录服务及路径授权属于 `src/world-init/`，应用装配属于 `src/app/agents/`。五个工具均由 `defineTool` 创建，输入严格拒绝未声明字段，路径以世界读取根为基准，只接受规范相对路径；模型不能提交世界 ID、授权根或记录负责人。`ownerAgentId` 仅可作为查询筛选条件。工具返回 JSON 对象，模型可见内容与规范值表达相同状态。

| 工具 | 输入 | 成功结果与含义 |
| --- | --- | --- |
| `catalog_register` | `path`、`summary` | `{ status: "registered", record, fileStatus }`；目标未登记，服务从实际文件生成摘要和 revision。 |
| `catalog_update` | `path`、`summary`、`revision` | `{ status: "updated", record, fileStatus }`；只更新自己记录，必须匹配读取到的 revision。移动文件时先删除旧记录，再登记新路径，不自动改动成果。 |
| `catalog_remove` | `path`、`revision` | `{ status: "removed", path }`；只删除自己记录，不删除成果。目标文件已经缺失时仍可基于目录中的规范路径和记录 revision 删除；不得为此读取或解析越权目标。 |
| `catalog_search` | 可选 `ownerAgentId`、`keyword`、`offset`、`limit`、`version` | `{ items, total, offset, nextOffset, version }`；每项为 `{ record, fileStatus }`。`offset` 默认 0，`limit` 默认 50、最大 100；后续页必须传入上次 `version`。 |
| `catalog_read` | `path` | `{ status: "found", record, fileStatus }` 或 `{ status: "not_registered", path }`；未登记与已登记但文件缺失明确区分。 |

查询按规范路径排序；`version` 为服务读取到的目录文档字节 SHA-256，目录内容变动时后续页返回 `CATALOG_CONFLICT`。版本只固定目录记录快照，各项 `fileStatus` 是各自检查时刻的结果，不保证不同项或页面在同一时刻检查。记录 `revision` 是由程序生成的 UUID，和目录分页版本、成果文件 `contentSha256` 分别使用，不可互换。简介关键词按区分大小写的普通子串匹配，不执行正则；没有筛选条件时查询所有记录。

服务以带 `code` 的受控错误区分 `CATALOG_INVALID_INPUT`、`CATALOG_FORBIDDEN`、`CATALOG_CONFLICT`、`CATALOG_NOT_FOUND`、`CATALOG_INVALID_DOCUMENT`、`CATALOG_IO_ERROR` 和 `CATALOG_CLOSED`；工具执行器把未取消情况下的 `Error.code` 传入工具错误信息。`catalog_read` 的未登记是正常结果，已登记文件丢失则返回 `fileStatus: "missing"`；对于被替换到越权位置的单项，使用 `fileStatus: "forbidden"` 且不读取该目标。`unreadable`、`changing` 逐项保留，不等同于空查询。外部摘要不一致的结果为 `stale`，不由工具自动更新简介。

文件写入工具均设置 `reportOnAbort: true`。现有 [ToolsService](../../../src/agents/plugins/tools/tools-service.ts) 在信号已取消且工具抛错时会将错误码覆盖为 `ABORTED`；因此目录工具对**可能已发布**的提交结果返回结构化结果，包含 `status: "committed"` 或 `"unknown"` 和可用的操作、路径与检查状态，不能依赖异常码传递提交结果。发布前取消则报告未提交的取消；其他失败与清理同时失败时，服务保留两个原因，工具返回不泄露宿主路径的稳定失败信息，并在可信调用侧保留完整错误。实现须测试取消发生在发布前、发布中、发布后及报告过程中；不得把 `isError: false` 单独当作提交成功，必须检查 `status`。

#### 第 1 步核对结论：调用示例

示例路径均相对世界读取根，返回值中的摘要与 revision 为示意值；实际摘要和 revision 由服务生成。

1. 主 Agent 完成自己的 `agents/main/world.md` 后调用 `catalog_register({"path":"agents/main/world.md","summary":"世界背景草案"})`，得到 `registered` 记录；目录不因此把草案确认为事实。再次登记同一路径得到 `CATALOG_CONFLICT`。
2. 角色 Agent 创建角色资料后调用 `catalog_register({"path":"agents/characters/<角色ID>/profile.md","summary":"角色建议及其背景"})`；主 Agent 可以 `catalog_search({"ownerAgentId":"creator"})` 和 `catalog_read({"path":"agents/characters/<角色ID>/profile.md"})`。主 Agent 对该路径执行 `catalog_update` 或 `catalog_remove` 得到 `CATALOG_FORBIDDEN`；若简介有误，由主 Agent 委派角色 Agent 处理。
3. 角色 Agent 先读取记录并取得 `revision`，再调用 `catalog_update({"path":"agents/characters/<角色ID>/profile.md","summary":"更新后的角色建议","revision":"<读取所得 revision>"})`。若成果在检查或提交后发生变化，结果明确区分未提交冲突和已提交但 `stale`；若成果被删除，详情返回 `missing`，负责人仍可用记录 revision 删除目录项。

#### 第 1 步核对结论：文件接口与限制

[文件服务](../../../src/agents/plugins/fs/fs/index.ts)提供 `resolve`、`stat`、`lstat`、`readBytes`、`readByteRange` 和带意图的 `writeText`；`FsVersion` 是不透明的新鲜度令牌，不是 SHA-256。成果摘要按原始字节计算，可使用有界字节窗口逐块哈希，读取前后检查目标和版本；窗口读取不构成系统级原子快照。目录 JSON 可通过单个可信 `LocalFileSystem` 实例使用 `writeText` 的版本意图，不能使用面向 Agent 的草稿后端写入受保护目录。

[本机后端](../../../src/agents/plugins/fs/fs-local/README.md)提供单文件暂存发布、实例内目标锁和版本检查，Windows 替换涉及保留 DACL；`writeText` 未公开“暂存完成、发布之前调用业务检查”的扩展点，也未提供与成果文件联合提交的事务。首版采用发布前检查成果、调用带目录版本意图的 `writeText`、发布后复核成果的顺序；如果复核发现变化，返回已提交及 `stale`，而不是声称拒绝了发布。提交期间的外部路径替换、硬链接和多个进程写入仍不能由此消除。若需求以后必须保证发布瞬间成果未变，需要单独设计可验证的事务或宿主隔离，不能把现有接口描述为已有此能力。

`writeText` 发布后清理暂存目录失败不保证回滚；目录服务应以实际后端结果和后续读取确认状态，不能把异常当作原文件必然未变。`readBytes` 有大小上限，分块 `readByteRange` 每次检查取消；`readText` 的 UTF-8 解码和换行处理不能代替原始字节摘要。文件观察策略按工具和 Session 路由，只服务观察与版本意图，不提供目录授权；目录服务需自行校验身份、路径与文件状态。

### 2. 实现版本化格式与目标校验

1. 在世界初始化业务层定义目录文档、记录及严格解析规则，验证世界 ID、路径形式、负责人、简介、摘要、revision、重复目标和未知版本。定义显式初始化与读取已有文件行为，禁止覆盖已有或无效数据。
2. 实现可信路径解析：以世界读取根为基准，检查调用者专属根、真实普通文件、跨世界与受保护目录；覆盖大小写、目录链接、junction、路径遍历、别名、目录目标和缺失文件。记录仅保存规范相对路径。
3. 添加格式和路径聚焦测试，包括 JSON 损坏、额外字段、重复记录、未知版本、错误世界、链接别名及相同目标的不同写法；验证拒绝后文件内容不变。

**验收**：有效文件可往返读取，所有无效或无法判断归属的记录明确失败；不修改角色索引及成果文件。

### 3. 实现世界级目录服务

1. 实现显式打开、关闭、单进程世界级共享和串行操作。按可信绑定授权登记、更新和删除；同一世界的不同身份共享队列，不同世界独立。服务不接受调用者通过业务参数伪造负责人。
2. 实现实际文件字节摘要、登记前后及发布前检查；实现 revision 冲突、重复登记拒绝、未登记和单项检查状态。查询使用确定顺序和目录版本分页，不把读取失败转成空结果。
3. 实现同目录暂存及受保护的单文件发布，处理取消、外部变更、发布失败与清理失败；关闭等待运行中操作，不删除成果。损坏文件和未知版本保持原样。
4. 使用受控门闩验证不同记录并发不丢失、同记录冲突、文件检查期间变化、目录外部变化、取消、写入失败与清理失败；验证旧请求不能删除重建后的新记录。

**验收**：目录服务能安全维护并查询记录，冲突和失败结果可观察，已有目录及成果不因失败被静默覆盖或删除。

### 4. 实现专用工具与可信装配

1. 在工具目录实现经第 1 步固定的模型工具；输入不包含权限参数，工具作用域绑定实际 Agent 身份和可信业务身份。工具结果明确区分成功、冲突、缺失、不可读、取消和越权。
2. 将同一个世界服务通过可信应用分别装配给主 Agent 和角色创建 Agent；角色 Agent 的独立框架只持有受限句柄。使用测试专用第二个特殊 Agent 验证第三个身份；不让一个 Agent 的释放关闭仍在使用的世界服务。
3. 普通文件工具不能写目录文件，角色服务仍仅在角色根内写角色资料；登记只记录这些成果，不直接修改它们。检查角色待审资料和确认状态在简介中不会被工具自动提升为事实。
4. 覆盖工具注销、父作用域关闭、子 Agent 取消、实例重建及世界服务释放；启动失败时回滚已创建的工具和服务句柄，清理失败报告真实结果。旧入口是否提供目录工具必须通过显式可信配置决定，不能静默扩大权限。

**验收**：真实工具调用中，每个 Agent 仅能维护自己的记录，同世界可查询，跨世界和伪造身份拒绝；无残留注册或提前关闭共享服务。

### 5. 双世界集成与交付

1. 使用两个世界、每个世界的主 Agent、角色 Agent 和测试特殊 Agent，通过真实注册、工具和 Session 执行登记、跨 Agent 查询、各自更新、越权拒绝、删除记录及重建；两个世界同名业务身份不串用。
2. 验证相对路径、绝对路径、遍历、链接、目录别名、大小写、不同世界、已确认资料、资料目录、文件缺失、读取失败和检查中变化；Windows junction、短名称或其他平台不支持的场景明确记录是否运行和跳过原因。
3. 运行目录格式、服务、工具、装配及受影响的文件沙箱、角色和子 Agent 聚焦测试与类型检查；构建并冒烟交付入口，检查 Markdown 链接和 Git 空白。固定模型替身与真实模型调用分别报告。
4. 更新世界初始化、工具和应用 README、必要架构说明及目录登记，新增本次重要工程决定的 Agent Note。记录持久化格式、初始化、资源所有权、部署限制、失败和恢复方式；不宣称已经实现自动对齐、确认提交、跨进程锁或长期记忆。

**交付验收**：资料目录由可信服务持久维护，专用工具提供受授权的登记与查询，受控测试证明并发、越权、版本冲突和失败语义；后续[版本对齐与对应子 Agent 更新](world-initialization-stage-5-workspace-plan.md#5-版本对齐与对应子-agent-更新)仍单独实施。
