# 第 6A 阶段：世界发展规划联合开发计划

本文联合细化[内容模块计划](world-initialization-stage-6a-content-modules-plan.md)的宏观发展蓝图、故事线组织和人物成长蓝图。三个内容模块由同一个世界发展规划 Agent 开发，共用一份开发计划，但各自保持职责和权威内容。用户已确认的方向见下文；文件、字段、工具及实施细节是设计提案，不表示已经实现或最终确定。

## 已确认的业务方向

1. 三个模块及其规划内容都归世界所有，一个世界可以服务多部小说；不以某一主角或单部小说作为世界发展的唯一中心。
2. 一个世界的宏观发展蓝图可以包含多个可能方向；方向可分别关联多个待审初始局势方案，并明确每项对各方案的适用条件。多个待审方案不等于同时成立，更不因被引用而自动选定。
3. 三个模块由一个世界发展规划 Agent 负责，统一规划和开发；主 Agent 协调、委派、核对和整合，仍可主动补充十个模块之外的必要内容。
4. 人物成长的详细规划由各自的**角色成长线**维护，包括成长方向、阶段和可能转折。**人物成长蓝图**有独立规划职责：组织多个人物的成长重点及相互影响，规划其与世界发展方向的呼应和留白，并引用相应成长线；它不重复维护成长线的详细正文。
5. 成长线为后续导演安排相关故事提供方向；角色在具体故事中的选择和实际变化由角色自身决定，实际发展可以偏离规划。蓝图、故事线及事件构想都不预定全部行动、遭遇和结局。
6. 用户确认每个角色只保留一条成长线；不同可能方向或局势下的规划可在该成长线内按需表达，具体组织与查询方式在资料契约步骤细化。

三个模块是世界初始化的内容职责，合并开发不等于合并成一个顶层模块、一个数据表或一份固定模板。不同世界可以有不同规划重点、详略和留白；第一版供用户审阅，保存、目录登记、Agent 成功返回或建立关联均不代表用户确认。

## 范围与内容归属

| 内容 | 归属与示例 |
| --- | --- |
| 宏观发展蓝图 | 规划世界可能发生的重大变化、条件及影响。例如缺水可能推动多城协商，也可能导致冲突扩大。 |
| 故事线组织 | 维护持续发展的叙事线路及其关联。例如不同城邦围绕水源分配持续协商的线路；它可关联宏观事件构想，但不是重大事件清单的另一份副本。 |
| 角色成长线 | 维护某个人的详细成长方向、阶段、可能转折及与故事的关联；可有长期和按需细化的阶段规划。它是故事线组织中按角色维护的成长规划，角色当前设定仍归人物模块。 |
| 人物成长蓝图 | 独立规划多个角色的成长重点、相互影响、与世界发展的呼应和明确留白；引用成长线，不再维护每个人的详细阶段和转折。 |
| 初始局势和历史 | 当前供水危机归初始局势，已经结束的青河战争归历史。三类规划读取并引用它们，不把候选局势当成已确认事实。 |
| 未来实际故事和世界变化 | 后续世界运行、导演安排、角色行动及事件记录处理；本阶段保存的是规划，不能因此推进世界或改写当前人物、组织与地点。 |

用户确认一项规划表示确认该规划，而不是确认未来事件已经发生。规划方向、角色认知、实际世界状态、审核状态和未知是不同概念；不得将其压缩成同一状态，也不能因为故事线关联事件构想就视作该事件已经发生。

## 当前能力与限制

- [初始局势插件](../../../src/agents/plugins/initial-situation/README.md)保存一个世界起点、多个待审方案及所属局势条目；它没有方案确认或选用流程，也不自动判断跨模块语义冲突。
- [历史插件](../../../src/agents/plugins/history/README.md)保存历史事件、时间和关联；[地图](../../../src/agents/plugins/map/README.md)、[组织](../../../src/agents/plugins/organization/README.md)、[人物](../../../src/agents/plugins/character/README.md)各自维护自身资料。不同模块读取和版本接口不同，不能假设已经存在统一跨模块存储或关联服务。
- [世界工作区和目录](../../../src/world-init/README.md)按世界和负责人约束资料范围；目录简介只是导航。现有专用 Agent 的 Preset、SystemPrompt、Tools、Session、可信引用绑定与持久委派可供复用，具体能力以[应用入口说明](../../../src/app/README.md)为准。
- 当前没有世界发展规划 Agent、三类规划的专用插件及存储、故事线执行器、角色成长运行机制或世界演化引擎。现有主 Agent 提示词中的规划目标不能当作上述能力已经实现。

## 两世界联合走查

### 资源有限的城邦群

初始局势方案 A 是上游封渠、下游抗议；方案 B 是暂时通水、协议不稳定。它们是同一世界、同一起点的两个待审候选，不能当作同时存在的事实。

| 规划对象 | 内容示例 | 关联和留白 |
| --- | --- | --- |
| 宏观发展方向 | 协商与共同管理；或者冲突扩大。 | 对 A、B 分别说明适用条件。可能举行一次多城谈判，但参与方、结果和是否发生均未定。 |
| 故事线 | “河谷水源分配”围绕各城利益、协商和分歧持续发展。 | 可关联多城谈判构想和多个角色成长线；该线路也可以包含没有单独宏观事件文件的阶段。 |
| 林岚成长线 | 从只顾本城利益出发，可能逐步认识到多城合作的重要性。 | 独立维护阶段、可能转折与相关故事线；不规定她必然让步或未来一定改变。 |
| 顾青成长线 | 可能从依赖宗门决定转向形成独立判断。 | 独立维护其规划与可能困境，不因关联林岚就推断两人的想法一致。 |
| 人物成长蓝图 | 规划两人的成长重点、相互影响及其与水源分配方向的呼应。 | 引用两条成长线，说明两人可能在协商中形成张力；实际影响、选择和结果保留弹性。 |

如果方案 A 后续调整为已经恢复通水，相关宏观方向、故事线和成长规划需要重新核对适用条件；不能自动选定方案 B、自动改写其他资料，或根据来源版本变化宣称已完成语义审查。

### 开放修仙世界

历史记录宗门因灵脉变化迁徙；初始局势是山门附近灵气紧张。宏观方向可以包括探索替代资源和争夺扩大；故事线可分别关注宗门内部协调与散修探索，两条线不要求都从属于同一条核心线。

散修可能逐渐改变对宗门的看法，宗门弟子可能重新理解自身责任。各自的成长细节由成长线维护；成长蓝图可规划两人的成长重点怎样互相映照及与资源争议呼应。远方灵脉是否存在、两人是否相遇、采取什么行动和最终变化均可留白，不能将规划变成必然结果。

## 三类规划的组织方案

### 宏观发展蓝图

建议每个世界维护一份宏观蓝图总览，按需组织多个**发展方向**及需要独立定位的**重大事件构想**。方向描述一段时期内可能发生的变化；事件构想描述相对具体的可能变化，如一次多城谈判。同一事件构想可关联多个方向或故事线；不要求为每个未来事件单独建档。

方向和构想可按需描述适用局势方案、条件、涉及范围、可能影响、有关内容与未知。条件可以是自然语言，不假设程序能判断“失去信任”；未知条件保留未知。时间可按世界内基准、相对顺序或文字说明表达，无法换算时保留原文，不把近似日期、文件时间或 Session 时间当作精确世界时间。

### 故事线与角色成长线

建议故事线按需要独立定位，记录名称、持续关注的冲突 / 主题、相关角色和组织、适用局势、可能阶段、与宏观方向或事件构想的关联及留白。世界重大故事线可以覆盖多个地区；地区或角色故事线不必都归属于它。阶段、分支与合流按实际需要建立，不强制所有故事形成同一棵树或排成完整时间线。

角色成长线是按人物维护的详细规划，建议能分别表达长期方向和必要的阶段、可能转折、相关故事与未知。人物 ID 与姓名分开；同一人物只保留一条成长线，可以关联多条故事线，不同候选局势和可能发展如何在该线内表达，连同版本及阶段关系在资料契约步骤结合案例确定。成长线的规划内容不能自动覆盖人物的当前认知、目标或关系。

### 人物成长蓝图

建议世界维护一份人物成长蓝图作为跨人物规划入口，并按需记录：本世界重点关注哪些人物、他们各自成长线之间可能产生的呼应或张力、与世界发展方向或故事线的关联，以及尚不规划的范围。蓝图可以提出需要进一步讨论的跨人物成长重点；每个人的详细阶段、可能转折和成长内容仍由该人物的成长线维护。

例如蓝图记录“林岚和顾青面对供水危机时，可能分别从地方利益和宗门责任出发，形成合作或分歧”，并引用两条成长线和水源故事线；林岚何时改变认知、顾青可能面临什么具体选择，各自写在成长线中。蓝图中的相互影响是规划关系，不代表两人已经相遇、彼此知情或一定做出对应选择。

## 跨模块关联与查询

建议全部规划对象使用程序生成、与名称分离的稳定 ID；允许重名。同一规划内容可有多个关联，例如一个宏观事件构想被多条故事线引用、一条成长线关联多个故事线。关系记录应说明类型、方向与含义；相关、可能促成、先后、因果、依赖和互斥不能相互推断。是否需要层级、多重归属、阶段图及循环约束，在契约步骤用实际案例确定，不强制建立通用图引擎。

适用局势按方案 ID 显式表达，并可引用该方案内局势条目；读取和写入时核验条目确属所述方案。对 A、B 的适用条件分别记录；暂未选择或尚未建立的方案保留未知 / 待关联说明，不编造 ID，也不把缺少关联解释为适用于所有方案。

人物、组织、关系、地点和历史引用按现有类型和实际 ID 解析；世界基础信息若只有已授权文档，引用实际文档或保留线索，不虚构对象 ID。读取和展示尽量使用权威正文；目录简介不能替代正文。关联不自动说明人物知情、组织成员身份、历史因果、未来行动或用户确认。

查询需支持从宏观方向找到相关故事线及成长蓝图、从人物或成长线找到相关故事线、从局势方案找到适用规划；反向查询说明关系的原始方向及已扫描范围。来源变化时检查真实版本或摘要并提示可能过期；来源缺失、未配置、无权、损坏、无法比较和读取失败应分开报告。版本只反映相应资料变化，不能证明语义冲突已经解决；跨模块读取不是原子快照。

## 存储与提取方案（建议）

建议为三个模块建立一个世界发展规划插件 `src/agents/plugins/world-development/`，集中存放格式、受控存储、查询、工具定义和注册。三个模块分别有清晰的存储范围及各自权威正文，不因同一插件或 Agent 而混写；具体目录和字段由契约步骤确定。以下为运行时负责人的目录示意，不是已经存在的文件：

```text
<世界发展规划负责人目录>/
  macro-development/
    blueprint.json                 # 世界宏观蓝图总览
    directions/<方向ID>.json       # 按需建立
    proposals/<构想ID>.json        # 按需建立的重大事件构想
  storylines/
    stories/<故事线ID>.json        # 按需建立的持续叙事线路
    growth-lines/<成长线ID>.json   # 人物详细成长规划
  character-growth/
    blueprint.json                 # 世界人物成长蓝图
    items/<规划项ID>.json          # 按需建立的跨人物规划项
  candidates/                      # 已确认资料的待审候选
```

总览负责明确重点、范围和入口，细节由方向、故事线、成长线或跨人物规划项各自维护；查询应根据真实文件和关联获取结果，目录简介不是正文。单个子目录是否需要继续拆分、成长线阶段是否独立文件、候选如何区分类型，由实际访问需求和契约步骤确认，不强制一个 Agent 对应一个文件。

建议采用版本化 JSON，格式版本从 1 开始，按类型、世界、ID 和必要关系校验；拒绝重复键、损坏内容、未知版本、越权和跨世界引用，保留原文件。既有 Markdown、人物资料、历史及局势文件不自动解析、迁移、覆盖或删除；后续格式变化先明确迁移或拒绝读取策略。

初始化阶段未确认规划按实际读取版本直接更新；已确认规划的修改参考现有历史 / 局势候选机制，保存待审候选及基线，不实现确认提交。未来世界演化导致规划调整时，需要保留旧规划及依据并关联实际发生内容；该历史留存、实际事件写入和确认流程另行开发，不能把初始化覆盖当作演化记录。

独占创建与版本条件更新分别报告结果；写入结果不确定时返回可核查目标，先核对实际文件再补做。目录登记与资料保存不是同一事务；工作区依赖单可信写入进程及现有路径检查，不声称跨进程锁、跨文件事务或系统级隔离。Session 可恢复对话，不单独证明业务任务完成。

## 插件工具规划

工具定义和注册集中在世界发展规划插件内部，以下名称是提案；具体参数、输出及错误契约在实现前确定。

| 工具组 | 职责与边界 |
| --- | --- |
| `world_development_macro_*` | 创建、读取、按版本更新宏观蓝图、发展方向和重大事件构想；不把未来构想写成历史事实。 |
| `world_development_storyline_*` | 创建、读取、更新和查找故事线、阶段及必要关联；不执行故事或固定角色行动。 |
| `world_development_growth_line_*` | 按人物建立、读取和更新角色成长线及阶段规划；不写入角色当前资料。 |
| `world_development_growth_blueprint_*` | 管理世界人物成长蓝图及跨人物规划项，引用成长线；不复制或重写成长线详细内容。 |
| `world_development_search` / `world_development_related_read` | 按世界、规划类型、人物、局势方案、故事线或方向查找，并从关联两端查询；同名列候选，返回已记录范围与分页版本。 |
| `world_development_reference_check` | 通过可信绑定核验局势方案与条目归属、人物、历史、地点和组织等引用及可用版本；区分未配置、缺失、无权、已变化和无法核验。 |
| `world_development_consistency_check` | 检查同世界身份、文件版本及可机械验证的关联，报告发现、来源和未检查范围；不自动裁决全部语义冲突或修改外部资料。 |
| `world_development_candidate_prepare` / `world_development_candidate_read` | 为已确认规划准备或读取待审候选，记录并检查基线；不执行确认提交。 |
| `delegate_world_development` | 主 Agent 向世界发展规划 Agent 提供任务和必要背景；可信应用绑定世界、身份、目录、Session、模型和权限。 |

查询结果只覆盖授权及实际记录范围；没有结果不代表世界没有相关内容。工具不接受模型自报角色身份或负责人路径来获得权限。有关当前人物、组织和历史的权威数据继续由相应模块维护，缺失能力保留线索或报告未配置，不自动创建对方资料。

## 世界发展规划 Agent 与协作

世界发展规划 Agent 负责三个模块的信息开发：读取用户构想、世界背景、需要的初始局势方案及相关历史、地点、组织、人物资料；按实际任务共同规划宏观方向、故事线与人物成长蓝图，按需创建角色成长线，并报告适用方案、引用、未知、冲突和未覆盖范围。一个故事线或人物成长规划可以先有概况，缺少信息时明确留白；无需每次创建全部三类成果。

建议新增独立 Preset、SystemPrompt、应用入口、Session 和专用委派工具；按可信配置装配世界发展规划插件及已有模块的只读句柄。主 Agent 决定是否委派、提供必要背景，并读取实际文件核对与整合；它不代替专用 Agent 编写这三个内容模块。专用 Agent 可独立运行或受托运行，不因模型传参改变世界、负责人或读取权限。

应用核验已借用句柄与同世界负责人目录，明确调用者持有的句柄、目录绑定及关闭责任；取消或启动失败时等待已受理操作并清理注册、会话与身份。恢复会话时先核查目录和实际文件，结果不确定时不能盲目重复创建。完整规划可能包含角色未知的秘密或未来构想，不能直接作为角色认知；角色视角及普通文件、目录和搜索的读取隔离留给后续角色运行机制设计，不在本阶段预建角色未来知识权限系统。

## 联合开发步骤与验收

第一步的实际能力核对、角色唯一成长线及双世界关联验收见[现状与联合场景走查](world-initialization-stage-6a-world-development-scenarios.md)。

1. **核对现状与联合场景。** 对照现有代码及修仙、城邦样例，落实一个蓝图多方向、多个候选局势和三类内容的边界；核对已确认的成长线 / 成长蓝图分工，列出需要独立定位与关联的内容。遇到影响近期实现的新业务歧义，先举例和推荐方案与用户商议。
2. **联合资料契约。** 基于两个样例确定宏观方向、事件构想、故事线、成长线和成长蓝图的最小输入输出、身份、状态、引用、局势适用、留白及关系语义；明确格式版本、旧资料保护、已确认候选和版本冲突。具体 Schema 不因本文示意自动成为已确认业务契约。
3. **插件存储与查询工具。** 在同一世界发展规划插件中实现经确定的三类资料格式、受控读写和对应工具；支持跨规划对象及局势方案的查询，核验真实外部引用，不复制其他模块正文。分项验证重名、多关联、不同局势候选、版本变化、越权、数据损坏、取消及发布结果不确定。
4. **专用 Agent 与主 Agent 接入。** 建立同时覆盖三个模块的职责提示、Preset、独立入口和专用委派；可信装配只读外部资料、规划插件及可选目录。验证其他专用 Agent 共存、目录与身份隔离、启动失败、取消、资源释放和会话恢复。
5. **端到端验证与交付。** 固定模型替身分别走查修仙世界和城邦群，从主 Agent 委派到三类实际规划文件及跨模块关联；覆盖同一蓝图对应多个待审局势方案、人物成长蓝图与成长线不重复维护、来源变化、无权、冲突提示、明确留白、目录过期、跨世界拒绝及失败恢复。单独用真实模型检验所选样例的工具使用与规划内容，报告人工审阅和未覆盖范围。完善文档并在完成本联合计划后等待用户指示，不自动进入世界专有模块或世界运行。

**验收：** 用户能按世界读取宏观发展蓝图、故事线和人物成长蓝图，定位各角色成长线，并核查规划对象之间及其适用初始局势方案的关联；详细成长内容与跨人物规划职责明确。规划、已发生历史、当前状态、人物认知及用户确认状态不混淆；不存在的能力、未核验资料和未知如实报告。

## 契约步骤需继续细化

- 一个宏观方向在不同局势方案下的适用说明如何表示；同一故事线、成长线或成长蓝图规划项是否需要单独限定适用方案，以具体例子避免候选方案串用。
- 故事线和每个人物唯一成长线的长期 / 阶段关系、不同可能方向的表达、分支与合流、多条线复用事件构想及跨人物规划项的引用方式；可查询需求先于结构设计。
- 条件、规划确定程度和展开等级是否需要固定枚举；用户要求、待审状态、未来规划及实际发生分别表达，不将建议字段提前视为业务决定。
- 用户审阅、规划确认、世界演化后的历史留存及实际结果与规划偏离后的调整，属于后续工作；本计划不将其伪装成现有能力。
