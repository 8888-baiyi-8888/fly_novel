# 初始局势：现状与验收场景

本文记录[初始局势计划](world-initialization-stage-6a-initial-situation-plan.md)的首步核对和开发验收依据。一个世界有一个初始化起始时点，可以保存多个待审方案；每个方案按需建立互相关联的局势条目，并保留总览。方案的保存不等于采用或确认。

## 实际能力

世界工作区按世界和负责人约束可读写目录，资料目录登记实际成果；目录记录不是正文或确认。历史事件支持初始化相对时间和规划者完整读取，但没有跨模块统一起点对象或时间换算。组织模块分别保存组织、组织关系和成员关系；地图维护地点和通路，人物模块维护人物及人物关系。它们的存储句柄、版本与查询接口不同，没有统一的跨模块局势服务。具体能力和限制以各模块说明为准。

历史 Agent 的可信引用绑定可借用地图、组织和人物句柄并核对世界及负责人；局势 Agent 尚不存在，不能假设它已经获得任何模块的读取权限。基础信息以现有成果文件和目录方式读取，不应虚构基础信息结构化 ID。各模块内容的审核状态与局势方案状态分开。

## 场景和验收

| 场景 | 输入与处理 | 验收 |
| --- | --- | --- |
| 修仙世界 | 灵脉变化引起迁徙的历史已保存；山门和宗门已有资料。起始时附近灵气紧张，散修与宗门争用资源，远方情况未知。 | 可定位当前局势及其历史、地点、组织引用；远方未知仍然可见，不推断角色知情或未来冲突结果。 |
| 城邦方案 A | 青河战争已结束；起点时上游封渠，下游抗议，谈判正在进行。组织敌对关系存在于组织模块。 | 总览指向供水和谈判局势；各条目独立保存，可查询关联；引用组织关系而非复制成第二份权威关系，不预定谈判结果。 |
| 城邦方案 B | 同一世界、同一起点的另一候选：暂时通水，协议不稳定。 | 两方案和各自条目可分别读取和修改；更改 A 不覆盖 B；不因为存在 B 就自动选择 B。 |
| 历史与当前状态 | 停战历史与组织当前敌对并存；水渠被毁的记录与局势中的正常通水缺少解释。 | 前者不自动判为冲突；后者列出实际来源及待核实事项，不自动改写历史、地图或局势。 |
| 数据不可用 | 某组织关系未建档、历史来源变更或读取无权。 | 分别保留未关联线索、来源过期或不可核验的说明；不能把未配置、无权或损坏解释成不存在。 |
| 失败恢复 | 写入结果不确定、主子 Agent 中断、重建同一 Session。 | 保留已写入成果，先核验文件和版本再继续；Session 本身不能证明任务完成，目录登记与业务保存分别报告。 |

## 后续约束

局势开发由专用 Agent 负责，主 Agent 协调和整合，仍可补充十个内容模块之外的内容。人物知道什么来自人物自身资料和后续实际经历；局势规划者可读的资料不能直接作为角色认知。未确认资料按版本修改，已确认资料的候选与后续确认流程保持分离；世界演化留存和角色运行隔离不在本阶段实现。实际存储结构与可机械核验的引用类型在下一步契约中细化。
