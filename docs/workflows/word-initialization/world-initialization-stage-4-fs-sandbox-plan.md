# 文件能力第五包：`dsh-fs-sandbox` 文件修改边界开发计划

本文细化[第四阶段的文件修改边界步骤](world-initialization-stage-4-file-tools-plan.md#5-dsh-fs-sandbox文件修改边界)。目标是在可信应用明确提供的授权范围内限制文件修改，逐包核对上游依赖，在真实后端上验证拒绝路径和资源释放。本文是开发计划，不表示沙箱已经接入。按编号一次实施一步，验收并报告后停止，等待用户指示再进入下一步或下一包。

## 范围与已知接入点

用户提供的 DeepSeek Harness 官方下载快照中，`packages/fs/fs-sandbox` 版本为 `0.2.2-rc.1`，源码包含 `src/index.ts`、`src/containment.ts`，测试包含 `tests/fs-sandbox.spec.ts` 和 `tests/containment.spec.ts`。快照没有已核验的 Git 提交标识；实施时记录实际使用文件的哈希和许可证，不将其冒充其他包曾使用的固定提交。

快照的 `SandboxedFileSystem` 扩展 `LocalFileSystem`，作为唯一的 `ctx.fs` 后端装配；它依赖 `ctx.sandboxPolicy`，针对写入、编辑、补丁、删除及移动检查修改目标，读取操作沿用本地后端。上游 `workspace-write` 使用 `writableRoots`，可能允许会话工作区、额外可写根及平台临时根；`read-only` 拒绝修改，`danger-full-access` 不限制修改。上述模式和临时根只是上游行为，不预先决定本项目的授权配置，也不假设单个工作区已经限制全部写入。

现有 [`@fly-novel/fs`](../../../src/agents/plugins/fs/fs/README.md) 暂未引入上游 `sandboxMode` 和修改方法的 `sandboxPolicy` 参数；[`@fly-novel/fs-local`](../../../src/agents/plugins/fs/fs-local/README.md) 的 `cwd` 是路径解析基准，不是授权边界；[观察策略](../../../src/agents/plugins/fs/fs-observation-policy/README.md)只提供观察与版本保护。可信应用须决定策略及工作区归属，模型提供的路径、参数和上下文不得自行扩大授权。读取、目录列举与搜索授权另行落实，本包不提供通用进程沙箱，不提前开发文件工具或生产 Agent 装配。

上游在检查前重新解析目标并将新目标交给后端，但路径检查与实际系统调用之间仍有符号链接或目录替换竞争；不能将它描述为内核隔离、跨进程事务或对恶意本地进程的完整安全边界。只有明确威胁模型和剩余风险后，才可决定是否满足本项目需求；如必须抵抗并发路径替换而选定实现无法保证，先列出阻塞及所需系统级能力，不以常规路径测试代替证明。

## 1. 核对上游依赖、契约与威胁模型

1. 核对指定快照的 `fs-sandbox` 全部源码、包清单、测试、公开入口、仓库及文件级许可证；记录版本、版权、源文件哈希、更新来源和本地适配范围。区分运行、peer、类型、构建及测试依赖；核对官方发布包的依赖、模块格式与项目 CommonJS／Cordis 兼容性，不因版本相同推断内容相同。
2. 递归核查 `dsh-sandbox`、`dsh-sandbox-policy`、`writableRoots` 及其实际传递依赖、Session 和提示词耦合，分清模式解析与进程沙箱的职责。比较官方包和源码移植的成本及许可证；仅将所选实现实际必需的辅助包列为独立前置步骤，不因名称相似引入平台进程沙箱。
3. 对照本地 `fs`、`fs-local` 的接口和调用方，列出恢复 `sandboxMode`、修改方法参数或其他契约的必要变更及测试；检查 `FsError`、版本保护、取消和移动部分成功的语义与运行时类身份。没有现成文件工具时，明确使用受信任的测试调用方，不伪造工具已接入。
4. 确定每个 Agent／Session 的策略由哪个可信组件创建、如何传递和释放，明确独立调用、缺少策略、无效根、只读模式和未知模式的拒绝或默认行为；不让模型可控参数、可伪造身份、宽松 fallback 或额外根绕过可信配置。对每次调用可传入策略的上游接口，明确调用者信任边界及禁止擅自提权的机制。
5. 制定威胁模型和受测边界：工作区、只读资料、草稿可写区域、允许或禁用的额外根及临时根；分别核对绝对路径、父目录、符号链接、链接替换和目标不存在时的解析。明确平台支持及无法消除的检查到使用竞争；若上游不能达到所需边界，记录差异和阻塞，未经确认不将其宣称为安全隔离。

**验收**：形成来源与完整依赖图、契约变更清单、策略信任边界和可复现的威胁模型；辅助包接入顺序明确，未解决的授权来源或关键竞争不会留给实现阶段猜测。

**依赖与接口。** 快照清单的 peer 为 `dsh-fs`、`dsh-fs-local`、`dsh-sandbox`、`dsh-sandbox-policy` 和 Cordis，开发依赖另含 `dsh-session-projection`；策略服务通过 projection 获取 Session 模式、可注入 system prompt，运行依赖包含 schemastery 与 zod。`dsh-sandbox` 定义进程沙箱契约和文件模式，依赖 `dsh-util-values`，其 `writableRoots` 在 `workspace-write` 添加工作区、显式附加根、`/tmp` 和系统临时目录。包声明中的依赖不等于最终移植所需的最小子集；须根据选定适配逐一确认，不能直接丢弃影响模式与授权的依赖。

上游文件工具的 `sandbox.ts` 先解析 Session 的常设策略，模式升级须经过审批，再把批准后的模式传入后端；只移植后端的可选策略参数并让工具直接转发模型参数会丢失这层审批。本项目 Loop 的 `workingDirectory` 来自可信配置并传给工具，但它本身不是后端修改授权；本地解析产生绝对 `displayPath` 和 realpath 身份，修改后端按 `targetKey` 执行。未来接入必须把可信策略绑定和工具参数分开验证，不能只凭字符串 Agent ID 或目录名认定权限。

**路径风险与决定。** 上游 `checkedTarget` 在修改前按 `displayPath` 重新解析并返回检查后的目标，移动分别检查两端；`isPathUnder` 先比较规范路径，再按设备／文件身份检查祖先。它不限制读取，`danger-full-access` 不限修改，缺省策略由服务决定。上游源码明确接受检查之后、实际系统调用之前祖先被替换的竞争窗口；本项目本地后端也不提供跨进程锁。因此常规目录和链接测试只能证明受控时序下的行为，不能证明恶意本地进程同时替换路径时的硬隔离。

用户选择先实现上游同等级的应用层修改边界并记录限制，生产装配前重新评估。生产启用仍要求单独验证读取和搜索授权、可信工作区配置，以及已确认资料保护；不能将此决定解释为接受恶意本地进程下的硬隔离。

**前置适配方案。** 将上游模式和可写根能力与策略服务分别作为前置工作区包接入，再接入继承本地后端的沙箱包；保留上游文件边界所需的模式和根语义，明确记录不引入的进程执行、会话投影和提权能力。可信应用在每个 Agent 作用域提供并校验固定策略，缺省为只读；`workspace-write` 的根须显式配置，附加根及上游平台临时根的效果必须在接口和测试中显式展示。初期不暴露模型可指定的模式覆盖，独立调用同样由受信任的作用域策略约束。Session 的工作目录不自动成为授权根；如将来引入每 Session 策略或升级，需另行设计可信绑定与审批并同步调用链。

现阶段可在沙箱后端作用域读取固定策略，不为每次修改增加上游可选策略参数：同一个后端实例只代表该 Agent 的固定策略，不允许调用方扩大授权。保留现有 `fs` 修改方法和观察事件契约，必要时补充只读的能力信息；`fs-local` 继续作为无边界后端，不声称获得沙箱保护。测试通过真实 Harness 分别装配不同 Agent 的策略与后端，覆盖未提供策略、无效根、不同实例和未知调用，不以服务作用域替代事件隔离。未来生产文件工具须在独立读取授权、搜索授权及业务资料保护完成后才能装配。

## 2. 按需接入前置契约与辅助包

前置子步骤：`@fly-novel/sandbox` 复用上游文件模式与可写根计算，保留平台临时根语义，不引入进程执行接口；包来源及调整见其 README。离线冻结锁文件安装、包构建及根计算聚焦测试 2 项通过。

前置子步骤：`@fly-novel/sandbox-policy` 提供 Agent 作用域不可变策略，默认只读，可写模式要求显式真实工作区；未装配策略的 Agent 不继承根服务。构建及策略、根计算和文件服务聚焦测试 17 项通过。该服务不执行文件授权，沙箱后端仍待接入；项目暂不实现上游 Session 模式投影和调用级提权。

1. 将第 1 步确认的每个必需辅助包作为独立子步骤逐一实施和验收：核对许可及来源，建立独立包、公共入口、类型与构建、最小适配和聚焦测试，再更新工作区、锁文件、源码映射与构建边界。每个辅助包完成后报告并停止；未确认需要的依赖不预先引入。
2. 按已确认方案调整 `@fly-novel/fs` 的模式和修改调用契约，逐一同步现有后端、所有调用方、类型测试与 README；未受沙箱保护的后端不得因类型变化被描述为已受保护。缺失或无效策略的行为在最早可判断处明确报错。
3. 验证策略根来自可信配置，不能通过工具参数或非本 Agent 的 Session 冒用；对默认值、重复装配、服务缺失、初始化失败及作用域释放进行测试。若选用的方案不需要更改现有契约，记录理由和等效验证。

**验收**：每个实际必需的前置包及契约单独可构建、可验证和可追溯，授权策略不会因缺少配置静默降级；未引入与文件修改无关的能力。

## 3. 建立沙箱后端与受控装配

1. 在 `src/agents/plugins/fs/fs-sandbox/` 建立独立工作区包，选择官方包或可追溯的源码适配；提供项目公共入口、类型声明、CommonJS 构建与 Harness 显式注册定义，测试放在 `src/agents/tests/`。同步工作区、锁文件、构建配置和目录说明，保留适用许可证和本地改动记录。
2. 根据已确定的可信策略来源实现五类修改的检查与委派；移动的源和目标分别校验，检查使用的目标身份必须与后端实际修改目标一致。保留现有版本保护、取消及部分成功语义，不依赖观察策略作为授权。
3. 明确作为唯一 `ctx.fs` 后端的装配、重复安装、依赖缺失、初始化失败、作用域销毁与重新装配；禁止与普通本地后端在同一作用域重复注册。生产 Preset 暂不加入后端，读取和搜索不因本包接入而获得授权。
4. 编写包说明及重要工程决定，记录授权来源、可写根、拒绝错误、默认行为、资源归属、平台差异、路径竞争限制、源码和更新方法；同步受影响接口文档与架构说明。

**验收**：包可独立类型检查及构建，导入无注册副作用，仅显式装配生效；未配置策略无法误用，生产 Agent 未获得新文件访问能力。

**第 3 步结果**：`@fly-novel/fs-sandbox` 复用上游目标重新解析与包含检查，依赖当前 Agent 的固定策略，不接受每次调用覆盖；公开 Harness 注册定义将其装配为 `ctx.fs`。真实 Harness 聚焦测试验证只读拒绝、工作区写入、非授权兄弟目录拒绝、重复文件后端注册拒绝、缺少策略拒绝及作用域释放，2 项通过。完整路径、移动与平台验证留在第 4、5 步；生产 Preset 未装配。

## 4. 路径边界和修改行为测试

1. 对写入、编辑、补丁和删除分别验证允许根内成功、只读模式拒绝、根外拒绝及错误码；移动覆盖源内／外与目标内／外组合，并验证拒绝时两端内容不变。版本过期、缺失目标、取消和后端错误保持各自语义，测试不以权限拒绝掩盖其他路径。
2. 覆盖相对路径、根本身、同名前缀的相邻目录、绝对路径、`..`、缺失祖先、目录与文件链接、链接指向根外及解析后替换；明确合法绝对路径可否使用，以最终授权位置为准，不把所有绝对路径一概视为越界。测试路径及链接在调用之前和受控检查点分别变更，记录无法封闭的检查后竞争。
3. 覆盖工作区根、额外根、平台临时根的真实配置与组合，包括默认值、禁用和越界场景；若上游策略允许系统临时根，测试不得把越界目录放在仍被允许的临时根中而误判。Windows 大小写、盘符、UNC、短名及目录链接与 POSIX 语义分别按可用平台验证，权限或能力不足只标记实际跳过项。
4. 以受控事件调用方组合观察策略与沙箱，核对授权拒绝、观察保护和后端调用的顺序与错误传播；不把意图事件、工作目录、版本号或词法前缀判断当作路径授权。

**验收**：每种修改和双端移动均有允许及拒绝实例，根配置、别名和已知竞争有证据；未覆盖平台及无法消除的路径替换窗口明确记录。

**第 4 步结果**：Windows 上真实后端与 Harness 的聚焦测试 11 项通过，覆盖五类修改、移动源／目标、只读、绝对路径、父目录、相邻目录、缺失祖先、目录链接及检查前链接替换；验证平台临时根和可信附加根的实际放行、版本过期与取消，以及与观察策略组合时越界仍被拒绝。未验证文件符号链接、Windows 短名／UNC、其他平台或检查完成后实际系统调用前的路径替换；后者仍是用户已知的上游同等级限制。

## 5. 真实后端、Agent 隔离与生命周期

1. 在互相隔离的临时目录中，通过真实 Harness 和沙箱后端验证多个 Agent 各自的可写根、只读策略、共享路径访问和销毁互不影响；覆盖策略缺失、无效及独立调用，不因全局事件总线或根 Context 服务继承误用其他 Agent 的配置。
2. 使用受控同步点验证取消、版本变化、错误和移动部分成功；对允许路径确认操作实际发生，对拒绝路径确认目标及其他位置未变化。区分应用级测试、操作系统权限和外部并发竞争，不把测试替身视为生产授权调用链。
3. 验证服务和策略的销毁、等待中的操作、重复关闭、初始化失败及重新装配；根据实现实际归属清理临时目录和监听句柄。跨平台限制及 Windows 文件符号链接、ACL 权限或 POSIX 模式位的跳过原因如实报告。

**验收**：真实后端和多 Agent 的受控授权行为可复现，失败与清理路径明确；生产启用前仍须独立完成读取、搜索和世界资料保护。
