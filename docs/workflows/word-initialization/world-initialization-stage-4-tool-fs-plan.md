# 文件能力第六包：`dsh-tool-fs` 文件工具开发计划

本文细化[第四阶段文件工具步骤](world-initialization-stage-4-file-tools-plan.md#6-dsh-tool-fs模型文件工具)。目标是复用官方文本文件工具，接入项目 Tools、文件契约及明确的读取／修改授权，验证观察事件和多文件补丁结果。按编号逐步实施，每步验收、提交后自动进入下一步；只有用户另行要求或出现必须决定的阻塞时停止。

## 来源与现状

用户提供的 DeepSeek Harness 官方下载快照 `packages/fs/tool-fs` 版本为 `0.2.2-rc.1`，仓库根许可证为 MIT、Copyright (c) 2026 DeepSeek，快照没有已核验 Git 提交标识。包清单 SHA-256 为 `f01a4276d00742e7c14839f4bd969de9d1cd1a15a8de2decae0af9d0cf865e5e`；入口、读取、写入、编辑、补丁入口源码哈希分别为 `a25592c2541fbc609b2b4576d365e58e9fc881e959d19bca9c1be16e78f0c469`、`a7f2c77f6bfaab1c8cba3aaf2fe187ba9c4ad75af905b54a6465a66760d1ab84`、`912db08eed1ea972a0a22fcded8428f6abde96fb588fd3f32529f4b5526ad6a8`、`276175218582695aa991cc8d044dd39f0aee667b90ac0f15964185865fc3211f`、`9973f523221eb3274858bb4a8dd4eec37c6f5b4da7eca592133842cb1b1b4802`；实施时对所有实际使用的源码和测试补齐哈希。

快照直接依赖 `diff`、schemastery、补丁库和两个工具辅助库；peer 包括文件契约、Tools、LLM、Session、工作目录、系统提示、沙箱策略、用户审批和附件。入口默认注册读、写、编辑，补丁默认关闭，图片依赖附件；本阶段仅接入 `read`、`write`、`edit` 和显式启用的 `apply_patch`，不提前实现图片、审批升级或搜索。上游工具用事件 actor 发出观察及意图，并将意图交给后端；当前项目已有相应事件和 Session 上下文，但策略按 Agent 身份路由，须通过真实工具链验证。

现有 [`read_file`](../../../src/tools/README.md) 以可信 `workingDirectory` 限定读取；[`fs-sandbox`](../../../src/agents/plugins/fs/fs-sandbox/README.md) 只约束修改，且其上游语义允许平台临时根，不能当成读取授权或资料保护。`stat` 与读取分离可能在外部并发修改时产生内容和版本不一致，不能把先 `stat` 后读取直接称为原子快照。文件沙箱路径检查后仍有替换窗口，生产启用前须重新评估；本阶段不自动装配生产 Agent。

## 1. 核对上游、依赖及授权方案

1. 阅读全部相关源码、测试、公开入口及许可证，核对快照和官方发布包的清单、模块格式与 Cordis／Tools 版本；区分必需的运行、peer、类型、构建和测试依赖，记录源文件哈希和本地改动。对实际需要的辅助库按包分别接入，不因图片或审批引入无关能力。
2. 对照上游的文件工具 schema、Tools 输出契约、错误映射、SystemPrompt、工作目录和观察事件；确定 read／write／edit／apply_patch 的最小可复用适配、工具生命周期和实际注册方式。明确所有调用方及 `read_file` 和 Skill 资源读取的保留或替换方案。
3. 明确独立读取授权：由可信应用指定 Agent 可读取的根和视图，读取、补丁预检与错误不得泄露根外内容；写入和删除由沙箱后端独立控制。区分解析基准和授权根，不允许模型自行选择或扩大根。核查上游临时目录的附加写入范围与业务资料保护，生产装配前保留用户要求的风险评估门槛。
4. 设计内容／版本一致性与失败处理：读取结果和观察版本必须有可验证关联；列出当前后端可提供的保证与仍可能出现的外部竞争。如需契约变化，明确变更、兼容策略和测试，不以观察策略或重试掩盖未解决风险。
5. 建立逐操作事件／后端顺序表：读取存在／缺失、写入、编辑、补丁、删除、移动源与目标、取消、监听器错误及部分成功。明确多文件补丁不是事务，失败时逐项报告已完成、未完成或结果未知。

**验收**：来源、依赖与适配路径可追溯；读取授权、版本关联和错误／部分成功语义可验证，必须的跨包前置事项明确。

## 2. 必要前置包与受控装配

1. 对第 1 步确认的每个必需辅助包分别核对来源、许可证和依赖，独立接入、测试并提交；复用项目已有包，避免复制已存在的补丁或工具服务。
2. 落实可信读取授权与所需后端契约变更，验证绝对／相对路径、缺失祖先、链接和不同 Agent 的隔离；不将 `cwd` 当作修改授权。对内容与版本的一致性按第 1 步方案实现和验证，并保留无法排除的竞争说明。
3. 建立 `src/agents/plugins/fs/tool-fs/` 独立包、公开入口和 CommonJS 构建，通过项目 Harness 显式注册工具与所需服务；注册失败和作用域销毁应注销工具，不改变生产 Preset。同步工作区清单、锁文件、构建映射、README 和 Agent Note。

**验收**：包和必需依赖可独立构建、类型检查及清理；缺失授权配置或依赖时明确失败，导入不注册工具或访问文件。

## 3. 文本读取、写入与编辑

1. 通过项目真实 ToolsService 验证 read 窗口、行号、字节／行长度上限、截断、缺失、非文本、取消及错误输出；成功读取才登记与结果对应的观察，确认缺失时登记缺失。验证观察监听器失败和读取前后文件变化。
2. 验证 write 创建／覆盖、edit 字面替换、重复匹配和失败；意图结果传给后端，成功后的新版本更新观察，失败不伪造观察。覆盖没有观察策略、只读策略、无所有者以及跨 Agent 的事件路由。
3. 覆盖根外读取与修改、绝对路径和符号链接、可信目录切换和未知调用者；不能把文件修改沙箱的临时根误作读取根。使用受控替身与独立临时目录，不依赖模型凭据。

**验收**：真实工具注册和执行路径的 schema、模型结果、授权与事件行为有正反例；未验证的并发窗口单独记录。

## 4. 多文件补丁与部分成功

1. 复用官方补丁解析、规划、预检与执行的适用行为，显式启用 `apply_patch`；覆盖新增、更新、删除、移动及同一文件重复操作。所有内部预检读取同样受读取授权约束，内部读取不冒充模型已观察。
2. 按操作顺序验证写／编辑／删除意图、源／目标授权和版本保护，成功后只更新实际完成的观察。以受控失败验证中间操作失败、移动源保留、取消和监听器异常；输出准确区分已提交、未执行和结果未知，不声称整体回滚。
3. 覆盖补丁路径遍历、链接、跨根移动和大量／无效输入；授权检查发生在读取内容或修改之前，不通过错误消息泄露未授权文件内容。

**验收**：受控多文件用例的磁盘状态、观察与模型结果一致，部分成功可重放和理解。

## 5. 生命周期、集成与交付

1. 验证工具按 Agent 实例注册与注销、重复注册、初始化失败、取消和销毁；固定模型替身通过真实 Loop 执行读取与修改，覆盖两个 Agent 的读取根、写入根及观察隔离。
2. 对照上游测试迁移适用行为与许可证，更新 `read_file`／Skill 调用方及文档；未引入图片、审批升级和搜索时明确边界。
3. 验证冻结锁文件安装、相关包和项目类型检查、干净构建、公开入口及导入无副作用、聚焦测试、许可、链接和空白检查；记录实际平台、通过与跳过结果。
4. 复核生产装配门槛：读取／搜索授权、上游临时根、恶意并发路径替换及世界资料保护未完成时不装配生产 Agent；本包验收后继续下一项子进程基础，不自动宣称整个第四阶段完成。

**验收**：工具真实执行链与模型输出可审查，权限和生命周期有证据，部分成功及尚未解决的风险如实记录。
