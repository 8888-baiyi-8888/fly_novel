# 第 6A 阶段：地图与空间模块开发计划

本文细化[内容模块逐项开发计划的地图与空间步骤](world-initialization-stage-6a-content-modules-plan.md#2-地图与空间)。世界初始化第一版的地区规划方向见[第一阶段业务场景](world-initialization-stage-1-plan.md#2-生成第一版供审阅)。本文是实施提案：除现有能力外，地图插件、工具、文件格式和 Agent 均尚未实现；其中具体数据契约和待确认问题须在实现前结合示例审阅。

## 目标与范围

地图与空间模块负责地点、地区的空间描述、父子层级及其他关联，表达整体范围、大致位置、层次、通行与障碍；地图与空间专用 Agent 负责按世界构想决定哪些内容需要深入、概述或保留留白。地点可以逐层包含子地点，层级是模块的核心能力，不要求所有分支展开到相同深度。它可独立运行，也可接受世界初始化主 Agent 委派。专用 Agent 不代替组织、人物和历史模块维护其完整资料；其他模块以地点引用关联实际成果。

本阶段将地图资料保存在可阅读的文档中。建议专门在 `src/agents/plugins/map/` 建立地图工作区插件，由可信应用为获授权 Agent 显式装配地图服务及工具；地图专用 Agent 的职责提示词和应用入口分别按现有 Agent 组织方式建立。插件名称和下面的工具名为待实施命名，不代表目录或接口已存在。

第一版建立可查询的文字地图，不要求渲染图片或自动生成完整世界；不实现 GIS、路径最优化、故事运行、角色行动或通用跨模块关系引擎。后续如需地图图片，可依据同一资料另行设计展示，不把图片像素作为地点权威记录。开发顺序不等于世界内容生成顺序；资料不足或地图未展开时，不虚构完整地图。

## 场景与边界

| 场景 | 需要表达的内容 | 不应推断 |
| --- | --- | --- |
| 资源有限的城邦群 | 三座城、水源与山谷的位置或相对方位；重点路段的通行、障碍及未知距离。外海按用户要求明确留白。 | 没有道路记录不代表道路不存在；未知距离不等于零；不因外海留白把群山之外全部设为禁止设定。 |
| 开放式修仙世界 | 大陆、山脉、宗门所在地点和只知名称的秘境；重点地区可有坐标概况，远方可留白。 | 宗门的成员、目标和控制权归组织资料；秘境入口与内部位置不必共享同一坐标系。 |
| 嵌套地点 | 世界 → 大陆 → 地区 → 城邦 → 城区 → 建筑，必要时继续细分；其他分支可以只有地区概况。 | 不要求每层都存在，也不因尚未创建子地点就断言没有子地点。 |
| 交叠区域 | 地理上的河谷、行政上的城邦辖区和势力活动范围可能重叠。 | 主要父子层级不能替代所有交叠、活动范围和行政关系，不由几何重叠推断管辖。 |
| 同名地点 | 两处同名的青山镇分别位于不同地区，名称查询返回两个候选及上下文。 | 不按名称自动选择唯一地点，不因名称相同合并。 |

与世界基础信息的交界：基础信息可以概述三座城邦共处一条河流流域；地图模块负责按需定位地点、表达空间关系和通行详情。基础信息 Agent 的建议不是地图模块已确认成果。地图 Agent 引用背景原文并区分用户要求、已有资料和本次建议；提炼背景不得凭空指定题材、扩展用户明确留白的范围或将建议写成已确认事实。

## 文档存储方案（建议）

### 目录与权威来源

可信应用为世界配置地图负责人的专属目录。下图是该目录内部**拟议格式示例**，实际根目录由应用配置，名称不能由模型授予权限；不要求用户预先创建每个子目录。

```text
地图负责人目录/
├── map.md                   世界空间概览、坐标参考与明确留白
└── places/
    ├── <地点ID>.md          地点正文和最小可机读元数据
    └── <地点ID>.md
```

`map.md` 是世界空间概览与坐标参考的权威文档；每个地点文件是该地点的权威文档。两者均为 UTF-8 Markdown，必要的机器可读信息放在 YAML front matter，正文供人和模型阅读；沿用现有 `yaml` 与 `zod` 技术，不以 YAML 标题或正文段落推断机器状态。地点文件名使用程序生成的稳定 ID，而非名称，改名不改变 ID 或路径；同一世界的 ID 唯一，其他世界的同名或同 ID 不自动是同一对象。用户确认前，目录登记、文件保存和 Agent 返回均只代表待审建议。

这是新模块首次建立的版本化文档格式，不将已有基础信息草稿或世界资料自动当作地图文件，也不改写角色、资料目录和 Session 现有格式。`formatVersion: 1` 只用于本格式；缺失版本、未知版本、重复 YAML 字段、非法编码、重复 ID 或损坏文档明确拒绝当作有效地图资料，保留原文件，不自动修复、覆盖或删除。将来升级时先指定版本递增、迁移或拒绝读取及备份策略；当前不存在需要隐式迁移的旧地图格式。

### 资料项与最小结构

下表描述拟议语义，最终字段名、表示方式和工具签名在格式设计步骤中确定，不要求模型手写 YAML。仅对身份、查询、定位和需校验的关系定义机器结构；历史、组织、人物或丰富的地点描写仍引用来源或写在适当正文中。

| 文档 | 必需的机器可读内容 | 按需内容与正文 |
| --- | --- | --- |
| 世界空间概览 `map.md` | 格式版本、该世界内的地图身份、资料状态；可信世界身份由装配绑定并与文档标识核对。 | 世界覆盖范围、一个或多个坐标参考系的 ID、原点 / 轴向、单位或比例、适用范围和精度说明；世界级明确留白、来源及概览正文。尚无可靠比例时明确未知，不编造真实距离。 |
| 地点文件 | 格式版本、地点 ID、名称、审核状态、资料展开程度、父级归属的明确状态；世界身份与所属地图由可信装配和文档校验绑定。 | 已确定父地点 ID、同名辅助说明、别名、可选坐标或大致方位、其他空间关系、来源、明确留白及地点正文；未知信息不自动补默认值。 |

建议第一版状态仅表达本模块可真实维护的待审建议，不提供模型工具直接设置 `confirmed`。既有用户给定或已确认的背景通过来源引用，不因写入建议文件变成用户确认；未来的确认和已确认视图接入第 7 阶段方案后另行设计。来源、待审状态、坐标精度和留白是不同维度，不合并为单一枚举。地图文件保留用户要求与 Agent 建议的可辨认表达；目录简介只用于定位。

### 地点资料状态（建议，待确认）

为了查找尚未详细建立的地点，建议每份地点文档独立保存**资料展开程度**，由负责该地点的 Agent 根据本地点已有正文判断，取值采用以下三个互斥等级。英文值只是拟议的机器标识，格式实现前与用户确认；不能通过正文长度或子地点数量自动判定。

| 展开程度 | 建议值 | 含义与示例 |
| --- | --- | --- |
| 未展开 | `unexpanded` | 已识别该地点，可能只有名称、父级或简短线索，尚未形成地点概况；例如只知道青河地区有一处东部山区。 |
| 概况 | `overview` | 已有足以辨认和理解地点的简要描述，但尚未按该世界当前需要进行详细设定；例如知道东部山区大致方位和地貌。 |
| 详细 | `detailed` | 已按本次任务或世界当前需要，较深入描述该地点的重要内容；例如曲水城已说明主要环境、布局和通行特征。它不是永远不需补充，也不表示所有字段或子地点齐全。 |

状态只描述**该地点自身资料**，不继承父地点或子地点的状态。曲水城可以是详细，下面的北城区仍可未展开；北城区变成概况时只更新北城区的文档。子地点列表和状态由地图插件查询并动态汇总，父地点不另存一份清单；查询未覆盖全部文档时明确报告不完整。没有地点文档不等于该地点是 `unexpanded`，只能报告没有找到已记录地点；只有知道地点存在且需要追踪时，才可创建未展开的简短地点建议。

**审核状态独立。** 展开程度不代表事实已确认：同一个地点可以是“详细、待审”，也可以将来成为“概况、已确认”。第 6A 阶段新建成果仍是建议；保存、登记及设为 `detailed` 均不触发确认。后续的待审修改和可信确认由第 7 阶段设计，不让模型自行改成已确认，也不预先声称所有状态流转已实现。

**未知和留白不作为展开等级。** “不知道这里是否有其他城镇”不是一个已知地点的状态；“外海明确留白”是用户对某范围或内容的约束，也不等于待开发任务。已知地点中某项未知、父级待定、坐标未知和明确留白分别记录；查找失败、无权、损坏或资料缺失是操作结果，不修改地点的展开程度。

**状态更新。** 新建时同时写入该地点正文与展开程度；后续完善时对该地点生成待审修改，并在同一候选文档中同步拟议状态，不能因为工具返回成功或子地点增加而自动升级。内容减少、被撤回或设计重点变化时可以建议下调，不强制状态单向递增；现有资料和状态保留至用户按后续确认流程处理。应根据本次世界规划需求判断，不规定所有地点必须达到 `detailed`。

### 地点父子系统（建议实现）

用户确定地点需要逐层包含子地点。建议采用**一个主要父地点加独立的其他空间关系**：主要父子层级用于组织和逐级浏览地点，行政管辖、势力范围、河流跨越及地理交叠另用带明确语义的关联表达，不因选择一个主要父地点而丢弃这些关系。一个地点本身既可以是子地点，也可以继续拥有子地点；不规定必须固定为大陆、省、市等几级。

```text
世界地图（map.md，作为顶层入口）
├── 玄洲大陆
│   └── 青河地区
│       └── 曲水城
│           ├── 北城区
│           │   └── 青石客栈
│           └── 南城区（只建概况，内部暂未展开）
└── 远方群岛（位置及内部结构待定）
```

每个地点仍使用稳定 ID 和独立文档，上图是**逻辑层级**，不要求把文件按目录嵌套；避免父级改名、移动时必须移动全部子文件。建议每个地点在自己文档中保存主要父级信息，父文件不重复保存一份权威子地点清单；插件按父级 ID 建立可重建的子地点索引，从同一份关系反向查询。地点名不必唯一，查询可展示“青河地区 / 曲水城 / 北城区”等祖先路径；该展示路径不是持久身份或文件路径。

主要父级至少区分：属于世界地图顶层、指向已知地点 ID、父级待定；父级待定或读取失败不能被当作顶层。`map.md` 是世界层级入口，不强行创建与世界配置重复的地点对象。顶层表示该地点直接归世界地图组织，不断言世界不存在更大的外部空间。父级 ID 必须属于同一世界地图；已知父级要能定位，未创建或无法确认的父级以待定及文字线索表达，不虚构 ID。

创建子地点时验证父级存在、身份与授权范围；禁止自为父级或形成循环。读取时如父文档缺失、损坏、无权或层级包含环，保留子文档并报告断链 / 无法判断，不静默改成顶层或删除。祖先、子地点和后代查询均需标出实际覆盖范围；未扫描完整、超过限制或读取失败时，空结果不能表述为没有子地点。

对于地点搬迁、更换主要父级或合并：保留地点 ID，先读取并核对地点及新父级版本、拒绝循环和跨世界引用，生成待审修改与影响线索；确认后如何提交和检查其他资料，留给第 7 阶段。第一版不实现递归删除、自动迁移所有后代或级联改写其他模块；相关成果保留，父级变化对展示路径的影响不等于子地点 ID 改变。按业务需要确定的多个空间归属或跨区域地点，通过其他明确关系表达；是否需要多个并列的主要父级，仍需结合用户场景确认。

### 坐标、范围和其他空间关系

- **坐标参考系。** 坐标必须指向 `map.md` 已声明的参考系；记录二维坐标值及该参考系的轴向、单位 / 比例和适用范围。例：城邦群示意平面可以定义东为 x 正方向、北为 y 正方向，单位为“示意格”，格与公里的换算未知；`(2, 1)` 因此只是相对位置，不可声称距离为 2 公里。缩放、旋转、参考系之间换算或地图范围调整前需明确影响，不自动转换旧坐标。
- **精度与缺失。** 坐标可标示概略或精确到明确的尺度；未知坐标、只知大致方位和用户明确留白分别表达。地图概览建议提供范围与大致尺度，符合第一阶段方向；无法确定时说明未知，不要求每个地点都有坐标。点坐标只表达选定参考点，不代表地区边界或行政范围。
- **地点与区域。** 主要父子层级按上一节维护；跨越多个区域、交叠或不确定的情况另用有明确语义的关联表达。第一版不要求多边形或完整地理拓扑；区域边界与重叠的详细表达按实际需求确定，不能以点坐标推断区域包含。
- **其他关系的权威归属。** 建议一条道路、跨区域等关系只写入其起点地点的文档，记录关系类型、目标地点 ID、方向 / 语义、来源或不确定说明；目标文档不维护另一份权威副本。查询目标的入边可扫描全部地点的关系并标注查询范围；对称或反向含义只在关系类型明确支持时呈现，不能自动发明另一条事实。主要父级只存于父级字段，不另写一条重复的普通包含关系。允许同一对地点有不同语义和多条关系；不允许按名称代替 ID 定位。
- **通行与距离。** 在关系或相关正文中按需记录通行方式、障碍、条件、方向、估计距离 / 时间及其单位与精度；无数据时报告未知。距离的坐标系、路线距离和直线距离不能混用；第一版不以欧氏距离替代实际行程，不自动推断双向可通行。未来需要路线寻优时再定义算法与数据充分性。
- **未解析引用。** 跨模块引用或尚未建立的地点线索可在正文中作为待定位线索；已登记的机器关系若目标缺失，应返回悬空关系及其来源，不假定目标不存在或自动创建目标。是否允许保存指向缺失 ID 的关系在实现前明确为校验规则；建议已知目标用 ID，未知目标使用正文线索，不分配虚构 ID。

### 文件示意

以下为虚构的概念示例，不是已经可运行的格式或固定内容模板。实际 Schema、坐标参考和状态字段以实施前确认的格式契约为准。

```markdown
---
formatVersion: 1
id: 11111111-1111-4111-8111-111111111111
name: 曲水城
status: suggested
detailLevel: overview
parent:
  kind: place
  id: 22222222-2222-4222-8222-222222222222
position:
  frame: river-valley
  x: 2
  y: 1
  precision: approximate
---

## 描述
Agent 建议：城邦位于河谷中游，交通条件待进一步讨论。

## 来源与留白
用户要求：外海留白。其他来源及无法判断的事项按实际资料记录。
```

该示例说明地点身份、主要父地点和可选坐标；子地点列表由插件依据子地点文档反向查询。示意坐标系 `river-valley` 需要在同一世界的 `map.md` 中定义。示例中的 ID 仅用于说明文件间定位，不是实际世界资料。

## 查询、提取与索引

地图插件的读取服务以文件正文为权威；建议启动或首次查询时扫描并解析授权地图目录，建立**仅驻留内存、可重建**的地点 ID、名称 / 别名、父子及其他关系索引。索引不作为用户数据、不写入额外数据库或权威清单；正文和元数据只维护一份。文件变更后通过显式重新扫描或可靠的版本核对刷新；文件监听事件仅可作为失效线索，不把未收到事件当作一致性证明。若日后数据规模证明需要持久索引，须单独设计索引版本、完整性、重建与失效策略。

| 意图 | 建议输入 | 结果与限制 |
| --- | --- | --- |
| 查找地点 | 名称 / 别名或关键词；必要时按区域线索、展开程度缩小范围。 | 返回所有匹配候选的 ID、名称、展开程度、审核状态、简要上下文及来源定位；分页和顺序稳定。同名不自动选一个，名称检索不承诺语义召回或世界中所有未登记资料。 |
| 读取地点 | 世界内地点 ID。 | 返回完整地点正文、元数据、相对路径和内容版本或摘要；需要外部背景时提供引用而非把目录简介当正文。 |
| 查询父级与祖先 | 地点 ID。 | 返回直接父级及按需逐层追溯的祖先、身份与来源；顶层、待定、断链和受限分别表达，检测循环。 |
| 查询子地点 | 世界顶层或某地点 ID，按需指定层数、展开程度筛选和分页。 | 默认返回直接子地点，可有限深度查询后代；从各自文档读取展开程度及审核状态并动态汇总，返回地点身份、父级及覆盖范围。深层查询不默认加载全部正文，取消或限制时不冒充完整。 |
| 查看关系 | 地点 ID，出边 / 入边及可选关系类型。 | 返回关系、另一端的 ID 和来源文档；入边依扫描结果汇总，不重复写目标文档。无法读取部分文件时报告不完整，不能声明无关联。 |
| 读取地图概览 | 当前可信世界。 | 返回 `map.md` 正文、坐标参考、范围和版本；缺失、未初始化、损坏、无权及不支持版本分别报告。 |

候选结果包含来源位置与版本；读取时核对目标身份、世界和授权范围。文件数量、单文件与总读取大小、查询页大小按可信配置设置并校验；到达限制、取消、损坏、文件变化或无权时返回明确失败或带范围的不完整结果，不能把它伪装成零结果。分页使用本次查询快照版本；后续页前核对范围和文档版本，变化则拒绝继续并要求重查，不声称跨文件事务快照。实时工作区受单可信写入进程约束；索引检查仍不能保证其他进程不恶意替换路径或建立硬链接。

## 地图插件、工具与 Agent 装配

建议在 `src/agents/plugins/map/` 建立独立 pnpm 工作区包 `@fly-novel/map`，提供文档解析 / 校验、受控存储服务、查询与 Cordis 服务插件；同包或独立工具适配是否拆分，在确定依赖和职责后按现有插件惯例选择，不预建通用地图框架。独立包不直接创建 LLM、用户界面或全局单例；服务由可信调用方提供世界身份、真实路径、允许读写的身份、文件后端及限制。插件作用域拥有注册、队列与索引，销毁时取消 / 等待进行中工作、注销工具并释放资源，失败如实传播。是否复用现有 `FileSystem`、沙箱及目录服务在原型验证后确定；不绕过已有授权与文件版本检查。

| 建议工具 | 功能与授权 |
| --- | --- |
| `map_overview_read` | 读取地图概览、坐标参考及正文；获授权的地图读取方可调用。 |
| `map_place_search` | 按名称 / 别名查询候选及分页；返回来源和完整性，不仅返回目录简介。 |
| `map_place_read` | 按已选地点 ID 读取正文及版本；同名由调用方先选择候选。 |
| `map_place_ancestors`、`map_place_children` | 查询父级 / 祖先及顶层或指定地点的子地点；支持受限深度、分页和完整性说明，不要求加载整个世界。 |
| `map_relations_read` | 查询出边及扫描得到的入边，明确方向、来源和不完整范围。 |
| `map_overview_create`、`map_place_create` | 地图负责人在其专属目录创建待审建议；程序分配身份 / 路径，独占创建，拒绝覆盖；来源和留白由 Agent 根据任务提供并可审阅。 |

工具名是设计建议。读取工具可由可信应用授予主 Agent、其他内容 Agent 或地图 Agent；写工具只授予地图负责人。工具输入不能改变世界、负责人、目录或访问权限；由可信装配绑定，不能靠提示词充当安全边界。地图 Agent 的 Preset、SystemPrompt 和独立应用入口复用既有 Cordis、LLM、Tools、Session 和工作区；主 Agent 通过专用委派工具提供任务及必要背景，持久 Provider 绑定稳定身份。共享资料目录按现有机制可选登记每个成果文件，摘要不代替地图查询，也不代表确认。缺少目录时按授权地图服务读取正文；文件保存成功和目录登记失败分别报告。

## 写入、并发和恢复

1. **新建。** `map.md` 首次创建采用 `createIfAbsent`；地点 ID 由程序生成，文件在 `places/` 内独占创建。创建前校验父级状态、父级存在性和世界边界；子地点不需要修改父地点文档。已有文档不覆盖，成功后返回实际路径、地点 ID 和版本；文件保存与目录登记分开报告。取消或错误发生在提交前 / 后的结果须据实际后端返回区分；不能确认时返回目标线索并先核实，不盲目重试。
2. **已有内容。** 第 6A 阶段优先支持新建和读取。第一版尚需完善时，建议生成独立的新建议或候选文档，保留旧成果；已有资料的局部修改、影响检查和确认提交属于第 7 阶段。若为了本模块实现候选写入，必须绑定基线版本并与当前正文分离，基线变动则拒绝提交；不对模型暴露直接确认工具。候选如何定位和跨文件提交由后续确认流程设计，不在本步宣称已实现。
3. **单一权威与部分成功。** 新建地点与其他地点的关系应尽量由一个地点文件承载；一次操作只承诺单文件结果，不能把多个地点写入或目录登记说成原子事务。多文件任务中途失败时保留已完成文档，逐项返回成功、失败或未知；重新读取实际文件及目录后再决定补做。单文件覆盖若未来允许，须使用实际读取得到的文件版本执行 `replaceIfVersion`，冲突时停止，不静默合并。
4. **隔离与释放。** 一个世界只有一个可信写入进程；同一地图服务序列化相关写入，身份忙时拒绝重入。父 Agent 取消传播至子 Agent，启动失败回滚资源，子运行和服务关闭须等待进行中工作；清理失败保留必要占用并返回错误。保存完成后取消不宣称文件回滚；Session 恢复对话，不证明资料提交完成。
5. **路径与外部变化。** 地图文件由可信根与程序生成 ID 拼接，校验真实路径、普通文件与符号链接边界；模型不能传入任意文件路径写入。路径和版本检查不能抵御不可信进程并发替换、硬链接及跨进程写入；遵守现有本机文件后端限制，不在本步改造 Windows 1175 行为。

## 开发步骤与验收

1. **确认业务契约。** 用两个样例核对地点展开程度与审核状态、多层父子组织、父级待定、区域交叠、坐标与尺度、留白和同名候选；先讨论文末未决事项。比较单文件和按地点分文件后确认文档归属、版本及层级表达；未确认的业务选择不能作为已生效契约。
2. **格式与受控存储。** 在地图插件工作区包中建立文档解析、序列化和必要校验；实现独占创建、受控读取和明确错误。验证无地图、未知版本、重复 ID、重名、非法 YAML、损坏、坐标参考不存在、父级缺失 / 跨世界 / 自引用 / 环和旧数据保留。
3. **查询与工具。** 实现内存可重建索引、地点查询、正文读取、概览、父级 / 祖先、子地点 / 限深后代和其他关系查询；覆盖方向、入边扫描、不完整范围、分页版本、尺寸限制、取消及文件变化。将工具绑定可信世界与身份；未授权写入、越界与不同世界混读须拒绝。
4. **专用 Agent 与装配。** 建立地图 Agent 的 Preset、职责提示词、独立入口及主 Agent 专用委派；绑定专属目录、Session 和可选目录服务，地图工具依角色显式装配。校验不影响已有角色与基础信息委派；世界、身份与权限不由模型选择。
5. **端到端与交付。** 用固定模型替身与真实工具走查两个样例，验证写入实际文档、按名称选候选、按 ID 读取、关系来源、坐标与留白、同世界共享及跨世界隔离；覆盖保存失败、结果不确定、取消、身份占用、Session 恢复和目录不可用。单独用真实模型检验规划与工具使用，记录实际成果和问题；固定替身不证明模型会正确选择、规划或遵循提示词。更新包、应用、架构及 Agent Note；报告未覆盖的平台和已知限制。

**验收**：地图 Agent 能按世界需要形成详略不同的多层地点待审文档，授权调用方可逐级查看父级、子地点、祖先及受限后代，并查询有来源的其他空间关系；资料缺失、同名、父级待定、未知与留白能够区分，保存不等于确认。第一版在用户审阅后按逐项计划等待指示，不自动进入组织模块。

## 实施前需要确认的业务问题

1. **坐标精度。** 城邦群只知道三城沿河的大致顺序时，建议允许使用示意格或相对方位，标注尺度未知；有足够信息再使用距离单位。用户是否希望第一版每个重点地点都必须给出示意坐标，还是允许只给方位与未知说明？
2. **主要父级与交叠。** 曲水城的主要父级可以是青河地区；它同时属于某行政区、某势力活动范围时，这些另作独立关联。建议一个地点只有一个主要父级、其他归属不受此限制；如果同一地点确实需要多个并列的主要父级，是否有具体场景？
3. **地点拆分。** 城、城区和建筑按需要分别建文档；只有名称的远方城镇可只建概略文档或保留待定位线索。是否符合预期？
4. **其他关系与待审。** 上游城到中游城的一条单向山路由起点文档维护，反向查询通过插件扫描，不自动推断反向通行。第一版地图成果统一是待审建议，确认与跨文件修改留给第 7 阶段。是否符合预期？
5. **资料展开程度。** 地点自身使用未展开、概况、详细三个等级，与审核状态分开，父子地点各自维护；“详细”不代表地点或子地点永远规划完成。是否采用这三个等级？
