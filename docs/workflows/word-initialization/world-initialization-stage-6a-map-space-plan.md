# 第 6A 阶段：地图与空间模块开发计划

本文细化[内容模块逐项开发计划的地图与空间步骤](world-initialization-stage-6a-content-modules-plan.md#2-地图与空间)。世界初始化第一版的地区规划方向见[第一阶段业务场景](world-initialization-stage-1-plan.md#2-生成第一版供审阅)。本文是实施计划：除现有能力外，地图插件、工具、文件格式和 Agent 均尚未实现；具体数据契约在开发时结合示例和已确定的业务方向细化。

## 目标与范围

地图与空间模块负责地点、地区的空间描述、父子层级及其他关联，表达整体范围、大致位置、层次、通行与障碍；地图与空间专用 Agent 负责按世界构想决定哪些内容需要深入、概述或保留留白。地点可以逐层包含子地点，层级是模块的核心能力，不要求所有分支展开到相同深度。它可独立运行，也可接受世界初始化主 Agent 委派。专用 Agent 不代替组织、人物和历史模块维护其完整资料；其他模块以地点引用关联实际成果。

本阶段将地图资料保存在可阅读的文档中。建议专门在 `src/agents/plugins/map/` 建立地图工作区插件，由可信应用为获授权 Agent 显式装配地图服务及工具；地图专用 Agent 的职责提示词和应用入口分别按现有 Agent 组织方式建立。插件名称和下面的工具名为待实施命名，不代表目录或接口已存在。

第一版建立可查询的文档地图，用多个规则矩形的组合表示一个地点的范围，以近似不规则区域；不要求渲染图片或自动生成完整世界，不实现 GIS、路径最优化、故事运行、角色行动或通用跨模块关系引擎。矩形组合能够表达较复杂的轮廓，但不能保证精确表示任意曲线或真实地形；其他几何表达留待后续。后续如需地图图片，可依据同一资料另行设计展示，不把图片像素作为地点权威记录。开发顺序不等于世界内容生成顺序；资料不足或地图未展开时，不虚构完整地图。

## 场景与边界

| 场景 | 需要表达的内容 | 不应推断 |
| --- | --- | --- |
| 资源有限的城邦群 | 三座城、水源与山谷的位置或相对方位；重点路段的通行、障碍及未知距离。外海按用户要求明确留白。 | 没有道路记录不代表道路不存在；未知距离不等于零；不因外海留白把群山之外全部设为禁止设定。 |
| 开放式修仙世界 | 大陆、山脉、宗门所在地点和只知名称的秘境；重点地区可有坐标概况，远方可留白。 | 宗门的成员、目标和控制权归组织资料；秘境入口与内部位置不必共享同一坐标系。 |
| 嵌套地点 | 世界 → 大陆 → 地区 → 城邦 → 城区 → 建筑，必要时继续细分；其他分支可以只有地区概况。 | 不要求每层都存在，也不因尚未创建子地点就断言没有子地点。 |
| 多个地图层面 | 同一世界可分别组织行政区划、山水地理等层面；河谷和城邦辖区可在同一区域交叠。 | 不把所有空间关系压进一套层级，不由图上的重叠推断管辖。 |
| 同名地点 | 两处同名的青山镇分别位于不同地区，名称查询返回两个候选及上下文。 | 不按名称自动选择唯一地点，不因名称相同合并。 |

与世界基础信息的交界：基础信息可以概述三座城邦共处一条河流流域；地图模块负责按需定位地点、表达空间关系和通行详情。基础信息 Agent 的建议不是地图模块已确认成果。地图 Agent 引用背景原文并区分用户要求、已有资料和本次建议；提炼背景不得凭空指定题材、扩展用户明确留白的范围或将建议写成已确认事实。

## 文档存储方案（建议）

### 目录与权威来源

可信应用为世界配置地图负责人的专属目录。下图是该目录内部**拟议格式示例**，实际根目录由应用配置，名称不能由模型授予权限；不要求用户预先创建每个子目录。

```text
地图负责人目录/
├── map.json                 世界空间概览、坐标参考与明确留白
├── places/
    ├── <地点ID>.json        地点资料、层级和坐标
    └── <地点ID>.json
└── connections/
    └── <连通ID>.json        两个地点之间的一条当前连通设定
```

用户确定使用 JSON。地图概览与每个地点各有一份权威 JSON 文件；地点文件名使用程序生成的稳定 ID，而非名称，改名不改变 ID 或路径。同一个地点出现在多个层面时共用同一 ID 和地点文件；同一世界的 ID 唯一，其他世界的同名或同 ID 不自动是同一对象。连通资料按下文的独立规则写入即作为当前设定；地点等其他成果的审核边界仍按现有规划处理。

### 文件格式

| 方案 | 优点 | 地图场景中的代价 |
| --- | --- | --- |
| Markdown 正文 + YAML 元数据 | 地点描述和手工阅读友好，与现有角色资料形式一致。 | 多层面、多父级、局部范围框和可查询关系需要放入结构化元数据；内容变复杂后 YAML 与正文的分工和编辑一致性较难维护。 |
| 单一 JSON 文档 | ID、父级、层面、坐标、状态及关系使用统一结构，可被插件校验和查询；地点描述、来源和留白也可保存在字符串或结构化字段中。 | 长篇中文阅读和手工编辑不如 Markdown 顺手；正文中的换行、引号由工具序列化，文件格式需严格校验。 |

JSON 是地图及地点的唯一权威文档：地图插件通过工具生成和读取，程序校验必要结构；人和 Agent 需要阅读时由工具组织可读的结果。地点的自然语言描述也保存在同一 JSON 文档，不同时维护一份独立的权威 Markdown 副本；如需 Markdown 报告，可从 JSON 临时生成供阅读，不反向作为数据源。每个地点一份文件的父子查询方式不变，后续不限定其他模块的存储格式。

这是新模块首次建立的版本化文档格式，不将已有基础信息草稿或世界资料自动当作地图文件，也不改写角色、资料目录和 Session 现有格式。`formatVersion: 1` 只用于本格式；缺失版本、未知版本、重复字段、非法编码、重复 ID 或损坏文档明确拒绝当作有效地图资料，保留原文件，不自动修复、覆盖或删除。解析器须能识别并拒绝重复 JSON 对象键，不能依赖普通 `JSON.parse` 静默采用最后一个值。将来升级时先指定版本递增、迁移或拒绝读取及备份策略；当前不存在需要隐式迁移的旧地图格式。

### 资料项与最小结构

下表描述拟议语义，最终字段名、表示方式和工具签名在格式设计步骤中确定，模型通过受控工具传递内容。仅对身份、查询、定位和需校验的关系定义机器结构；历史、组织、人物或丰富的地点描写仍引用来源或写在地点内容中。

| 文档 | 必需的机器可读内容 | 按需内容与正文 |
| --- | --- | --- |
| 世界空间概览 `map.json` | 格式版本、该世界内的地图身份、资料状态；可信世界身份由装配绑定并与文档标识核对。 | 按世界实际需要定义的地图层面、世界覆盖范围、坐标参考系、原点 / 轴向、单位或比例、适用范围和精度说明；世界级明确留白、来源及概览内容。尚无可靠比例时明确未知，不编造真实距离。 |
| 地点文件 | 格式版本、地点 ID、名称、审核状态、资料展开程度；世界身份与所属地图由可信装配和文档校验绑定。 | 按层面记录父级归属及其明确状态、同名辅助说明、别名、可选空间范围或大致方位、其他空间关系、来源、明确留白及地点内容；未知信息不自动补默认值。 |
| 连通文件 | 格式版本、连通 ID、起点和终点地点 ID、方向。 | 道路、水路等方式、条件、障碍、估计距离 / 时间和描述；每条连通只保存一份，不标记用户或 Agent 来源及审核状态，未知内容保持未知。 |

地点与地图概览的审核状态仍按既有方案设计，不提供模型工具直接设置 `confirmed`；既有用户给定或已确认的背景通过来源引用。连通资料使用用户明确指定的独立规则：写入即为当前连通设定，不区分用户要求或 Agent 构思，也不附待审状态；后续更改覆盖该连通资料。地点审核、坐标精度和留白等维度不合并为单一枚举。目录简介只用于定位。

### 地点资料状态

为了查找尚未详细建立的地点，每份地点文档独立保存**资料展开程度**，由负责该地点的 Agent 根据本地点已有内容判断。用户同意以下三个互斥等级；英文值是拟议的机器标识，格式实现前确定；不能通过正文长度或子地点数量自动判定。

| 展开程度 | 建议值 | 含义与示例 |
| --- | --- | --- |
| 未展开 | `unexpanded` | 已识别该地点，可能只有名称、父级或简短线索，尚未形成地点概况；例如只知道青河地区有一处东部山区。 |
| 概况 | `overview` | 已有足以辨认和理解地点的简要描述，但尚未按该世界当前需要进行详细设定；例如知道东部山区大致方位和地貌。 |
| 详细 | `detailed` | 已按本次任务或世界当前需要，较深入描述该地点的重要内容；例如曲水城已说明主要环境、布局和通行特征。它不是永远不需补充，也不表示所有字段或子地点齐全。 |

状态只描述**该地点自身资料**，不继承父地点或子地点的状态。曲水城可以是详细，下面的北城区仍可未展开；北城区变成概况时只更新北城区的文档。子地点列表和状态由地图插件查询并动态汇总，父地点不另存一份清单；查询未覆盖全部文档时明确报告不完整。没有地点文档不等于该地点是 `unexpanded`，只能报告没有找到已记录地点；只有知道地点存在且需要追踪时，才可创建未展开的简短地点建议。

**审核状态独立。** 展开程度不代表事实已确认：同一个地点可以是“详细、待审”，也可以将来成为“概况、已确认”。第 6A 阶段新建成果仍是建议；保存、登记及设为 `detailed` 均不触发确认。后续的待审修改和可信确认由第 7 阶段设计，不让模型自行改成已确认，也不预先声称所有状态流转已实现。

**未知和留白不作为展开等级。** “不知道这里是否有其他城镇”不是一个已知地点的状态；“外海明确留白”是用户对某范围或内容的约束，也不等于待开发任务。已知地点中某项未知、父级待定、坐标未知和明确留白分别记录；查找失败、无权、损坏或资料缺失是操作结果，不修改地点的展开程度。

**状态更新。** 新建时同时写入该地点正文与展开程度；后续完善时对该地点生成待审修改，并在同一候选文档中同步拟议状态，不能因为工具返回成功或子地点增加而自动升级。内容减少、被撤回或设计重点变化时可以建议下调，不强制状态单向递增；现有资料和状态保留至用户按后续确认流程处理。应根据本次世界规划需求判断，不规定所有地点必须达到 `detailed`。

### 地点父子系统（建议实现）

用户确定地点需要逐层包含子地点，地图可以有城市划分、山水等多个并行层面。每个层面可以有自己的父子层级，一个地点可按需要出现在不同层面；不把所有层面压成一个主要父级。层面名称和层级按世界构想确定，不预设每个世界必须使用相同图层。一个地点本身既可以是子地点，也可以继续拥有子地点；不规定必须固定为大陆、省、市等几级。

```text
城市划分层面：世界 → 青河地区 → 曲水城 → 北城区 → 青石客栈
山水地理层面：世界 → 青河流域 → 泠川 → 支流
```

每个地点仍使用稳定 ID 和独立文档，上图是**按层面组织的逻辑层级**，不要求把文件按目录嵌套；避免父级改名、移动时必须移动全部子文件。同一个地点跨层面共用同一文档和 ID；同名不自动视为同一个地点。地点在自己文档中按层面记录父级信息，父文件不重复保存一份权威子地点清单；插件按层面和父级 ID 建立可重建的子地点索引，从同一份关系反向查询。地点名不必唯一，查询可展示某层面上的祖先路径；该展示路径不是持久身份或文件路径。

同一子地点可以有多个父地点，按其范围及所属情况确定，不限制为单一父级。每个父子关联都要指出所属层面、父级 ID 和子地点在该父画布中的一个或多个局部框；多个父级对应各自的局部框集合，不能只保存一个脱离父级的坐标。一个跨区域地点在不同父级中可能只记录各自覆盖的部分，不能要求不同父级换算出的范围完全相同；同一区域的共同部分存在不一致时报告可判断的冲突，不取任意结果掩盖。根据坐标判断范围时，矩形重叠或包含只能提供空间依据，行政归属等语义不能由几何自动确认。

世界初始化时按近期故事需要建立地图；要建立子地图时，先建立其父地图的概略内容及必要的上级链，不能让子地图悬空。没有近期需求的兄弟地图可以不创建或不详细化；资料查询仍不能把未发现的兄弟地点当成不存在。

每个已记录的层面归属至少区分：属于该层面顶层或指向一个以上已知地点 ID。`map.json` 是世界地图及层面的入口，不强行创建与世界配置重复的地点对象；顶层不等于世界不存在更大的外部空间。父级 ID 必须属于同一世界地图，并在对应层面的语义下核验。尚不能确定父级的地点线索可以保留在讨论或已有资料中；正式创建子地图前补齐必要父级概况，不虚构 ID 或产生悬空子地图。读取时遇到历史数据损坏、缺失或无权则报告断链，不以顶层冒充。

创建子地点时验证父级存在、身份与授权范围；禁止自为父级或形成循环。读取时如父文档缺失、损坏、无权或层级包含环，保留子文档并报告断链 / 无法判断，不静默改成顶层或删除。祖先、子地点和后代查询均需标出实际覆盖范围；未扫描完整、超过限制或读取失败时，空结果不能表述为没有子地点。

对于地点搬迁、某层面更换父级或合并：保留地点 ID，先读取并核对地点及新父级版本、拒绝该层面内的循环和跨世界引用，生成待审修改与影响线索；确认后如何提交和检查其他资料，留给第 7 阶段。第一版不实现递归删除、自动迁移所有后代或级联改写其他模块；相关成果保留，父级变化对展示路径的影响不等于子地点 ID 改变。层面、层面间关联及跨区域关系的具体表示须在实现前结合场景确认。

### 坐标、范围和其他空间关系

- **坐标参考系与范围框。** 用户确认每张父地图的局部画布横纵坐标均为 `0..1000`，左上角为 `(0,0)`，x 向右增大、y 向下增大；地图上方对应的实际方位由世界地图说明，不能自动认定为北方。一个地点相对某个父地图的范围可以由一个或多个不旋转、与坐标轴平行的矩形框组成，每个框表示为 `[左, 上, 右, 下]`；实际范围是这些框的并集，而不是只保留所有框的最外包围框。例如 `(100,100,400,700)` 与 `(400,400,700,700)` 拼成一个近似 L 形区域。框可按实际分布不相邻；重叠区域不应重复计算，框之间未覆盖的空隙不能视为地点范围。组合框是规则矩形近似，不保证精确还原曲线或真实地理边界。每个世界使用一套世界比例，由 Agent 创建地图时设置并记录；子地图采用父地图内的局部坐标，局部画布归一化不是另一套世界物理比例。数值校验、重叠与边界接触的判定规则在格式设计时明确；世界比例、地图覆盖范围或方向规则变化需明确影响，不自动改写旧坐标。
- **逐层坐标计算。** 插件提供坐标换算工具：指定地点、经过的父级链和目标祖先，可换算到任一上级画布；目标为世界根时得到世界地图坐标。每一级依据父地图局部画布到其上级画布的映射，分别变换子地点的每个矩形框，保留组合范围及空隙，不能只返回包围框。例如父框在上级画布为 `[100,200,500,600]`，子框在父局部画布为 `[250,250,750,750]`，则换算后的子框为 `[200,300,400,500]`。父地图多个分离范围的映射见下节。父级多条路径时调用方指定路径，或分别计算多条路径并标明各自范围；缺边、映射数据不可用、循环、路径不唯一或结果冲突时明确报告，不静默猜测。计算结果默认是派生值，不再保存一份权威全局坐标；世界物理距离还需世界比例和实际范围支持，不能仅凭归一化坐标推算。
- **精度与缺失。** 坐标可标示概略或精确到明确的尺度；未知坐标、只知大致方位和用户明确留白分别表达。地图概览建议提供范围与大致尺度，符合第一阶段方向；无法确定时说明未知，不要求每个地点都有坐标。点坐标只表达选定参考点，不代表地区边界或行政范围。
- **地点与区域。** 父子层级按所属层面维护；跨层面、跨区域、交叠或不确定的情况使用有明确语义的关联表达。第一版不要求多边形或完整地理拓扑；区域边界与重叠的详细表达按实际需求确定，不能以矩形框或点坐标推断行政包含。
- **其他关系的权威归属。** 每条道路等连通关系使用一份独立 JSON 文件记录起点、终点、方向、条件及必要说明，不改写两个地点或维护反向副本；插件可据此查询入边和出边。写入后即为当前连通设定，不记录用户或 Agent 来源；无法确定的条件仍如实表达。方向性必须明确，不能从反查自动推断反向通行。各层面的父级只存于地点文件的层级字段，不另写一条重复的普通包含关系。允许同一对地点有不同语义和多条连通；不允许按名称代替 ID 定位。非连通的跨区域等关系如何保存，在具体需求出现时另行明确。
- **通行与距离。** 当两个兄弟地图建设完整或剧情需要时，按需设定它们的通行方式、障碍、条件、方向、估计距离 / 时间及精度；尚未设定不等于不通行。距离的坐标系、路线距离和直线距离不能混用；第一版不以欧氏距离替代实际行程，不自动推断双向可通行。未来需要路线寻优时再定义算法与数据充分性。
- **未解析引用。** 跨模块引用或尚未建立的地点线索可在正文中作为待定位线索；已登记的机器关系若目标缺失，应返回悬空关系及其来源，不假定目标不存在或自动创建目标。是否允许保存指向缺失 ID 的关系在实现前明确为校验规则；建议已知目标用 ID，未知目标使用正文线索，不分配虚构 ID。

### 分离范围与多父级的局部画布映射

建议**每个地点只有一个完整的局部画布**。画布用该地点完整范围的最小外包矩形映射到 `0..1000`；地点实际范围仍由内部的矩形集合表示，外包框中未被覆盖的区域不是该地点。这个外包框只负责确定坐标如何换算，不能拿它代替真实的矩形集合进行归属或区域搜索。

例如群岛在其父地图画布上由两个矩形组成：左岛 `[100,200,300,400]` 和右岛 `[700,200,900,400]`。它们的外包框是 `[100,200,900,400]`，群岛自己的局部画布因此是：

```text
局部画布 x: 0       250                 750       1000
            ┌────────┐                   ┌────────┐
            │ 左岛   │      海上空隙     │ 右岛   │
            └────────┘                   └────────┘
```

在局部坐标中，左岛范围是 `[0,0,250,1000]`，右岛范围是 `[750,0,1000,1000]`；中间 `x=250..750` 是画布中用于保持两岛相对位置的空间，不属于群岛的已记录范围。如果左岛内某港口的框是 `[50,200,150,400]`，逐层换算到父地图后是 `[140,240,220,280]`。地图插件仍保留港口和群岛各自的实际框；搜索落在空隙中的地点时不能因为外包框覆盖空隙就说它属于群岛。

**多父级时不能只用每个父级内的局部片段算外包框。** 例如世界上甲、乙地区左右相邻，各占世界画布一半；一座城市整体跨越两区，其世界范围为 `[400,200,600,600]`。在甲的局部画布中城市只覆盖 `[800,200,1000,600]`，在乙的局部画布中只覆盖 `[0,200,200,600]`。如果分别把这两个片段铺满城市画布，会把城市错误缩放两次。

建议每条父子关联除保存该地点在**该父级内实际覆盖的矩形集合** `localBoxes`，还保存一个 `frameBox`：完整子地点的 `0..1000` 画布在该父地图坐标系中对应的参考矩形。`frameBox` 是换算参考，不是实际覆盖范围；跨父级时允许它超出父画布的 `0..1000`，而 `localBoxes` 只记录该父级内的实际部分。上例中，甲的 `frameBox` 为 `[800,200,1200,600]`，乙的为 `[-200,200,200,600]`；两条路径都表示同一城市完整画布，分别映射到世界范围 `[400,200,600,600]`。

地点的完整范围可以将各父级内的 `localBoxes` 通过各自 `frameBox` 反向映射到该地点自己的局部画布，再取矩形并集；重叠部分不重复计算。父级之间有重叠时，同一片范围可以在多条关联中出现，但应表达一致的共同空间，不得因重复出现扩大面积。此结果只覆盖已记录、可读取且映射可用的父级部分；缺少任何必要片段时标明不完整，不能称为完整范围。各层面的归属语义可能不同，计算时须明确选用哪些关联，不能把行政归属或未记录的范围仅凭叠图自动推断。

`map_coordinates_convert` 按调用者选择的父级链，逐级应用 `frameBox` 的平移与缩放，并分别换算全部矩形；可明确选择返回“地点完整范围”或“该父级内的实际覆盖部分”，结果标明选择、路径、参考版本及范围。不能因为 `frameBox` 越界就自动裁掉跨父级部分，也不能把 `frameBox` 的空白当作实际地点。只有 `localBoxes` 而无法可靠确定完整画布映射时，允许保留已知片段，但转换依赖该映射的后代时返回无法计算，不根据片段猜测 `frameBox`。同一地点多路径到共同祖先后，对可以比较的重叠部分检查一致性；超出精度容差时报告各路径和冲突，不自动覆盖。容差、边界接触、范围片段与参考框的一致性校验需在格式设计中具体确定。

归一化画布的横纵数值相同，不意味着地图在物理世界是正方形：世界比例与实际覆盖宽高共同定义真实尺度。逐层映射需保持同一世界比例和各参考框之间的一致性；无法核实真实比例时只返回画布坐标，不编造公里数。该方案只使用轴对齐矩形与平移缩放，不引入旋转或复杂形状。

### 文件示意

以下为虚构的 JSON 概念示例，用于解释同一地点的多父级和多矩形范围；字段名和坐标区间均未最终确定，也不是已经可运行的接口。

```json
{
  "formatVersion": 1,
  "id": "11111111-1111-4111-8111-111111111111",
  "name": "曲水城",
  "status": "suggested",
  "detailLevel": "overview",
  "parents": [
    {
      "layer": "administrative",
      "id": "22222222-2222-4222-8222-222222222222",
      "localBoxes": [[100, 100, 400, 700], [400, 400, 700, 700]]
    },
    {
      "layer": "geography",
      "id": "33333333-3333-4333-8333-333333333333",
      "localBoxes": [[300, 200, 700, 800]]
    }
  ],
  "description": "Agent 建议：城邦位于河谷中游，交通条件待讨论。"
}
```

该示例中行政层面的两个框共同表示曲水城在对应父地图内的范围，地理层面的一个框则相对另一个父地图；两者属于同一地点而非两份正文。子地点列表由插件依据子地点文档反向查询。两个层面及局部画布约定需要在同一世界的地图概览中定义。示例中的 ID 仅用于说明文件间定位，不是实际世界资料。

## 查询、提取与索引

地图插件的读取服务以文件正文为权威；建议启动或首次查询时扫描并解析授权地图目录，建立**仅驻留内存、可重建**的地点 ID、名称 / 别名、父子及其他关系索引。索引不作为用户数据、不写入额外数据库或权威清单；正文和元数据只维护一份。文件变更后通过显式重新扫描或可靠的版本核对刷新；文件监听事件仅可作为失效线索，不把未收到事件当作一致性证明。若日后数据规模证明需要持久索引，须单独设计索引版本、完整性、重建与失效策略。

| 意图 | 建议输入 | 结果与限制 |
| --- | --- | --- |
| 查找地点 | 名称 / 别名或关键词；必要时按区域线索、展开程度缩小范围。 | 返回所有匹配候选的 ID、名称、展开程度、审核状态、简要上下文及来源定位；分页和顺序稳定。同名不自动选一个，名称检索不承诺语义召回或世界中所有未登记资料。 |
| 读取地点 | 世界内地点 ID。 | 返回完整地点正文、元数据、相对路径和内容版本或摘要；需要外部背景时提供引用而非把目录简介当正文。 |
| 查询父级与祖先 | 地点 ID 和层面。 | 返回该层面的直接父级及按需逐层追溯的祖先、身份与来源；顶层、待定、断链和受限分别表达，检测循环。 |
| 查询子地点 | 层面及世界顶层或某地点 ID，按需指定层数、展开程度筛选和分页。 | 默认返回该层面的直接子地点，可有限深度查询后代；从各自文档读取展开程度及审核状态并动态汇总。每个结果说明与查询父级的归属，以及授权范围内该地点的其他已记录父级和所属层面，避免误以为独属于当前父级；父级信息受限或不完整时明确标注，不泄露无权查看的身份。深层查询不默认加载全部正文，取消或限制时不冒充完整。 |
| 查看连通 | 地点 ID，出边 / 入边及可选连通类型。 | 返回连通信息、另一端的 ID 和对应连通文件；入边依扫描结果汇总，不重复写目标文档。无法读取部分文件时报告不完整，不能声明无关联。 |
| 读取地图概览 | 当前可信世界。 | 返回 `map.json` 内容、坐标参考、范围和版本；缺失、未初始化、损坏、无权及不支持版本分别报告。 |

候选结果包含来源位置与版本；读取时核对目标身份、世界和授权范围。文件数量、单文件与总读取大小、查询页大小按可信配置设置并校验；到达限制、取消、损坏、文件变化或无权时返回明确失败或带范围的不完整结果，不能把它伪装成零结果。分页使用本次查询快照版本；后续页前核对范围和文档版本，变化则拒绝继续并要求重查，不声称跨文件事务快照。实时工作区受单可信写入进程约束；索引检查仍不能保证其他进程不恶意替换路径或建立硬链接。

## 地图插件、工具与 Agent 装配

建议在 `src/agents/plugins/map/` 建立独立 pnpm 工作区包 `@fly-novel/map`，提供文档解析 / 校验、受控存储服务、查询与 Cordis 服务插件；同包或独立工具适配是否拆分，在确定依赖和职责后按现有插件惯例选择，不预建通用地图框架。独立包不直接创建 LLM、用户界面或全局单例；服务由可信调用方提供世界身份、真实路径、允许读写的身份、文件后端及限制。插件作用域拥有注册、队列与索引，销毁时取消 / 等待进行中工作、注销工具并释放资源，失败如实传播。是否复用现有 `FileSystem`、沙箱及目录服务在原型验证后确定；不绕过已有授权与文件版本检查。

以下工具名和字段名是设计提案，不表示现有可调用接口。所有工具由可信应用绑定世界和身份；读取工具授予获授权的资料使用方，创建工具仅授予地图负责人。列表查询统一返回匹配项、实际覆盖范围、完成 / 不完整状态及版本化分页信息；无法判断时不伪装成空结果。

| 建议工具 | 主要输入 | 返回 / 使用场景 |
| --- | --- | --- |
| `map_overview_read` | 无世界参数；世界由可信装配绑定。 | 读取世界地图概览、层面、世界比例、画布约定、来源和文件版本；区分未初始化、无权、损坏与不支持版本。 |
| `map_place_search` | 名称或别名、可选层面 / 父地点 / 展开程度、分页。 | 返回地点 ID、名称、状态和父级线索；同名返回多个候选，不自动选定。同一地点跨层面只返回其身份，附匹配层面。 |
| `map_place_read` | 已选地点 ID。 | 返回地点 JSON 的可读内容、审核 / 展开状态、各层面父级及局部多框、来源、文件路径和版本；不把简介当正文。 |
| `map_place_ancestors` | 地点 ID、层面、可选深度与分页。 | 沿该层面的所有父级路径返回父级与祖先；区分世界顶层、断链、无权和不完整，处理多父级及重复祖先。 |
| `map_place_children` | 世界顶层或父地点 ID、层面、可选深度 / 展开程度 / 分页。 | 动态读取子地点自身资料汇总直接子地点或限深后代；每个结果显示本次匹配的父级，以及授权范围内的其他已记录父级和层面，附父级信息是否完整的说明，不要求父文件维护子项清单。未展开与缺少记录分开；无法读取或无权访问时不声称当前父级是唯一父级。 |
| `map_coordinates_convert` | 地点 ID、要换算的父级路径、目标祖先或世界画布、完整范围或父级内覆盖范围。 | 沿参考框逐层返回对应范围的所有矩形及映射链 / 版本；未指定且路径不唯一、参考框缺失、冲突或超限时报告，不能仅返回外包框。 |
| `map_area_search` | 层面、参考画布及一个或多个查询矩形、分页。 | 返回与查询区域有交集的已记录地点及其命中的范围线索；框覆盖仅表明空间交集，不推断行政归属或可通行。查询范围 / 文件不完整时标注。 |
| `map_connections_read` | 地点 ID、方向 / 连通类型及分页。 | 查询该地点当前的出入连通设定，返回连通 ID、两端 ID、方式、方向、条件和文件版本；反向查询不推断反向可通行，没有记录不等于不通。 |
| `map_overview_create` | 世界范围、层面、比例和画布约定等建议内容。 | 仅地图负责人可独占创建世界概览 JSON，返回路径和版本；不能确认事实或覆盖已有资料。 |
| `map_place_create` | 名称、展开程度、父级关联及各父画布的多框、描述和来源。 | 仅地图负责人可创建建议；程序生成 ID / 路径，验证各父级及范围并独占保存；返回 ID、路径和版本。父级未建立时先创建必要父级概况。 |
| `map_connection_create` | 已存在的起点和终点 ID、连通方式、方向及必要条件。 | 在两个兄弟地图已建设完整或剧情需要时，由地图负责人独占创建一份单独的连通 JSON；程序生成连通 ID / 路径，只维护一份记录，单向 / 双向含义明确，不修改两个地点文件。成功写入即是当前连通设定，不需要额外审核或来源标记。 |
| `map_connection_update` | 连通 ID、完整的新连通内容，以及读取到的当前文件版本。 | 地图负责人以新内容覆盖同一连通文件，保留连通 ID；校验两端、方向和权限。文件自读取后变化时拒绝覆盖，需重新读取后决定，避免误覆盖较新的修改。写入结果不确定时先核实文件，不另建副本或盲目重试。 |

**多父级查询示例。** 查询城市划分层面“青河地区”的子地点时，曲水城的结果除了标明“本次匹配：青河地区”，还列出该地点文档中可授权读取的其他父级，例如地理层面的“泠川流域”；查询另一个父级也能得到同一个曲水城 ID，不复制地点文件。其他父级是否完整应随查询结果报告；若某个父级无权读取，不能通过名称、ID 或计数泄露它，也不能宣称该地点只属于青河地区。

**连通资料示例。** 青河城和曲水城都已有地图或近期故事需要它们往来时，地图 Agent 可创建“青河城 → 曲水城，沿河道路，枯水期可行”。成功写入后它就是当前地图中的连通设定，不记录由谁提出，也不自动推断反方向道路。如果后来决定改为双向道路，先读取这条连通并取得版本，再用新内容覆盖同一份文件；此后查询得到新的双向设定。

首版不因为工具列出就实现完整路线规划、自动计算道路通行时间、地图绘图或对外确认。具体参数结构、矩形数量 / 查询深度上限由可信配置确定；工具输入不接受世界路径、身份和权限。查询结果的 JSON 结构由工具返回，按需展示可读文本；数据持久化仍以各自 JSON 文件为准。

工具名是设计建议。读取工具可由可信应用授予主 Agent、其他内容 Agent 或地图 Agent；写工具只授予地图负责人。工具输入不能改变世界、负责人、目录或访问权限；由可信装配绑定，不能靠提示词充当安全边界。地图 Agent 的 Preset、SystemPrompt 和独立应用入口复用既有 Cordis、LLM、Tools、Session 和工作区；主 Agent 通过专用委派工具提供任务及必要背景，持久 Provider 绑定稳定身份。共享资料目录按现有机制可选登记每个成果文件，摘要不代替地图查询，也不代表确认。缺少目录时按授权地图服务读取正文；文件保存成功和目录登记失败分别报告。

## 写入、并发和恢复

1. **新建。** `map.json` 首次创建采用 `createIfAbsent`；地点 ID 由程序生成，文件在 `places/` 内独占创建。创建前校验父级状态、父级存在性和世界边界；子地点不需要修改父地点文档。已有文档不覆盖，成功后返回实际路径、地点 ID 和版本；文件保存与目录登记分开报告。取消或错误发生在提交前 / 后的结果须据实际后端返回区分；不能确认时返回目标线索并先核实，不盲目重试。
2. **已有内容。** 连通资料由地图负责人使用 `map_connection_update` 按当前版本直接覆盖，不建立待审副本。地点和地图概览的局部修改、影响检查与确认提交仍属于第 7 阶段；若实现候选写入，必须绑定基线版本并与当前正文分离。连通变更仅更新指定连通文件，不自动改写地点或其他关联资料。
3. **单一权威与部分成功。** 父级归属在子地点文件中维护，独立连通设定在连通文件中维护，不分别复制到多个地点文件；一次操作只承诺单文件结果，不能把多个地点写入或目录登记说成原子事务。多文件任务中途失败时保留已完成文档，逐项返回成功、失败或未知；重新读取实际文件及目录后再决定补做。连通覆盖使用实际读取得到的文件版本执行 `replaceIfVersion`，冲突时停止，不静默合并；失败或结果不确定时核实实际文件，不假定更新已经成功或已回滚。
4. **隔离与释放。** 一个世界只有一个可信写入进程；同一地图服务序列化相关写入，身份忙时拒绝重入。父 Agent 取消传播至子 Agent，启动失败回滚资源，子运行和服务关闭须等待进行中工作；清理失败保留必要占用并返回错误。保存完成后取消不宣称文件回滚；Session 恢复对话，不证明资料提交完成。
5. **路径与外部变化。** 地图文件由可信根与程序生成 ID 拼接，校验真实路径、普通文件与符号链接边界；模型不能传入任意文件路径写入。路径和版本检查不能抵御不可信进程并发替换、硬链接及跨进程写入；遵守现有本机文件后端限制，不在本步改造 Windows 1175 行为。

## 开发步骤与验收

1. **核对业务契约。** 用两个样例核对地点展开程度与审核状态、多层父子组织、父级概况、区域交叠、坐标与尺度、留白和同名候选；依据已确定的 JSON、坐标和连通规则细化文档归属、版本与层级表达。
2. **格式与受控存储。** 在地图插件工作区包中建立 JSON 解析、序列化和必要校验；实现独占创建、受控读取和明确错误。验证无地图、未知版本、重复字段 / ID、重名、非法 JSON、损坏、坐标参考不存在、父级缺失 / 跨世界 / 自引用 / 环和旧数据保留。
3. **查询与工具。** 实现内存可重建索引、地点查询、内容读取、概览、父级 / 祖先、子地点 / 限深后代、范围搜索、逐层坐标换算及连通查询；细化世界宽高、单位与比例的表示，根据世界实际宽高换算距离，不把归一化坐标直接当成公里数。多父路径采用统一精度，比较结果时容忍该精度内的数值误差，超出容差则报告冲突，不擅自选择；连通类型、字段和过期版本错误按实际格式定义。覆盖多框空隙、重叠不重复、方向、入边扫描、不完整范围、分页版本、尺寸限制、取消及文件变化。将工具绑定可信世界与身份；未授权写入、越界与不同世界混读须拒绝。
4. **专用 Agent 与装配。** 建立地图 Agent 的 Preset、职责提示词、独立入口及主 Agent 专用委派；绑定专属目录、Session 和可选目录服务，地图工具依角色显式装配。校验不影响已有角色与基础信息委派；世界、身份与权限不由模型选择。
5. **端到端与交付。** 用固定模型替身与真实工具走查两个样例，验证写入实际文档、按名称选候选、按 ID 读取、连通记录的创建及覆盖、坐标与留白、同世界共享及跨世界隔离；覆盖过期版本、保存失败、结果不确定、取消、身份占用、Session 恢复和目录不可用。单独用真实模型检验规划与工具使用，记录实际成果和问题；固定替身不证明模型会正确选择、规划或遵循提示词。更新包、应用、架构及 Agent Note；报告未覆盖的平台和已知限制。

**验收**：地图 Agent 能按世界需要形成详略不同的多层地点资料，授权调用方可逐级查看父级、子地点、祖先及受限后代，并查询当前连通设定；连通创建后即生效，更新覆盖同一记录并拒绝过期版本。地点资料缺失、同名、父级待定、未知与留白能够区分。第一版在用户审阅后按逐项计划等待指示，不自动进入组织模块。
