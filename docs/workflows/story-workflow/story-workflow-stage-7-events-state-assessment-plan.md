# 故事级工作流第七阶段：事件、状态变化与故事评估

本文细化[总体开发计划](story-workflow-development-plan.md)第七阶段，对应[判断结果并记录变化](story-workflow.md#6-判断结果并记录变化)和[评估子故事、父故事与故事线](story-workflow.md#7-评估子故事父故事与故事线)。按[学习型开发要求](../../development-plan.md#学习型开发要求)逐步实现和验收，接口和持久化格式细节在对应步骤确定。

## 实现路线

先从第六阶段已结算的场景读出实际发生的经过及行动判断。可信应用在明确绑定的世界运行范围内建立有来源的事件，按版本核对并应用一项最小的世界状态变化。子导演回报事件、状态写入和未决事项，父导演用这些证据评估目标并安排后续子故事。原事件、来源和历史版本可独立重读，后续计划调整另存决定。

| 记录 | 职责及权威来源 |
| --- | --- |
| 场景证据与事件 | [场景互动和结果](../../../src/story-workflow/README.md#场景互动记录)提供发言、感知、尝试、规则判断及结果。应由应用核对世界、运行、故事、场景和证据版本，确认哪些结果可进入本轮事件记录。事件保存已发生的经过、直接结果和依据。 |
| 状态变化提案 | 导演可提出一个结构化变化，引用事件、目标业务 ID、期望版本、旧值与拟用值。可信应用核对来源、授权和版本，明确接受、拒绝或待核查。 |
| 当前世界状态与应用回执 | 世界运行状态存储负责判断当前值与版本。可信写入入口按预期版本应用获准变化，以稳定操作 ID 记录结果。父导演采用经回执与当前版本共同核对的状态。 |
| 回报与评估 | [故事推进](../../../src/story-workflow/workflow.ts)已支持子故事回报、父导演逐项推进、一次补充和结束评估。第七阶段把这些决定与可重读的事件、状态回执和未决事项关联。角色认知和私有会话按照原授权边界访问。 |

首版只贯通一个世界、一个连续故事运行、一种小范围状态目标，使用场景和故事内顺序定位。状态目标选用「这支商队的临时等候状态」，持久化位置由可信应用选择并与初始化正文、交付、场景和 Session 根隔离。世界时间与并行写入调度、长期记忆、正式故事线状态发布及通用多目标事务由后续阶段设计。第八阶段负责故事安排的用户审阅流程。本阶段的写入授权来自可信调用方预先选定的窄范围，模型输出只是提案。

## 曲水城的最小验收资料

| 事项 | 固定来源及预期用途 |
| --- | --- |
| 夜间闭门、商队抵达、等候点 | 复用第四至第六阶段的交付规则、带来源的抵达事件及当前场景采纳的地图提案。场景采用的临时位置以具体来源和适用范围标识。 |
| 等候安排说出口 | 从守卫发言与相关感知记录读取，「请在门外等候」证明提出了安排。固定用例另核对哪名角色实际听见。 |
| 商队移动与驻留 | 固定替身提供成功、受阻或未决版本。只有行动结果确认为车队已停在指定位置的用例才支持应用「已在城外等候」。受阻保留实际停留位置，未决保留待核查状态。 |
| 目标与后续决策 | 预设父故事目标包含「让车队安全等候」与「妥善处理入城请求」。完成等候可支持前一项达成，入城仍可未决。另设条件变化提前终止和补充机会用尽的分支。 |

## 分步开发

### 1. 核查证据、状态所有权和接入点

- **输入与动作。** 沿第六阶段场景结果、互动链摘要、行动判断及[双世界固定替身](../../../src/world-init/tests/initialization-delivery-e2e.test.ts)追踪证据，再对照[子故事回报、父故事评估、批次继续](../../../src/story-workflow/README.md)。盘点可用于验证真实发生、可见性与结算的记录，以及当前世界状态是否已有可验证的写入入口。
- **交付及验收。** 只读形成入口和差异清单，明确事件与状态的读取者、写入者、版本、范围和失败方式。固定商队业务身份、状态初始版本、成功或受阻证据、状态授权与父故事评估目标。说明如何处理历史的模拟记录及旧版本场景。

### 2. 生成并重读有证据的场景事件

- **输入与动作。** 可信应用为已核对的场景结果建立版本化事件，绑定 `worldId`、`runId`、`storyId`、`sceneId`、事件 ID、场景结果版本及实际证据引用。明确事件粒度。首版建议按场景保存一次结算事件，内部保留按互动序号排列的发言、已确认行动结果、失败经过和未决事项。事件采用须有明确的本轮运行来源，旧模拟与固定试演按其原身份读取。
- **交付及验收。** 支持从事件追踪场景、回合和判断，也能从场景定位事件。重试同一来源只产生一份记录。测试缺少结算、场景身份或摘要失配、未知格式、原记录损坏及重复保存。计划、仅提出的行动、传闻和未决信息按各自性质保存。

### 3. 建立最小世界状态和变化校验

- **输入与动作。** 明确一个世界运行状态入口及权威存储。用稳定商队 ID 读取「已抵达、尚未安置」及预期版本。状态提案引用支持变化的事件与行动结果。可信应用核对来源、目标、状态迁移、权限和当前版本，确定可应用、拒绝或待核查。应用先冻结获准操作和预期版本。
- **交付及验收。** 可独立重读商队状态及获准操作的证据。发言、规则通过和未成功确认的行动都无法单独支持修改。测试错世界、错业务目标、旧版本、缺少授权及重复操作标识携带不同内容。

### 4. 应用变化并保存可核查回执

- **输入与动作。** 通过可信写入入口按期望版本执行单目标变化。选定能重读的提交点，保证一次状态写入可按操作 ID 核查。首版优先让新状态版本保留操作 ID、内容摘要和事件引用，使状态已写、回执未返回时有证据可查。记录已应用、确定未应用、冲突与结果未知。恢复先核对实际版本和已保存操作，保持事件历史。
- **交付及验收。** 车队确实停在等候点时，重开后能读到新版本及回执。并发或重复提交只有一次业务效果。分别验证写入前失败、写入后回执缺失、版本冲突和结果仍未知。无法核实时阻止依赖该状态的后续决定。其他状态及初始化资料保持原版本。

### 5. 将事件和状态证据接入子导演回报与父导演评估

- **输入与动作。** 用已核对的事件、状态回执和未决项形成子故事回报，并沿现有多层推进交给直接上级。父导演依据每项目标和引用证据决定达成、未达成或提前终止。规划下一个子故事前提供实际进展和可核对的当前状态。任务需要的证据仍未知时保留待核查，避免以回报文字补足。
- **交付及验收。** 固定替身可追溯父导演为何认定等候目标达成以及为何仍需处理入城。已保存子故事的场景、事件和状态回执保持可读。评估、暂停与回报字段涉及持久化变化时显式处理旧版本，绑定所用证据的版本。

### 6. 验证后续安排、一次补充和结束条件

- **输入与动作。** 在现有逐个规划基础上，让下一子故事采用世界实际状态。若计划数量用完且仍未达成，沿用一次补充的限制。补充后仍未达成时，记录对父故事的调整及依据。若暴雨封路等条件令目标无法推进，记录提前终止原因和未决事项。
- **交付及验收。** 覆盖达成后推进、未达成后补充一次、补充后调整、提前终止及旧暂停继续。比较调整前后的事件和状态记录，已发生经过可按原版本重读。父故事结束与各项目标结果能分别核对。

### 7. 贯通曲水城固定替身验收

- **输入与动作。** 从已结算的城门演绎进入事件写入、单目标状态应用、子故事回报和父导演评估。重开后按商队、事件或父子故事身份双向核对。运行状态未写、冲突和回执缺失分支，核对父导演只采用可证明的结果。
- **交付及验收。** 提供一条可独立重跑的集成用例及应用入口说明，覆盖状态写入失败、未知结果、重试和历史证据保留。运行相关测试、类型检查和正式构建入口冒烟测试，记录实际命令与结果。固定替身结果与任何真实模型观察分别报告。
