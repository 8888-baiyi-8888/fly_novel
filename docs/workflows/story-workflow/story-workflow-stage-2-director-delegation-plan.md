# 故事级工作流第二阶段：父子导演协作开发计划

本文细化[总体开发计划](story-workflow-development-plan.md)的第二阶段。业务约定以[故事级工作流](story-workflow.md)为准；本计划按可运行能力逐步扩展，不代表规划中的能力已经实现。

按照[学习型开发要求](../../development-plan.md#学习型开发要求)，每步开始先说明问题、使用示例、输入输出和预期行为，确定当前步骤需要的接口后再实现；完成后用实际示例和相关测试验证，并对照 DeepSeek Harness 中实际涉及的设计。未得到明确指示，不自动进入下一步。

## 目标与开发主线

建立由程序控制故事推进、导演负责规划和判断的父子导演协作：先让一个导演规划并保存事件，再跑通一个子故事的父子协作，接着推进多个兄弟故事，最后将同一套协作方式用于多层故事。程序管理计划、层级和进度；导演不需要靠同步嵌套调用一直等待下级。

本阶段使用调用方提供的固定背景和明确标记的模拟演绎结果，不实现真实角色互动、场景演绎或世界状态写入。父导演与子导演的规划、任务交付、判断、评估和回报通过实际 Agent 调用验证；固定模型替身用于可重复测试，不能证明真实模型的规划质量。写作流程、并行故事调度和完整跨进程故障恢复不在本阶段实现。

计划、模拟结果和实际发生的世界事件始终区分。需要保存的资料从第一步开始采取与当前范围相匹配的版本、校验及失败处理；后续扩大持久化格式时明确迁移或拒绝读取策略，保留已有数据。Session 不能单独证明业务步骤或世界状态写入完成。

## 当前基础

仓库已有[导演预设](../../../src/agents/director/preset.ts)、[导演应用入口](../../../src/app/agents/director.ts)及相关提示词测试；预设不代表故事工作流已接通。[SubAgent 服务](../../../src/agents/plugins/subagent/subagent/README.md)和[通用委派工具](../../../src/agents/plugins/subagent/tool-subagent/README.md)提供一次性委派能力，其中通用工具前台等待最终结果，不自动提供故事层级调度或中途汇报。每步开始时结合对应代码和测试判断是否复用，不预设必须使用某一种 Provider。

第一步可以由可信调用方直接提供固定世界背景；实际接入初始化交付和世界当前状态属于[总体计划](story-workflow-development-plan.md)的后续阶段，不能因为固定示例走通就声称世界资料已经接通。

以下使用曲水城示例贯穿开发：已知城门夜间关闭；“城防与商贸关系可能趋紧”是发展方向。商队夜间抵达后，守卫和商队如何行动由实际演绎决定；测试可以提供“拒绝开门、商队扎营”的**模拟结果**，不得把它当成世界中已经发生的事实。

## 分步开发

### 1. 单导演规划并保存初步事件

**解决的问题：**程序需要从输入资料得到一轮可继续处理的事件初步安排，而不是只获得一段无法核对的模型对话。

**使用示例：**调用方提供曲水城的固定背景，程序调用导演，导演提出商队抵达等初步事件；程序保存后可重新读取。若导演判断当前没有可推进的事件，应说明原因并等待，不强行生成事件。

**开发范围：**复用导演 Preset 和 Harness，由可信调用方绑定模型、资料和保存位置；程序为本轮及事件分配业务身份，保存必要的初步安排。模型不能选择记录根或授予权限。只确定保存和读取当前计划所需的最小记录，不提前设计完整父子树；事实、发展方向和计划保持可区分。

**完成后可运行：**给定固定资料，调用导演生成并保存一组初步事件，关闭并重新读取计划；可明确报告没有可推进事件或规划失败。

**验证：**固定模型替身验证输入传递、结果保存和重读、空结果与无效结果的区分、模型或写入失败及实例清理；未知版本或损坏的记录保留原文件并拒绝误读。真实模型可用时另行检查规划质量，否则说明未执行。此步不实现父子导演协作。

### 2. 一个子故事的父子导演协作闭环

**解决的问题：**验证父导演交出的子故事能由独立子导演接收，并在获得演绎结果后向父导演回报。

**使用示例：**程序选择“商队夜间抵达”，父导演完善背景、目标和约束；程序创建子导演并交付任务。子导演组织本次模拟演绎，可信模拟器提供守卫拒绝开门等结果；子导演根据模拟经过形成回报，程序保存并交给父导演。

**开发范围：**在第一步计划上建立一个父故事与一个子故事的最小关联；程序负责调用、任务交接和资源释放。父导演、子导演均通过实际 Agent 装配运行，二者的必要上下文和回报在本步结合示例确定。模拟器只替代尚未实现的演绎，不代替子导演总结回报；不直接写入真实世界状态。

**完成后可运行：**一次父导演规划、单个子导演接收任务、模拟演绎、子导演回报和父导演接收的闭环。此步暂不处理兄弟故事或继续拆分。

**验证：**固定模型替身驱动实际导演调用，检查背景、目标、约束及模拟结果是否传到正确实例，回报是否包含必要依据且未被当作世界事实；覆盖未授权选择、启动与运行失败、取消和资源清理。实例身份、业务故事身份和 Session 身份不能混用。

### 3. 多个兄弟故事依次推进

**解决的问题：**本轮初步安排可能包含多个故事；前一个的结果可能使后一个原计划不再合适。

**使用示例：**“商队夜间抵达”的模拟结果是守卫拒绝开门、商队扎营；父导演看到子导演回报后，将下一故事完善为处理城外货物，而不是直接沿用原先的城内安排。

**开发范围：**复用第二步闭环，程序管理同层选择、执行顺序和进度；每次交付前，父导演结合已经保存的结果完善当前故事。可以根据实际情况调整或取消未发生的计划并记录原因；不提前确定所有后续细节，也不改写已经发生的内容。

**完成后可运行：**同一父故事下至少两个子故事依次处理；后一个实际使用基于前一个结果完善后的任务。

**验证：**使用偏离原计划的模拟结果检查父导演收到回报、下一任务发生相应变化，以及继续、调整或取消时的记录。前一故事失败或结果不明时不得假装完成后继续；真实模型质量与固定替身行为分开报告。

### 4. 多层父子导演协作

**解决的问题：**子故事本身可能仍然太大，需要继续拆分；不能为每个层级编写不同的故事流程。

**使用示例：**子导演判断“商队抵达”需要拆成更小的子故事；其中一个继续向下拆分，另一个已经适合直接模拟演绎。下级结果返回直接上级，最终逐层返回最初的父导演。

**开发范围：**在第二、三步基础上增加导演对当前故事“继续拆分或适合直接演绎”的判断。需要拆分时复用初步规划、父子交付和兄弟推进能力；程序按需扩充文件中的父子关系及进度，安排下级并逐层回报。父子是相对职责，不预设固定故事层数，也不要求父 Agent 一直保持同步等待。

**完成后可运行：**通过同一套业务机制处理至少父、子、孙三层，并能在下级结束后返回正确上级；同层不同故事可以有不同拆分深度。

**验证：**覆盖拆分与直接演绎两条路径、兄弟顺序、逐层回报及必要上下文；验证中间层启动或运行失败、取消和清理。记录格式若需变化，先处理已有版本；模型返回计划不能替代已经执行的结果。

### 5. 父故事完成评估与补充推进

**解决的问题：**预估的子故事都处理过后，父故事目标可能仍未达成。

**使用示例：**预估的三个子故事结束后，城防和商贸矛盾仍未解决；父导演评估实际结果，最多增加一个子故事。增加后仍未达成，就按实际结果调整父故事相关内容。

**开发范围：**父导演依据本层子故事的结果评估父故事，而非仅依据执行数量。复用前面已建立的推进和回报能力处理补充子故事；父故事也可以因条件变化而结束或终止，记录原因和未解决事项，不改写已发生的经过。

**完成后可运行：**父故事能够在目标达成、未达成或条件变化时形成与实际结果一致的评估及回报。

**验证：**覆盖目标达成、子故事用完仍未达成、最多增加一个、增加后仍未达成以及提前终止。检查已处理故事不被重新设定或重复执行；补充结果仍区分模拟与真实事实。

### 6. 用户控制本次推进数量

**解决的问题：**用户不必等待整轮结束，可控制一次演绎多少个最小子故事。

**使用示例：**用户未指定数量时使用 5；本次在不同父故事下完成 5 个最小子故事后停止开始新的演绎，保存未完成层级与进度；用户继续时从已有进度推进。

**开发范围：**在已有多层推进上接入用户数量设置，数量只针对最小子事件，不是父故事数或场景数。结合实际流程确定完成与计数时机、失败或结果不明如何处理、继续时数量如何指定；达到数量不代表父故事或本轮已经结束。

**完成后可运行：**一轮可以分多次推进并接续已有进度，已处理结果和父子关系保留。

**验证：**覆盖默认 5、用户指定值、跨层计数、达到数量暂停、继续后不重复处理，以及失败和取消时的计数；在实际契约确定前，不把模拟原型的计数方式当成最终约定。

### 7. 重大情况提前汇报

**解决的问题：**子导演还没有完成故事时，可能遇到影响父故事方向的情况。

**使用示例：**城门交涉进行中发生影响父故事方向的情况，子导演向父导演汇报；程序暂停受影响事件，父导演决定继续、调整或终止，程序传达决定并安排后续处理。

**开发范围：**在既有正常回报上增加中途汇报，区分汇报、上级决定和最终结果。先明确程序如何定位上级、传递决定、处理送达失败及取消；受影响事件等待决定，其他无关事件的并行调度不在本步实现。

**完成后可运行：**子故事未结束时，子导演能够获得对应父导演的决定，并由程序按决定继续、调整或结束。

**验证：**覆盖中途汇报、正确上级、决定传达和继续或终止，以及父导演失败、取消、重复通知和清理；中途汇报不能被记录为最终回报。

### 8. 完整运行与恢复边界验证

**解决的问题：**前面逐步建立的能力需要共同运行，且暂停或失败后要能分辨实际进度。

**使用示例：**用曲水城固定资料和可信模拟器，从本轮规划、多层拆分、兄弟推进、数量暂停与继续、逐层评估到本轮结束，再验证用户选择继续演化后基于新输入规划下一轮。

**开发范围：**检查故事计划、模拟结果、父子关系、导演数据及运行进度的归属和关联；完善当前流程所需的保存、读取、失败处理和继续边界。完整跨进程故障恢复、真实世界状态及其他后续能力仍按总体计划开发；不把已经暂停或结果不明的操作自动重放。

**完成后可运行：**通过声明的入口运行完整的多层父子导演模拟流程；本轮结束与本次数量暂停分别可识别，继续操作读取已有进度或在用户选择后开始新一轮。

**验证：**运行聚焦的单元、集成及构建产物入口检查，覆盖版本不支持、记录损坏、写入冲突、失败、取消、清理和已完成事项不重复执行。报告实际运行的命令及结果；真实模型或外部服务不可用时说明跳过原因，不将替身验证描述为真实模型通过。更新受影响的模块、目录和架构说明。

## 每步共同遵循

- 导演决定创作内容及拆分；程序控制进度与数据边界；角色的行动留给角色。测试可以控制模型输出，但不能把替身的固定回答当作导演的真实判断能力。
- 每一步只补充当前可运行流程必需的数据、校验和失败处理；文件格式从首次持久化起就要有版本与旧数据处理策略，不能等到最后一步才考虑数据保护。
- 子导演回报通常在子故事结束后产生；提前汇报属于第 7 步。父故事最多增加一个子故事的业务约定在第 5 步实现，不与用户本次演绎数量混淆。
- 真实世界资料读取、角色认知、规则计算、事件与状态更新、完整恢复及写作依照[总体计划](story-workflow-development-plan.md)的对应阶段开展；本阶段的模拟流程不能声称这些能力已接入。
