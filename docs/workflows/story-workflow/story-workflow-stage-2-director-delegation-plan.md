# 故事级工作流第二阶段：父子导演委派开发计划

本文细化[总体开发计划](story-workflow-development-plan.md)的第二阶段，业务约定以[故事级工作流](story-workflow.md)为准。本文是开发计划；其中的实施建议和待讨论问题不代表已经确定的接口或已实现的能力。按[学习型开发要求](../../development-plan.md#学习型开发要求)，每步先说明使用方式和预期行为，再确定接口、实现和验证；本阶段完成后等待明确指示，不自动进入下一阶段。

## 目标与范围

程序管理一轮事件的初步安排、文件记录、父子层级和推进顺序，安排导演逐层判断、拆分和评估。父导演围绕当前父故事，将一个子故事的背景、目标和约束交给子导演；子导演可以继续拆分，结束后向父导演回报结果、变化、未解决事项及必要依据。发生影响父故事方向的重大情况时，子导演能够提前汇报，由父导演决定如何继续。父导演依据实际结果完善下一子故事，不能将规划或模拟结果当作已发生的世界事实。

本阶段用固定背景和明确标记的模拟结果验证协作，不实现真实角色调用、场景演绎、世界状态写入、完整故事存储、用户审阅或并行故事调度。建立最小文件记录以保存计划、父子关系和进度；先确定格式版本、读取校验及失败后的保留和恢复或拒绝策略。模拟结果不能作为已发生事件的证明，完整恢复能力在后续阶段完善。完整场景经过的持久化及按需查看随故事记录能力设计；本阶段示例可由测试提供可核对的模拟经过。

## 已有基础与差距

- [基础导演预设](../../../src/agents/director/preset.ts)已有导演提示词、Loop、Session 和模型装配；父子是故事层级职责，不意味着需要分别建立两套导演类型。
- [SubAgent 服务](../../../src/agents/plugins/subagent/subagent/README.md)通过 Provider 启动子运行，调用方接收结果并负责释放；启动失败、取消和清理有现有契约。
- [Spawn Provider](../../../src/agents/plugins/subagent/subagent-spawn-in-process/README.md)与[进程内驱动](../../../src/agents/plugins/subagent/subagent-in-process-driver/README.md)可以启动独立子 Agent 并等待最终结果。项目提供的可信创建方式和配置见[Agent 包说明](../../../src/agents/README.md)。
- [通用委派工具](../../../src/agents/plugins/subagent/tool-subagent/README.md)可由可信装配固定子 Preset，模型提供任务；它前台等待最终结果并释放子运行，不继承父会话。它不说明运行中向父导演提前汇报的能力，也不自动实现故事层级协作。
- [持续子 Agent Provider](../../../src/agents/plugins/subagent/subagent-persistent-in-process/README.md)支持由可信应用绑定持续身份，但不会自行保存或恢复 Session；是否需要它应由提前汇报和继续执行的实际需要决定，不预先选定。
- 第一阶段的固定替身检查已验证基础调用；真实模型示例未获得输出，生成质量仍需单独验证。

## 使用示例与待确认的交互

父导演收到“处理曲水城城防与商贸矛盾”的任务及固定背景，规划初步安排，将“夜间抵达的商队如何处理入城请求”交给子导演，并说明城门规则等约束。子导演若认为任务仍需拆分，可将更小的任务交给下一级；测试用模拟结果表示守卫拒绝开门、商队在城外扎营。父导演收到结果后，结合未解决的货物问题规划下一子故事，不能把拒绝改成开门。

另一示例中，子导演在任务尚未结束时发现模拟的城门发生火灾，可能影响父故事方向。子导演向父导演汇报当前情况，受影响的事件暂停等待父导演决定继续、调整或终止；决定如何传回、如何区分提前汇报与最终结果，须在本阶段确定。该示例中的事实均由测试提供，不代表世界中实际发生。

## 分步开发

### 1. 盘点与确定最小协作方式

- 核对第一阶段导演入口、提示词、现有委派工具、Spawn 创建器及相关测试，画清父 Agent、子运行句柄、Session 和资源所有权；核查子导演再次委派时的可信装配是否可用。
- 用上述示例讨论任务交付的必要上下文、结果与模拟依据如何表达，明确父导演如何获得结果、何时可继续，以及失败与未完成如何区分。父子关系与故事层级相关，不把运行 ID 或 Session ID 当作故事 ID。
- 比较复用通用工具和扩展现有委派能力的适用范围；确定模型能做什么、可信应用绑定什么，以及是否需要新的业务工具。只设计本阶段所需能力。
- **验收：**能说明从调用方输入到父子协作结果的具体过程，以及创建、取消和释放由谁负责；确定本阶段文件记录范围、版本、失败策略、已知限制和接口后再实现。

### 2. 保存初步安排并实现单层调度与回报

- 程序安排导演形成一组事件初步安排并保存文件，再选择当前事件，交由可信装配的导演处理；明确导演 Preset、模型配置和上下文范围，后续事件不提前定稿。
- 子导演返回任务结果及必要依据；测试替身明确标记模拟经过、变化和未解决事项。调用方区分正常完成、失败、取消和基础设施异常；正常输出不自动成为世界事实。
- 验证父导演实际接收到结果并可继续作出规划；不将固定替身的回复当成模型理解能力的证明。
- **验收：**固定模型替身覆盖任务交付、上下文隔离、回报及偏离计划的结果；验证未授权 Preset、启动失败、子任务失败及句柄释放，不虚报成功。

### 3. 递归委派与资源归属

- 程序安排导演判断当前事件是否拆分；需要时保存子事件初步安排与父子关系，逐个调度下级导演。子导演在本层可承担父导演职责；先支持串行协作，不引入并行故事调度，也不依赖上级调用持续嵌套等待。
- 明确每层运行及其子运行的所有者、父任务取消传播、启动中取消、失败后的释放以及重复清理。检查可重复清理和晚到结果，避免结束的运行继续改变所属状态；需要限制资源时先明确配置和理由，不把技术限制当成固定故事层数。
- **验收：**至少走通父、子、孙三层任务和逐层回报；覆盖中间层失败、取消、创建失败和清理失败，核对各层实例及运行句柄释放，已完成结果不被伪造或改写。

### 4. 提前汇报与继续执行

- 受影响的事件暂停等待父导演决定；确定决定如何传回、无法送达或父任务取消时如何处理，以及多层汇报如何定位目标。区分中途情况、父导演决定和最终回报，不能把中途汇报当作子故事结束；其他无关事件能否继续留到并行调度阶段。
- 对照现有前台等待工具、一次性运行和持续子 Agent 的能力，选择满足已确认交互的最小机制；若需扩展，明确通信所有权、等待与取消、异常及清理，再进行实现。
- **验收：**模拟重大情况，在最终结果之前让父导演收到依据并作出决定，验证决定传达后的继续或终止；覆盖取消、父导演失败、通知失败、重复汇报和清理，不声称支持进程重启恢复。

### 5. 根据结果继续规划

- 程序将最终回报交给父导演，对照当前父故事目标评估，根据模拟结果完善下一兄弟事件；一层处理完后逐层向上评估。若测试涉及预估数量用完，遵循最多增加一个、之后按实际结果调整的业务约定。
- 用明确标记的测试数据保留已发生结果与尚未发生的计划；本阶段不写入真实世界状态，最小文件记录与正式故事记录的关系在第三阶段明确。
- 根据用户给定的本次最小子事件数量控制模拟演绎，未指定时使用 5；达到数量后保留未完成进度。计数时机、失败计数与继续时的数量设置先行确定，不将数量限制当作父事件或整轮演化完成。
- **验收：**覆盖目标达成、未达成、偏离计划及需要提前终止的情况；验证父导演获得前序结果、未改写模拟历史，并区分下一步建议与实际事件。

### 6. 整体验证与官方对照

- 通过项目声明的入口使用固定模型替身走通单层、多层、提前汇报和后续规划；覆盖取消、失败和清理，运行与实际修改相关的聚焦测试及类型检查。涉及构建入口时显式构建并冒烟检查。
- 如模型和网络可用，使用曲水城与另一题材观察真实输出；分别报告是否执行、模型能否理解委派及结果，不以一次输出证明稳定可靠。缺少凭据或调用失败时明确记录，不能伪装通过。
- 对照 DeepSeek Harness 官方与本阶段实际涉及的子 Agent 委派、Agent 生命周期和通信机制，解释异同、适用边界及原因；没有对应业务能力时明确说明。
- **验收：**报告实际检查及结果，说明模拟与真实世界运行的区别、未覆盖部分和已知限制；文档、入口和目录说明与最终实现一致。

本轮最初事件均处理完后，完整工作流等待用户选择继续演化，再读取当前状态规划新一轮；本阶段可用模拟入口验证该边界，不声称真实世界演化已贯通。

## 本阶段需要讨论的问题

1. 提前汇报后的父导演决定如何传达，以及失败和取消时如何处理。
2. 每次委派和回报最少需要哪些上下文与依据；哪些内容由可信应用绑定，哪些由导演组织。
3. 如何以文件表示多层关系与运行进度，并区分计划、模拟结果和真实世界事件；不得将 Session 当作业务完成凭据。
4. 最小子事件数量的计数时机、失败计数和继续时的数量设置；资源限制及失败后的具体重试与恢复方式。

上述问题随相应步骤讨论和确认，不预设最终协议、存储格式或具体调度实现。本阶段的最小文件记录先定义版本与失败策略；完整故事持久化、真实状态更新和跨进程恢复分别进入后续阶段。
