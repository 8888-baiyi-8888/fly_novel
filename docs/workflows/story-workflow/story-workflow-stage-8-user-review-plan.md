# 故事级工作流第八阶段：用户审阅

本文细化[总体开发计划](story-workflow-development-plan.md)第八阶段，落实[暂停、恢复与用户介入](story-workflow.md#暂停恢复与用户介入)中的父故事安排审阅。首版通过可信应用入口展示初步安排、记录决定并继续。按[学习型开发要求](../../development-plan.md#学习型开发要求)逐步实现和验收。

## 实现路线

父导演保存本层的初步子故事安排后，在启动第一个子故事之前检查审阅设置。根故事和递归拆分形成的父故事使用同一规则。可信应用固定当时的安排、可选方案、推荐项和版本。用户选择或超时结算先保存决定，程序再从该父故事的第一个待推进子项继续。后续子故事的具体任务仍由父导演根据已有结果逐个形成。

| 审阅模式 | 行为 |
| --- | --- |
| 关闭 | 延续既有多层故事推进，安排保存后直接继续。省略审阅配置时沿用此模式。 |
| 限时等待 | 持久记录开始时间与截止时间。截止前接受可信用户选择。到期仍未选择时，由应用按审阅记录中的推荐项结算，决定来源标为超时自动选择。 |
| 持续等待 | 保留待审阅状态，直到有明确用户选择或取消。没有截止时间。 |

首版只审阅父故事的初步安排。普通角色动作、人物死亡等剧情变化沿用演绎、判断和结果记录。已推进的事件与状态保留原有证据。第七阶段的一次补充按既有评估和推进规则处理，本阶段的审阅点放在初步拆分保存后。并行故事中多份审阅的展示和调度留给后续阶段。

## 审阅内容与决定

| 内容 | 约定 |
| --- | --- |
| 待审阅内容 | 展示父故事的目标、约束和初步子故事安排。可选方案均使用应用校验过的稳定 ID，展示必要差异与推荐理由。选项的最小验收采用同一批子故事的两种顺序。原计划仍可重读，最终采用的顺序由审阅决定引用。只有一份安排时，展示该安排及继续的选项。 |
| 审阅记录 | 绑定运行、父故事、安排及相关评估依据的摘要。保存实际展示的内容、选项、推荐项、模式和期限。来源改变且影响选择时，旧审阅失效，重新展示后取得决定。 |
| 用户决定 | 可信应用从用户交互获得选项或明确取消，写入决定来源、审阅 ID、所见版本、所选方案及决定时间。过期、选项不存在、归属错误及来源变化分别拒绝。 |
| 超时决定 | 应用根据权威时钟检查截止时间并采用已保存的推荐项。读取待审阅状态和执行超时结算使用独立入口。应用在线时可在到期触发结算，重开应用时检查已到期的记录。记录实际结算时间和规定截止时间。 |
| 中断与继续 | 离开界面、取消本次调用或进程退出保留已保存的等待状态。明确取消审阅记录可信用户的终止选择。决定已保存但推进结果未知时先核对业务记录及消费标记，再判断可否继续。 |

同一审阅版本只能接受一个决定。用户提交、取消和超时结算使用同一个独占提交边界。在该边界内用应用时钟校验，按 `当前时刻 < 截止时间` 接受限时用户选择，达到截止时间由超时结算处理。相同决定可重读已保存结果，冲突决定应明确拒绝。继续时再次核对决定及采用的安排，并独占取得推进位置。

## 曲水城固定验收

父故事提出「先核对闭门规则和等候条件，再考虑货物安置」及「先组织门外等候方案，再核对规则适用条件」两种安排。两者沿用已配置的地图、状态和目标证据。推荐第一种，用户选择第二种时，首个实际推进的子故事随所选顺序变化。后续任务需读回已完成子故事和当前状态再定，并保留第七阶段的事件与状态回执。使用固定模型与可控制时钟分别验证手动选择、推荐回退和持续等待。

## 分步开发

### 1. 核查审阅位置和原有暂停语义

- **输入与动作。** 沿[应用入口](../../../src/app/story-workflow.ts)、[多层推进](../../../src/story-workflow/workflow.ts)和[暂停恢复](../../../src/story-workflow/progress.ts)检查根故事与嵌套父故事的拆分保存、子项推进前检查和暂停独占消费。对照[世界初始化的用户决定入口](../../../src/app/world-initialization-workflow.ts)盘点可复用的可信动作与版本绑定原则。
- **交付及验收。** 只读列出插入点、读取和写入责任。明确审阅等待与批量演绎暂停的区别、原有计划和回报的兼容读取方式，以及首次进入与继续入口的归属校验。

### 2. 定义审阅配置、选项和版本化记录

- **输入与动作。** 在可信故事运行入口集中解析三种模式。限时模式校验正数时长并固定截止时间。定义审阅记录、稳定选项、推荐项及决定格式。初版对可选顺序校验归属、重复、缺失及依赖约束，缺少可选替代时提供继续当前安排。原始安排、审阅快照和实际采用安排分别按其职责读取。
- **交付及验收。** 重开后可完整读回用户看到的安排。拒绝非法时长、身份不匹配、推荐项失效、未知版本、重复选项或正文损坏。旧计划与已有格式的暂停按原语义读取。

### 3. 把审阅等待接入根故事与嵌套父故事

- **输入与动作。** 在初步拆分持久化后、写入首个子项决定前检查该父故事的审阅设置。启用时保存可重开的审阅和推进位置，返回可展示的待审阅状态。关闭时走原推进路径。可信展示入口返回父故事可见内容、截止时间和可操作选项。等待期间释放本次导演调用资源。
- **交付及验收。** 验证根层与嵌套层都能停住且尚无首个子故事的执行记录。审阅等待与正常批次暂停可分别核查。重开和离开界面时恢复原审阅版本与期限，未产生新模型调用或新的审阅副本。

### 4. 接通用户选择、取消与限时结算

- **输入与动作。** 实现可信用户选择和明确取消入口，以及应用执行的超时结算入口。使用可替换时钟和同一独占决定边界处理争用。复核原安排与选项版本。没有有效推荐项或证据失配时，保留待核查状态供应用显示。
- **交付及验收。** 覆盖截止前选择、恰好到期、到期后选择、持续等待、明确取消、重复请求和用户选择与超时并发。超时只采用已保存推荐项，记录来源和实际结算时间。决定读取不会修改记录。

### 5. 按决定继续并核对实际采用的安排

- **输入与动作。** 程序从已确认或已超时结算的决定恢复对应父故事，校验采用方案并独占推进。区分决定已保存、尚未消费、已经消费及推进结果不明。按采用顺序推进，并把审阅依据关联到后续回报和暂停核查。结束或取消后保持已保存证据可读。
- **交付及验收。** 手选另一顺序后，从所选子项开始。同一决定重复继续不会重复启动故事。模拟决定已写但响应丢失和消费后中断。只有证据足以定位时才继续，避免盲目重跑。

### 6. 贯通曲水城固定替身验收

- **输入与动作。** 通过正式应用入口展示曲水城方案，完成关闭审阅、手动采用、限时回退、持续等待和取消路径。加入嵌套父故事与重开进程的用例，并从历史记录对照选项、决定来源、实际推进顺序和后续子故事回报。
- **交付及验收。** 用户能从应用入口查询审阅待办、选择、取消和按决定继续，固定替身可重复验证。覆盖旧批次暂停、审阅后的新暂停及第七阶段事件和状态回执仍可重读。运行聚焦测试、类型检查和正式构建入口冒烟测试，记录实际命令与结果。
