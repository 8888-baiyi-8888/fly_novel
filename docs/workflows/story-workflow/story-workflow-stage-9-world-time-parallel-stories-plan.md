# 故事级工作流第九阶段：世界时间与并行故事

本文细化[总体开发计划](story-workflow-development-plan.md)第九阶段，对应[并行故事与角色时间](story-workflow.md#并行故事与角色时间)。按[学习型开发要求](../../development-plan.md#学习型开发要求)逐步实现和验收。首版在同一世界的一段有限时间内推进两条独立故事线，验证共享角色、地点可达性和一项共享状态的先后关系。

## 实现路线

可信应用为两条故事线指定共同的世界时间基准，绑定各自的运行，并在一段有限的时间窗内登记可独立结算的场景。导演提出场景时间、地点和参与需求，应用核查来源、版本、角色与状态依赖，批准排期后再允许演绎。不同故事线可以同时运行资源独立的场景。同一角色前后涉及的场景按世界时间排队，后续场景需要等到前段相关行动、角色认知及所需状态存在可核对的结算记录。

| 对象 | 首版约定 |
| --- | --- |
| 世界时间 | 可信应用设置世界内时间起点，使用非负安全整数分钟和半开区间 `[start, end)`。业务依赖使用世界时间，执行超时、审阅截止及诊断日志使用应用时钟。场景内部沿用互动序号。同一世界分钟内的前后关系由同一场景序号或显式依赖确定。 |
| 时间窗与排期 | 每个世界同一时段只由一个可信调度入口受理。执行前固定当前时间窗及其资源声明，包括可能因审阅而等待的早期场景。尚未获准演绎的场景可显式修订。新发现的参与者、写入目标或提前插入的场景需要重新核查涉及的承诺；已开始或结算的区间和证据不可回填改写。时间窗结束须核对未决记录，再开放其后的排期。 |
| 调度单元 | 首版以可独立结算的场景为单元。应用把区间、角色、地点和状态读写权限绑定到世界、运行、故事与场景身份。一个故事可以横跨多段；角色先完成前一段后，即可参与另一故事，原故事后续段落可以等待。若要在某个场景的中间离场交接，先把它设计为分别结算的场景。 |
| 角色与通行 | 以世界 ID 和角色业务 ID 跨运行核对占用。首版拒绝同一角色的场景区间重叠，包括同地点重复演绎。前场结算给出结束地点，后场开始地点不同则核查方向、通行条件、所需时长和来源版本。路线缺失、条件不明及时间不足分别报告。 |
| 共享状态 | 场景声明需要读取和可能写入的业务目标。首版使用第七阶段的商队状态。相同目标的读写、写写排期按世界时间协调，重叠时要求调整。只读同一版本可以并行。前场已确认的变化以结束时刻生效，后场入场时固定可见版本和依据，应用写入前按预期版本再次核查。 |

时间窗登记覆盖后续场景实际依赖的角色和状态。角色临时加入、场景延长或行动涉及未声明状态时，在实际调用角色或写入前停止并重新核查；不能将临时需求补记为已获授权。首版限定单可信写入进程和有限并发，地点间通行只校验已知直连路线或经应用授权的固定证据。通用寻路、跨进程写入、跨世界调度和时间跳转留待后续需求。

### 运行与证据边界

- 排期状态至少区分待核查、等待前置、可推进、执行中、已结算及取消。等待原因应暴露受影响的角色、地点、共享目标、审阅批次或前置场景。时间相同且资源独立的场景使用稳定的候选顺序分配运行名额，完成先后以各自保存的证据为准。
- 领取前在同一世界内串行执行就绪核查与占用写入，一次领取当前场景需要的全部角色和状态权限。等候模型、模拟器或用户时不持有协调锁，应用保留任务所处阶段的业务占用及可读进度。运行句柄绑定排期及领取版本；重复领取或失效句柄不能再派发角色或提交变化。
- 场景结算核对互动、角色相关行动、事件和必要的状态回执后，记录实际结束位置与下游可用引用。排期区间是准入窗口，未确认的行动保留未决。明确取消且尚无业务效果时才可直接撤销占用；部分完成或结果不明时保留证据，等待核查相关资源，独立场景可继续。
- 后续场景先核对共享角色的前置位置和历次参与证据，再向该角色投递经单独授权的观察和经历。沿用每个子故事中的逐角色运行器和 Session，跨故事传递版本化的业务引用，过滤未收到的消息和其他角色私料。共享状态的版本可供应用调度检查，角色能否知道状态仍按场景可感知及资料授权判断。
- 审阅等待和按数量暂停沿用第八阶段及原批次继续入口。晚段场景不能因早段审阅超时或调用中断而自动放行，只有保存的决定和经核查的业务结算才能解除对应依赖。批准改变执行顺序后重新核查排期。若续跑点不明，保留领取记录和原占用，应用按实际角色响应、事件与回执核查，禁止自动重放有未知效果的操作。

## 曲水城固定验收

起点采用可信夹具提供的当夜世界时间。地图、夜间闭门规则、商队到达和等候状态沿用前几阶段的固定资料。新夹具为北门、值所和北门至值所的有向路线提供业务 ID、适用条件及版本，定长旅程为 10 分钟。

| 场景 | 排期及预期 |
| --- | --- |
| 甲线城门交涉 | 守卫和领队于北门在 `[0, 10)` 交涉。行动确认后，商队等候状态在第 10 分钟生效。保留守卫听到的内容及仅领队获知的私下信息。 |
| 乙线值所准备 | 书记员在值所的 `[2, 8)` 准备登记，资源独立。用两个可控闸门验证该场景在甲线仍执行时确实获准开始。 |
| 乙线守卫交接 | 守卫从北门到值所，最早第 20 分钟开始交接；`[8, 12)` 重叠，`[15, 18)` 通行时间不足。即使有效排期已登记，也必须等甲线完成守卫相关行动并确认结束地点。守卫可使用自己听见的信息，书记员等守卫明确转述后才能知道。 |
| 商队共享状态 | 另一段与旧写入窗口重叠的商队状态写入被拒绝。依赖等候结果的后段只使用前段确认的版本。回执不明时后段保持等待；不读写商队目标的场景可以继续。 |

## 分步开发

### 1. 核查入口与固定验收条件

- **输入与动作。** 沿[多层故事推进](../../../src/story-workflow/workflow.ts)、[暂停与审阅](../../../src/story-workflow/progress.ts)、[场景互动](../../../src/app/story-scene-interaction.ts)、[角色运行器](../../../src/app/story-character-runtime.ts)和[商队状态](../../../src/app/story-convoy-state.ts)梳理角色出场、行动结束、结算、读写和关闭时机。核对[地图连通格式](../../../src/agents/plugins/map/format.ts)及[世界访问协调](../../../src/util/world-access.ts)可复用的校验和进程边界。
- **交付及验收。** 只读列出已有证据和缺口，确定两个故事运行的身份、记录根、时间窗、路线、角色和共享目标夹具。确认现有场景序号只定位场景内顺序，现有世界协调只覆盖接入的应用操作。

### 2. 定义世界时间、排期及版本化记录

- **输入与动作。** 绑定世界、时间窗、故事运行和场景，定义时间起点、区间、地点、角色与状态读写声明、依赖及版本。保存批准安排和修订理由，建立只读查询。区分资源顺序依赖和需要特定业务结果的依赖；后者在前项取消时必须重新计划。核查循环、未来依赖、越界和晚到的插入请求。
- **交付及验收。** 重开后能读回相同窗口与声明。拒绝身份混用、反向区间、越界、循环依赖、未知格式、损坏正文及旧版本提交。已有故事和暂停继续按原格式读取，缺少可信时间的旧记录不自动获得排期。

### 3. 核查角色占用与地点可达性

- **输入与动作。** 按世界角色查找当前场景的直接前后安排。使用固定起始位置或前场已确认的结束位置，核对通行方向、时间和条件；地图只提供可信证据，资料不足时返回可查的等待原因。建立角色冲突查询与校核，角色组按一次操作整体受理。
- **交付及验收。** 独立角色可重叠，同角色重叠被拒绝。同地点区间相接可在前置结算后推进，不同地点仅在旅程条件满足时放行。覆盖缺路线、逆向连接、路线来源变化、实际结束位置有变及多人领取部分失败。

### 4. 建立多故事调度、执行领取和暂停

- **输入与动作。** 在可信应用引入按时间窗调度的入口。复用故事树各自的父子推进和批次证据，在场景调用前独占领取并检查审阅、前置和取消状态。同一运行的父子决定仍按原顺序推进。用受控并发推进独立场景，挂起受影响的分支，公开只读就绪和等待状态。取消或关闭时停止新领取，等待已受理调用清理后再核查业务占用。
- **交付及验收。** 两个独立场景可实际同时执行，共享角色只有一个有效领取。限时或持续审阅中的早段阻挡依赖场景，独立分支可以推进。验证领取竞争、重复继续、领取后取消及关闭时回调返回，已生效记录和未决标记可重读。

### 5. 接通跨故事角色经历和可见性

- **输入与动作。** 从已结算场景提取角色自己的已确认行动与获准观察，记录世界时间、角色、参与和感知证据版本。下一场景在调用角色前，校验相关前置已完成并将授权内容送入所属角色的认知输入。重复继续时按来源及投递目标核对，避免重复投递；来源变更时停止并重新准备。
- **交付及验收。** 守卫可在值所使用自己在北门听见的话和完成的行动。书记员及其他未接收者保持原认知，直至相关信息实际传给他们。覆盖部分听闻、私下消息、取消的参与、未决响应和新进程重新组装角色认知。

### 6. 接通共享状态冲突与结算

- **输入与动作。** 为获准的状态目标固定有效时刻和版本读取范围。写入前复核排期权限、已采用事件、预期版本与可信状态授权。结算写入引用实际回执和结束位置，按业务效果解除依赖。先读回证据，再处理拒绝、并发版本变化和有写入但响应丢失的情况。
- **交付及验收。** 覆盖相同目标的读读、读写和写写；未来版本不能进入较早场景。重复结算不得再次应用变化，结果不明不得启动依赖者。取消或失败后的无关场景可以继续，已发生的事件和已应用状态保留可核对证据。

### 7. 贯通曲水城固定替身并验收恢复边界

- **输入与动作。** 通过可信应用公开入口运行甲乙两条故事线。保存一份可核对的时间窗视图，串联排期、采用版本、角色参与、事件、共享状态、回报和等待原因。从角色等待、已领取但响应丢失、状态回执待核查三个位置重开，执行本阶段允许的继续操作。
- **交付及验收。** 固定替身证明并发、先后、可达性、授权和中断行为都成立。覆盖旧的串行故事、审阅继续和旧版本记录读取。执行聚焦测试、类型检查、正式构建入口冒烟，记录实际结果。第十阶段继续处理跨模块完整恢复入口及更广泛的故障诊断。
