# 故事级工作流第一阶段：基础导演 Agent 开发计划

本文细化[总体开发计划](story-workflow-development-plan.md)的第一阶段；业务约定以[故事级工作流](story-workflow.md)为准。本文是待实施计划，不表示故事工作流已经运行。按照[学习型开发要求](../../development-plan.md#学习型开发要求)，先确认使用方式和接口，再实现与验证；完成本阶段后等待明确指示，不自动进入下一阶段。

## 目标和边界

让一个导演 Agent 接收调用方提供的故事任务和固定背景，自主提出父故事方向、子故事初步安排以及当前可展开的场景和参与者建议。导演根据任务决定规划细度；本阶段输出是建议，不是已经发生的事件，也不更新世界状态。

本阶段不实现父子导演实际委派、角色调用、场景演绎、世界资料查询或补充、故事持久化、审阅等待、规则计算和调度。可在建议中提及参与者或需要补充的资料，但不得宣称已经调用角色、补充设定或完成故事。

## 使用方式与预期行为

可信调用方装配模型和导演实例，提供任务及明确标注的背景文本，调用导演并接收文本结果，最后按实际创建方式释放资源。先沿用现有 `agent.run({ prompt })` 的调用方式作为讨论起点；是否需要更薄的应用封装，核查现有入口后再定，不预设新的数据结构或协议。

示例输入可包含：曲水城夜间关闭城门是已知规则；商队即将抵达是本次起点；“城防与商贸关系可能趋紧”是发展方向；城门地形和守卫态度尚不明确。任务是围绕这一局势提出父故事目标、子故事初步安排，以及当前适合展开的场景和可能参与者。

期望导演提出有背景、目标和约束的安排，说明未知资料及需要时的补充；将未来事件表述为计划或可能性，不写成已经发生。导演可以选择与示例不同的合理安排，不指定守卫或领队必须作出的决定。调用失败或取消时向调用方报告，不能返回虚构的完成结果。

## 逐步实施

### 1. 核对入口与职责

阅读预设、提示词、应用创建函数、Harness 创建及销毁契约和现有测试，梳理调用者、实例与框架的资源归属。记录现有入口是否满足固定背景输入、错误传播和释放；只对本阶段必要缺口提出修改。确认输入内容、文本输出及调用方式后再编码，避免提前设计故事存储格式。

**完成条件：**能用上述示例说明谁提供背景、谁运行导演、谁负责释放，以及现有入口是否需要调整。

#### 核对结论

- **输入和输出：**可信调用方将任务、已知事实、发展方向和未知资料组织为 `prompt`，调用 `agent.run({ prompt })`，成功得到 `{ content }` 文本；这份文本是导演建议。调用方负责解释和使用结果，当前接口不校验规划是否合理或持久化故事。
- **创建和释放：**`bootstrapAgents()` 建立框架；直接使用 `factory.create` 时工厂不持有实例，调用方负责等待 `agent.dispose()`。使用 `manager.create` 时实例由 Manager 登记，调用方通过 `manager.dispose(id)` 或 `manager.disposeAll()` 等待清理。初始化失败由 Agent 清理已创建的插件作用域；清理同时失败时汇总错误。
- **运行和取消：**`run` 将请求交给 Loop，失败或取消以 Promise 拒绝传播；`agent.cancel()` 中止当前请求并拒绝排队请求，`dispose()` 等待 Loop 收尾并释放插件作用域。现有导演应用创建函数返回实例，调用方负责销毁；它不暴露 Manager，不能依靠 Manager 管理通过工厂创建的实例。
- **入口判断：**现有 Harness 的文本调用足以承载固定背景，无需为了本阶段新增故事输入结构或专用接口。应用创建函数固定读取 `deepseek` 配置，无法直接注入固定模型替身；测试可像现有应用测试那样替换配置读取，或直接通过 Harness 注入适配器。是否调整应用入口应以第三步的实际使用和生命周期验证为依据，当前未发现必须新建入口的证据。
- **职责缺口：**现有提示词只要求根据目标、规则和人物状态安排处境并保留角色自主性，尚未明确父故事和子故事初步规划、事实与发展方向的区别及未知资料。第二步应完善这些职责；预设未装配工具，不能声称已读取世界资料或实际委派。
- **验证缺口：**现有提示词测试验证装配、隔离和实例销毁；应用测试创建并销毁导演，但没有通过该应用入口运行导演，也未针对导演入口验证模型失败或取消。上述判断来自代码与测试阅读，尚未在本小步执行测试或验证真实模型质量。
### 2. 完善导演职责

在现有导演提示词及必要装配中表达本阶段职责：围绕所给方向和局势规划，区分事实、计划和未知，按需提出场景与参与者；为角色保留自主选择，承认资料不足。避免要求固定数量的场景或将所有子故事细节提前定稿。只描述本阶段能做到的行为，不赋予未装配的工具能力。

**完成条件：**检查实际发送给模型的系统提示词与调用输入；导演和角色的提示词作用域仍隔离，输出仍为建议。

### 3. 最小调用与生命周期

优先使用现有 Harness 和应用装配。若核查发现现有创建函数无法满足使用和释放要求，仅修复本阶段必要问题；明确成功、模型失败、取消以及创建或运行失败后的资源归属。调用方提供固定背景，配置与凭据通过项目现有机制提供，不将真实凭据写入示例。

**完成条件：**通过项目声明的入口创建、调用和释放实例；失败和取消可观察，不泄漏资源或静默伪造成功。

### 4. 验证与对照

使用固定模型替身验证导演预设和提示词装配、示例输入传递、返回值、模型失败、取消及清理；复用现有覆盖，只为新增行为补充必要测试。固定回复不能证明模型理解：另外准备曲水城示例和一个不同题材示例，检查真实模型输出是否区分事实与规划、保留角色自主性并指出必要未知；真实模型不可用时记录跳过原因，不称其通过。根据实际改动运行聚焦测试、类型检查和必要的构建入口检查，并更新相关说明。

完成验证后，对照 DeepSeek Harness 官方与本阶段实际涉及的 Agent 装配、提示词或调用机制，说明可比范围、异同及原因；没有直接对应功能时明确说明，不强行类比。

**完成条件：**报告实际执行的检查及限制，区分确定性调用测试与生成质量观察，列出尚未接入的后续能力。

## 阶段完成标准

调用方可以通过已验证的入口提供固定背景并获得导演建议；导演职责和例子体现计划与事实分离、角色自主和资料留白。相关错误与清理路径经过聚焦验证，文档与代码一致。此结果不证明父子导演协作、实际角色参与、事件写入或完整故事运行已经实现。
