# 故事级工作流第十阶段：恢复与完整运行入口

本文细化[总体开发计划](story-workflow-development-plan.md)第十阶段，对应[暂停、恢复与用户介入](story-workflow.md#暂停恢复与用户介入)。按[学习型开发要求](../../development-plan.md#学习型开发要求)逐步实现和验收。首版在一个可信应用进程内装配曲水城的完整故事运行，并验证进程退出后能从持久记录核查和继续。

## 实现路线

可信应用启动时绑定世界、初始化交付、运行记录根、模型装配、用户审阅设置和可选的世界时间窗。正式入口贯通准备规划、逐层推进、场景资料核查、角色演绎、事件采用、状态回执、父导演评估和轮次结果。遇到等待或中断，应用返回可重读的运行标识及当前处理位置。重开时先只读诊断，再由明确的应用动作继续、核查现有结果或提交用户决定。

| 能力 | 计划入口与职责 |
| --- | --- |
| 装配与开始 | 由可信 Node.js 应用打开运行服务，校验目录和世界归属，显式借用或持有地图、人物、世界初始化与调度句柄。开始时分配稳定运行入口 ID，保存所选配置和来源并关联已生成规划。相同开始请求重读原身份；内容有冲突时拒绝。 |
| 核查运行 | 按可信绑定只读读取业务证据，返回运行、轮次和当前处理对象、关联的审阅或排期状态、已确认结果以及阻塞原因。缺失、无权、来源变化、读取失败、格式损坏和结果不明各有明确状态。并行故事分别报告进展及依赖。 |
| 继续与核对 | 继续指定已核对的批次或保存点。核对动作重读现有证据，必要时仅补写对应的派生记录。审阅选择、取消、超时结算及按授权应用状态仍调用既有可信入口。操作绑定用户看到的版本或诊断时核对的证据，请求执行前再次校验。 |
| 结束与下一轮 | 通过根回报、评估及其引用的场景、事件和状态核查本轮是否结束。用户明确选择开始下一轮后，用更新后的可信输入建立独立规划，关联前轮身份及结果版本。已完成轮次可重读。 |

首版交付可直接调用的正式应用入口和使用固定数据的本地样例。延续单可信写入进程约定。应用负责身份授权、配置和资源释放，模型只收到本步骤需要的资料，不取得确认、核对或发布权限。写作生成及通用管理界面不属于本阶段。

### 持久记录和独占推进

运行入口记录保存世界和交付版本、计划与前轮关联、目标及审阅规则版本，以及关联的调度和状态来源标识。每份业务正文仍由所属模块保存。新增记录需有明确版本、归属和读取上限。旧故事格式继续按原入口读取；只有可信绑定和证据足以定位恢复动作时才接入统一继续。

有业务写入的步骤先保存操作意图，分配稳定操作 ID 与预期版本，再走该业务入口的独占领取、写入和回执核对。应用发现已有最终文件时按身份及摘要读回，比对成功后只补写缺失的进度引用。每次继续先复查当前记录、前置证据、配置兼容性和消费标记，再独占领取对应位置。重复请求返回已确认结果或待核查位置；并发请求或过期版本不能启动第二次演绎。

导演输出若用于固化任务、拆分、回报或评估，先保存经验证的输出，再产生对应业务记录。只有明确没有外部效果的结构化生成可按原输入与操作身份重新执行。出现文件已创建但发布结果未明、审阅领取后中断等情况，先对照业务记录判断下一安全操作；仅有领取标记且现有证据不足时保留待核查。关闭应用停止新领取，传播取消并等待已受理操作和 Agent 释放；持久记录保留其实际状态。

### 按保存点恢复

| 保存点 | 首版恢复约定 |
| --- | --- |
| 资料与初步规划 | 核查原交付、目录及当时选用的资料版本。已有规划按原快照读回；尚未开始的规划可使用已记录的请求开始。候选生成或采纳中断时，分别核对领取、候选及应用采纳证据，保留原采纳范围。 |
| 审阅、批次和父子推进 | 复用尚未消费的原批次以及有效审阅决定。只读查询待审阅状态；应用按需显式结算限时等待。已领取批次从保存的父子选择、任务、拆分、子项回报及评估重建可证实的推进位置。下一步已开始且缺少证据时停住。 |
| 场景与角色 | 已保存设置且尚无角色或业务占用时可重新准备；有有效的回合起点、决定和调度证据时从下一待执行回合继续。角色响应已保存但尚未进入互动记录时，可核对后补挂同一响应。只有领取而缺响应时保留待核查。重装逐角色 Agent 时重新授权已保存的认知来源，业务认知不从内存 Session 或其他角色的私有历史恢复。 |
| 排期与并行依赖 | 复用排期身份与原领取证据核查场景，必要时用既有结算核查入口补记结束位置和共享状态。新增回合继续动作必须证明原执行已结束且独占接管当前排期，不能再发一份场景领取。未决场景继续约束关联角色和状态，独立分支可推进。 |
| 事件和状态 | 已结算场景缺事件采用时先验证原授权，再按稳定身份采用。检查操作意图、原事件、实际状态和应用回执。状态已应用且回执可重读时补齐引用；确定尚未应用时由可信入口核对原授权及期望版本后继续同一操作；结果不明或来源失配时等待核查。 |
| 模拟、回报和评估 | 已结算场景可从当时保存的模拟结果或经核验的场景集合构造回报输入。只有可信模拟器明确写下最后一个场景或结束凭据后，才可从场景集合补齐模拟。回报、父导演接收或评估已保存时引用原版本，缺少派生结果且输入完整时只执行缺失步骤。 |

## 曲水城固定验收

以初始化交付中的夜间闭门规则和可信的商队抵达资料开始。导演提出初步安排，应用停在审阅，随后经明确决定继续。场景准备检查北门和等候点，可按原权限核对已有地图或采纳一次提案。守卫、领队分别使用角色授权信息演绎，程序保存感知、实际行动和结算。采用事件后应用商队状态，子故事回报及父评估引用可核对的证明。用户可在本轮结束后用更新的世界资料明确开始下一轮。

在同一夹具中加入值所故事线，通过第九阶段排期验证早期审阅或北门写入不明时值所独立准备仍能进行，依赖守卫交接或商队版本的场景保持等待。固定替身用保留和中断不同保存点的方式证明恢复后未重复启动角色、采用事件、应用商队变化或确认审阅。

## 分步开发

### 1. 核查既有启动、记录与恢复位置

- **输入与动作。** 沿[故事应用入口](../../../src/app/story-workflow.ts)、[批次恢复](../../../src/story-workflow/progress.ts)、[世界排期](../../../src/app/story-world-schedule.ts)、[现有调试入口](../../../src/app/story-workflow-debug.ts)和[初始化交付契约](../word-initialization/world-initialization-stage-9-contract.md)追踪业务读取、领取、写入和释放。区分可直接复用的暂停、审阅和结算入口，与尚缺稳定保存点的运行步骤。
- **交付及验收。** 只读形成接入点和恢复矩阵。逐项记下权威记录、所需授权、重开后能定位的身份、允许的下一动作及必须停住的条件。确定固定替身和故障注入点。

### 2. 建立可信装配和版本化运行身份

- **输入与动作。** 定义统一入口的配置和运行记录。校验真实目录、世界与交付的匹配、模型和角色配置版本、审阅策略及调度、状态来源。明确启动、借用、异步关闭和启动失败后的清理。持久关联运行入口 ID、开始请求和生成的计划 ID，覆盖规划已保存但关联响应丢失的情况。
- **交付及验收。** 合法配置可打开、关闭、重开并定位原运行。拒绝跨世界、目录重叠、权限失配、未知格式、损坏数据和同一请求 ID 对应内容变化；重复开始不会另建一轮。

### 3. 实现统一只读诊断

- **输入与动作。** 从计划、父子树、审阅、场景、互动、排期、已采用事件和商队回执读取权威依据，投影可继续位置及受阻范围。输出稳定的状态和原因，附来源或缺口的身份及版本。应用根据调用权限展示公共结果，角色私有 Session 和认知继续通过独立授权查看。
- **交付及验收。** 区分等待审阅、排期阻塞、可继续、已完成、已终止和结果待核查。覆盖状态已应用但回报缺失、来源变化、读取失败和证据损坏。查询重复执行也不写文件、不领取批次、不调用模型。

### 4. 接通完整运行和审阅继续

- **输入与动作。** 正式入口从可信资料准备、规划到父子推进，串联用户审阅、场景资料选取、角色装配、互动和场景结算。启用排期时通过调度器放行场景。应用有限地推进至完成或可读的暂停点，向调用方暴露等待、结束和失败，并复用已有用户决定与超时入口。
- **交付及验收。** 曲水城固定替身从交付经审阅走到首个场景结算。验证暂停、重开、按已确认决定继续，及独立分支在等待期间推进。调用结束和失败后均能释放对应资源。

### 5. 恢复场景、事件及状态应用

- **输入与动作。** 按保存点核对角色参与、互动尾部、模拟结束凭据、排期占用和实际状态。为继续已确认但未附着的结果提供稳定动作。对状态已应用但回执响应丢失的路径，读取原操作的版本和正文确认实际效果并补齐引用。
- **交付及验收。** 覆盖角色仅领取、响应已存但未挂接、互动可接续、结算后缺事件、已获准未应用及已应用但响应丢失。证明重复诊断和重复恢复不会重复调用同一角色、采用同一事件或写入同一状态。缺凭据时保留待核查，独立分支可以继续。

### 6. 恢复父子推进并支持显式下一轮

- **输入与动作。** 用已核对的模拟、回报和评估重建父子推进位置。补写可证实的派生记录，再从首个未开始的子项继续，保留第七阶段的一次补充和提前终止语义。根据最终根结果及证据展示结束状态。用户明确选择时用更新输入创建与原轮关联的新规划。
- **交付及验收。** 场景已结算、导演回报失败时可重新形成回报并向上继续；有同一回报时可直接核对。已领取但无法确定效果的步骤能明确停住。下一轮必须绑定经核查的上一轮结果，重复启动请求读回原关联。

### 7. 贯通曲水城恢复验收及构建产物入口

- **输入与动作。** 用正式应用入口和实际构建产物跑完整样例。至少在审阅等待、场景中断、状态写入后响应丢失三个位置关闭或退出进程后重开。逐阶段对照业务记录和调用次数，核对新一轮身份、关联和世界资料版本。补齐应用入口说明、记录契约和样例操作。
- **交付及验收。** 从初始化交付到根结果的证据可追溯，未决动作保持可诊断，重开可继续具备完整依据的位置。运行聚焦测试、类型检查和构建产物冒烟，记录实际结果及真实模型验证范围。已有串行、审阅和并行流程均有兼容验证。
