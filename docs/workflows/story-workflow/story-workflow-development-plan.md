# 故事级工作流开发计划

本文按依赖顺序规划从导演 Agent 到完整故事运行的开发阶段；阶段内容是实施建议，不代表能力已经实现，也不替代[故事级工作流](story-workflow.md)中已确定的业务约定。具体接口、数据格式和未确定的业务规则在对应阶段结合示例讨论后确定。写作流程不属于本计划。

## 开发起点与方式

仓库已有导演和角色 Agent 基础预设；预设存在不代表已支持故事规划、角色调用或故事运行。世界初始化提供相关资料和交付契约，接入时须核查实际实现、交付范围和版本，不能假定所有规划资料均可直接使用。每阶段先盘点可复用能力，明确使用示例和缺口，再实现、验证；优先贯通小范围行为，后续逐步替换或扩展，不能把测试替身当成完整能力。

示例贯穿各阶段：导演围绕曲水城与商队的矛盾安排父故事，先委派“商队夜间抵达城门”，再根据守卫与商队的实际互动决定下一步。示例不预设角色选择和事件结果。

## 阶段安排

### 1. 基础导演 Agent

详细步骤见[第一阶段开发计划](story-workflow-stage-1-director-plan.md)。

- **目标：**使导演能够理解故事任务和可用背景，自主提出故事方向、场景安排和所需参与者。
- **开发：**盘点导演预设、提示词、Harness 装配和现有测试；补齐本阶段所需的导演职责及最小调用入口。先使用固定背景验证，不要求连接完整世界或存储。
- **验收：**固定模型替身验证装配、输入输出、失败和资源清理；用示例检查导演能区分发展方向与已发生事实。真实模型验证单独报告。

### 2. 父子导演委派

详细步骤见[第二阶段开发计划](story-workflow-stage-2-director-delegation-plan.md)。

- **目标：**程序管理事件计划和层级进度，安排导演逐层拆分、回报，并依据实际结果继续规划。
- **开发：**盘点并复用已有 Agent 能力，建立程序控制的规划、文件保存、逐层拆分和回报循环；先确定最小文件记录的版本、读取及失败处理策略，用可控替身模拟子故事结果。
- **验收：**验证计划保存、多层拆分、兄弟事件逐个处理、逐层回报和根据结果规划；覆盖重大情况提前汇报、失败、取消和清理。

### 3. 故事、场景与运行记录

- **目标：**让父子故事、场景及执行进度可定位、保存和读取。
- **开发：**先讨论故事、场景、事件和世界状态的归属与关联，以及记录粒度；明确身份、版本、并发冲突、旧数据迁移或拒绝读取策略。分别保存 Agent 自身数据和业务运行数据，不用 Session 充当完成凭据。
- **验收：**创建并重读父子故事与场景，核对关联、进度和实际结果；覆盖未知版本、损坏、写入冲突及中断后的读取，不删除已有数据。

### 4. 世界资料接入与按需补充

- **目标：**导演从可信范围读取初始化交付和世界运行资料，并按故事需要补充设定。
- **开发：**盘点现有资料读取、交付依据和专用 Agent；区分已发生事实、发展规划、留白、未覆盖和读取失败。设计并接入按需委派地图等能力及补充结果的处理边界，不将 Agent 返回直接视为已确认事实。
- **验收：**以城门资料不足为例验证发现缺口、委派补充和再次检查；覆盖缺失、无权、读取失败与补充失败，规划不能被当作历史。

### 5. 角色调用与认知

- **目标：**导演按场景需要选择和调用角色，角色基于自身认知自主参与。
- **开发：**盘点角色预设、实例、会话和资料访问能力；讨论角色身份与实例如何对应、导演如何提出参与请求、场景上下文如何交付，以及角色可感知信息如何形成。明确调用失败、取消和清理；角色不能自动读取全局资料。
- **验收：**守卫与商队领队分别获得各自知道的信息并自主回应；验证角色不参与、调用失败及信息隔离，导演目标不直接指定角色行为。

### 6. 场景演绎与行动判断

- **目标：**导演组织场景，角色多轮互动，形成可记录的实际结果。
- **开发：**接通导演、角色和场景记录；导演决定场景组织与结束。预留世界规则判断接口，规则尚未建立时占位判断返回 `true`，导演仍判断行动结果。具体规则与组合方式留待讨论。
- **验收：**演绎城门交涉，区分行动尝试与实际结果；验证拒绝、等待或意外结果可以保留，场景结束不等于矛盾解决。

### 7. 事件、状态变化与故事评估

- **目标：**记录已发生的经过和状态变化，并由父导演依据结果推进故事。
- **开发：**讨论事件与世界状态的权威归属、写入边界和关联；区分记录结果、提出变化和实际应用变化。接通子导演回报、父故事评估及逐个规划后续子故事；预估数量用完后最多增加一个，仍未达成则按实际结果调整父故事相关内容。
- **验收：**覆盖目标达成、未达成及提前终止；验证失败或结果不明时不声称状态已更新，已发生事件不因调整计划而改写。

### 8. 用户审阅

- **目标：**在父故事形成子故事初步安排后，按用户设置继续或等待审阅。
- **开发：**实现审阅开关、限时等待和持续等待；可选内容展示选项及推荐项，记录用户选择或超时自动选择的来源。审阅不提前确定所有后续子故事，人物死亡等重大变化不另设确认。
- **验收：**覆盖关闭审阅、用户选择、限时未选和持续等待，以及取消或中断；超时选择不能记录为用户确认。

### 9. 世界时间与并行故事

- **目标：**支持故事线在相同或交叉世界时间发展，同时协调角色和共享状态。
- **开发：**先讨论时间推进、角色占用、事件暂停与继续、地点可达性及共享状态冲突；再建立适合实际场景的调度方式。角色此前相关行动完成后，后续事件才能使用相应经历；角色不自动知晓其他故事线。
- **验收：**验证两条故事线使用同一角色时按世界时间先后处理，必要时暂停和恢复；覆盖占用释放、冲突及取消，不能仅凭执行锁证明时间和地点合理。

### 10. 恢复与完整运行入口

- **目标：**从已保存的业务记录核对实际进度并继续运行，贯通故事级工作流。
- **开发：**明确各阶段的保存点、未完成操作、部分失败和结果不确定的处理；恢复时核查故事、场景、事件、状态及 Agent 数据。建立正式入口，串联资料读取、导演规划、审阅、逐层调度、角色演绎、结果记录和向上评估；本轮结束后根据用户选择开始新一轮。
- **验收：**从初始化资料运行示例至父故事结束，覆盖审阅等待、场景中断、状态写入结果不明及恢复；核对实际结果，避免重复产生业务效果。验证构建产物入口；外部模型或服务不可用时明确报告跳过范围。

## 阶段依赖与待讨论事项

前三阶段建立导演、委派和可追溯记录；第四至七阶段逐步接通世界、角色及一次故事演绎；第八至十阶段完善用户控制、并行和完整恢复。开发中若某阶段需要更早持久化或恢复，应先实现并验证满足该阶段的最小能力，不等待最后阶段才处理数据安全。

故事与事件的存储组织、角色实例与调用方式、认知传播、规则计算、状态更新和并行调度的具体方案尚未确定。每项在对应阶段先用具体例子讨论并确认，再形成必要契约和详细计划；本计划不把建议或开发顺序视为已确认的接口设计。
