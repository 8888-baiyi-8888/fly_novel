# 故事级工作流第六阶段：场景演绎与行动判断

本文细化[总体开发计划](story-workflow-development-plan.md)第六阶段，落实[感知分发与下一位回应者](story-workflow.md#感知分发与下一位回应者)。首版复用子导演及其预设，通过单独的结构化调用为一次场景事件给出逐角色感知和下一位回应者。可信应用负责核验、保存、投递和启动角色。按[学习型开发要求](../../development-plan.md#学习型开发要求)逐步实现和验收。

## 前置能力与阶段边界

第四阶段提供版本化场景设置及可重读的世界、地图和提案依据。第五阶段提供参与者身份、逐角色认知、角色实例复用和响应记录。第六阶段把这些能力串成单场景、多轮、逐次唤起一个角色的演绎循环。首版使用场景内序号和固定的相对位置、可听条件；跨场景传播、全局时间调度、长期记忆更新和世界状态写入由后续阶段处理。

第五阶段交接的响应须能按场景和角色定位，保存参与尝试 ID、角色 ID、发言、行动尝试及独立受限的私有内容。发言携带表达方式和目标受话者时应保留该信息，供第六阶段结合现场判断。角色原始会话留在实例内。第六阶段使用经过校验的响应记录驱动互动，并保留原有场景记录读取能力。见[第五阶段开发计划](story-workflow-stage-5-character-participation-plan.md)。

## 分步开发

### 1. 核查入口并冻结城门验收条件

- **输入与动作。** 从[场景设置与结果](../../../src/story-workflow/README.md#保存和读取场景设置)、[世界证据读取](../../../src/app/story-map-scene.ts#L211)和[可信模拟器](../../../src/story-workflow/simulation.ts)追踪场景启动、推进、结算和中断点。读第五阶段实际响应与角色调用接口，确认权限、句柄归属和结果可重读性。准备领队、守卫、副手的固定位置、可听条件、交付规则和场景初始状态。
- **交付及验收。** 只读列出可复用入口及缺口。用同一场景固定三类事件依据：领队私语时副手隔门且不在听闻范围，公开发言时守卫听清而副手只听到片段，位置或环境未核实时保留待确认。副手使用固定验收身份。每条条件都能指出来源及适用时点。

### 2. 建立场景事件和记录映射

- **输入与动作。** 从第五阶段已保存的角色响应提取可感知的发言和行动尝试，按场景序号保存事件与发生时的场景依据。确定初版格式及大小限制。为 `响应 → 事件 → 逐角色感知 → 调度 → 下一次参与尝试` 定义正向和反向读取，保留未收到或待确认的判定。使用同一事件身份绑定本次感知与调度决定，明确完整记录可被读取的保存点。
- **交付及验收。** 可从事件查全部感知判定及调度，或从角色尝试查到实际使用的观察和原始事件。原始响应的私有字段只经授权入口读取。测试未知版本、损坏、重号、悬空引用、跨场景引用和未保存完整的记录。旧场景按原格式继续读取。

### 3. 装配子导演的感知与调度调用

- **输入与动作。** 应用向子导演提供同一时点的场景依据、可感知事件和当时参与者。子导演在一次结构化响应中为每位参与者给出收到、部分收到、未收到或待确认，以及可核对依据。同步返回一位回应者及触发引用，或等待、交导演核查、结束场景的建议。应用核验事件版本、角色覆盖、身份、感知限制和引用。原话片段从原发言取用，声明、转述和推断保留其性质。
- **交付及验收。** 复用子导演预设，建立独立的调用契约和拒绝路径。固定替身验证漏判角色、编造原话、给明确听不到的人投递、使用超范围信息选人，以及输入版本变化时拒绝保存。待确认保留记录并暂缓投递。角色私有 Session 与内心活动不进入子导演调用。

### 4. 接通观察投递和逐角色调度

- **输入与动作。** 应用先保存校验通过的感知与调度决定，再查被选角色在相应时点的待用观察，由第五阶段入口启动或复用其角色实例。其他角色保持静置，获准观察留待自己的轮次。按调度身份和参与尝试关联实际请求采用的观察。说明确认投递、待用和结果不明时的语义。若参与者只等待或拒绝参与，按场景新触发、导演复核或结束推进。
- **交付及验收。** 最小循环实现领队发言、子导演判断、守卫回应。验证副手这轮静置，在自己后续获得新触发时仍能收到此前核准的观察。验证已用触发且场景无变化时停止重复唤起，取消、超时和重开后能查到原尝试，未知结果保持待核查。独占取得已保存的待执行调度，避免并发或重复启动同一回合。

### 5. 接入行动判断、场景结束和结果记录

- **输入与动作。** 当角色提出移车等行动时，分别保存尝试、世界规则判断与导演确认的实际结果。预留世界规则判断接口，首版占位返回 `true` 只表示规则检查通过。将实际发生且可感知的结果作为后续场景事件，继续使用同一感知分发。由子导演判断场景可以结束、仍需等待或需要核查，可信应用核对所保存的状态再写入场景结果。
- **交付及验收。** 验证同一项移车尝试可以受阻、成功或留待核查。守卫只会收到其可感知的实际结果。场景结束可以保留城门关闭和入城未决等结果。按第四阶段既有归属核对场景结果与故事回报，缺失证据的过程仍可独立重读。

### 6. 完成曲水城多轮固定替身验收

- **输入与动作。** 通过正式应用入口读入第四阶段的曲水城场景，以第五阶段的角色调用执行固定多轮。运行私语未被副手听见、公开发言只听到片段、行动被阻及无人回应等路径。中断后重开记录核查，检查原角色会话隔离与重复调用控制。
- **交付及验收。** 按事件或角色回合追溯原始响应、可见性依据、实际模型输入和下一次响应。核对角色请求顺序、未选角色未启动、被撤回和未收到的内容未进入请求、已保存决定和调用失败能区分。运行聚焦测试、类型检查和构建入口冒烟测试，记录实际命令与结果。固定替身与真实模型观察分别报告。
