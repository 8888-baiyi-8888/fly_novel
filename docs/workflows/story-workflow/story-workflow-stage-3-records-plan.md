# 故事级工作流第三阶段：故事、场景与运行记录

本文细化[总体开发计划](story-workflow-development-plan.md)的第三阶段。业务约定以[故事级工作流](story-workflow.md)为准。以下步骤是建议实施顺序，步骤中的能力以各自验收为准。

按[学习型开发要求](../../development-plan.md#学习型开发要求)推进。每步先确定当前使用方式和必要接口，再做最小实现、示例和验证。按实际涉及的记录或会话边界对照 DeepSeek Harness，说明可比范围。完成当前一步后，按用户指示进入下一步。

## 当前基础与阶段目标

[现有模块](../../../src/story-workflow/README.md)已保存初步规划、父子故事节点、拆分与推进决定、模拟经过、回报、提前汇报、父故事评估及批次暂停记录。已有整轮和分批测试可作为回归基线。当前模拟器提供最小子故事的模拟经过，模块缺少供后续角色演绎使用的独立场景记录，以及能从同一个故事身份查到场景、结果和推进位置的核查路径。

本阶段从现有故事记录出发，先让调用方查到故事及其层级，再让一个最小子故事拥有可独立保存和读取的场景，最后核对场景经过、子故事回报与整轮进度。贯穿示例使用曲水城。父故事安排“商队夜间抵达”，第一个场景是城门交涉。测试可让可信模拟器提供“守卫拒绝开门，商队暂留城外”的经过。该经过标为模拟，场景结束与父故事目标达成分别判断。

阶段范围截至业务记录和记录核查。世界资料接入、真实角色 Agent 调用与认知、行动判断和世界事实写入按[总体计划](story-workflow-development-plan.md)的后续阶段开展。完整的异常恢复、并行调度和写作也在本阶段之外。

## 记录边界

| 对象 | 本阶段的职责 | 示例 |
| --- | --- | --- |
| 故事与初步事件 | 保存任务、计划身份、父子关系、推进顺序和已保存的回报引用。初步事件沿用现有身份，选中后关联相应故事。 | “商队夜间抵达”是初步事件。其子故事任务可以是“处理入城请求”。 |
| 场景 | 归属一个可直接演绎的最小子故事。保存相对顺序、处境、演绎经过和结束结果，使调用方能分别读取设置和结果。 | “城门交涉”与“城外安置”是两个可分别核查的场景。 |
| 运行记录 | 记录本轮和本批推进位置，核对故事、场景、回报及完成证据。 | 第一个场景有模拟经过，第二个仍待处理，本轮保持未结束。 |
| 世界事件与状态 | 保留与未来已发生事实及状态写入的职责边界。现阶段使用模拟结果，不从计划、场景或回报生成世界事实。 | 模拟中的“商队扎营”只保留在故事运行内。 |
| Agent Session 与 Memory | 由 Agent 管理。业务记录可关联已有身份供核查。完成由业务结果判断。 | 有一条“已经完成”的消息，但缺少已保存的场景结果时，业务仍待核查。 |

下面建议沿用当前故事工作流的文件存储和身份，不为开发步骤创建源码模块。字段、记录版本、写入约束和查询方式在对应步骤确定。对已有数据，优先采用新增记录的方式。若确实需要变更旧格式，先确定显式兼容、迁移或拒绝读取策略及验证样例，再改读取和写入。

## 分步开发

### 1. 核查现有配置与入口

**输入与动作。** 从[故事应用入口](../../../src/app/story-workflow.ts)、[真实模型调试入口](../../../src/app/story-workflow-debug.ts)和固定替身测试追踪实际生效的配置。核对规划与运行记录的根目录、受保护目录、目录的创建方和读取方，以及每批数量、模型、模拟器、取消和超时分别在哪里设置。按需对照[配置说明](../../../src/config/README.md)和已保存样例，区分入口参数、代码默认值、测试配置与本机配置。

**本步交付。** 一份配置核查清单，每项记录来源、生效入口、默认值或必填条件，以及是否能直接复用。列出文档、配置或实现之间的差异，以及第三阶段确实需要补的缺口。模型配置只记录非敏感设置和凭据引用是否可用。

**完成标准。** 能说明一次曲水城调试的记录写到哪里、由谁指定、继续时读取哪一套目录，并能区别真实调试和固定替身使用的配置。此步只读核查，完成后再进入记录盘点与后续实现。

### 2. 盘点现有记录，确定最小读取路径

**输入与动作。** 用固定模型替身跑一次曲水城规划、多层子故事和分批暂停，从已有记录追踪规划、根故事、子故事、模拟经过、回报、暂停和整轮结果。分别记录每种文件的写入者、身份、读取入口、完成证据和部分写入时的含义。

**本步交付。** 定出第三阶段所需的最小查询清单，包括按规划找到根故事、按故事找到上级和当前安排、按故事列出场景及结果、按批次核查运行位置。确定哪些读取可以直接复用，哪些需要新增。明确老记录缺少场景时的读取语义。

**完成标准。** 能用现有文件解释曲水城一次暂停处于哪个故事和批次，区分已有记录与待补能力。保留一份现有版本样例作为后续兼容验证输入。

### 3. 跑通父子故事读取，建立场景的归属基础

**输入与动作。** 给定可信记录目录、规划 ID 和目标故事 ID，复用或补齐读取能力。沿已保存的根故事、拆分和补充安排定位直接上级、同层顺序及下级结果。查询时区分已安排但还没有节点的事件、已取消事件和已完成故事。

**本步交付。** 一个调用方可用的故事读取入口。它能返回故事任务、直接上级和有记录依据的子项进展，并明确报告身份不匹配、资料缺失或结果无法确认。

**完成标准。** 从重新打开的存储读取根故事、子故事和孙故事，查到正确上级。用其他规划的故事 ID、失配的父 ID 和缺失记录验证拒绝路径。同一规划里尚未开工的子项仍可在安排中找到。

### 4. 保存和重读一个场景

**输入与动作。** 给定一个已确定直接演绎的子故事，用固定资料建立“城门交涉”场景。先实现创建和读取，并能按故事和顺序找到场景。随后用第二个场景验证同一故事可包含多个场景，同一场景只属于一个故事。

**本步交付。** 场景有程序分配的业务身份，关联运行、故事与场景顺序。场景设置至少能表达当前处境和导演准备信息。地点、时间、参与者的引用只纳入本步有实际用途且可核查的部分。

**完成标准。** 重开存储后能找到两个场景并按同一顺序读取。跨运行或错误故事的关联、重复身份或顺序冲突得到明确错误，已有记录保留。已保存设置的场景显示为待演绎。

### 5. 保存场景经过和结果，关联子故事回报

**输入与动作。** 让现有可信模拟器和固定模型替身给“城门交涉”写入一份模拟经过与结束结果，分别验证场景设置已保存、演绎结果已保存、子故事回报已保存三个时点。让一个子故事从两个场景汇总，保留结果引用以便从回报定位原始经过。

**本步交付。** 提供场景结果的保存和读取能力。沿已有演绎与回报入口接入记录，明确一次可信结果何时允许结算场景，何时可以形成子故事回报。单场景结束后仍可继续同故事的下一个场景。正常结束、终止和未决的处理由实际记录区分。

**完成标准。** 重新读取回报时能追到两个场景的原始记录，并明确这些结果是模拟。验证场景结果不可被重复写入覆盖、引用其他故事的场景会被拒绝，以及有设置但无结果或有场景结果但无故事回报时均可正确核查。

### 6. 从保存的证据核查运行进度

**输入与动作。** 分别模拟正常按量暂停、场景设置后中断、结果写入后回报失败，以及整轮结束。用已保存的故事节点、场景结果、子故事回报和批次记录重读这些状态。保留区别正常暂停、结果不确定与完成所需要的最小信息。

**本步交付。** 一个运行进度核查路径。可定位当前故事、相关场景、已经确认的结果和下一待处理位置。在现有按量暂停继续入口上核查新增场景记录与已保存的完成证据，沿用批次独占消费方式。

**完成标准。** 正常暂停可继续，已确认的演绎不重复执行。缺失证据或写入结果不确定时能指出待核查的位置，不自动重放。模拟完成数量仍按最小子故事计算，一个故事包含多个场景也只计一次。Session 有记录而业务结果缺失时，核查结果仍为未完成或待核查。

### 7. 验证从故事到场景和整轮结果的完整读取

**输入与动作。** 使用曲水城的固定资料通过声明入口跑完整例子。规划父子故事，为最小子故事保存两个场景，保存模拟结果并向上回报，按量暂停后重开存储继续，再核对整轮完成记录。

**本步交付。** 可重复运行的集成用例、必要的记录和入口说明，以及供后续场景演绎接入的最小契约。更新相关模块文档和受影响的目录说明。

**完成标准。** 用一组运行 ID 和故事 ID 能查到初步计划、层级、场景设置与经过、回报、暂停或整轮结果。聚焦验证覆盖旧格式、未知版本、损坏、冲突、部分写入、取消和重复继续。报告实际跑过的命令与结果。固定替身用于验证流程和存储，真实模型若另行运行，应单独报告观察范围。
