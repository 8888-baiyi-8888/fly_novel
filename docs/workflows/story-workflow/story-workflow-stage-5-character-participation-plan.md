# 故事级工作流第五阶段：角色调用与认知

本文细化[总体开发计划](story-workflow-development-plan.md)的第五阶段，对应[故事级工作流](story-workflow.md)中的场景组织、提供角色认知与角色首次响应。每步按[学习型开发要求](../../development-plan.md#学习型开发要求)核对实际输入、输出和拒绝条件。接口、格式及验收数据在对应步骤确定。

## 实现路线

从第四阶段已保存的曲水城城门场景出发。在直接演绎故事中，由子导演根据场景提出参与候选和可感知线索，由可信应用核对角色身份、场景归属、资料版本与逐角色授权。应用在当前子故事内按角色首次调用时装配 Agent，后续串行复用同一角色的实例和会话，每次传入本轮独立核准的认知输入。同一场景的守卫和商队领队各自响应。为验证复用，可让守卫在同一子故事收到第二次独立邀请。角色之间的回应传播按第六阶段设计。

## 曲水城的验收资料

| 资料 | 守卫可获知 | 商队领队可获知 | 固定依据 |
| --- | --- | --- | --- |
| 城门关闭、城外有人到达 | 站在值守位置可见城门关闭，可观察到城外车队。 | 站在城外可见城门关闭，知道自己带队抵达。 | 第四阶段场景证据加可信应用批准的分角色观察片段。观察城门关闭只说明眼前状态。 |
| 夜间闭门规定 | 知道值守规定，例外条件以所选交付与角色授权为准。 | 初始输入只提供目视的闭门状态。知道正式规则需要独立的已知来源。 | 交付规则加守卫知悉依据，分别保存来源。 |
| 易腐货物及当前顾虑 | 本轮没有获准知悉商队内部货单或领队的私有顾虑。 | 知道自己的货物容易变质，可以自行决定是否提起。 | 与领队身份绑定的固定事实与个人认知条目。 |
| 临时等候点 | 只有可信应用核实其值守位置、知悉或感知依据后才提供。 | 只有可信应用确认其可观察、已知或收到告知后才提供。 | 第四阶段的采纳记录加逐角色可见性依据。采纳范围限于当前场景。 |
| 导演目标、发展方向及其他角色的私有内容 | 不进入角色输入。 | 不进入角色输入。 | 导演计划用于安排处境，角色响应依据人物自身目标与可知资料。 |

守卫与领队使用可重复生成的固定档案和稳定角色 ID。已有第四阶段样例不用作这两人的正式档案。每个可知条目同时记录世界或场景来源、版本、知悉依据及接收角色。测试附加一条带确切来源的未核实传闻，提示词保留其不确定性。明确未知可作为待辨认的问题，隐藏事实及其内容仍留在授权边界之外。

## 角色实例的归属与复用

- **装配。** 每次直接演绎由应用建立一个绑定 `worldId`、`runId`、`storyId` 的角色实例表，表内以 `characterId` 查找唯一活动实例。应用首次收到已授权邀请时按角色配置调用 `AgentManager.create`。不同角色可使用不同插件，同类角色也可共享预设。第五阶段使用 Agent Loop 默认的实例内 Session，省略持久化 `sessionId`、`resumeSessionId` 和历史种子，由各实例创建自己的空会话。导演请求只含业务角色身份和参与契机。
- **调用。** 应用为每次邀请核对场景与角色，再将本轮获准材料交给该实例的 `run`。Agent Loop 从自身 Session 的 `deriveMessages()` 取得历史。应用每次只向同一实例提交一轮，待上一轮结束再提交下一轮。现有 `cancel()` 会取消当前轮次并拒绝该实例里已排队的轮次。每次参与尝试另存业务记录。
- **重新装配。** 实例表保留所用插件配置版本，以及历次注入会话的资料身份、版本和授权依据。复用前核对旧材料仍允许用于本轮；无法确认时释放实例，重新装配并用本轮获准资料开启空会话。初版角色插件从可信配置装配，进入模型历史的资料须经应用核准并能追溯。失败或中断留下未决轮次时丢弃该活动会话并保留业务记录。子故事切换或进程重开时，应用用获准的已保存业务材料重新组装输入。
- **角色间信息传递。** 角色会话由本角色实例持有。第五阶段保存角色响应，区分发言、行动尝试与私有内容，并保留场景、发出者及响应身份。这些记录中的可感知内容由第六阶段的子导演接手，按[感知分发与下一位回应者](story-workflow.md#感知分发与下一位回应者)判断逐角色感知及下一位回应者。私有认知、内心活动和原始 Session 消息留在各自的角色边界内。
- **释放。** 子故事完成、退出或取消时停止接受新调用，取消活动轮次并等待清理。失败后无法确认会话可安全继续时，释放该实例并保留尝试记录供核查。清理失败须保留错误和原调用状态。实例复用节省重复装配，模型调用次数及 Session 上下文大小仍由实际轮次和输入决定。

## 分步开发

### 1. 核查角色入口、场景接入点和固定资料

- **输入与动作。** 沿 `createCharacterAgent`、角色预设、`delegate_character`、人物存储与场景读取追踪实际输入和生命周期。查看第四阶段固定场景的城门证据、目录版本和地图提案采纳，确认有哪些信息可从既有来源取得。逐项列出守卫与领队档案、角色身份、位置和知悉依据的缺口。
- **交付及验收。** 形成可核对清单，写明来源、版本、选择者、读取者、能力边界和清理责任。列出两名角色各自允许进入提示词的字段，并写明哪些固定数据仍需创建。本步只读。

### 2. 绑定参与请求与角色身份

- **输入与动作。** 以同一世界下已保存、待演绎的城门场景为入口。子导演提出候选角色及当前参与契机，应用在该场景获准候选中解析正式 `characterId`，核对 `worldId`、`runId`、`storyId`、`sceneId` 与人物档案版本。请求只描述处境和回应机会，角色可自主选择如何参与。优先使用现有场景创建后的应用边界承接请求。
- **交付及验收。** 得到可单独核查的参与请求，先用固定身份验证两人分别绑定到正确档案。测试同名异世界、未知角色、无权、缺失或过期档案、错场景与重复请求，均在启动模型前处理。请求记录和 Agent 实例使用独立身份。

实际入口为 `bindStoryCharacters` 和 `selectStoryCharacters`。固定替身在第四阶段场景创建后选择角色，验证候选边界及重复邀请。见[应用说明](../../../src/app/README.md)和[固定替身用例](../../../src/world-init/tests/initialization-delivery-e2e.test.ts)。

### 3. 组装逐角色认知输入

- **输入与动作。** 可信应用逐条读取并授权人物资料、可感知的场景事实和固定既有认知，保留正文片段、来源身份、版本、可见性依据和认知类型。至少能表达眼前观察、自己已知、未核实的传闻与明确未知。模型输入只含该角色的档案片段、处境、自身目标和本轮可知条目。优先显式选取片段，禁止通过全量场景文本、父导演提示词或完整世界证据传递私有信息。
- **交付及验收。** 生成两份可重读、可对照的认知输入。用独有测试字串检查两边提示词都没有收到对方私料、故事发展方向或隐藏地图信息。来源未覆盖、缺失、无权、不可读和版本变化分别处理。必需来源不可核对时停在准备阶段。

绑定的 `prepare` 核对当前场景、档案版本及逐角色授权，返回可供角色调用和保存的版本化来源片段。读取校验拒绝世界发展方向，并将场景正文和地图证据裁剪为获准片段。见[应用说明](../../../src/app/README.md)。

### 4. 装配并复用角色 Agent，取得自主响应

- **输入与动作。** 首次调用按可信角色配置装配，后续同角色调用复用当前子故事持有的实例。每次传入核准输入及取消信号，使用调用级超时。模型返回有类型的发言、行动尝试、等待或不参与。若输出内心活动，使用独立的私有字段，向其他角色和公共场景投影时移除。
- **交付及验收。** 用固定替身验证守卫连续两次调用只装配一次，第二次模型请求带有守卫第一轮的私有测试标记，领队的模型请求没有该标记，反向同样验证。核对两人各自的插件配置和会话。权限收紧后，检查新会话的模型请求及资料来源已移除撤回内容。验证失败后的会话隔离，以及退出和取消时的清理。区分不参与、等待、无效输出、模型失败、超时与取消。模型工具权限按每个角色的可信配置核对，行动尝试保留待判断。

`openStoryCharacterRuntime` 按角色惰性装配并持有实例，每轮重核认知授权。固定替身核对同一角色连续请求的历史、撤回资料后的新会话及对方私有内容隔离。见[角色运行器](../../../src/app/story-character-runtime.ts)。

### 5. 保存参与尝试并接回场景准备

- **输入与动作。** 将 `participationId`、场景及角色身份、调用输入及来源、输出与终态保存为版本化故事记录。第一次启动前记录尝试身份，只有占用而没有可核对结果时保留待核查。相同请求重读原尝试，显式重试使用新身份并保留原记录。向场景提供可用的参与状态、发言和行动尝试。角色业务记录的读取受身份或应用授权控制。
- **交付及验收。** 重开后能从场景找到两名角色分别收到的材料和响应。覆盖一次成功一次失败、重复执行、损坏或未知版本、错误角色读取与关闭后重读。已有场景和模拟记录继续按各自版本读取。角色回应可以独立重读，场景完成仍沿用实际演绎和结果语义。

格式 1 的参与占用先于模型调用保存，结果绑定占用摘要。已授权的场景视图提供可感知响应，完整档案片段与内心活动需按角色授权读取。见[参与记录](../../../src/story-workflow/README.md#角色参与记录)。

### 6. 贯通曲水城的固定替身验收

- **输入与动作。** 使用第四阶段的曲水城城门场景、固定守卫和商队领队，通过正式故事应用入口依次完成候选选择、逐角色认知、角色调用及重读。比较实际模型请求和保存的认知依据。加入同一子故事内再次邀请守卫的用例，核对实例复用，以及领队私有内容始终未进入守卫会话。分别验证领队说出货物风险、不参与及一方调用中断的情况。
- **交付及验收。** 同一场景可从两个角色角度验证资料权限和自主响应，且世界档案及交付不发生写入。按[第六阶段交接要求](story-workflow-stage-6-scene-interaction-plan.md#前置能力与阶段边界)核对响应包含可稳定定位的角色、场景和参与尝试身份，以及可区分的发言、行动尝试和私有内容。运行聚焦测试、类型检查和构建冒烟验证，记录实际命令及结果。固定替身结果与任何另行安排的真实模型观察分别报告。

#### 固定替身验证
